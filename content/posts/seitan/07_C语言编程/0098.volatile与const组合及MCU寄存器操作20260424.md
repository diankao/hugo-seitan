# volatile与const组合及MCU寄存器操作

## 题目

volatile和const同时修饰一个变量是什么含义？MCU寄存器操作中为什么必须加volatile？编译器优化会带来什么问题？

## 考察点

volatile语义、const语义、编译器优化行为、MCU寄存器访问。

## 回答要点

### 1. volatile 和 const 同时修饰的含义

```c
volatile const uint32_t *reg = (volatile const uint32_t *)0x40001000;
```

| 关键字 | 作用 | 含义 |
|--------|------|------|
| `const` | 告诉**编译器**程序不会通过该指针修改值 | 只读（编译期约束） |
| `volatile` | 告诉**编译器**每次都必须从内存读取，不能缓存到寄存器 | 值可能被外部因素改变 |

**组合含义**：这个变量的值可能随时被硬件或其他因素改变，我的代码不会去修改它喵~

**典型场景**：只读硬件寄存器喵~

```c
#define UART_SR   (*(volatile const uint32_t *)0x40011000)
#define UART_DR   (*(volatile uint32_t *)0x40011004)

uint8_t uart_read(void) {
    while (!(UART_SR & (1 << 5)));
    return (uint8_t)UART_DR;
}
```

- `UART_SR` 是 `volatile const`：状态寄存器，程序只读，但硬件随时改变它
- `UART_DR` 是 `volatile`（非 const）：数据寄存器，程序需要写入

### 2. 为什么 MCU 寄存器必须加 volatile

#### 不加 volatile 的后果

```c
uint32_t *sr = (uint32_t *)0x40011000;

while (!(*sr & 0x20)) {
}
```

编译器看到 `*sr` 在循环中没被修改，会优化为**只读一次**喵~

```arm
; 优化前（正确）
loop:
    LDR   R0, [SR_ADDR]
    TST   R0, #0x20
    BEQ   loop

; 优化后（错误！死循环）
    LDR   R0, [SR_ADDR]     ; 只读一次
loop:
    TST   R0, #0x20         ; 永远用同一个值
    BEQ   loop
```

#### 编译器优化带来的三类问题

| 问题 | 描述 | 示例 |
|------|------|------|
| 缓存到寄存器 | 编译器认为变量不变，只读一次存入寄存器 | 等待标志位变成死循环 |
| 删除"冗余"读写 | 编译器认为连续两次写同一变量，第一次无意义 | 连续写寄存器被删掉一次 |
| 指令重排 | 编译器认为不影响单线程语义，重排读写顺序 | 先写数据后写使能，被重排反了 |

```c
volatile uint32_t *ctrl = (volatile uint32_t *)0x40001000;
volatile uint32_t *data = (volatile uint32_t *)0x40001004;

*data = 0x42;
*ctrl = 0x01;
```

加了 `volatile`，编译器保证按源码顺序执行喵~ 不加的话，编译器可能先写 `ctrl` 再写 `data`，导致触发时数据还没准备好喵~

### 3. volatile 的局限性

| volatile 能做的 | volatile 不能做的 |
|----------------|------------------|
| 阻止编译器缓存变量 | 不保证原子性（多字节读写仍可被打断） |
| 阻止编译器重排 | 不提供硬件内存屏障（多核可见性） |
| 保证每次从内存读取 | 不替代锁/信号量等同步机制 |

### 4. volatile 的常见应用场景

| 场景 | 原因 |
|------|------|
| 硬件寄存器 | 值由硬件改变，编译器不知道 |
| 中断与主循环共享变量 | 值由 ISR 改变，编译器不知道 |
| 多线程共享变量（单核） | 值由其他线程改变 |
| DMA 缓冲区 | 值由 DMA 控制器改变 |
| setjmp/longjmp 之后的局部变量 | 防止编译器将变量缓存在寄存器中 |

### 5. CMSIS 中的寄存器定义

```c
// CMSIS 标准库中所有寄存器都是 volatile
typedef struct {
    __IO uint32_t CR;
    __IO uint32_t CFGR;
    __IO uint32_t CIR;
    __IO uint32_t APB1RSTR;
} RCC_TypeDef;

// __IO 展开为 volatile
#define __IO volatile

// __I 展开为 volatile const（只读寄存器）
#define __I  volatile const

// __O 展开为 volatile（只写寄存器，实际就是 volatile）
#define __O  volatile
```
