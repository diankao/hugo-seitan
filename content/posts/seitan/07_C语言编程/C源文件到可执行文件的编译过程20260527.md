# C源文件到可执行文件的编译过程

## 题目

C 文件到可执行文件经历哪些步骤？

## 考察点

编译原理基础、GCC 工具链、预处理/编译/汇编/链接四个阶段的输入输出。

## 回答要点

### 1. 四个阶段总览

```
main.c ──[预处理]──> main.i ──[编译]──> main.s ──[汇编]──> main.o ──[链接]──> a.out
         预处理器          编译器          汇编器          链接器
        (cpp/cc1)        (cc1)          (as)           (ld)
```

| 阶段 | 工具 | 输入 | 输出 | 做了什么 |
|------|------|------|------|---------|
| 预处理 | cpp / cc1 | `.c` | `.i` | 展开宏、处理 #include、条件编译 |
| 编译 | cc1 | `.i` | `.s` | 语法分析 → 中间代码 → 优化 → 汇编 |
| 汇编 | as | `.s` | `.o` | 汇编指令 → 机器码（目标文件） |
| 链接 | ld | `.o` + 库 | 可执行文件 | 符号解析、地址重定位 |

### 2. 阶段一：预处理（Preprocessing）

```bash
gcc -E main.c -o main.i
```

**处理内容**：

| 指令 | 处理方式 |
|------|---------|
| `#include <stdio.h>` | 将头文件内容**原样插入** |
| `#define MAX 100` | 全文替换 `MAX` → `100` |
| `#ifdef DEBUG ... #endif` | 条件为真保留，为假删除 |
| `#pragma` | 传递给编译器 |
| 注释 `//` `/* */` | **全部删除** |

```c
// main.c
#include <stdio.h>
#define MAX 100

int main(void) {
    int arr[MAX]; // 定义数组
    printf("%d\n", MAX);
    return 0;
}

// 预处理后 main.i（简化）
// ... stdio.h 的几千行内容 ...
int main(void) {
    int arr[100];
    printf("%d\n", 100);
    return 0;
}
```

### 3. 阶段二：编译（Compilation）

```bash
gcc -S main.i -o main.s
```

**处理流程**：

```
词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 优化 → 汇编代码生成
```

- **词法分析**：将源码拆成 token（关键字、标识符、常量、运算符）
- **语法分析**：构建抽象语法树（AST），检查语法错误
- **语义分析**：类型检查、作用域检查
- **中间代码**：生成平台无关的中间表示（如 GIMPLE/RTL）
- **优化**：常量折叠、死代码消除、循环优化等
- **生成汇编**：输出对应架构的汇编指令

```asm
// main.s（ARM64）
    .section .text
    .globl main
main:
    stp x29, x30, [sp, -32]!
    mov x29, sp
    mov w0, #100
    str w0, [sp, 28]
    adrp x0, .LC0
    add x0, x0, :lo12:.LC0
    bl printf
    mov w0, #0
    ldp x29, x30, [sp], 32
    ret
```

### 4. 阶段三：汇编（Assembly）

```bash
gcc -c main.s -o main.o
# 或
as main.s -o main.o
```

将汇编指令翻译为**机器码**，生成**可重定位目标文件**（`.o`）。

```
main.o 的结构（ELF格式）：

┌──────────────┐
│ ELF Header   │  文件类型、架构、入口点
├──────────────┤
│ .text        │  代码段（机器指令）
├──────────────┤
│ .data        │  已初始化的全局/静态变量
├──────────────┤
│ .bss         │  未初始化的全局/静态变量（不占文件空间）
├──────────────┤
│ .symtab      │  符号表（函数名、变量名及其地址）
├──────────────┤
│ .rel.text    │  需要重定位的代码位置
├──────────────┤
│ .rel.data    │  需要重定位的数据位置
└──────────────┘
```

**关键点**：此时函数调用和全局变量的地址还是**占位符**（0），需要链接器填充真实地址。

### 5. 阶段四：链接（Linking）

```bash
gcc main.o utils.o -o main -lm
# 或
ld main.o utils.o -o main -lc -lm
```

**链接器做两件事**：

#### 5.1 符号解析（Symbol Resolution）

将每个目标文件中引用的符号（函数名、变量名）与其定义关联起来。

```
main.o:
    调用 printf   → 未定义符号，需要在 libc 中找到
    调用 my_func  → 未定义符号，需要在 utils.o 中找到
    定义 main     → 导出符号

utils.o:
    定义 my_func  → 导出符号
    调用 malloc  → 未定义符号，需要在 libc 中找到
```

如果找不到某个符号的定义 → **链接错误**（`undefined reference`）。

如果同一个符号有多个定义 → **链接错误**（`multiple definition`）。

#### 5.2 地址重定位（Relocation）

将每个 .o 文件中的占位地址替换为真实的内存地址。

```
重定位前（main.o 中）：
    bl 0x00000000    // 调用 printf，地址是占位符

重定位后（可执行文件中）：
    bl 0x7ffff7a8400 // printf 的真实地址
```

#### 5.3 静态链接 vs 动态链接

| 特性 | 静态链接 | 动态链接 |
|------|---------|---------|
| 链接时机 | 编译时 | 运行时 |
| 库文件 | `.a`（静态库） | `.so`（共享库） |
| 可执行文件大小 | 大（包含库代码） | 小（只包含引用） |
| 更新库 | 需重新编译 | 替换 .so 即可 |
| 启动速度 | 快 | 略慢（需加载 .so） |

### 6. 一步到位的命令

```bash
# 完整编译（四个阶段一步完成）
gcc main.c -o main

# 分步执行
gcc -E main.c -o main.i       # 预处理
gcc -S main.i -o main.s       # 编译
gcc -c main.s -o main.o       # 汇编
gcc main.o -o main            # 链接

# 嵌入式交叉编译示例
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -Os main.c -o main.elf
arm-none-eabi-objcopy -O binary main.elf main.bin  # 生成烧录文件
```

### 7. 常见错误对应阶段

| 错误类型 | 出现阶段 | 示例 |
|---------|---------|------|
| 语法错误 | 编译 | `error: expected ';' before '}'` |
| 未声明标识符 | 编译 | `error: 'printf' undeclared` |
| 类型不匹配 | 编译 | `warning: implicit conversion` |
| 未定义引用 | 链接 | `undefined reference to 'my_func'` |
| 多重定义 | 链接 | `multiple definition of 'var'` |
| 找不到头文件 | 预处理 | `fatal error: 'myheader.h' file not found` |
| 宏展开错误 | 预处理 | 宏参数副作用等运行时问题 |

### 8. 面试速记

- **四个阶段**：预处理 → 编译 → 汇编 → 链接
- **预处理**：展开宏和 #include，删除注释
- **编译**：源码 → 汇编代码（语法检查、优化）
- **汇编**：汇编代码 → 机器码（.o 目标文件）
- **链接**：合并 .o 文件，解析符号，重定位地址
- **语法错误在编译阶段，undefined reference 在链接阶段**
