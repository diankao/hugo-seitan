# C++模板元编程与泛型编程

## 题目

C++ 模板是什么？模板元编程是怎么回事？泛型编程和面向对象编程有什么区别？`typename` 和 `class` 有什么区别？

## 考察点

模板基础语法、模板特化与偏特化、SFINAE、C++20 concepts、编译期计算、模板在嵌入式中的应用

## 回答要点

### 1. 模板基础：为什么需要模板

C++ 模板的核心动机：**写一份代码，适用于多种类型**。

```cpp
// 不用模板：每种类型写一个函数
int maxValue(int a, int b) { return a > b ? a : b; }
float maxValue(float a, float b) { return a > b ? a : b; }

// 用模板：一份代码覆盖所有可比较类型
template<typename T>
T maxValue(T a, T b) {
    return a > b ? a : b;
}

maxValue(3, 5);          // T = int
maxValue(1.5f, 2.3f);    // T = float
maxValue<std::string>("hello", "world");  // 显式指定
```

**模板 vs C 宏的对比：**

| 维度 | 宏（#define） | 模板（template） |
|------|-------------|----------------|
| 类型安全 | 无 | 有 |
| 调试 | 难（预处理阶段展开） | 较易（编译阶段） |
| 作用域 | 全局 | 遵循作用域规则 |
| 错误信息 | 难读 | C++20 前也难读，concepts 改善 |
| 复杂逻辑 | 困难 | 支持（特化、偏特化、SFINAE） |

### 2. 函数模板与类模板

**函数模板：**

```cpp
template<typename T>
T maxValue(T a, T b) {
    return a > b ? a : b;
}

// 模板重载
template<typename T>
T maxValue(T a, T b, T c) {
    return maxValue(maxValue(a, b), c);
}
```

**类模板：**

```cpp
template<typename T, int Size>
class RingBuffer {
    T buffer[Size];
    int head = 0, tail = 0, count = 0;
public:
    bool push(const T& item) {
        if (count >= Size) return false;
        buffer[tail] = item;
        tail = (tail + 1) % Size;
        ++count;
        return true;
    }

    bool pop(T& item) {
        if (count <= 0) return false;
        item = buffer[head];
        head = (head + 1) % Size;
        --count;
        return true;
    }

    bool isEmpty() const { return count == 0; }
    bool isFull() const { return count >= Size; }
};

RingBuffer<int, 64> intBuf;       // 嵌入式常用：固定大小环形缓冲区
RingBuffer<float, 32> floatBuf;
```

### 3. 模板参数：类型参数与非类型参数

```cpp
// 类型参数（最常见）
template<typename T>
struct Wrapper { T value; };

// 非类型参数（整数、枚举、指针等）
template<typename T, int N>
struct Array { T data[N]; };

// 模板模板参数
template<typename T, template<typename> class Container>
class Stack {
    Container<T> data;
};

Stack<int, std::vector> s;  // Container = std::vector
```

**`typename` vs `class`：**

在模板参数声明中两者完全等价。但 `typename` 还有第二个用途：告诉编译器某个依赖模板参数的名称是类型。

```cpp
template<typename T>
void func() {
    // T::iterator 可能是类型，也可能是静态变量
    // 必须用 typename 明确告诉编译器这是类型
    typename T::iterator it;
}
```

**建议：模板参数统一用 `typename`，更语义化。**

### 4. 模板特化与偏特化

**全特化：** 对某个具体类型提供专门实现。

```cpp
// 通用版本
template<typename T>
struct TypeInfo {
    static const char* name() { return "unknown"; }
    static int size() { return sizeof(T); }
};

// 全特化：针对 int
template<>
struct TypeInfo<int> {
    static const char* name() { return "int"; }
    static int size() { return 4; }
};

// 全特化：针对指针类型
template<typename T>
struct TypeInfo<T*> {
    static const char* name() { return "pointer"; }
};
```

**偏特化：** 对一类类型提供实现（仅类模板支持）。

```cpp
// 通用版本
template<typename T, typename Alloc>
class Vector { /* ... */ };

// 偏特化：固定第二个参数
template<typename T>
class Vector<T, MyAlloc> { /* ... */ };

// 偏特化：针对数组类型
template<typename T, int N>
struct ArraySize {
    static constexpr int value = N;
};

// 偏特化：嵌套数组
template<typename T, int N, int M>
struct ArraySize<T[N][M]> {
    static constexpr int value = N * M;
};
```

### 5. SFINAE —— 替换失败不是错误

SFINAE（Substitution Failure Is Not An Error）是模板元编程的核心机制：模板参数替换失败时，不会报编译错误，而是将该重载从候选集中移除。

```cpp
#include <type_traits>
#include <iostream>
#include <vector>

// 只对整数类型启用
template<typename T>
typename std::enable_if<std::is_integral<T>::value, T>::type
process(T value) {
    std::cout << "整数处理: " << value << std::endl;
    return value * 2;
}

// 只对浮点类型启用
template<typename T>
typename std::enable_if<std::is_floating_point<T>::value, T>::type
process(T value) {
    std::cout << "浮点处理: " << value << std::endl;
    return value + 0.5;
}

// 只对有 size() 方法的类型启用
template<typename T>
auto getSize(const T& container) -> decltype(container.size()) {
    return container.size();
}

process(42);        // 调用整数版本
process(3.14);      // 调用浮点版本
// process("hello"); // 编译错误：两个重载都不匹配
```

**SFINAE 常用工具：**

| 工具 | 用途 |
|------|------|
| `std::enable_if` | 条件启用/禁用模板 |
| `std::is_integral` | 判断是否整数类型 |
| `std::is_pointer` | 判断是否指针 |
| `std::is_same` | 判断两个类型是否相同 |
| `std::decay` | 去除引用和 cv 限定 |
| `decltype` | 获取表达式类型 |

### 6. C++20 Concepts —— 模板约束的现代写法

Concepts 大幅简化了 SFINAE 的写法，编译错误信息也更友好。

```cpp
#include <concepts>
#include <iostream>

// 定义 concept
template<typename T>
concept Numeric = std::is_arithmetic_v<T>;

template<typename T>
concept HasSize = requires(T t) {
    { t.size() } -> std::convertible_to<std::size_t>;
};

// 用 concept 约束模板
template<Numeric T>
T add(T a, T b) {
    return a + b;
}

// requires 子句写法
template<typename T>
    requires HasSize<T>
void printSize(const T& container) {
    std::cout << "Size: " << container.size() << std::endl;
}

// 多种写法等价
template<typename T> requires std::integral<T> void foo(T);
template<std::integral T> void foo(T);
void foo(std::integral auto x);
```

**Concepts vs SFINAE 对比：**

| 维度 | SFINAE | Concepts |
|------|--------|----------|
| 可读性 | 差 | 好 |
| 错误信息 | 几百行模板展开 | 直接告诉你哪个约束不满足 |
| 组合性 | 困难 | `requires` 可组合 |
| 标准 | C++11 起 | C++20 起 |

### 7. 编译期计算与 constexpr

```cpp
// 编译期阶乘
constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}
static_assert(factorial(5) == 120);  // 编译期计算

// 编译期斐波那契
template<int N>
struct Fibonacci {
    static constexpr int value = Fibonacci<N-1>::value + Fibonacci<N-2>::value;
};

template<>
struct Fibonacci<0> { static constexpr int value = 0; };

template<>
struct Fibonacci<1> { static constexpr int value = 1; };

static_assert(Fibonacci<10>::value == 55);

// C++14+ 更推荐用 constexpr 函数代替模板元编程
constexpr int fib(int n) {
    int a = 0, b = 1;
    for (int i = 0; i < n; ++i) {
        int tmp = a + b;
        a = b;
        b = tmp;
    }
    return a;
}
static_assert(fib(10) == 55);
```

### 8. 模板在嵌入式中的实际应用

**固定大小容器（无动态分配）：**

```cpp
template<typename T, int MaxSize>
class StaticVector {
    alignas(T) unsigned char storage[sizeof(T) * MaxSize];
    int count = 0;
public:
    bool push_back(const T& item) {
        if (count >= MaxSize) return false;
        new(&storage[count * sizeof(T)]) T(item);
        ++count;
        return true;
    }

    T& operator[](int i) {
        return *reinterpret_cast<T*>(&storage[i * sizeof(T)]);
    }

    int size() const { return count; }
};
```

**寄存器操作（零开销抽象）：**

```cpp
template<uintptr_t Addr>
struct Reg32 {
    static volatile uint32_t* ptr() {
        return reinterpret_cast<volatile uint32_t*>(Addr);
    }
    static void write(uint32_t val) { *ptr() = val; }
    static uint32_t read() { return *ptr(); }
    static void setBits(uint32_t mask) { *ptr() |= mask; }
    static void clearBits(uint32_t mask) { *ptr() &= ~mask; }
};

// STM32 GPIOA_ODR 地址
using GPIOA_ODR = Reg32<0x40020014>;
GPIOA_ODR::setBits(1 << 5);   // PA5 输出高电平
GPIOA_ODR::clearBits(1 << 5); // PA5 输出低电平
```

**类型安全的硬件抽象：**

```cpp
template<int Pin>
struct GpioPin {
    static void setHigh() { GPIOA_ODR::setBits(1 << Pin); }
    static void setLow()  { GPIOA_ODR::clearBits(1 << Pin); }
    static void toggle()  { *GPIOA_ODR::ptr() ^= (1 << Pin); }
};

using LedRed = GpioPin<5>;
using LedGreen = GpioPin<6>;

LedRed::setHigh();
LedGreen::toggle();
```

### 9. 常见面试追问

**Q：模板代码写在哪里？头文件还是源文件？**

模板定义通常放在头文件中。因为模板在实例化时编译器需要看到完整定义。如果放在 `.cpp` 中，其他编译单元无法实例化。可以用显式实例化（`extern template`）减少编译时间和代码膨胀。

**Q：模板会导致代码膨胀吗？**

会。每种不同的模板参数组合都会生成一份代码。`Vector<int>` 和 `Vector<float>` 是两个独立的类。缓解方法：把与类型无关的逻辑提取到非模板基类中。

**Q：泛型编程和面向对象编程有什么区别？**

| 维度 | 面向对象（OOP） | 泛型编程（GP） |
|------|----------------|---------------|
| 多态方式 | 运行时（虚函数） | 编译时（模板） |
| 性能 | 有虚表开销 | 零开销 |
| 类型约束 | 继承体系 | concepts / SFINAE |
| 灵活性 | 需要公共基类 | 任何满足接口的类型 |
| 适用场景 | 运行时多态 | 编译时多态、性能敏感 |

**Q：嵌入式项目中用模板需要注意什么？**

- 控制模板实例化数量，避免 Flash 膨胀
- 优先用 `constexpr` 函数代替复杂的模板元编程
- 使用静态断言（`static_assert`）在编译期捕获错误
- 注意模板代码对编译器优化的敏感性（不同编译器/优化级别行为可能不同）
