# assert断言机制

## 题目

1. assert 的作用是什么？
2. assert 和静态断言 static_assert 有什么区别？
3. 在嵌入式开发中如何合理使用 assert？

## 考察点

断言机制的理解、调试与发布模式的区别、防御性编程思想、嵌入式场景下的断言策略。

## 回答要点

### 1. assert 基本概念

`assert` 是 C 标准库 `<assert.h>` 提供的宏，用于在运行时检查一个条件是否为真。如果条件为假，程序会终止并输出诊断信息喵~

```c
#include <assert.h>

void process(int *ptr, int size) {
    assert(ptr != NULL);
    assert(size > 0);
    assert(size <= 1024);

    for (int i = 0; i < size; i++) {
        ptr[i] = i * 2;
    }
}
```

当 `assert` 失败时，输出类似：

```
Assertion failed: ptr != NULL, file main.c, line 5
```

### 2. assert 的工作原理

```c
#ifdef NDEBUG
#define assert(condition) ((void)0)
#else
#define assert(condition) \
    ((condition) ? (void)0 : __assert_fail(#condition, __FILE__, __LINE__, __func__))
#endif
```

| 模式 | 宏定义 | assert 行为 |
|------|--------|------------|
| Debug | 未定义 `NDEBUG` | 检查条件，失败则终止 |
| Release | 定义了 `NDEBUG` | 完全移除，零开销 |

在 Release 模式下，`assert` 被编译器完全移除，不产生任何代码喵~

### 3. assert 的使用原则

#### 应该用 assert 的场景

```c
int stack_pop(Stack *s) {
    assert(s != NULL);
    assert(s->top > 0);
    return s->data[--s->top];
}

void array_set(int *arr, int index, int value, int capacity) {
    assert(index >= 0 && index < capacity);
    arr[index] = value;
}
```

这些是**开发者假设为真的不变量**，如果违反说明程序有 bug 喵~

#### 不应该用 assert 的场景

```c
FILE *fp = fopen("config.txt", "r");
assert(fp != NULL);

int *p = (int *)malloc(100 * sizeof(int));
assert(p != NULL);
```

文件打开失败、内存分配失败是**合法的运行时错误**，应该用错误处理而非断言喵~

正确做法：

```c
FILE *fp = fopen("config.txt", "r");
if (fp == NULL) {
    perror("fopen failed");
    return -1;
}

int *p = (int *)malloc(100 * sizeof(int));
if (p == NULL) {
    fprintf(stderr, "malloc failed\n");
    return -1;
}
```

### 4. assert vs 错误处理

| 维度 | assert | 错误处理（if/return） |
|------|--------|----------------------|
| 目的 | 发现编程 bug | 处理运行时异常 |
| Release 行为 | 被移除 | 始终存在 |
| 失败后 | 终止程序 | 可恢复 |
| 适用场景 | 不变量检查 | 用户输入、IO、网络 |
| 例子 | `assert(index < size)` | `if (fp == NULL)` |

### 5. 静态断言 static_assert（C11）

`static_assert` 在**编译时**进行检查，不产生运行时开销喵~

```c
#include <assert.h>

static_assert(sizeof(int) == 4, "int must be 4 bytes");
static_assert(sizeof(void *) == 8, "64-bit platform required");

typedef struct {
    uint8_t  id;
    uint16_t value;
} sensor_data_t;

static_assert(sizeof(sensor_data_t) <= 8, "sensor_data_t too large for CAN frame");
```

| 维度 | assert | static_assert |
|------|--------|---------------|
| 检查时机 | 运行时 | 编译时 |
| 条件要求 | 运行时表达式 | 常量表达式 |
| Release 行为 | 被移除 | 始终存在（编译期） |
| 典型用途 | 参数检查 | 类型大小、平台约束 |
| 头文件 | `<assert.h>` | `<assert.h>`（C11） |

### 6. 嵌入式中的 assert 策略

#### 6.1 自定义断言宏

嵌入式系统中 `printf` 和 `abort()` 可能不可用，需要自定义断言行为喵~

```c
#define EMBED_ASSERT(expr) \
    do { \
        if (!(expr)) { \
            LogError("ASSERT FAIL: %s, %s:%d", #expr, __FILE__, __LINE__); \
            NVIC_SystemReset(); \
        } \
    } while(0)
```

#### 6.2 不同安全等级的策略

| 安全等级 | assert 行为 | 适用场景 |
|---------|------------|---------|
| 调试阶段 | 串口打印 + 死循环 | 开发调试 |
| 测试阶段 | 日志记录 + 软复位 | 集成测试 |
| 生产阶段 | 完全禁用或仅记录 | 正式发布 |
| 安全关键 | 不可禁用，触发安全状态 | 医疗/航空 |

#### 6.3 MISRA C 对 assert 的态度

MISRA C 对 `assert` 有限制：

- **Rule 11.4**：建议不要使用库函数 `assert`
- 原因：`assert` 失败会导致程序终止，在安全关键系统中不可接受
- 替代方案：使用自定义的错误处理机制，进行优雅降级

```c
typedef enum {
    ERR_NONE = 0,
    ERR_NULL_PARAM,
    ERR_INVALID_RANGE,
    ERR_HARDWARE_FAULT
} error_code_t;

error_code_t sensor_read(sensor_t *sensor, float *out) {
    if (sensor == NULL || out == NULL) {
        return ERR_NULL_PARAM;
    }
    if (!sensor->initialized) {
        return ERR_HARDWARE_FAULT;
    }

    *out = ADC_Read(sensor->channel);
    return ERR_NONE;
}
```

### 7. 常见面试题

#### Q1：assert 能否检查内存分配失败？

不能。`malloc` 返回 `NULL` 是合法的运行时行为，不是 bug。应该用 `if` 检查喵~

#### Q2：Release 版本中 assert 还有效吗？

无效。定义了 `NDEBUG` 后，`assert` 被替换为 `((void)0)`，完全不产生代码喵~

#### Q3：如何在 Release 版本中保留检查？

使用自定义宏，或者直接用 `if` 条件判断喵~

```c
#ifdef DEBUG
#define CHECK(cond) assert(cond)
#else
#define CHECK(cond) \
    do { if (!(cond)) { log_error("check failed: %s", #cond); } } while(0)
#endif
```

### 8. 总结

| 要点 | 说明 |
|------|------|
| assert 本质 | 调试期的不变量检查宏 |
| Release 行为 | 被完全移除，零开销 |
| 正确用法 | 检查开发者假设（前置条件、不变量） |
| 错误用法 | 检查运行时错误（IO、内存、网络） |
| static_assert | 编译时检查，C11 引入 |
| 嵌入式建议 | 自定义断言宏，根据安全等级选择策略 |
