# C11文件独占创建x模式

## 题目

C11 标准为 `fopen()` 新增了带 `x` 字母的写模式（`"wx"`、`"wbx"`、`"w+x"` 等）。围绕这个模式：

1. `x` 模式的语义是什么？文件已存在时打开会发生什么？
2. 使用 `x` 模式打开失败时，已存在的源文件内容会受影响吗？它与不带 `x` 的 `w` 模式有什么区别？

## 考察点

`fopen()` 各文件打开模式的语义、C11 新增 `x` 后缀的独占创建（exclusive create）行为及其失败时的安全性。

## 回答要点

### 1. x 模式解决什么问题

先看传统 `"w"` 模式的危险之处：

```c
FILE *fp = fopen("config.ini", "w");
```

- 如果 `config.ini` 已存在，这一行执行瞬间文件就被**截断为 0**（长度清空、内容销毁），不管你后面写入是否成功；
- 常见事故：两个进程同时用 `"w"` 打开同一文件互相覆盖；脚本误把输出重定向到源文件；把要"追加"的文件错用 `"w"` 打开导致原始数据全丢。

C11 的 `x` 后缀把"检查不存在 + 创建"做成**原子操作**，语义是**独占创建（exclusive create）**：

- 文件不存在 → 创建并打开，其余行为同 `w`；
- 文件已存在 → 打开失败返回 `NULL`，`errno` 置为 `EEXIST`，**原文件一个字节都不动**。

"独占创建"的核心价值就是**保护已有文件**：带 `x` 的模式打开失败时（文件已存在、权限不足等），源文件内容毫发无损，绝不会因为打开失败而被删掉。

```c
FILE *fp = fopen("config.ini", "wx");
if (fp == NULL) {
    if (errno == EEXIST) {
        printf("config.ini 已存在，拒绝覆盖\n");
    }
    return -1;
}
```

典型用途：锁文件（lock file）、只允许初始化一次的配置、防止多实例重复创建。

### 2. 常用模式组合速查

| 模式 | 文件不存在时 | 文件已存在时 | 读 | 写 | 备注 |
|------|-------------|-------------|----|----|------|
| `"r"` | 失败 | 从头读 | ✓ | ✗ | 只读打开的默认选择 |
| `"w"` | 新建 | **截断为 0** | ✗ | ✓ | 会毁掉已有内容 |
| `"a"` | 新建 | 在末尾追加 | ✗ | ✓ | 日志文件常用 |
| `"r+"` | 失败 | 保留内容，可读写 | ✓ | ✓ | 就地修改 |
| `"w+"` | 新建 | **截断为 0** | ✓ | ✓ | 同样会清空 |
| `"a+"` | 新建 | 追加 | ✓ | 写只能追加 | |
| `"wx"` / `"wbx"` / `"w+x"` | 新建 | **打开失败（EEXIST）** | ✗或✓ | ✓ | C11 独占创建，失败不伤原文件 |

规律：

- `b` 只影响换行符处理（文本/二进制），在 Linux 上无差别，Windows 上必须区分；
- `x` 只能与 `w` 系组合（独占**创建**），不能接在 `r`、`a` 后面；
- 判断失败原因用 `errno`：`EEXIST` 表示文件已存在，`EACCES` 表示权限不足。

### 3. 与其他"安全创建"手段的关系

| 手段 | 层面 | 特点 |
|------|------|------|
| `fopen("...", "wx")` | C 标准库（C11 起） | 可移植性最好，跨平台代码首选 |
| `open(path, O_CREAT \| O_EXCL, mode)` | POSIX 系统调用 | Linux 下更底层，`O_EXCL` 与 `O_CREAT` 组合即独占创建 |
| Windows `_wfopen(..., "wx")` / `CreateFile(CREATE_NEW)` | Windows | MSVC 的 CRT 早已支持 x，`CREATE_NEW` 是原生 API 等价物 |

`O_CREAT | O_EXCL` 与 `"wx"` 语义同源：检查与创建是原子的，天然适合做跨进程的互斥锁文件。

### 4. 小结

- `w` 系模式打开已有文件 = **截断清空**，这是默认的破坏性行为；
- `x` 后缀 = **独占创建**：只有文件不存在才成功，失败时原文件**绝不会**被删除；
- 实践建议：凡是"这个文件本不该存在"的场景（锁文件、首次初始化），优先用 `"wx"` 代替 `"w"`，把误覆盖扼杀在打开阶段。
