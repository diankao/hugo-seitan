# vector扩容原理与性能优化

## 题目

1. `vector` 扩容原理是什么？
2. 如何避免 `vector` 频繁扩容？

## 考察点

STL 动态数组底层机制、均摊时间复杂度、内存与性能优化。

## 回答要点

### 1. vector 的三根指针模型

`std::vector` 本质是管理一块连续内存的动态数组，内部用三个指针描述当前状态：

```cpp
template <typename T, typename Alloc>
class vector {
    T* start_;          // 当前内存块起始
    T* finish_;         // 已使用元素末尾（size）
    T* end_of_storage_; // 内存块末尾（capacity）
public:
    size_t size()     const { return finish_      - start_; }
    size_t capacity() const { return end_of_storage_ - start_; }
};
```

```
start_         finish_       end_of_storage_
  │              │                  │
  ▼              ▼                  ▼
  [0][1][2][3][4][ ][ ][ ][ ][ ]    ← 已用 size=5, 容量 capacity=10
  └──── 已使用 ──┘└─── 未使用 ───┘
```

### 2. 扩容的触发与流程

当 `size == capacity` 时再 `push_back`，必须扩容：

```cpp
void push_back(const T& value) {
    if (finish_ == end_of_storage_) {
        grow();                  // 扩容
    }
    *finish_ = value;
    ++finish_;
}

void grow() {
    size_t old_cap = capacity();
    size_t new_cap = old_cap == 0 ? 1 : old_cap * 2;   // 2 倍增长（MSVC）或 1.5 倍（GCC/Clang）

    // 1. 分配新内存
    T* new_mem = allocator::allocate(new_cap);

    // 2. 把旧元素"移动"或拷贝到新内存
    for (size_t i = 0; i < size(); ++i) {
        new (new_mem + i) T(std::move_if_noexcept(start_[i]));
    }

    // 3. 析构旧元素
    for (size_t i = 0; i < size(); ++i) {
        start_[i].~T();
    }

    // 4. 释放旧内存
    allocator::deallocate(start_, old_cap);

    // 5. 更新三指针
    finish_           = new_mem + size();
    start_            = new_mem;
    end_of_storage_   = new_mem + new_cap;
}
```

扩容的关键点：
- **新容量按倍数增长**：GCC/Clang 用 2 倍，MSVC 用 1.5 倍。
- **整体搬移**：分配 → 移动/拷贝 → 析构旧 → 释放旧。
- **指针、迭代器、引用全部失效**：因为底层内存地址变了。

### 3. 为什么是 2 倍或 1.5 倍？均摊 O(1)

每次扩容把容量翻倍，使得 `push_back` 的**均摊时间复杂度为 O(1)**：

```
容量序列（2倍）：1, 2, 4, 8, 16, 32, ...
push_back n 次，总搬移次数 ≈ n/2 + n/4 + ... + 1 ≈ n
平均每次 ≈ 1 次拷贝
```

#### 1.5 倍 vs 2 倍

| 增长因子 | 内存利用率 | 复用机会 | 典型实现 |
|---------|-----------|---------|---------|
| 1.5 倍 | 较好 | 经过几次扩容后，旧的内存块大小可能正好等于某次新容量，可被复用 | MSVC、Facebook folly |
| 2 倍 | 较差（永远无法复用旧块） | 无 | libstdc++、libc++ |

数学上：当增长因子 < 2（如 1.5）时，`F(n) - F(n-1) >= F(n-1)` 在若干次后成立，意味着旧内存块有可能被后续分配复用，从而减少堆碎片。

### 4. 扩容的隐藏代价

```cpp
std::vector<std::string> v;
for (int i = 0; i < 100000; ++i) {
    v.push_back(std::to_string(i));   // 不预留，约 log2(100000)≈17 次扩容
}
// 每次扩容都要：分配新内存 + 移动 5万~10万个 string + 析构旧的 + 释放旧的
// 总拷贝次数 ≈ n（均摊），但内存分配次数 ≈ log n
```

对于非平凡类型（如 `std::string`、含堆指针的对象），扩容的拷贝/移动开销可能很大。

### 5. 如何避免频繁扩容

#### 方法一：`reserve()` 预留容量（最常用）

```cpp
std::vector<int> v;
v.reserve(100000);                    // 一次性分配，之后 push_back 不再扩容
for (int i = 0; i < 100000; ++i) {
    v.push_back(i);                   // 永远命中 size < capacity 分支
}
```

`reserve(n)` 把容量直接扩到 ≥ n，但不改变 `size`（不构造元素）。如果已知最终规模，这是首选优化。

#### 方法二：`resize()` + 赋值（需要默认构造时）

```cpp
std::vector<int> v;
v.resize(100000);                     // 改变 size，元素默认初始化为 0
for (int i = 0; i < 100000; ++i) {
    v[i] = i;                         // 直接下标赋值，无扩容
}
```

#### 方法三：构造时直接指定大小

```cpp
std::vector<int> v(100000);           // 构造时分配并值初始化
std::vector<int> v(100000, 0);        // 指定初值
```

#### 方法四：批量插入

```cpp
std::vector<int> v;
std::vector<int> src(100000, 1);
v.reserve(src.size());
v.insert(v.end(), src.begin(), src.end());   // 一次性插入，可能内部计算好容量
```

#### 方法五：`shrink_to_fit` 反向收缩（C++11）

```cpp
std::vector<int> v(1000);
v.resize(10);                         // size 变 10，但 capacity 仍是 1000
v.shrink_to_fit();                    // 请求释放多余内存（非强制）
```

### 6. `size` 与 `capacity` 的区别

```cpp
std::vector<int> v;
v.reserve(100);        // capacity=100, size=0
v.push_back(1);        // capacity=100, size=1
v.pop_back();          // capacity=100, size=0  ← 注意 capacity 不变
```

| 属性 | 含义 | `reserve` 改变 | `resize` 改变 | `clear` 改变 |
|------|------|---------------|--------------|-------------|
| `size()` | 实际元素个数 | 否 | 是 | 变为 0 |
| `capacity()` | 已分配容量 | 是 | 可能 | 否 |

### 7. 迭代器失效规则

| 操作 | 失效规则 |
|------|----------|
| `push_back` 触发扩容 | 所有迭代器、指针、引用失效 |
| `push_back` 未扩容 | 失效 `end()`（其他安全） |
| `reserve(n)` 若 n > capacity | 全部失效 |
| `insert`/`erase` 中间元素 | 从插入/删除点起向后失效 |
| `clear` | 全部失效（size 变 0） |

```cpp
std::vector<int> v = {1, 2, 3};
auto it = v.begin();
v.push_back(4);          // 若扩容，it 失效！
// *it;                  // UB，可能崩溃
```

安全做法：扩容后重新取迭代器；或先用 `reserve` 避免中途扩容。

### 8. 嵌入式场景下的考量

- **堆碎片**：在内存受限的 MCU 上，vector 反复扩容会严重碎片化，建议 `reserve` 或用静态数组。
- **异常安全**：扩容分配失败会抛 `std::bad_alloc`，实时系统中可考虑用固定容量的 `std::array` 或自实现的 ring buffer。
- **placement new + 内存池**：自定义 allocator 让 vector 从预分配池中取内存，避免动态堆分配。

## 扩展问题

面试官可能会追问：
- `emplace_back` 和 `push_back` 的区别？（前者原地构造，省一次移动/拷贝）
- `vector` 和 `deque` 的扩容区别？（deque 分段连续，扩容只加一段，不搬移旧元素）
- `reserve` 之后 `push_back` 还会扩容吗？（不会，直到超过 reserve 的容量）
- 为什么扩容用 `std::move_if_noexcept`？（强异常安全的类用拷贝而非移动，避免移动到一半抛异常导致数据丢失）
