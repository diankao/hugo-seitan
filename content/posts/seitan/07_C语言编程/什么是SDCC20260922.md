# 什么是SDCC

## 题目

1. 什么是 SDCC？
2. 它和 Keil、GCC 是什么关系？

## 考察点

是否了解开源嵌入式编译器版图：SDCC 的定位（面向 8 位小 MCU 的免费 C 编译器套件）、它与 GCC/Keil 的分工、它的 ISO C 符合度与已知偏差。

## 回答要点

### 1. SDCC 是什么：面向小型 MCU 的开源 C 编译器套件

SDCC = **Small Device C Compiler**，由 Sandeep Dutta 于 2000 年前后发起，GPL 授权。官方自述是 "retargettable, optimizing Standard C (ANSI C89, ISO C99, ISO C11, ISO C23) compiler suite"——当前 4.x 版本的标准符合度在 8 位机编译器里是最高的。

它填的空当很明确：**GCC 的后端面向 32/64 位架构（外加 AVR、XTensa 等），8 位机和 Z80 系没有 GCC 可用**，SDCC 就是这个领域里的"开源 GCC"。

而且它不只是编译器，是一整套工具链：

| 组件 | 作用 |
|------|------|
| sdcc | 编译器本体 |
| sdcpp | 预处理器（基于 GCC cpp） |
| sdas / sdld | 汇编器与链接器（基于 ASXXXX） |
| ucsim | 指令级模拟器，无硬件也能跑程序 |
| sdcdb | 源码级调试器 |
| sdar 等 sdbinutils | 归档、符号表等二进制工具 |
| packihx / makebin | 生成 Intel HEX / BIN 烧录文件 |

运行库采用 GPL + linking exception：**闭源固件可以直接链接**，商用没有授权障碍。

### 2. 支持哪些目标

| 目标家族 | 代表芯片/场景 |
|---------|--------------|
| Intel MCS-51 | 8051/8052/8032、DS80C390 |
| Zilog Z80 系 | Z80、Z180、Z80N、eZ80、R800、SM83（Game Boy CPU）、Rabbit 2000/3000/4000、TLCS-90 |
| STMicro STM8 | STM8S/STM8L |
| Freescale HC08/S08 | 车规老 8 位机 |
| MOS 6502 / WDC 65C02 | Apple II 等复古平台（与 cc65 竞争） |
| Padauk PDK | 几毛钱的一次性编程 MCU（pdk14/pdk15） |
| PIC16 / PIC18 | 无维护状态，别作为选型理由 |

两个容易认错的点：SDCC 常被当成"PIC 编译器"，实际上 PIC 端口处于无人维护状态；而 Game Boy 开发圈用的 GBDK-2020 工具链，底层就是 SDCC 的 SM83 后端。

### 3. 和 Keil C51 的关系：8051 上的一对老对手

| 维度 | Keil C51 | SDCC |
|------|----------|------|
| 授权 | 商业（PK51 授权费） | GPL，免费 |
| 平台 | Windows（µVision） | Windows/Linux/macOS，命令行为主 |
| 优化/代码密度 | 通常更好（商业优化器打磨几十年） | 4.x 进步大，一般场景够用 |
| 生态 | µVision IDE + RTX51 RTOS + 大量中间件 | 命令行 + VS Code/PlatformIO/Eclipse 自行搭配 |
| 标准 | ANSI C 为主，偏差较多 | C89~C23 大部分符合 |

语法上二者不兼容，SDCC 用双下划线关键字。同一个 8051 定时器中断，两种写法：

SDCC：

```c
#include <8051.h>

void timer0_isr(void) __interrupt(1)
{
    TH0 = 0xFC;
}

void main(void)
{
    TMOD = 0x01;
    ET0 = 1;
    EA = 1;
    TR0 = 1;
    while (1);
}
```

Keil C51：

```c
#include <reg52.h>

void timer0_isr(void) interrupt 1
{
    TH0 = 0xFC;
}
```

### 4. ISO C 符合度与已知偏差

SDCC 支持到 C23（含部分 C2y 草案特性），但手册里公开声明了若干偏差，都是 8 位目标机的现实约束：

- **mcs51 默认函数不可重入**：参数和局部变量用静态覆盖分配（省 RAM），递归和多线程调用需要显式加 `reentrant` 关键字
- **浮点格式**：历史上默认是自有格式，手册原话 "somewhat similar to IEEE, but it is not IEEE"（不支持 denormal，位级布局与 IEEE 不同），浮点位级互操作前要按所用版本手册确认——详见《int和float占几个字节》
- **库是子集**：只有 libc 的精简版（printf 有多个变体），没有 POSIX
- **目标特有扩展**：`__data`、`__xdata`、`__code`、`__pdata`、`__bit` 等存储类关键字，代码可移植性换来了对哈佛架构的精确控制

### 5. 在哪会遇见 SDCC

- **8051 的零成本方案**：存量代码维护和国际开源社区项目。注意国内语境：低价位新设计早已被国产 32 位接管（沁恒 CH32V003、普冉 PY32 等 RISC-V/Cortex-M0，价格比 8 位机还低、性能更强），"为省 PK51 授权费用 SDCC 做 8051 新设计"在国内不是主流路径
- **STM8 三选一之一**：IAR（商业）、Cosmic（2019 年起免费注册）、SDCC（开源）——这也是国内工程师最可能实际碰到 SDCC 的地方
- **Padauk PDK 的开源选项**：官方工具免费但闭源且仅限 Windows（"Mini-C"，本质是套了 C 语法的汇编宏）；SDCC + Free PDK 开源烧录方案是社区替代路线，也是跨平台开发的唯一选择
- **复古计算**：Game Boy（SM83/GBDK-2020）、MSX 与 Z80 家用机、Apple II 的 6502
- **平台集成**：PlatformIO 把 SDCC 作为 mcs51/stm8 等平台的工具链选项

与编译器版图的更多背景（为什么不拿 MSVC/GCC 干这些活）详见《为什么嵌入式不用MSVC》；构建系统层面的全景详见《C与C++构建系统与包管理全览Makefile与CMake与qmake与Keil与vcpkg》。

### 6. 面试速记

- SDCC = **Small Device C Compiler**，GPL 开源，Sandeep Dutta 发起，标准符合度到 C23
- 目标：**8051、Z80 系（含 Game Boy 的 SM83）、STM8、HC08/S08、6502/65C02、Padauk PDK**；PIC 端口无人维护
- 套件含 ASXXXX 系汇编器/链接器、ucsim 模拟器、sdcdb 调试器；库 GPL+LE，闭源固件可链接
- 8051 上是 Keil C51 的免费替代，语法不兼容（`__interrupt(1)` vs `interrupt 1`）
- 已知偏差：mcs51 默认不可重入（`reentrant`）、历史浮点格式非 IEEE、库为子集
