# 运算符重载的成员与友元形式

## 题目

下列运算符重载函数中，属于友元函数的是（）

```cpp
A. Base operator+(Base);
B. Base operator--(Base);
C. Base operator&&(Base, Base);
D. Base operator++(Base,int);
```

常见口诀说"成员函数形式一般只有一个参数，友元函数形式一般有两个参数"，为什么答案是 B、C、D 而 A 是成员形式？

## 考察点

成员/友元两种重载形式的参数规律、运算符的目数（单目/双目）、前后缀自增自减的占位参数、各运算符的强制形式与工程惯例。

## 回答要点

### 1. 判定公式：先数操作数，再数参数

"成员一个参数、友元两个参数"的口诀**只对双目运算符成立**。普适的判断方法是先看运算符天生需要几个操作数：

| 形式 | 参数个数 | 原因 |
|------|---------|------|
| 成员函数 | 操作数个数 **− 1** | 左操作数（或唯一操作数）就是 `*this`，不占参数位 |
| 非成员（友元）函数 | 操作数个数 | 所有操作数都要显式写在参数表里 |

后缀 `++`/`--` 额外多一个**占位 int**（不算操作数，纯粹用来和前缀区分签名）。

### 2. 逐项判定

| 选项 | 运算符 | 天生操作数 | 成员版应有参数 | 非成员版应有参数 | 实际参数 | 判定 |
|------|--------|-----------|---------------|------------------|----------|------|
| A | `+` | 2（双目） | 1 | 2 | 1 | 成员 |
| B | `--` | 1（前缀单目） | 0 | 1 | 1 | 友元 |
| C | `&&` | 2（双目） | 1 | 2 | 2 | 友元 |
| D | `++` | 1（后缀单目）+ 占位 int | 1（只有占位 int） | 2（Base + int） | 2 | 友元 |

A 和 B 同样只有一个参数、判定却相反，差别全在目数：

```cpp
Base operator+(Base);    // + 需要 2 个操作数：this + 参数，正好凑齐 → 成员
// a + b  被解释为  a.operator+(b)

Base operator--(Base);   // -- 只需要 1 个操作数：参数就是全部，this 没活干 → 非成员
// --a    被解释为  operator--(a)，没有对象在"点"前面
```

换个角度验证 B：假如它是成员函数，参数表的 `Base` 加上隐含的 `this` 就有两个操作数——可 `--` 不作用于两个东西，矛盾，所以只能是全局/友元函数。

后缀的占位 int：`a++` 和 `++a` 的函数名都叫 `operator++`，编译器靠一个从不使用的 int 参数区分两者，四种合法写法：

```cpp
Base& operator++();               // 成员版前缀：++a
Base  operator++(int);            // 成员版后缀：a++（int 仅占位）
Base  operator++(Base);           // 友元版前缀
Base  operator++(Base, int);      // 友元版后缀 → 就是选项 D
```

### 3. 全家族签名对照表

T 代表本类。注意同一运算符**成员版和友元版只能二选一**，两个都定义会对 `a + b` 产生二义性。

| 运算符 | 成员版签名 | 友元版签名 | 规定 / 惯例 |
|--------|-----------|-----------|------------|
| 双目算术 `+ - * / %` | `T operator+(const T&) const` | `friend T operator+(const T&, const T&)` | 皆可；惯例非成员（左右对称） |
| 复合赋值 `+= -= *=` | `T& operator+=(const T&)` | `friend T& operator+=(T&, const T&)` | 皆可；惯例成员 |
| 赋值 `=` | `T& operator=(const T&)` | ✗ | **只能成员** |
| 前缀 `++ --` | `T& operator++()` | `friend T& operator++(T&)` | 皆可；惯例成员 |
| 后缀 `++ --` | `T operator++(int)` | `friend T operator++(T&, int)` | 皆可；惯例成员 |
| 单目 `- ! ~` | `T operator-() const` | `friend T operator-(const T&)` | 皆可 |
| 单目 `*`（解引用，智能指针用） | `T& operator*() const` | 理论可行 | 惯例成员 |
| 比较 `== != < >` | `bool operator==(const T&) const` | `friend bool operator==(const T&, const T&)` | 皆可；惯例非成员；C++20 可 `= default` |
| 流 `<< >>` | ✗ | `friend ostream& operator<<(ostream&, const T&)` | **只能非成员**（左操作数是 ostream） |
| 下标 `[]` | `int& operator[](size_t)` + const 版 | ✗ | **只能成员** |
| 调用 `()` | `R operator()(参数...)` | ✗ | **只能成员**（仿函数） |
| 箭头 `->` | `T* operator->() const` | ✗ | **只能成员** |
| 类型转换 | `operator int() const`（无返回类型） | ✗ | **只能成员** |
| `&&` `\|\|` `,` | 能写 | 能写 | **都不该写**（丢短路/求值顺序） |

### 4. 返回值规律

| 类别 | 返回类型 | 原因 |
|------|---------|------|
| 双目算术（`+`） | `T`（返回值） | 产生新对象，不动操作数，参数和函数都带 const |
| 复合赋值（`+=`）、前缀 `++` | `T&`（返回 `*this`） | 就地修改自身，链式 `a += b += c` 要返回同一个对象 |
| 后缀 `++` | `T`（返回旧值） | 语义是"先取旧值再自增"，旧值是副本 |
| 流（`<<`） | `ostream&` | 链式 `cout << a << b`，必须返回同一个流 |
| 比较、逻辑 | `bool` | — |

### 5. 完整可跑示例（分数类，全部采用惯例写法）

```cpp
#include <iostream>
using namespace std;

class Fraction {
    int num, den;   // 分子、分母
public:
    Fraction(int n = 0, int d = 1) : num(n), den(d) {}

    // 复合赋值：成员版，返回 *this 的引用
    Fraction& operator+=(const Fraction& rhs) {
        num = num * rhs.den + rhs.num * den;
        den *= rhs.den;
        return *this;
    }

    // 双目 +：非成员版，复用 +=，天然支持 3 + f 这种左操作数转换
    friend Fraction operator+(Fraction lhs, const Fraction& rhs) {
        lhs += rhs;
        return lhs;
    }

    // 前缀 ++：成员版，0 参数，返回自身引用
    Fraction& operator++() {
        num += den;
        return *this;
    }

    // 后缀 ++：成员版，占位 int，返回旧值副本
    Fraction operator++(int) {
        Fraction old = *this;
        num += den;
        return old;
    }

    // 相等比较：成员版
    bool operator==(const Fraction& rhs) const {
        return num * rhs.den == rhs.num * den;
    }

    // 流输出：只能非成员，返回 ostream& 支持链式
    friend ostream& operator<<(ostream& os, const Fraction& f) {
        return os << f.num << "/" << f.den;
    }
};

int main() {
    Fraction f(1, 2), g(1, 3);
    cout << f + g << endl;                          // 5/6
    cout << 3 + f << endl;                          // 7/2（左操作数 3 隐式转换，靠非成员版）
    ++f; cout << f << endl;                         // 3/2
    f++; cout << f << endl;                         // 5/2
    cout << boolalpha << (f == Fraction(5, 2));     // true
}
```

前缀/后缀的友元版等价写法（与成员版二选一）：

```cpp
friend Fraction& operator++(Fraction& f) { f.num += f.den; return f; }     // 前缀
friend Fraction  operator++(Fraction& f, int) {                            // 后缀
    Fraction old = f;
    f.num += f.den;
    return old;
}
```

### 6. 容易翻车的细节

1. **`<<` 永远写不成成员**：成员版的左操作数必须是本类，而 `cout << f` 的左操作数是 `ostream`——除非修改标准库的类，否则只能全局非成员。
2. **`3 + f` 是非成员版的独家能力**：成员版 `f.operator+(3)` 能把 3 转成分数，但 `3.operator+(f)` 不存在（3 是 int）；非成员版 `operator+(Fraction, Fraction)` 两个参数都能转换，左右通吃。
3. **`[]`、`()`、`->`、`=`、类型转换是"成员五人组"**：语言强制，没有友元版。`[]` 记得写 const/non-const 两个重载，否则 const 对象下标读会被编译器拦下。
4. **后缀比前缀天然低效**：要拷贝一份旧值返回，这也是"循环里能用 `++i` 就别用 `i++`"的根源（对迭代器这类重载了 `++` 的类才明显）。
5. **`&&`、`||`、`,` 语法上允许重载**，但重载后从"短路+定序"退化成"两个操作数都求值、顺序不定"，工程上视为禁区。
6. **严谨性备注**：裸签名判定的其实是"非成员函数"，"友元"是考试语境的习惯叫法——只有当函数需要访问类私有成员、在类内声明为 `friend` 时才真是友元。判定依据始终是参数特征，不是有没有 friend 关键字。
