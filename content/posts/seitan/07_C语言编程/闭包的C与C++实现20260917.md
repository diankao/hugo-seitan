# 闭包的C与C++实现

## 题目

C 语言没有闭包吗？在没有语言支持的情况下如何用 C"手动实现"闭包？C++ 的 lambda 和闭包又是什么关系？

## 考察点

闭包三要素（代码、环境、绑定）在 C/C++ 中的对应物、C 手动闭包三件套（struct + 函数 + void* 上下文）、C++ lambda 的脱糖视角、两者的性能与类型安全对比。

## 回答要点

### 1. 闭包三要素与 C 的缺憾

闭包 = **函数代码 + 捕获的词法环境 + 两者的绑定**（概念详见《闭包概念与跨语言对比》）。判断标准：能否在定义作用域之外被调用、且仍能访问定义时的外层局部变量。

C 的函数指针只携带代码入口地址，不携带环境：

```c
typedef int (*fn_t)(int);

static int add10(int x) { return x + 10; }

fn_t f = add10;    // f 只有代码地址，没有任何"记住外层变量"的能力
```

所以 C 没有语言级闭包。但 C 程序员天天在**手工模拟**闭包——回调函数 + 上下文指针。

### 2. C 手动闭包三件套：struct + 函数 + void* 传递

```c
#include <stdio.h>

typedef int (*next_fn)(void *ctx);

/* 环境结构体：承担"捕获变量"的存储 */
typedef struct {
    int base;
    int step;
} counter_ctx;

/* 代码：第一个参数负责把环境传回来 */
static int counter_next(void *ctx_)
{
    counter_ctx *ctx = ctx_;        /* 拆箱：从 void* 还原环境 */
    ctx->step += 1;
    return ctx->base + ctx->step;
}

int main(void)
{
    counter_ctx ctx = {100, 0};     /* 实例化 = 捕获 */
    next_fn fn = counter_next;      /* 代码与环境的绑定靠调用方配对 */

    printf("%d\n", fn(&ctx));       /* 102 */
    printf("%d\n", fn(&ctx));       /* 103：环境跨调用持续存在 */
    return 0;
}
```

这个模式在 C 生态里无处不在：

| 场景 | 函数 | 环境 |
|------|------|------|
| `qsort_r` / `qsort_s` | 比较函数 | `void *thunk`/`context` |
| pthread | 线程入口函数 | `void *arg` |
| RTOS 任务创建 | 任务函数 | `void *pvParameters`（FreeRTOS） |
| 中断/事件回调注册 | 回调函数 | 用户上下文指针 |

本质都是把"环境"作为独立参数和函数配对传递——正是闭包在机器层面做的事。

### 3. C++ lambda：编译器替你生成的闭包

C++11 的 lambda 表达式会被编译器生成为一个**独一无二的匿名类**（闭包类型），捕获的变量成为其成员，函数体成为 `operator()`：

```cpp
#include <cstdio>

int main()
{
    int x = 10;
    int y = 20;
    auto f = [x, &y](int a) { return a + x + y; };

    // 编译器概念上的"脱糖"结果：
    // class __lambda {
    //     int  x;      // [x]  按值捕获 → 成员副本
    //     int& y;      // [&y] 按引用捕获 → 成员引用（底层是指针）
    // public:
    //     __lambda(int x_, int& y_) : x(x_), y(y_) {}
    //     int operator()(int a) const { return a + x + y; }
    // };
    // auto f = __lambda{x, y};

    printf("%d\n", f(1));    // 31
    return 0;
}
```

对比第 2 节的 C 版本，一一对应关系非常清晰：

| 闭包要素 | C 手动闭包 | C++ lambda |
|---------|-----------|-----------|
| 环境存储 | struct 的字段 | 匿名类的数据成员 |
| 捕获语义 | 存副本（值）/ 存指针（引用）自己选 | `[x]` / `[&x]` 显式声明 |
| 代码载体 | 普通函数，首参收环境指针 | `operator()`（类内定义、隐式 inline） |
| 绑定方式 | 函数指针 + `void*` 结对注册 | 语言内建，捕获即绑定 |

lambda 的捕获方式细节、`mutable`、初始化捕获、`std::function` 等展开见《lambda表达式本质与实现机制》。

### 4. 真正的差别

1. **类型安全**：C++ 每个 lambda 是独立类型，捕获了什么编译器全程清楚；C 的 `void *ctx` 到回调里拆箱，类型全靠约定，传错结构体编译器不吭声。
2. **内联与性能**：C++ 的 `operator()` 是内联候选，捕获变量就在闭包对象里，热路径上可以达到零开销；C 的回调经函数指针间接调用，编译器通常无法内联，环境访问还多一次指针解引用。
3. **代码量**：一行 lambda 对应 C 的 struct + 转接函数 + 注册三件套，捕获集合一变就得再写一套。
4. **生命周期**：这点半斤八两——C++ `[&]` 捕获局部变量后闭包出域再调用是未定义行为；C 的 `ctx` 指向栈上结构体、回调异步触发时栈已弹开同样是未定义行为。都是"环境必须活得比闭包久"。

### 5. 两座桥

**无捕获 lambda → 函数指针**：捕获列表为空 `[]` 的 lambda 可以隐式转换为普通函数指针，此时"环境"为空，闭包退化成裸函数，与 C 的纯函数回调完全等价：

```cpp
#include <cstdlib>

int arr[] = {3, 1, 4, 1, 5};
std::qsort(arr, 5, sizeof(int),
           [](const void *a, const void *b) {
               return *(const int *)a - *(const int *)b;
           });
```

有捕获的 lambda 不能这样转换，必须经 `std::function` 或全局变量中转——这也是 C 接口（回调 + `void*`）与 C++ lambda 互操作的常用手法：lambda 本体不捕获，把环境放进 `void*` 传过去，在回调里转回具体类型。

**`std::function` ≈ C 函数指针方案的对应物**：裸 lambda 是零开销档；一旦装进 `std::function` 做类型擦除，就可能引入堆分配和间接调用，间接性回到了 C 函数指针的水平。对比性能时应拿"裸 lambda vs C 手动闭包"才公平。
