# MySQL死锁解决方案

## 题目

MySQL死锁问题产生原因及如何解决？

## 考察点

MySQL死锁的产生原因、死锁检测与预防、事务隔离级别、锁机制。

## 回答要点

### 1. 死锁产生原因

MySQL死锁是指两个或多个事务相互等待对方释放锁，从而导致事务无法继续执行的情况喵~

| 原因 | 说明 |
|------|------|
| 并发访问 | 多个事务同时访问同一个资源，访问方式不同（读/写），导致锁冲突 |
| 锁的顺序 | 多个事务请求锁的顺序不同，导致循环等待 |
| 锁的粒度 | 锁的粒度太细或太大，都可能导致死锁 |

**典型死锁场景：**

```sql
-- 事务A
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;  -- 锁住id=1
UPDATE accounts SET balance = balance + 100 WHERE id = 2;  -- 等待id=2

-- 事务B（同时执行）
BEGIN;
UPDATE accounts SET balance = balance - 50 WHERE id = 2;   -- 锁住id=2
UPDATE accounts SET balance = balance + 50 WHERE id = 1;   -- 等待id=1 → 死锁！
```

### 2. 解决方案

#### 2.1 优化SQL语句

通过优化SQL语句，减少事务的数量和时间，从而减少死锁的发生概率喵~

#### 2.2 调整锁的粒度

通过调整锁的粒度，使得锁的数量和范围都适当，从而减少死锁的发生概率喵~

#### 2.3 调整事务隔离级别

通过调整事务隔离级别，使得事务的访问方式和范围适当，避免两个事务同时对同一个资源进行修改喵~

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 锁开销 |
|---------|------|-----------|------|--------|
| READ UNCOMMITTED | 是 | 是 | 是 | 最低 |
| READ COMMITTED | 否 | 是 | 是 | 低 |
| REPEATABLE READ | 否 | 否 | 是 | 中 |
| SERIALIZABLE | 否 | 否 | 否 | 最高 |

#### 2.4 统一加锁顺序

使用相同的加锁顺序，从而避免死锁问题的发生喵~ 例如始终按照 id 从小到大的顺序获取锁喵~

```sql
-- 正确：统一按id从小到大加锁
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

#### 2.5 限制事务等待时间

通过限制事务等待时间（`innodb_lock_wait_timeout`），使得事务在等待一定时间后自动回滚，避免死锁长时间占用资源喵~

```sql
SET innodb_lock_wait_timeout = 10;
```

#### 2.6 监控死锁

```sql
SHOW ENGINE INNODB STATUS;

-- 查看最近死锁信息
SELECT * FROM information_schema.INNODB_LOCKS;
SELECT * FROM information_schema.INNODB_LOCK_WAITS;
```

通过以上措施，可以有效地解决MySQL死锁问题，提高数据库的性能和稳定性喵~
