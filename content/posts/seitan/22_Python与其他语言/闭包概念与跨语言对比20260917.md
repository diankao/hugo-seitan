# 闭包概念与跨语言对比

## 题目

什么是闭包？为什么叫"闭"包？Python 的闭包和 JavaScript、Go、Rust、Java 等语言里的闭包是同一个概念吗？

## 考察点

闭包的定义（函数 + 词法环境）、自由变量的封闭过程、Python 闭包的底层机制（cell 对象与晚绑定）、各语言捕获策略的差异。

## 回答要点

### 1. 闭包的定义：函数代码 + 定义时的词法环境

闭包（closure）= **函数代码 + 定义它时的词法环境（捕获的外层变量绑定）的打包体**。概念源自 Peter Landin 在 1964 年对 λ 演算表达式机械求值的研究。

名字的由来可以从"开放 → 封闭"的过程理解：

```python
def outer():
    x = 10
    def inner():
        return x + 1   # x 是 inner 的自由变量：不是参数，也不在 inner 内定义
    return inner
```

- 函数体里含有**自由变量**（不属于参数、也不在函数内定义的变量），这样的函数是"开放"的，单独看没有确定的含义；
- 把函数体和"变量 → 值"的绑定环境打包在一起，自由变量全部有了着落，函数就成了"封闭"的整体——这就是**闭包**的字面含义；
- 于是闭包可以逃出定义它的作用域（被 return、被存进容器、被传给其他模块），走到哪儿都能正确访问那些变量，因为环境随身携带。

### 2. 判断标准

一条标准就够：**一段代码能否在定义作用域之外被调用、且仍能访问定义时的外层局部变量**。能，就是闭包。

反例是 C 语言的函数指针：函数指针只携带代码入口地址，不携带环境，所以在别处调用时无法访问定义处的局部变量——函数指针不是闭包（C 手动模拟闭包的方式见《闭包的C与C++实现》）。

### 3. Python 闭包的底层：cell 对象

Python 的函数是对象，捕获的外层变量放在 cell 对象里，通过 `__closure__` 查看：

```python
def make_counter():
    count = 0
    def counter():
        nonlocal count     # 声明后才能修改外层变量，否则赋值会创建新的局部变量
        count += 1
        return count
    return counter

c = make_counter()
print(c(), c(), c())                       # 输出 1 2 3，count 生活在闭包环境里

print(c.__closure__)                       # (<cell at 0x...: int object at 0x...>,)
print(c.__closure__[0].cell_contents)      # 3，直接看到 cell 里的值
```

两个要点：

- **捕获的是变量（cell 引用），不是定义时的值快照**；
- 修改外层变量必须加 `nonlocal`，否则函数内的赋值语句会把变量变成新的局部变量。

### 4. 晚绑定：经典陷阱

因为捕获的是变量本身，循环里创建的多个函数共享同一个循环变量，调用时才查它的最终值：

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])        # [2, 2, 2]，不是 [0, 1, 2]

# 修复：用默认参数在定义时做值快照
fs = [lambda i=i: i for i in range(3)]
print([f() for f in fs])        # [0, 1, 2]
```

JavaScript 里 `var` 有同款问题，`let` 的块级作用域（每次迭代一个新变量）是语言层面的修复；Go 在 1.22 之后也是每次迭代新建循环变量，同样是语言层面的修复。

### 5. 各语言闭包对比：同一概念，不同捕获策略

| 语言 | 捕获语义 | 特点 |
|------|---------|------|
| Python | 捕获变量的引用（cell），晚绑定 | 修改需 `nonlocal`；`__closure__` 可查看 |
| JavaScript | 捕获引用，晚绑定 | 与 Python 几乎同款；`let` 修复循环坑 |
| C++ | 捕获列表显式指定：`[x]` 按值、`[&x]` 按引用 | 捕获策略完全交给程序员 |
| Go | 捕获变量本身（引用语义） | 1.22 起循环变量每轮新建 |
| Rust | 所有权介入，闭包分 `Fn`/`FnMut`/`FnOnce` 三类 | 可 `move` 捕获，编译器按只读/可变/消耗分类 |
| Java | 只能捕获 effectively final 变量 | 近似值快照，捕获后不可变 |

结论：Python 的闭包没有任何偏离标准的地方，它就是标准闭包 + Python 的一套具体决策（引用捕获、晚绑定、`nonlocal` 才可写）。

### 6. 闭包的典型应用：装饰器

Python 装饰器是闭包最大的用武之地——装饰器本质上就是一个"接收函数、返回新函数"的闭包（系统展开见《Python装饰器》）：

```python
import time
from functools import wraps

def timed(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):       # 闭包捕获了 fn
        t0 = time.perf_counter()
        result = fn(*args, **kwargs)
        print(f"{fn.__name__} 耗时 {time.perf_counter() - t0:.3f}s")
        return result
    return wrapper

@timed
def work():
    time.sleep(0.1)

work()    # 输出 work 耗时 0.1xx s
```

### 7. 与数学"闭包"的词源关系

只是同词根的不同概念。数学（及编译原理）里的闭包指"对某种规则封闭的最小集合"，编程闭包借用了"封闭"的隐喻（把自由变量封闭进环境）。详细辨析见《数学与编译原理中的闭包》，两者词源相通、语义无关。
