# Python装饰器

## 题目

什么是装饰器？`@` 符号到底做了什么？为什么需要装饰器，怎么自己写一个？

## 考察点

装饰器的本质（函数替换的语法糖）、闭包在装饰器中的角色、`functools.wraps` 的作用、带参数的装饰器、类装饰器、装饰器的执行时机。

## 回答要点

### 1. 去魅第一步：@ 就是函数替换的语法糖

装饰器的一切神秘感都来自 `@` 符号，把它翻译成等价代码就懂了：

```python
def deco(fn):
    print(f"装饰 {fn.__name__}")
    return fn          # 先看最简单的：原样返回

@deco
def hello():
    print("hello")

# 上面的 @deco 完全等价于下面两步：
# def hello(): ...
# hello = deco(hello)

hello()    # 输出 hello
```

**`@deco` 只做一件事：把下面的函数名传给 deco，再用返回值替换掉这个函数名。** 装饰器就是"接收函数、返回新函数"的函数，仅此而已。

### 2. 手写一个实用的装饰器：执行日志

装饰器想"加点料"，就要返回一个**新的**函数——这里闭包登场了（闭包概念见《闭包概念与跨语言对比》）：

```python
import functools

def log(fn):
    @functools.wraps(fn)                     # 作用见第 3 节
    def wrapper(*args, **kwargs):            # 闭包捕获了 fn
        print(f"调用 {fn.__name__}，参数 args={args} kwargs={kwargs}")
        result = fn(*args, **kwargs)         # 前后包夹：这就是"装饰"
        print(f"{fn.__name__} 返回 {result}")
        return result
    return wrapper

@log
def add(a, b):
    "两数相加"
    return a + b

add(1, 2)
# 调用 add，参数 args=(1, 2) kwargs={}
# add 返回 3
```

新函数的三要素，也是所有装饰器的固定套路：

1. **闭包捕获原函数** `fn`——环境随身携带，这就是装饰器能工作的原因；
2. **`*args, **kwargs` 通用转发**——不关心原函数签名，任何函数都能装饰；
3. **返回 wrapper**——完成函数替换。

### 3. functools.wraps：不加会怎样

被装饰后，`hello` 实际指向的是 `wrapper`，函数的元信息（名字、文档字符串）全变成 wrapper 的：

```python
@log
def add(a, b):
    "两数相加"
    return a + b

print(add.__name__)    # 不加 wraps：'wrapper'；加了：'add'
print(add.__doc__)     # 不加 wraps：None；加了：'两数相加'
```

`functools.wraps` 本身也是个装饰器，作用是把原函数的 `__name__`、`__doc__` 等元信息复制到 wrapper 上。调试、序列化、文档生成都会读这些属性，所以**写装饰器永远带上 wraps** 是标准习惯。

### 4. 带参数的装饰器：再多包一层

`@repeat(3)` 比 `@repeat` 多了括号和参数——括号意味着**先调用再装饰**，所以需要三层：

```python
import functools

def repeat(times):                          # 第一层：接收装饰器参数
    def deco(fn):                           # 第二层：接收被装饰函数
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):       # 第三层：真正干活的新函数
            result = None
            for _ in range(times):
                result = fn(*args, **kwargs)
            return result
        return wrapper
    return deco

@repeat(3)
def greet():
    print("hi")

greet()     # 打印三次 hi

# @repeat(3) 等价于：greet = repeat(3)(greet)
# 先求值 repeat(3) 得到 deco，再用 deco 装饰 greet
```

记法：**普通装饰器两层（deco + wrapper），带参数的装饰器三层（最外层吃参数）**。

### 5. 类装饰器：需要记忆状态时更自然

闭包也能记状态（用 `nonlocal`），但当装饰器需要维护的状态变多时，写成类更清晰——实例属性代替 cell：

```python
import functools

class CountCalls:
    def __init__(self, fn):
        functools.update_wrapper(self, fn)  # 类版 wraps
        self.fn = fn
        self.count = 0

    def __call__(self, *args, **kwargs):    # 实例可调用 = 能当函数用
        self.count += 1
        print(f"第 {self.count} 次调用 {self.fn.__name__}")
        return self.fn(*args, **kwargs)

@CountCalls
def work():
    return "done"

work(); work()
# 第 1 次调用 work
# 第 2 次调用 work
```

关键点：`__call__` 让实例表现得像函数，所以 `@CountCalls` 替换后 `work` 是一个可调用的对象。`functools.update_wrapper` 是 `wraps` 的非装饰器版本。

### 6. 标准库里的常用装饰器

不是所有装饰器都要自己写，标准库已经备好了高频款：

| 装饰器 | 作用 |
|--------|------|
| `@staticmethod` / `@classmethod` | 方法不绑定实例 / 绑定类 |
| `@property` | 把方法变成属性访问（getter/setter） |
| `@functools.lru_cache` | 自动缓存函数结果，递归/重复计算的性能神器 |
| `@functools.wraps` | 装饰器配套，保留元信息 |
| `@dataclass` | 自动生成 `__init__`/`__repr__` 等 |

`lru_cache` 示例——感受一下装饰器的杠杆力：

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(60))    # 瞬间出结果；去掉缓存这将是天文时间的重复计算
```

### 7. 执行时机与叠加顺序

两个容易困惑的行为：

**装饰发生在 def 执行时（模块导入时），不是函数调用时**——所以装饰器里的 `print` 在导入时就打出来了。

**多个装饰器从下往上应用，执行时从上往下包裹（洋葱模型）**：

```python
@a
@b
def f(): ...
# 等价于：f = a(b(f))
# 调用 f 时：a 的逻辑在外层，b 的逻辑在内层
```

### 8. 装饰器与闭包的关系

一句话收束：**装饰器 = "接收函数、返回函数"协议 + 闭包实现**。`@` 语法只是替换动作，真正让新函数记住原函数的是闭包捕获（wrapper 的 `__closure__` 里就装着 `fn`）。没有闭包就没有装饰器，这也是 Python 里闭包最大的用武之地。
