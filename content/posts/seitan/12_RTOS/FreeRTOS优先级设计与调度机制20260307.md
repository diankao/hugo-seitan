# FreeRTOS优先级设计与调度机制

## 标签
#操作系统 #面试题 #FreeRTOS #任务调度 #优先级设计

## 问题描述
FreeRTOS中任务调度机制是怎样的？如何进行任务优先级设计？

## 参考答案

### FreeRTOS调度机制

#### 1. 调度算法

FreeRTOS支持多种调度算法：

**抢占式调度（默认）**：
- 高优先级任务就绪时立即抢占CPU
- 低优先级任务被中断后进入就绪态
- 系统总是运行最高优先级的就绪任务

**协作式调度**：
- 任务必须主动让出CPU
- 通过taskYIELD()实现
- 适用于特定应用场景

**时间片轮转**：
- 同优先级任务轮流执行
- 时间片可通过configTICK_RATE_HZ配置
- 需要启用configUSE_TIME_SLICING

#### 2. 调度器配置

**关键配置参数**：
```c
#define configUSE_PREEMPTION              1    // 启用抢占式调度
#define configUSE_TIME_SLICING            1    // 启用时间片轮转
#define configTICK_RATE_HZ               1000  // 系统滴答频率
#define configIDLE_SHOULD_YIELD          1    // 空闲任务让步
```

**调度器启动**：
```c
void main(void) {
    HAL_Init();
    SystemClock_Config();
    
    // 创建任务
    xTaskCreate(Task1, "Task1", 128, NULL, 3, NULL);
    xTaskCreate(Task2, "Task2", 128, NULL, 2, NULL);
    xTaskCreate(Task3, "Task3", 128, NULL, 1, NULL);
    
    // 启动调度器（不会返回）
    vTaskStartScheduler();
    
    while(1);  // 不会执行到这里
}
```

### 任务优先级设计

#### 1. 优先级范围

**FreeRTOS优先级定义**：
```c
// 在FreeRTOSConfig.h中
#define configMAX_PRIORITIES  7  // 最大优先级数量（0到configMAX_PRIORITIES-1）
```

**优先级说明**：
- 数字越大，优先级越高
- 优先级0是最低优先级
- 优先级configMAX_PRIORITIES-1是最高优先级

#### 2. 优先级分配原则

**基于实时性要求**：
```c
#define PRIORITY_HIGHEST      6  // 关键实时任务
#define PRIORITY_HIGH         5  // 高优先级任务
#define PRIORITY_NORMAL       3  // 普通任务
#define PRIORITY_LOW          2  // 低优先级任务
#define PRIORITY_LOWEST       1  // 后台任务
#define PRIORITY_IDLE         0  // 空闲任务
```

**优先级分配策略**：

| 任务类型 | 优先级 | 说明 |
|---------|--------|------|
| 中断处理任务 | 6-7 | 实时性要求极高，执行时间短 |
| 安全关键任务 | 5-6 | 影响系统安全，需要快速响应 |
| 通信任务 | 4-5 | 需要及时处理数据，避免丢包 |
| 控制任务 | 3-4 | 需要定期执行，有一定实时性 |
| 用户界面 | 2-3 | 对响应时间有一定要求 |
| 数据处理 | 2-3 | 计算密集型，可以适当降低优先级 |
| 监控任务 | 1-2 | 周期性检查，不需要实时响应 |
| 日志记录 | 1-2 | 后台任务，不影响主功能 |

#### 3. 实际应用示例

**IoT设备优先级设计**：
```c
// 任务优先级定义
#define PRIORITY_NETWORK_IRQ      7  // 网络中断（最高）
#define PRIORITY_SAFETY_MONITOR   6  // 安全监测
#define PRIORITY_COMMUNICATION    5  // MQTT通信
#define PRIORITY_SENSOR_PROCESS   4  // 传感器数据处理
#define PRIORITY_UI_CONTROL       3  // 用户界面控制
#define PRIORITY_DATA_LOG         2  // 数据记录
#define PRIORITY_STATUS_MONITOR   1  // 状态监控
#define PRIORITY_IDLE             0  // 空闲任务

// 创建任务
void main(void) {
    // 网络中断任务
    xTaskCreate(NetworkIRQ_Task, "NetIRQ", 256, NULL, 
                PRIORITY_NETWORK_IRQ, NULL);
    
    // 安全监测任务
    xTaskCreate(SafetyMonitor_Task, "Safety", 128, NULL, 
                PRIORITY_SAFETY_MONITOR, NULL);
    
    // MQTT通信任务
    xTaskCreate(MQTT_Task, "MQTT", 512, NULL, 
                PRIORITY_COMMUNICATION, NULL);
    
    // 传感器处理任务
    xTaskCreate(SensorProcess_Task, "Sensor", 256, NULL, 
                PRIORITY_SENSOR_PROCESS, NULL);
    
    // 用户界面任务
    xTaskCreate(UI_Task, "UI", 256, NULL, 
                PRIORITY_UI_CONTROL, NULL);
    
    vTaskStartScheduler();
}
```

### 任务状态转换

#### 状态转换图

```
           创建
            ↓
    +-------------+
    |   Created   |
    +-------------+
            ↓
    +-------------+
    |   Ready     | ←─ 阻塞超时/事件到达
    +-------------+
            ↓ 高优先级就绪
    +-------------+
    |  Running    | ←─ 任务切换
    +-------------+
        ↓     ↓
    让出CPU  阻塞
        ↓     ↓
    +-------------+   +-------------+
    |   Ready     |   |  Blocked    |
    +-------------+   +-------------+
                          ↓
                    超时/事件到达
```

#### 状态转换示例

```c
void Task1(void *param) {
    while(1) {
        // 运行态
        ProcessData();
        
        // 调用vTaskDelay，从运行态转为阻塞态
        vTaskDelay(100);  // 阻塞100ms
        
        // 延时结束，从阻塞态转为就绪态
        // 调度器调度，从就绪态转为运行态
    }
}

void Task2(void *param) {
    while(1) {
        // 等待信号量，从运行态转为阻塞态
        xSemaphoreTake(xSemaphore, portMAX_DELAY);
        
        // 获取到信号量，从阻塞态转为就绪态
        ProcessEvent();
        
        // 让出CPU，从运行态转为就绪态
        taskYIELD();
    }
}
```

### 常见问题与解决方案

#### 1. 优先级反转

**问题**：低优先级任务持有高优先级任务需要的资源，中优先级任务抢占低优先级任务，导致高优先级任务长时间等待。

**解决方案**：
```c
// 使用互斥锁（自动优先级继承）
SemaphoreHandle_t xMutex = xSemaphoreCreateMutex();

void HighPriority_Task(void *param) {
    xSemaphoreTake(xMutex, portMAX_DELAY);
    CriticalSection();
    xSemaphoreGive(xMutex);
}

void LowPriority_Task(void *param) {
    xSemaphoreTake(xMutex, portMAX_DELAY);
    LongOperation();  // 高优先级任务会被提升到与低优先级相同
    xSemaphoreGive(xMutex);
}
```

#### 2. 任务饥饿

**问题**：高优先级任务频繁执行，低优先级任务长时间得不到执行机会。

**解决方案**：
- 限制高优先级任务的执行时间
- 使用优先级继承或优先级天花板
- 定期提升低优先级任务的优先级

```c
void BoostLowPriorityTask(void) {
    TaskHandle_t xLowTask = GetLowPriorityTask();
    vTaskPrioritySet(xLowTask, PRIORITY_HIGH);
    
    // 等待任务执行完成
    vTaskDelay(100);
    
    // 恢复原始优先级
    vTaskPrioritySet(xLowTask, PRIORITY_LOW);
}
```

#### 3. 过多任务切换

**问题**：任务切换频繁，影响系统性能。

**解决方案**：
- 合理设计任务粒度
- 避免不必要的任务切换
- 使用消息队列批量处理数据

```c
// 不好的做法：频繁切换
void Task1(void *param) {
    while(1) {
        ProcessOneData();  // 处理一个数据
        vTaskDelay(1);      // 切换任务
    }
}

// 好的做法：批量处理
void Task1(void *param) {
    while(1) {
        ProcessBatchData();  // 批量处理数据
        vTaskDelay(10);      // 减少切换次数
    }
}
```

### 性能优化

#### 1. 减少调度延迟

**优化方法**：
- 使用优先级继承机制
- 减少临界区执行时间
- 使用DMA等硬件加速

```c
// 快速处理中断
void UART_IRQHandler(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;
    
    // 只保存数据，不进行复杂处理
    uint8_t data = UART_ReceiveByte();
    xQueueSendFromISR(xQueue, &data, &xHigherPriorityTaskWoken);
    
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

// 复杂处理交给任务
void UART_Task(void *param) {
    uint8_t data;
    while(1) {
        xQueueReceive(xQueue, &data, portMAX_DELAY);
        ProcessData(data);  // 复杂处理
    }
}
```

#### 2. 优化任务数量

**原则**：
- 任务数量不宜过多（一般< 10个）
- 相关功能可以合并到一个任务
- 使用状态机处理多种状态

```c
// 不好的做法：任务过多
xTaskCreate(LED1_Task, "LED1", 64, NULL, 1, NULL);
xTaskCreate(LED2_Task, "LED2", 64, NULL, 1, NULL);
xTaskCreate(LED3_Task, "LED3", 64, NULL, 1, NULL);

// 好的做法：合并到一个任务
xTaskCreate(LED_Task, "LED", 64, NULL, 1, NULL);

void LED_Task(void *param) {
    while(1) {
        LED1_Toggle();
        vTaskDelay(100);
        LED2_Toggle();
        vTaskDelay(100);
        LED3_Toggle();
        vTaskDelay(100);
    }
}
```
