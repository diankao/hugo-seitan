# RTOS内存池机制与内存分配优化

## 题目

RTOS 的内存池机制如何优化内存分配？

## 考察点

RTOS 内存管理方案、内存池原理、与 malloc 的对比、FreeRTOS 内存管理实现。

## 回答要点

### 1. 问题：为什么不用标准 malloc

标准 C 库的 `malloc/free` 在 RTOS 环境中有严重问题：

| 问题 | 说明 |
|------|------|
| 非线程安全 | 多任务同时 malloc 会破坏堆数据结构 |
| 时间不确定 | 堆碎片化时，malloc 耗时从 μs 飙到 ms |
| 碎片化 | 反复分配释放后，明明有总空间但找不到连续块 |
| 无失败处理 | malloc 失败返回 NULL，嵌入式系统可能没有优雅的失败策略 |

```c
// 标准malloc的时间不确定性
void *p1 = malloc(100);   // 可能 5μs
free(p1);
void *p2 = malloc(100);   // 碎片化后可能 500μs！
// 在硬实时系统中，这种不确定性不可接受
```

### 2. FreeRTOS 的五种内存管理方案

FreeRTOS 源码中提供了 5 个 `heap_x.c` 文件：

| 方案 | 实现 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| heap_1 | 只分配不释放 | 最简单，确定性强 | 不能释放，只增不减 | 创建后不删除任务的系统 |
| heap_2 | 最佳适配 + 链表 | 支持释放 | 不合并碎片，碎片严重 | 已弃用 |
| heap_3 | 封装标准 malloc | 简单 | 依赖编译器实现，不确定 | 不推荐 |
| heap_4 | 首次适配 + 合并 | 支持释放 + 合并相邻块 | 仍有外部碎片 | **最常用** |
| heap_5 | 多内存区域的 heap_4 | 支持非连续 RAM | 复杂 | 内部 + 外部 RAM 共用 |

#### heap_4 核心：首次适配 + 相邻合并

```c
// heap_4 的空闲块链表结构
typedef struct A_BLOCK_LINK {
    struct A_BLOCK_LINK *pxNextFreeBlock;
    size_t xBlockSize;
} BlockLink_t;

// 分配算法（首次适配）
void *pvPortMalloc(size_t xSize) {
    // 1. 加上块头开销
    xSize += sizeof(BlockLink_t);
    xSize = 对齐到 8 字节;

    // 2. 遍历空闲链表，找到第一个够大的块
    BlockLink_t *pxBlock = xStart.pxNextFreeBlock;
    while (pxBlock->xBlockSize < xSize) {
        pxBlock = pxBlock->pxNextFreeBlock;
        if (pxBlock == NULL) return NULL;  // 没找到
    }

    // 3. 如果块够大，拆分成两块
    if ((pxBlock->xBlockSize - xSize) > 最小块大小) {
        // 拆分：返回多余的块
        BlockLink_t *pxNewBlock = (BlockLink_t *)(((uint8_t *)pxBlock) + xSize);
        pxNewBlock->xBlockSize = pxBlock->xBlockSize - xSize;
        pxBlock->xBlockSize = xSize;
        // 插入空闲链表
    }

    return (void *)(((uint8_t *)pxBlock) + sizeof(BlockLink_t));
}

// 释放算法（合并相邻块）
void vPortFree(void *pv) {
    BlockLink_t *pxBlock = (BlockLink_t *)(((uint8_t *)pv) - sizeof(BlockLink_t));

    // 1. 标记为空闲
    pxBlock->xBlockSize |= 1;  // 最低位表示空闲

    // 2. 按地址排序插入空闲链表
    // 3. 检查并合并相邻的空闲块
    if (前一个块也是空闲) 合并;
    if (后一个块也是空闲) 合并;
}
```

### 3. 内存池机制

#### 3.1 原理

内存池（Memory Pool）预先分配固定大小的块，分配和释放都是 O(1) 操作：

```
内存池结构：

┌──────┬──────┬──────┬──────┬──────┬──────┐
│ 块 0 │ 块 1 │ 块 2 │ 块 3 │ 块 4 │ 块 5 │
│ 64B  │ 64B  │ 64B  │ 64B  │ 64B  │ 64B  │
└──┬───└──┬───└──┬───└──┬───└──┬───└──┬───┘
   │       │       │       │       │      │
   ▼       ▼       ▼       ▼       ▼      ▼
 空闲链表：0 → 1 → 2 → 3 → 4 → 5 → NULL

分配：取链表头部（O(1)）
释放：插回链表头部（O(1)）
```

#### 3.2 实现

```c
typedef struct {
    uint8_t *pool_base;
    size_t   block_size;
    size_t   block_count;
    size_t   free_count;
    uint8_t *free_list;
} mem_pool_t;

int mem_pool_init(mem_pool_t *pool, size_t block_size, size_t block_count) {
    pool->block_size = block_size;
    pool->block_count = block_count;
    pool->free_count = block_count;
    pool->pool_base = (uint8_t *)malloc(block_size * block_count);

    uint8_t *p = pool->pool_base;
    pool->free_list = p;

    for (size_t i = 0; i < block_count - 1; i++) {
        void **next = (void **)p;
        *next = p + block_size;
        p += block_size;
    }
    *(void **)p = NULL;

    return 0;
}

void *mem_pool_alloc(mem_pool_t *pool) {
    if (pool->free_count == 0) return NULL;

    void *block = pool->free_list;
    pool->free_list = *(uint8_t **)block;
    pool->free_count--;
    return block;
}

void mem_pool_free(mem_pool_t *pool, void *block) {
    *(void **)block = pool->free_list;
    pool->free_list = (uint8_t *)block;
    pool->free_count++;
}
```

#### 3.3 内存池 vs malloc 对比

| 特性 | 内存池 | malloc/free |
|------|--------|------------|
| 分配时间 | **O(1)**（取链表头） | O(n)（遍历空闲链表） |
| 释放时间 | **O(1)**（插回链表头） | O(n)（合并相邻块） |
| 碎片 | **无外部碎片**（固定大小） | 有外部碎片 |
| 内存利用率 | 有内部碎片（块大小固定） | 内部碎片少 |
| 线程安全 | 加锁简单（只操作链表头） | 需要锁整个堆 |
| 确定性 | **完全确定** | 不确定 |

### 4. 实际工程中的混合策略

```c
// 常见做法：不同大小用不同的内存池
typedef struct {
    mem_pool_t small_pool;    // 32 字节块 × 64 个
    mem_pool_t medium_pool;   // 128 字节块 × 32 个
    mem_pool_t large_pool;    // 512 字节块 × 8 个
} memory_manager_t;

void *mem_alloc(size_t size) {
    if (size <= 32)       return mem_pool_alloc(&mgr.small_pool);
    else if (size <= 128) return mem_pool_alloc(&mgr.medium_pool);
    else if (size <= 512) return mem_pool_alloc(&mgr.large_pool);
    else                  return NULL;  // 或回退到 heap
}

// FreeRTOS 中可以用 xQueueCreate 之类的函数创建队列
// 队列控制块本身可以用内存池管理
```

### 5. 面试速记

- **内存池**：固定大小块预分配，分配/释放 O(1)，无外部碎片
- **heap_4**：FreeRTOS 最常用方案，首次适配 + 相邻合并
- **malloc 的问题**：时间不确定、线程不安全、碎片化
- **实际做法**：关键路径用内存池，初始化阶段可以用 heap
