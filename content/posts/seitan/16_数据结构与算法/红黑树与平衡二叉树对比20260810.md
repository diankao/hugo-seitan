# 红黑树与平衡二叉树对比

## 题目

红黑树和完全平衡二叉树（AVL）有什么区别？为什么 STL 的 `map`/`set` 选红黑树？

## 考察点

自平衡二叉搜索树原理、平衡策略的权衡、STL 容器底层选型理由。

## 回答要点

### 1. 两者都是"自平衡二叉搜索树"

二叉搜索树（BST）在最坏情况（有序插入）会退化为链表，操作变 O(n)。为保持高效，需要"平衡"机制。红黑树和 AVL 树是两种经典的平衡方案，它们的**平衡严格程度不同**。

| 维度 | AVL 树（完全平衡） | 红黑树（弱平衡） |
|------|-------------------|-----------------|
| 平衡条件 | 任一节点的左右子树高度差 ≤ 1 | 满足 5 条红黑性质（见下） |
| 平衡严格度 | 严格（高度差不超过 1） | 宽松（最长路径 ≤ 最短路径 2 倍） |
| 插入旋转次数 | 最多 1 次（单/双旋） | 最多 2 次 |
| 删除旋转次数 | 可能 O(log n) 次向上回溯 | 最多 3 次 |
| 查找性能 | 略优（树更矮） | 略劣（但差距小） |
| 增删性能 | 较差（频繁重平衡） | 较好（重平衡代价小） |
| 典型应用 | 数据库索引、查找密集场景 | STL map/set、内核调度（CFS）、epoll |

**关键权衡**：AVL 查找快但增删代价高；红黑树三者均衡。当增删频繁时红黑树更优，所以 STL 选了它。

### 2. AVL 树的平衡机制

```c
typedef struct avl_node {
    int key;
    struct avl_node *left, *right;
    int height;          // 节点高度
} avl_node;

// 平衡因子 = 左子树高 - 右子树高，必须在 {-1, 0, 1}
int balance_factor(avl_node* n) {
    return height(n->left) - height(n->right);
}

// 插入后从下往上更新高度并调整
avl_node* insert(avl_node* root, int key) {
    // 1. 标准 BST 插入
    if (!root) return new_node(key);
    if (key < root->key) root->left  = insert(root->left, key);
    else                  root->right = insert(root->right, key);

    // 2. 更新高度
    root->height = 1 + max(height(root->left), height(root->right));

    // 3. 计算平衡因子
    int bf = balance_factor(root);

    // 4. 四种失衡情况，旋转修复
    if (bf > 1 && key < root->left->key)        return rotate_right(root);        // LL
    if (bf < -1 && key > root->right->key)      return rotate_left(root);         // RR
    if (bf > 1 && key > root->left->key) {                                          // LR
        root->left = rotate_left(root->left);
        return rotate_right(root);
    }
    if (bf < -1 && key < root->right->key) {                                        // RL
        root->right = rotate_right(root->right);
        return rotate_left(root);
    }
    return root;
}
```

AVL 的特点是：插入失衡时**一次旋转即可恢复**，但删除可能需要从删除点一直旋转到根（O(log n) 次）。

### 3. 红黑树的五条性质

红黑树通过给节点着色 + 五条约束来保证"近似平衡"：

```c
typedef enum { RED, BLACK } color_t;

typedef struct rb_node {
    int key;
    struct rb_node *left, *right, *parent;
    color_t color;
} rb_node;
```

**五条性质**：
1. 每个节点要么红要么黑。
2. **根节点是黑色**。
3. 每个叶子节点（NIL 空节点）是黑色。
4. **红色节点的子节点必须是黑色**（即不能有两个连续的红节点）。
5. **从任一节点到其所有叶子节点的路径，包含相同数目的黑色节点**（黑高相同）。

由这五条可推出：**最长路径（红黑相间）不超过最短路径（全黑）的 2 倍**，从而保证高度 O(log n)。

### 4. 为什么红黑树增删更高效

红黑树放宽了平衡要求，允许树更高一点，换来**更少的重平衡操作**：

| 操作 | AVL 树 | 红黑树 |
|------|--------|--------|
| 插入：旋转次数 | ≤ 1 次 | ≤ 2 次 |
| 插入：颜色调整 | 无 | 可能向上传播到根 |
| 删除：旋转次数 | O(log n)（最坏一路旋到根） | ≤ 3 次 |
| 删除：颜色调整 | O(log n) | O(log n) |

对于 `map`/`set` 这种既查找又频繁增删的容器，红黑树的综合性能更好。

### 5. 高度对比（直观感受）

假设有 n 个节点：

| 树种 | 高度上界 | n=10⁶ 时典型高度 |
|------|---------|----------------|
| 完全不平衡 BST（链表） | n | 10⁶ |
| AVL 树 | ≈ 1.44 log₂(n) | ≈ 29 |
| 红黑树 | ≤ 2 log₂(n+1) | ≈ 40 |

差距不大，所以红黑树查找略慢但增删明显更快。

### 6. STL 为什么选红黑树

STL 的 `map`/`set`/`multimap`/`multiset` 都用红黑树（GCC 的 `__rb_tree`、MSVC 的 `_Tree`）作为底层：

1. **综合性能均衡**：增删查都是 O(log n)，且常数因子小。
2. **增删代价小**：容器在使用中频繁增删，红黑树重平衡代价小。
3. **实现相对简单**：相比 AVL 的 O(log n) 删除调整，红黑树的删除调整虽然概念复杂但操作次数有上界。
4. **迭代器稳定性**：红黑树节点式结构，增删不影响其他节点位置，迭代器不失效。

> 对比：Linux 内核的进程调度 CFS 也用红黑树（按虚拟运行时间排序，频繁增删 task）；epoll 内部用红黑树管理监听的 fd；Java 的 `TreeMap`、C# 的 `SortedDictionary` 也都是红黑树。

### 7. AVL 适合什么场景

AVL 树在**查找密集、增删稀少**的场景仍有优势（树更矮）：

- 数据库索引（虽然实际多用 B+ 树，AVL 用于教学和小规模索引）
- 只构建一次、大量查询的静态数据
- 对查找延迟敏感、要求严格平衡的场合

### 8. 旋转操作（两者通用）

两种树都靠**旋转**调整结构，旋转本身不破坏 BST 性质：

```c
// 右旋（以 y 为支点）
//     y                x
//    / \              / \
//   x   C    →       A   y
//  / \                  / \
// A   B                B   C

avl_node* rotate_right(avl_node* y) {
    avl_node* x = y->left;
    avl_node* B = x->right;

    x->right = y;
    y->left  = B;

    update_height(y);
    update_height(x);
    return x;          // 新子树根
}

// 左旋是对称操作
```

### 9. 与 B 树 / B+ 树 / 跳表对比（延伸）

实际工程中还要考虑其他平衡结构：

| 结构 | 特点 | 典型应用 |
|------|------|---------|
| 红黑树 | 二叉，O(log n)，节点式 | STL map、CFS、epoll |
| AVL | 二叉，严格平衡 | 教学、查找密集 |
| B 树 / B+ 树 | 多路，矮胖，磁盘友好 | 数据库索引（MySQL InnoDB） |
| 跳表 | 多层链表，概率平衡 | Redis zset、LevelDB MemTable |
| Treap | 树+堆，随机化平衡 | 教学竞赛 |

数据库用 B+ 树而非红黑树，是因为**磁盘 IO 是块设备**，B+ 树每节点存多个 key 减少 IO 次数；红黑树每个节点一次 IO 反而低效。

## 扩展问题

面试官可能会追问：
- 红黑树最多旋转几次？（插入 ≤ 2，删除 ≤ 3）
- 红黑树的黑高是什么？为什么能保证 O(log n)？（性质 5 保证黑高一致，最长路径 ≤ 2 倍最短）
- B+ 树为什么比红黑树更适合做数据库索引？（矮胖、磁盘块对齐、叶节点链表支持范围扫描）
- 跳表相比红黑树的优势？（实现简单，并发友好，范围查询天然支持）
