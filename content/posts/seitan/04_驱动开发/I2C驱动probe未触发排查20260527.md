# I2C驱动probe未触发排查

## 题目

I2C 驱动的 probe 函数没有被调用，怎么排查？

## 考察点

Linux设备驱动模型、设备树与平台驱动的匹配机制、I2C子系统、调试方法论。

## 回答要点

### 1. probe 触发的前提条件

I2C 驱动的 probe 被调用，需要满足**三个条件**：

```
① 设备树中有对应的 I2C 设备节点（compatible 匹配）
② I2C 总线驱动已加载（i2c-controller 驱动正常工作）
③ I2C 设备驱动已加载（module_init / module_i2c_driver）
       │
       ▼ 三者缺一不可
内核将设备和驱动进行匹配 → 调用 probe
```

### 2. 排查步骤

#### 步骤一：确认设备树节点存在且正确

```bash
# 1. 查看设备树是否生效
ls /proc/device-tree/i2c@*/i2c-device@*/

# 2. 查看完整设备树信息
dtc -I fs /sys/firmware/devicetree/base

# 3. 检查 compatible 属性
cat /sys/firmware/devicetree/base/i2c@ff150000/sensor@50/compatible
# 应该输出：vendor,sensor-name
```

**设备树典型写法**：

```dts
// 设备树中的 I2C 控制器节点
&i2c1 {
    status = "okay";          // 必须是 "okay"

    // I2C 设备节点
    sensor@50 {               // @后面是 I2C 从地址
        compatible = "bosch,bme280";  // 必须与驱动中的 of_device_id 匹配
        reg = <0x50>;         // I2C 从地址
        status = "okay";
    };
};
```

**常见问题**：

| 问题 | 检查方法 |
|------|---------|
| 节点 status = "disabled" | 查看设备树，改为 "okay" |
| compatible 拼写错误 | 与驱动代码对比 |
| reg 地址错误 | 对照芯片数据手册 |
| I2C 控制器节点未使能 | 父节点 status 也要 "okay" |
| 设备树未编译/未加载 | 检查 .dtb 是否更新 |

#### 步骤二：确认 I2C 总线驱动已加载

```bash
# 查看 I2C 总线是否注册
ls /sys/bus/i2c/

# 查看已注册的 I2C 适配器
ls /sys/class/i2c-adapter/
# 或
cat /sys/class/i2c-adapter/i2c-*/name

# 查看 I2C 控制器驱动是否加载
lsmod | grep i2c
dmesg | grep i2c
```

```bash
# 如果 I2C 控制器驱动没有加载
dmesg | grep "i2c.*controller"
# 应该看到类似：
# i2c i2c-0: RK3x I2C adapter
```

**常见问题**：

| 问题 | 检查方法 |
|------|---------|
| I2C 控制器驱动未编译进内核 | `make menuconfig` 检查 |
| I2C 控制器时钟未使能 | 检查 CCU/CRU 时钟配置 |
| I2C 引脚复用未配置 | 检查 pinctrl 节点 |

#### 步骤三：确认设备驱动已加载

```bash
# 查看驱动是否已注册到 I2C 总线
ls /sys/bus/i2c/drivers/
# 应该看到你的驱动名

# 查看模块是否加载
lsmod | grep your_driver

# 手动加载驱动
insmod your_driver.ko
# 或
modprobe your_driver
```

#### 步骤四：确认 compatible 匹配

```bash
# 查看驱动支持的 compatible 列表
cat /sys/bus/i2c/drivers/your_driver/module/of/compatible
# 或从源码查看 of_device_id 表
```

```c
// 驱动代码中的 of_device_id 必须与设备树一致
static const struct of_device_id bme280_of_match[] = {
    { .compatible = "bosch,bme280" },   // 必须与设备树完全一致
    { .compatible = "bosch,bme680" },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, bme280_of_match);

static struct i2c_driver bme280_driver = {
    .driver = {
        .name = "bme280",
        .of_match_table = bme280_of_match,  // 关键：必须设置
    },
    .probe = bme280_probe,
    .remove = bme280_remove,
};
module_i2c_driver(bme280_driver);
```

**常见不匹配情况**：

```c
// 设备树：compatible = "bosch,bme280"
// 驱动：  .compatible = "bosh,bme280"     // 拼写错误！bosch → bosh
// 结果：不匹配，probe 不调用
```

#### 步骤五：查看内核日志

```bash
# 最关键的调试手段
dmesg | tail -50
dmesg | grep -i "i2c\|probe\|your_driver\|error\|fail"

# 开启动态调试
echo 'file drivers/i2c/* +p' > /sys/kernel/debug/dynamic_debug/control
echo 'file your_driver.c +p' > /sys/kernel/debug/dynamic_debug/control

# 查看 I2C 设备扫描结果
i2cdetect -y 0   // 扫描 i2c-0 总线上的所有设备
```

### 3. 完整排查流程

```
probe 没被调用
       │
       ▼
┌──────────────────┐
│ dmesg 有报错吗？  │──Yes──▶ 根据错误信息修复
└──────┬───────────┘
       │ No
       ▼
┌──────────────────┐
│ /sys/bus/i2c/    │──No──▶ I2C 控制器驱动未加载
│ 存在吗？         │       检查内核配置和设备树
└──────┬───────────┘
       │ Yes
       ▼
┌──────────────────┐
│ i2cdetect 能扫描 │──No──▶ 硬件问题或 I2C 引脚配置错误
│ 到设备吗？       │
└──────┬───────────┘
       │ Yes
       ▼
┌──────────────────┐
│ 设备树节点存在且 │──No──▶ 修改设备树，添加设备节点
│ compatible 正确？│
└──────┬───────────┘
       │ Yes
       ▼
┌──────────────────┐
│ 驱动已加载？     │──No──▶ insmod / modprobe 加载驱动
│ lsmod 能看到？   │
└──────┬───────────┘
       │ Yes
       ▼
┌──────────────────┐
│ compatible 完全  │──No──▶ 修改驱动或设备树使其一致
│ 一致？           │
└──────┬───────────┘
       │ Yes
       ▼
   检查 probe 返回值
   是否 probe 被调用但返回了错误
```

### 4. 高级调试技巧

```bash
# 在驱动中添加调试打印
static int my_probe(struct i2c_client *client, const struct i2c_device_id *id) {
    dev_info(&client->dev, "probe called, addr=0x%02x\n", client->addr);
    // ...
}

# 使用 ftrace 追踪 probe 调用
echo function > /sys/kernel/debug/tracing/current_tracer
echo my_probe > /sys/kernel/debug/tracing/set_ftrace_filter
echo 1 > /sys/kernel/debug/tracing/tracing_on
cat /sys/kernel/debug/tracing/trace

# 查看 ACPI 下的 I2C 设备（x86 平台）
ls /sys/bus/acpi/devices/
```

### 5. 面试速记

- **三个前提**：设备树节点 + I2C 总线驱动 + 设备驱动
- **核心匹配**：设备树 `compatible` = 驱动 `of_device_id`
- **排查命令**：`dmesg`、`i2cdetect`、`ls /sys/bus/i2c/`
- **常见原因**：compatible 不匹配、设备树 status 为 disabled、I2C 控制器未使能
- **快速验证**：`i2cdetect` 能否扫描到设备地址，确认硬件和总线正常
