# Keil中printf重定向的两种方式

## 题目

在Keil开发STM32时，如何通过串口重定向`printf`输出？有哪些方式？

## 考察点

- 理解`printf`底层机制（`fputc`重定向）
- 了解MicroLIB与标准C库的差异
- 理解semihosting概念及为什么嵌入式需要禁用它

## 回答要点

### 1. 方式一：Use MicroLIB（勾选一下就行）

Options for Target → Target 选项卡 → 勾选 **Use MicroLIB**。

MicroLIB 是 ARM 提供的精简版 C 标准库，只需要重写 `fputc` 就行：

```c
int fputc(int ch, FILE *f) {
    while(USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET) {}
    USART_SendData(USART1, ch);
    return ch;
}
```

完事。不需要 `#ifdef PRINT_TO_UART`，不需要 `#pragma import(__use_no_semihosting_swi)`，不需要那些 `__stdout`、`_sys_exit`、`_ttywrch` 的桩函数。

### 2. 方式二：标准库（不勾MicroLIB）

用 ARMCC 默认的完整 C 标准库。标准库默认会尝试用 **semihosting**（通过调试器做 I/O），所以在嵌入式上必须手动禁用：

```c
#pragma import(__use_no_semihosting_swi)   // 禁用 semihosting
struct __FILE { int handle; };             // 自定义 FILE 结构
FILE __stdout;                             // 提供 stdout
void _sys_exit(int x) { while(1); }       // 提供退出桩函数
void _ttywrch(int ch) { }                 // 提供写字符桩函数
int ferror(FILE *f) { return EOF; }       // 提供错误桩函数
```

少写一个都会导致链接报错或者程序卡死。

### 3. 两种方式对比

| 特性 | MicroLIB | 标准库 |
|------|----------|--------|
| 配置方式 | 勾一个选项 | 写一堆桩函数 |
| 代码体积 | 更小 | 更大 |
| 功能 | 精简，够用 | 完整 |
| printf浮点 | 不支持 `%f` | 支持 `%f` |

### 4. 结论

两种都能用，效果一样。如果嫌麻烦，直接勾上 **Use MicroLIB**，然后把桩函数全删了只留 `fputc`，更干净。
