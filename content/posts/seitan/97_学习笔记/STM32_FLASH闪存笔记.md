# STM32 FLASH闪存（15-1 概述 / 15-2 读写与芯片ID）笔记

---

## 一、FLASH简介

### 基本概念
闪存（Flash）是一种**非易失性存储器**，掉电后数据不会丢失。本节特指STM32的**内部闪存**，即程序下载时存储的地方。

### STM32F103的FLASH组成

| 部分 | 起始地址 | 容量（C8T6） | 用途 | 是否可读写 |
|------|----------|-------------|------|-----------|
| **程序存储器（主存储器）** | 0x08000000 | 64KB | 存储程序代码 | ✅ 可擦除、可编程 |
| **系统存储器（启动程序代码）** | 0x1FFF0000 | 2KB | 原厂BOOTLOADER，用于串口下载 | ❌ 不可修改 |
| **选项字节（用户选择字节）** | 0x1FFF8000 | 16字节 | 存储配置参数（读写保护等） | ✅ 可擦除、可编程 |

> 注意：平时说的芯片容量64K、128K只指**程序存储器**，不包括系统存储器和选项字节。

### 存储器映射地址速查

| 地址前缀 | 区域 | 存储介质 | 特性 |
|---------|------|---------|------|
| **0x0800** | 程序存储器 | FLASH | 掉电不丢失，程序代码 |
| **0x1FFF** | 系统存储器/选项字节 | FLASH | BOOTLOADER和配置参数 |
| **0x2000** | 运行内存（SRAM） | SRAM | 掉电丢失，运行时变量 |
| **0x4000** | 外设寄存器 | SRAM | 外设控制寄存器 |
| **0x1000** | 内核外设总线 | SRAM | NVIC等内核外设 |

## 二、闪存模块组织

### 不同容量产品的页分配

| 产品类型 | 总页数 | 每页大小 | 总容量 | C8T6范围 |
|---------|--------|---------|-------|----------|
| 小容量（LD） | 32页 | 1KB | 32KB | - |
| **中容量（MD）** | **128页** | **1KB** | **128KB** | **0~63页（64KB）** |
| 大容量（HD） | 256页 | 2KB | 512KB | - |

### C8T6（中容量64KB）页地址分配

```
页号    起始地址          结束地址
第0页   0x08000000        0x080003FF
第1页   0x08000400        0x080007FF
第2页   0x08000800        0x08000BFF
...
第62页  0x0800F800        0x0800FBFF
第63页  0x0800FC00        0x0800FFFF

页起始地址规律：以 0x0000、0x0400、0x0800、0x0C00 结尾
```

> **小贴士**：页起始地址的最后一个十六进制数，除以16后取整就是页号。例如0x08000400 → 400÷16=64 → 第64页（仅限中容量每页1KB的情况）。

### 闪存基本特性（与W25Q64相同）

| 特性 | 说明 |
|------|------|
| **擦除单位** | 页（Page） |
| **写入前必须擦除** | 只能1写0，不能0写1 |
| **擦除后数据** | 全变为0xFF |
| **擦除/写入需等待** | 操作期间忙标志置1，需等待操作完成 |
| **写保护** | 可通过选项字节配置某些页只读 |

## 三、闪存存储器接口（FPEC）

### 控制器作用
闪存存储器接口（Flash Memory Interface），也叫**闪存编程和擦除控制器（FPEC）**，是闪存的**管理员外设**。

| 作用 | 说明 |
|------|------|
| 控制擦除和编程 | 向控制器的寄存器写入指令，控制器自动操作闪存 |
| 接收CPU指令 | CPU通过读写寄存器与控制器通信 |
| 管理保护机制 | 解锁、加锁、写保护等 |

### 控制器寄存器

| 寄存器 | 地址偏移 | 功能 |
|--------|---------|------|
| **KEYR（密钥寄存器）** | +0x04 | 写入KEY1和KEY2解锁 |
| **CR（控制寄存器）** | +0x10 | 配置擦除/编程操作、启动位 |
| **SR（状态寄存器）** | +0x0C | 忙标志、错误标志 |

> 寄存器地址：0x40022000（外设起始地址），每个寄存器4字节（32位）。

## 四、读写FLASH的用途

### 1. 存储用户数据（掉电不丢失）

利用程序存储器的**剩余空间**存储配置参数，节省外挂存储芯片成本。

```
程序代码（通常占前几KB）
        ↓
    大片空白空间
        ↓
    存储用户数据（建议用最后几页）
```

**注意事项**：
- 必须避开程序本身，否则程序会自我破坏无法运行
- 建议用最后几页（如C8T6的第62、63页）
- 可通过Keil的MAP文件查看程序占用大小

### 2. 在程序中编程（IAP）—— 程序自我更新

实现程序的**在线升级（OTA）**，允许程序在运行过程中修改自身代码。

#### ICP vs IAP

| 方式 | 全称 | 下载方式 | 特点 |
|------|------|---------|------|
| **ICP** | In-Circuit Programming（在电路编程） | JTAG/SWD、系统存储器（串口） | 更新整个程序，需要外部工具 |
| **IAP** | In-Application Programming（在应用编程） | 任意通信接口（串口/USB/WiFi等） | 程序自主完成升级，可实现远程升级 |

#### IAP实现流程

```
程序存储器
├─ 主程序区（正常运行位置）
└─ BOOTLOADER区（程序更新时不会被覆盖）

升级过程：
1. 跳转到自写BOOTLOADER
2. 通过串口/USB等接收新程序数据
3. 调用FLASH读写，将新程序写入主程序区
4. 跳转回主程序或复位
```

> 与系统存储器BOOTLOADER的区别：自写BOOTLOADER可以任意指定写入位置、启动方式、通信接口，更灵活。

## 五、FLASH操作流程

### 读取数据
**直接使用指针访问即可**，不需要通过FPEC控制器。

```c
uint32_t data = *(uint32_t *)0x08000000;  // 读取0x08000000地址的32位数据
```

### 擦除操作

#### 页擦除

| 步骤 | 操作 | 库函数 |
|------|------|--------|
| 1 | 解锁 | `FLASH_Unlock()` |
| 2 | 等待上次操作完成 | 内部自动调用`FLASH_WaitForLastOperation()` |
| 3 | 配置页擦除：写入页地址到AR寄存器 | - |
| 4 | 启动擦除：CR的START位置1 | - |
| 5 | 等待擦除完成 | 内部自动调用`FLASH_WaitForLastOperation()` |
| 6 | 加锁 | `FLASH_Lock()` |

> 封装函数：`FLASH_ErasePage(uint32_t Page_Address)`

#### 全擦除

| 步骤 | 操作 | 库函数 |
|------|------|--------|
| 1 | 解锁 | `FLASH_Unlock()` |
| 2 | 等待 | 内部自动 |
| 3 | 配置全擦除：CR的MER位置1 | - |
| 4 | 启动擦除：START位置1 | - |
| 5 | 等待 | 内部自动 |
| 6 | 加锁 | `FLASH_Lock()` |

> 封装函数：`FLASH_EraseAllPages()`

### 编程（写入）操作

#### 写入半字（16位）

| 步骤 | 操作 | 库函数 |
|------|------|--------|
| 1 | 解锁 | `FLASH_Unlock()` |
| 2 | 等待 | 内部自动 |
| 3 | 配置编程：CR的PG位置1 | - |
| 4 | 写入数据：`(uint16_t *)Address = Data` | 指针写入 |
| 5 | 等待 | 内部自动 |
| 6 | 加锁 | `FLASH_Lock()` |

> 封装函数：`FLASH_ProgramHalfWord(uint32_t Address, uint16_t Data)`

#### 写入字（32位）

内部实现为**两次半字写入**：
1. 在Address写入Data的低16位
2. 在Address+2写入Data的高16位

> 封装函数：`FLASH_ProgramWord(uint32_t Address, uint32_t Data)`

### 选项字节操作

与主存储器类似，但需要额外解锁选项字节的小锁。

| 函数 | 用途 |
|------|------|
| `FLASH_EraseOptionBytes()` | 擦除选项字节 |
| `FLASH_ProgramOptionByteData()` | 编程自定义数据 |
| `FLASH_EnableWriteProtection()` | 配置写保护 |
| `FLASH_ReadOutProtection()` | 配置读保护 |

> **警告**：配置读写保护不当可能导致芯片自锁，无法下载程序。可用STM32 ST-LINK Utility工具解除保护。

## 六、库函数详解

### 解锁与加锁

| 函数 | 功能 |
|------|------|
| `FLASH_Unlock()` | 向KEYR写入KEY1（0x45670123）和KEY2（0xCDEF89AB）解锁 |
| `FLASH_Lock()` | 将CR的LOCK位置1，防止误操作 |

### 擦除函数

| 函数 | 返回值 | 说明 |
|------|--------|------|
| `FLASH_ErasePage(uint32_t Page_Address)` | FLASH_Status | 擦除指定页 |
| `FLASH_EraseAllPages(void)` | FLASH_Status | 全擦除（慎用！） |
| `FLASH_EraseOptionBytes(void)` | FLASH_Status | 擦除选项字节 |

### 编程函数

| 函数 | 返回值 | 说明 |
|------|--------|------|
| `FLASH_ProgramHalfWord(uint32_t Address, uint16_t Data)` | FLASH_Status | 写入半字（最常用） |
| `FLASH_ProgramWord(uint32_t Address, uint32_t Data)` | FLASH_Status | 写入字（内部调用两次半字写入） |

### 返回状态码（FLASH_Status枚举）

| 状态 | 含义 |
|------|------|
| `FLASH_COMPLETE` | 操作成功 |
| `FLASH_BUSY` | 芯片忙 |
| `FLASH_ERROR_PG` | 编程错误 |
| `FLASH_ERROR_WRP` | 写保护错误 |
| `FLASH_TIMEOUT` | 等待超时 |

### 其他辅助函数

| 函数 | 用途 |
|------|------|
| `FLASH_WaitForLastOperation(uint32_t Timeout)` | 等待上次操作完成（内部自动调用） |
| `FLASH_GetFlagStatus()` | 获取标志位 |
| `FLASH_ClearFlag()` | 清除标志位 |
| `FLASH_GetStatus()` | 获取当前状态 |

## 七、读取芯片ID

### ID存储位置

| ID类型 | 地址 | 数据格式 | 说明 |
|--------|------|---------|------|
| **F_SIZE** | 0x1FFFF7E0 | 16位 | FLASH容量（单位：KB） |
| **UID** | 0x1FFFF7E8 | 96位（3×32位） | 芯片唯一ID，每个芯片不同 |

### 读取方法

```c
// 读取FLASH容量
uint16_t flash_size = *(uint16_t *)0x1FFFF7E0;  // C8T6读出0x0040（64KB）

// 读取96位UID
uint32_t uid_0 = *(uint32_t *)0x1FFFF7E8;
uint32_t uid_1 = *(uint32_t *)0x1FFFF7EC;
uint32_t uid_2 = *(uint32_t *)0x1FFFF7F0;
```

## 八、STM32 ST-LINK Utility工具

### 功能概览

| 功能 | 用途 |
|------|------|
| 查看闪存内容 | 可视化显示指定地址的闪存数据 |
| 直接修改闪存 | 选中数据单击即可修改（底层会执行擦除+写入） |
| 配置选项字节 | 图形化配置读保护、写保护等参数 |

### 使用步骤

1. 连接ST-Link
2. 点击"Connect"按钮
3. 设置起始地址（如0x08000000）和查看大小（如0x10000=64KB）
4. 选择数据宽度（32位/16位/8位）
5. 查看或修改数据

### 选项字节配置

打开 **Target → Option Bytes**，可配置：
- 读保护（Read Out Protection）
- 写保护（Write Protection）
- 用户选项
- 自定义数据（Data0/Data1）

> **救砖方法**：如果芯片因读写保护无法下载程序，用此工具取消保护即可救活。

## 九、代码分层设计

### 工程结构

```
main.c（应用层）
    ↓ 调用
Store模块（管理层）
    ↓ 调用
MyFlash模块（底层）
```

### 分层职责

| 层级 | 模块 | 职责 |
|------|------|------|
| **底层** | MyFlash | 封装读取、擦除、编程三个基本操作 |
| **管理层** | Store | 实现数据存储管理：SRAM数组 ↔ FLASH备份，初始化自动加载 |
| **应用层** | main | 直接操作SRAM数组，调用Store保存函数 |

### MyFlash底层函数示例

```c
// 读取32位字
uint32_t MyFLASH_ReadWord(uint32_t Address) {
    return *(volatile uint32_t *)Address;
}

// 读取16位半字
uint16_t MyFLASH_ReadHalfWord(uint32_t Address) {
    return *(volatile uint16_t *)Address;
}

// 读取8位字节
uint8_t MyFLASH_ReadByte(uint32_t Address) {
    return *(volatile uint8_t *)Address;
}
```

> **volatile关键字**：防止编译器优化，确保每次都从内存读取（与寄存器访问一致）。

## 十、重要注意事项

1. **解锁/加锁成对**：擦除和编程前解锁，操作后加锁，防止误操作
2. **写入前必须擦除**：只能1写0，不能0写1，擦除后全为0xFF
3. **避开程序代码**：存储用户数据时用最后几页，不要覆盖程序
4. **等待操作完成**：库函数内部已自动调用等待，一般不需要单独调用
5. **选项字节慎用**：配置读写保护不当可能导致芯片自锁
6. **全擦除慎用**：`FLASH_EraseAllPages()`会擦除程序，导致程序丢失
7. **ST-LINK占用问题**：使用STM32 ST-LINK Utility时，下载程序前需先断开连接
8. **地址必须32位**：函数形参地址类型始终为`uint32_t`，与指针访问宽度无关
