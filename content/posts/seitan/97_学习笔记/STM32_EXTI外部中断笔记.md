# STM32 EXTI外部中断 笔记

## 一、本节程序现象

### 程序1：对射式红外传感器计次
- 接一个红外对管传感器，OLED显示数字
- 用挡光片挡住红外对管 → 模块输出指示灯灭（输出高电平）
- 移开挡光片 → 指示灯亮（输出低电平）
- **灭→亮之间产生下降沿** → 触发外部中断 → 数字+1
- 屏幕对挡光次数进行统计

### 程序2：旋转编码器计次
- 接旋转编码器，屏幕显示数字
- 旋转编码器 → 数字跟随变化

## 二、中断基本概念

### 中断定义
在主程序运行过程中，出现了特定的**中断触发条件**（中断源），使得CPU暂停当前正在运行的程序，转而去处理中断程序，处理完成后又返回原来被暂停的位置继续运行。

### 中断触发条件举例
| 中断源 | 触发条件 |
|--------|----------|
| 外部中断（EXTI） | 引脚发生电平跳变 |
| 定时器（TIM） | 定时时间到了 |
| 串口（USART） | 接收到数据 |

### 为什么需要中断？
- 外部中断来了不处理 → 下一个跳变信号覆盖
- 串口接收中断来了不读数据 → 下一个数据覆盖原来的
- **没有中断 → 主程序只能不断查询是否有事件发生，不能干其他事**
- **有了中断 → 主程序放心执行其他事，有中断时再去处理**

> 闹钟比喻：定了闹钟就可以放心睡觉，时间到了闹钟提醒你（= 产生中断信号）。没有闹钟就得不断看时间，没法安心睡觉。

## 三、中断优先级

### 定义
当有多个中断源**同时**申请中断时，CPU会根据中断源的轻重缓急进行裁决，优先响应更紧急的中断源。优先级由程序员根据需求自行设置。

### 中断嵌套
当一个中断程序正在运行时，又有新的**更高优先级**的中断申请 → CPU再次暂停当前中断程序，转去处理新的中断程序，处理完成后依次返回。

```
主程序 → 中断A → 中断B（更紧急）→ 返回中断A → 返回主程序
```

能否进行中断嵌套也由中断优先级决定。

---

## 四、中断执行流程

### 单次中断
```
主程序执行中...
    ↓ 中断条件满足
    ↓ 硬件自动保存断点（保护现场）
    ↓ 跳转到中断服务函数
    ↓ 执行中断处理代码
    ↓ 恢复现场
    ↓ 返回断点继续执行
```

> 保护现场和还原现场由编译器自动完成，C语言编程不需要手动处理。

### C语言程序中的中断结构
```c
int main(void)
{
    while (1)
    {
        // 主程序：正常情况下不断循环执行
    }
}

void EXTI1_IRQHandler(void)
{
    // 中断服务函数：中断来临时由硬件自动调用，不需要手动调用
    // 处理中断事件...
}
```

## 五、STM32的中断资源

### 基本参数
- **68个**可屏蔽中断通道（F1系列最多数量，具体型号以数据手册为准）
- 包括 TIM、ADC、USART、SPI、I2C、RTC 等几乎所有模块都能申请中断
- 使用 **NVIC** 统一管理中断
- 每个中断通道拥有 **16个** 可编程优先等级
- 可对优先级进行分组：**抢占优先级** 和 **响应优先级**

### 中断资源分类

| 类型 | 举例 | 说明 |
|------|------|------|
| **内核中断**（灰色） | 复位中断、NMI不可屏蔽中断、硬件失效、总线错误等 | 一般用不到，了解即可 |
| **外设中断** | 窗口看门狗、PVD电源电压监测、EXTI外部中断、TIM定时器等 | 常用 |

### 中断向量表
- 程序中的中断函数地址由编译器分配，**不固定**
- 但硬件中断跳转只能跳到**固定地址**
- 解决方案：在内存中定义一个**地址固定的列表**（中断向量表），中断发生先跳到这里，再跳转到实际中断函数
- C语言编程不需要管，编译器自动处理

## 六、NVIC——嵌套中断向量控制器

### 基本结构
```
EXTI ──┐
TIM  ──┤
ADC  ──┼──→ NVIC（统一分配优先级）──→ CPU
USART ─┤
SPI  ──┘
```

- NVIC是内核外设，是CPU的"小助手"
- 多个中断输入 → NVIC根据优先级排队 → 一个输出给CPU
- CPU不需要管中断排队的事

> 叫号系统比喻：CPU是医生，NVIC是叫号系统。病人（中断）统一取号，叫号系统按优先级安排顺序，医生专心看病就行。

### 优先级分组

NVIC的中断优先级由**优先级寄存器的4位**决定（0\~15，共16个等级）。

**数值越小，优先级越高，0是最高优先级。**

这4位可以切分为**高n位的抢占优先级**和**低(4-n)位的响应优先级**：

| 分组 | 抢占优先级位数 | 抢占取值范围 | 响应优先级位数 | 响应取值范围 |
|------|---------------|-------------|---------------|-------------|
| 组0 | 0位 | 0 | 4位 | 0\~15 |
| 组1 | 1位 | 0\~1 | 3位 | 0\~7 |
| 组2 | 2位 | 0\~3 | 2位 | 0\~3 |
| 组3 | 3位 | 0\~7 | 1位 | 0\~1 |
| 组4 | 4位 | 0\~15 | 0位 | 0 |

### 抢占优先级 vs 响应优先级

| 类型 | 作用 | 比喻 |
|------|------|------|
| **抢占优先级** | 高的可以**中断嵌套**（打断正在执行的中断） | 紧急病人直接冲进诊室打断上一个病人 |
| **响应优先级** | 高的可以**优先排队**（多个中断同时等待时先执行） | 排队时紧急病人插队 |
| 两者均相同 | 按**中断号**排队，数值小的优先 | 先来后到 |

> STM32的中断**不存在先来后到**的排队方式，任何时候都是优先级高的先响应。

## 七、EXTI外部中断

### 基本介绍
- **EXTI** = External Interrupt（外部中断）
- 可以监测**指定GPIO口**的电平变化
- 当指定GPIO口产生电平变化时，EXTI立即向NVIC发出中断申请
- 经NVIC裁决后即可中断CPU主程序，执行对应的中断程序

### 触发方式
| 触发方式 | 说明 |
|----------|------|
| **上升沿触发** | 低电平 → 高电平的瞬间触发 |
| **下降沿触发** | 高电平 → 低电平的瞬间触发 |
| **双边沿触发** | 上升沿和下降沿都触发 |
| **软件触发** | 引脚无变化，程序里执行代码触发 |

### 支持的GPIO口
- 支持**所有GPIO口**，任意GPIO口都可以作为外部中断引脚
- **相同Pin号不能同时触发中断**
  - 例如 PA0 和 PB0 不能同时用
  - PA1、PB1、PC1 只能选一个作为中断引脚
  - 因为 EXTI0 只能连接一个 Pin0，EXTI1 只能连接一个 Pin1

### EXTI通道（中断线）分配
| EXTI线 | 对应引脚 | 中断函数 |
|--------|----------|----------|
| EXTI0 | PA0/PB0/PC0/...（选一个） | `EXTI0_IRQHandler` |
| EXTI1 | PA1/PB1/PC1/...（选一个） | `EXTI1_IRQHandler` |
| EXTI2 | PA2/PB2/PC2/...（选一个） | `EXTI2_IRQHandler` |
| EXTI3 | PA3/PB3/PC3/...（选一个） | `EXTI3_IRQHandler` |
| EXTI4 | PA4/PB4/PC4/...（选一个） | `EXTI4_IRQHandler` |
| EXTI9\~5 | PA5\~PA9/PB5\~PB9/... | `EXTI9_5_IRQHandler`（共用） |
| EXTI15\~10 | PA10\~PA15/PB10\~PB15/... | `EXTI15_10_IRQHandler`（共用） |

> EXTI0\~4 各有独立中断函数，EXTI5\~9 共用 `EXTI9_5_IRQHandler`，EXTI10\~15 共用 `EXTI15_10_IRQHandler`。
