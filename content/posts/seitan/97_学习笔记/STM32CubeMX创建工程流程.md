# STM32CubeMX创建工程流程

## 1. 软件准备

### 1.1 安装STM32CubeMX
- 在ST公司官网下载STM32CubeMX软件
- 下载地址：ST官网或网上搜索即可找到

### 1.2 注册ST账号
- 必须注册ST账号才能使用软件
- 打开软件后需要登录
- 如果无法更新，尝试以管理员身份运行

### 1.3 软件包管理
- 右侧界面可管理软件安装和芯片软件包
- 可以对STM32CubeMX本身进行更新
- 芯片软件包可在工程创建时自动下载安装
- 不需要手动安装，联网即可自动下载

## 2. 创建工程的三种方式

### 2.1 从MCU选择创建工程（推荐）
- 适用于自己画的板子或第三方开发板
- 选择具体的MCU芯片型号

### 2.2 从ST开发板创建工程
- 适用于ST官方开发板
- 会自动初始化开发板上的相关外设
- 可以更快速进行开发

### 2.3 从示例工程创建工程
- 使用ST提供的示例工程
- 一般使用较少
- 可作为参考

## 3. 选择MCU芯片

### 3.1 搜索芯片型号
- 在搜索框中输入芯片型号
- 例如：输入"F103"筛选STM32F1系列

### 3.2 选择具体型号
- 常用型号：STM32F103C8T6 或 STM32F103C6T6
- C8和C6的区别：
  - C8的Flash存储空间是C6的一倍
  - 对于小型应用开发，两者区别不大

### 3.3 通过资源筛选芯片
- 可通过芯片上的资源来筛选
- 例如：ADC数量、定时器数量等
- 适用于不知道选择哪种芯片时
- 软件会自动推荐合适的芯片

## 4. 基本配置

### 4.1 RCC配置（时钟控制）
**配置步骤：**
1. 打开左侧`System Core` → `RCC`
2. **高速时钟HSE**：
   - 选择`Crystal/Ceramic Resonator`（晶体振荡器）
   - 这是外部高速时钟
   - 底部参数保持默认

3. **低速时钟LSE**：
   - 一般不需要开启
   - 用于RTC（实时时钟）

### 4.2 SYS配置（系统配置）
**重要配置：**
1. **Debug配置**：
   - 必须勾选`Debug`选项
   - 选择调试接口：
     - **No Debug**：不启用调试功能，程序只能下载一次，第二次无法下载，需要通过串口方式重新刷写，不推荐选择
     - **Serial Wire**：串行线调试接口（推荐），使用2根线（SWDIO、SWCLK）+ 1根地线，共3根线，占用引脚少，传输速度快，支持ST-Link和J-Link，是最常用的调试方式
     - **JTAG (4 pins)**：传统JTAG调试接口，使用4根线（TDI、TDO、TCK、TMS）+ 1根地线，共5根线，功能完整但占用引脚较多，适用于需要JTAG特性的场景
     - **JTAG (5 pins)**：传统JTAG调试接口（5线版），使用5根线（TDI、TDO、TCK、TMS、nTRST）+ 1根地线，共6根线，增加了复位控制线，功能最完整
     - **Trace Asynchronous Sw**：异步跟踪接口，在Serial Wire基础上增加跟踪功能，用于实时调试和性能分析，需要额外硬件支持
   - **推荐选择**：`Serial Wire`即swd接口，引脚占用少，功能够用，兼容性好
   - **注意事项**：
     - 如果选择No Debug，程序只能下载一次
     - 第二次无法下载
     - 需要通过串口方式重新刷写

2. **SysTick配置**：
   - 一般选择`SysTick`作为系统滴答时钟源
   - 在不涉及FreeRTOS的情况下，使用SysTick足够
   - 也可以选择TIM作为时钟源

3. 这里还有一个system wakeup勾，没说是什么东西，会占用pa1引脚，暂时不管他。

## 5. 时钟配置

### 5.1 时钟树配置界面
- 点击顶部`Clock Configuration`选项卡
- 界面看起来复杂，但结构并不复杂

### 5.2 时钟信号流向

**输入时钟源：**
1. **LSE（低速外部时钟）**：
   - 频率：32.768kHz
   - 频率固定为32.768kHz的原因：
     - 2^15 = 32768，方便二进制分频
     - 经过分频后可以得到1Hz、2Hz、4Hz等标准时间单位
     - 最常用的RTC时钟频率标准
   - **相关引脚**：
     - PC14 (OSC32_IN)：32.768kHz晶振输入引脚
     - PC15 (OSC32_OUT)：32.768kHz晶振输出引脚
     - 这两个引脚连接外部32.768kHz晶振
   - **主要用途**：
     - RTC（实时时钟）：提供精准的时间基准
     - 低功耗定时器：唤醒定时器使用LSE作为时钟源
     - 看门狗（IWDG）：独立看门狗可以使用LSE
   - **特点**：
     - 低功耗：32.768kHz频率低，功耗极小
     - 高精度：32.768kHz晶振精度高（±3ppm）
     - 持续运行：即使MCU进入低功耗模式，LSE仍可保持运行
     - 备用电源：可使用VBAT引脚连接纽扣电池供电
   - **使用场景**：
     - 时钟应用：需要精准时间显示的设备
     - 低功耗设备：需要周期性唤醒的传感器节点
     - 数据记录：需要时间戳的数据采集系统
   - **配置建议**：
     - 一般不使用：如果不是RTC应用，可以保持灰色
     - 需要RTC时：勾选LSE并连接32.768kHz晶振
     - 注意PC14、PC15被占用：这两个引脚不能用作GPIO

2. **HSE（高速外部时钟）**：
   - 频率：通常8MHz（范围4~16MHz）
   - STM32F103C8T6开发板一般使用8MHz晶振
   - **注意事项**：如果是其他开发板，需确认晶振频率

3. **HSI（高速内部时钟）**：
   - 频率：8MHz（内部RC振荡器）
   - **特点**：
     - 不需要外部晶振，节省PCB空间和成本
     - 启动速度快，无需等待晶振稳定
     - 频率固定为8MHz，无法通过软件调整
   - **缺点**：
     - 精度较低：误差通常在±1%左右
     - 受温度影响大：温度变化时频率会漂移
     - 不适合需要精确时钟的应用
   - **适用场景**：
     - 对时钟精度要求不高的应用
     - 快速启动场景
     - 成本敏感的产品
     - 无外部晶振的简化设计
   - **推荐使用HSE的原因**：
     - 外部石英晶体精度高（±50ppm）
     - 温度稳定性好
     - 适合大多数应用场景

### 5.3 时钟配置步骤

**第一步：选择PLL源时钟**
1. 找到`PLL Source Mux`（多路复用器）
2. 选择`HSE`（外部高速时钟）
3. **原因**：
   - HSI（内部RC振荡器）存在较大误差
   - 受温度影响较大
   - 有条件时尽量使用外部石英晶体振荡器

**第二步：配置PLL倍频**
1. PLL（锁相环）的作用：对时钟进行倍频
2. 配置`PLL Multiplier`：
   - 选择倍频系数（2~16）
   - STM32F103C8T6最高主频72MHz
   - 选择9倍频：8MHz × 9 = 72MHz

**第三步：选择系统时钟源**
1. 找到`System Clock Mux`
2. 选择`PLLCLK`（PLL时钟输出）
3. 系统时钟SYSCLK变为72MHz

**第四步：配置分频器**
1. **AHB分频器**：
   - HCLK（高速总线时钟）最大72MHz
   - 不需要分频，保持/1

2. **APB1分频器**：
   - PCLK1最大36MHz
   - 必须配置为/2（72MHz ÷ 2 = 36MHz）
   - 否则会出现红色错误

3. **APB2分频器**：
   - PCLK2最大72MHz
   - 不需要分频，保持/1

### 5.4 时钟配置要点
- 配置完成后不应有红色错误提示
- 可以根据需求配置其他频率
- 某些外设（如SPI、CAN）可能需要特定的时钟频率
- 一般情况直接配置为最高主频72MHz

## 6. 外设配置

### 6.1 GPIO配置示例（LED点灯）
**选择引脚：**
- 选择PC13（注意不要选择PC14、PC15）
- PC14、PC15用于外部低速晶振

**配置GPIO：**
- 点击芯片引脚
- 选择功能（如GPIO_Output）
- 配置GPIO参数：
  - **GPIO output level**：输出电平（High/Initial/Low）
    - High：初始输出高电平
    - Low：初始输出低电平
    注意在江协科技的板子上如果希望reset之后关灯应该默认为high。
  - **GPIO mode**：GPIO模式
    - Output Push Pull：推挽输出（最常用）
    - Output Open Drain：开漏输出
  - **GPIO Pull-up/Pull-down**：上拉/下拉
    - No pull-up and no pull-down：无上下拉（浮空）
    - Pull-up：上拉
    - Pull-down：下拉
  - **Maximum output speed**：最大输出速度
    - Low：低速（低功耗）
    - Medium：中速
    - High：高速（常用）
    - Very High：极高速
  - **User Label**：用户标签
    - 给引脚起个名字，方便识别
    - 生成的代码中会用到这个名字

### 6.2 其他外设配置
- **Connectivity**：串口、SPI、I2C等
- **Timers**：定时器配置
- **Analog**：ADC、DAC等
- **Middleware**：FreeRTOS、USB等

## 7. 生成代码

### 7.1 项目设置
- 设置项目名称
- 设置项目路径
- 选择IDE（如Keil MDK-ARM、IAR等）

### 7.2 代码生成选项

**基本配置：**
- 选择生成代码的语言（C/C++）
- 配置生成选项
- 点击`GENERATE CODE`生成代码

**Project Manager → Project选项卡：**

1. **Toolchain / IDE**：
   - 选择开发工具：
     - MDK-ARM V5：Keil MDK 5（常用）
     - STM32CubeIDE：ST官方IDE
     - EWARM：IAR Embedded Workbench
     - GCC：GCC编译器
     - Other：其他工具链

2. **Project Location**：
   - Project Location：项目保存位置
   - Application Structure：应用结构
     - Basic：基本结构
     - Advanced：高级结构
     - No：不生成示例代码

3. **Firmware Package**：
   - 选择HAL库版本
   - Copy necessary library files only：仅复制必要库文件（推荐）
   - Copy all used libraries firmware files：复制所有使用过的库文件

**Project Manager → Code Generator选项卡：**

1. **Generated Function Calls**：
   - 选择生成方式：
     - STM32 HAL（LL）：使用HAL库驱动
     - STM32 LL：使用LL库驱动（更底层，更高效）
     - STM32 LL + HAL：混合使用
   - 建议：新手使用HAL，追求性能可使用LL

2. **Backup previously generated files when re-generating**：
   - 勾选：重新生成时备份旧文件
   - 推荐勾选：避免意外丢失修改

3. **Delete previously generated files when not re-generated**：
   - 勾选：删除不再使用的文件
   - 推荐勾选：保持项目整洁

4. **Set all free pins as analog watchdog**：
   - 勾选：未使用的引脚设为模拟看门狗
   - 不勾选：未使用引脚保持默认状态
   - 建议不勾选：避免干扰调试

5. **Keep User Code when re-generating**：
   - 勾选：保留用户代码（必须勾选）
   - 在`/* USER CODE BEGIN */`和`/* USER CODE END */`之间的代码会被保留
   - 不勾选：重新生成会覆盖所有代码（危险）

6. **Generate peripheral initialization as a pair of '.c/.h' files per peripheral**：
   - 勾选：每个外设生成一对.c/.h文件
   - 不勾选：所有外设初始化放在一个文件
   - 推荐勾选：便于管理，结构清晰

**生成过程：**
1. 点击`GENERATE CODE`按钮
2. 等待代码生成完成
3. 生成完成后会提示是否打开工程
4. 可选择直接打开工程文件夹

### 7.3 生成后的文件结构

**主要目录结构：**
```
Project_Name/
├── Core/                           # 核心代码目录
│   ├── Inc/                         # 头文件目录
│   │   ├── main.h                   # 主程序头文件
│   │   ├── stm32f1xx_it.h           # 中断处理头文件
│   │   ├── stm32f1xx_hal_conf.h     # HAL库配置头文件
│   │   └── stm32f1xx_conf.h        # 芯片配置头文件
│   └── Src/                         # 源文件目录
│       ├── main.c                    # 主程序文件
│       ├── stm32f1xx_it.c           # 中断处理源文件
│       ├── stm32f1xx_hal_msp.c      # HAL库初始化源文件
│       ├── system_stm32f1xx.c        # 系统初始化源文件（时钟树配置后主要修改此文件）
│       └── stm32f1xx_hal_timebase_tim.c # 时钟基准源文件（如果使用TIM）
├── Drivers/                        # 驱动程序目录
│   ├── STM32F1xx_HAL_Driver/        # HAL驱动库
│   │   ├── Inc/                    # HAL库头文件
│   │   └── Src/                    # HAL库源文件
│   └── CMSIS/                      # CMSIS标准接口
│       ├── Device/ST/STM32F1xx/    # 设备特定文件
│       └── Include/                 # CMSIS头文件
├── MDK-ARM/                       # Keil工程目录（如果选择Keil）
│   ├── Project.uvprojx              # Keil工程文件
│   ├── Debug/                      # 调试输出目录
│   └── ...                         # 其他编译相关文件
├── .ioc/                          # CubeMX配置文件目录
│   └── Project_Name.ioc             # CubeMX工程配置文件
└── Makefile                        # Make构建文件
```

**重要文件说明：**

1. **main.c/main.h**：
   - main.h：包含主要头文件、函数声明、宏定义
   - main.c：主程序文件，包含main()函数和while(1)循环
   - 用户代码区域：
     - `/* USER CODE BEGIN */` 和 `/* USER CODE END */` 之间
     - 在这些区域添加的代码在重新生成时不会被覆盖

2. **stm32f1xx_it.c/stm32f1xx_it.h**：
   - 中断服务程序
   - 包含各种中断处理函数
   - 如SysTick、EXTI、UART等中断

3. **stm32f1xx_hal_msp.c**：
   - HAL库初始化代码
   - 由CubeMX自动生成
   - 包含HAL_MspInit()等初始化函数

4. **system_stm32f1xx.c**（时钟树配置后主要修改此文件）：
   - **作用**：系统时钟初始化文件
   - **内容**：
     - SystemInit()函数：系统启动时调用的初始化函数
     - 时钟配置：根据CubeMX时钟树配置设置各个时钟源、分频器
     - Flash配置：设置Flash等待周期等参数
   - **时钟树配置的影响**：
     - 修改HSE、HSI、PLL配置会更新此文件
     - 修改AHB、APB1、APB2分频会更新此文件
     - 修改系统时钟源会更新此文件
   - **调用时机**：
     - 在main()函数之前调用
     - 由启动文件startup_stm32f1xx_xx.s调用
     - 在进入main()之前完成时钟配置

5. **.ioc文件**：
   - CubeMX配置文件
   - 记录所有外设配置
   - 重新打开CubeMX可以恢复之前配置

5. **HAL库文件**：
   - STM32F1xx_HAL_Driver目录
   - 包含所有外设的HAL驱动函数
   - 如HAL_GPIO_WritePin()、HAL_UART_Transmit()等

**代码重新生成规则：**
- 保留用户代码：在USER CODE区域的代码不会被覆盖
- 覆盖自动代码：非USER CODE区域的代码会被重新生成
- 建议将自定义代码写在USER CODE区域
- 修改.ioc文件后重新生成代码

## 8. 重要注意事项

### 8.1 调试配置
- **必须**配置Debug为Serial Wire
- 否则只能下载一次程序
- 避免无法二次下载的问题

### 8.2 时钟配置
- 确认外部晶振频率
- APB1总线必须分频（最大36MHz）
- 配置完成后确保无红色错误

### 8.3 引脚选择
- 避免使用特殊功能引脚
- PC14、PC15用于外部低速晶振
- 某些引脚可能有默认功能

## 9. CubeMX与传统标准外设库的区别

### 9.1 为什么标准外设库模板使用"写死"的时钟配置

**历史背景：**
- 标准外设库（Standard Peripheral Library，SPL）发布于2011年左右
- STM32CubeMX推出于2014年
- 在CubeMX出现之前，开发者需要手动配置时钟

**设计理念差异：**

| 对比项 | 标准外设库（SPL） | STM32CubeMX |
|---------|---------------------|--------------|
| 定位 | 纯代码库 + 模板文件 | 图形化配置工具 |
| 时钟配置方式 | 预定义在模板中 | 根据GUI选择自动生成 |
| 灵活性 | 需要手动改代码修改 | 图形界面配置 |
| 时钟可视化 | 无 | 时钟树图表 |
| 上手难度 | 开箱即用，适合初学者 | 需要学习工具使用 |

**"写死"其实是"模板默认值"：**

1. **不是真正写死**：
   - system_stm32f10x.c是一个模板文件
   - 本意是让开发者根据需要修改宏定义
   - 通过注释/取消注释来选择不同配置

2. **为什么默认72MHz**：
   - STM32F103C8T6最高主频72MHz
   - 大多数应用都使用最高频率以获得最佳性能
   - 所以默认配置为72MHz是最常见的需求

3. **如何修改（传统方式）**：
   ```c
   // 在system_stm32f10x.c中（大约第106-116行）
   // 需要修改频率时，注释掉72MHz，启用其他选项
   
   // 默认72MHz
   #define SYSCLK_FREQ_72MHz  72000000
   
   // 如果需要其他频率，注释掉上面的，启用下面之一
   // #define SYSCLK_FREQ_56MHz  56000000
   // #define SYSCLK_FREQ_48MHz  48000000
   ```

4. **CubeMX的改进**：
   - 图形化配置界面，直观易懂
   - 时钟树可视化，信号流向清晰
   - 自动生成初始化代码，减少手动修改
   - 支持多种时钟组合，灵活度高

### 9.2 优缺点对比

**标准外设库（SPL）：**
- **优点**：
  - 开箱即用，模板直接可用
  - 适合初学者快速上手
  - 代码结构简单，容易理解
- **缺点**：
  - 修改时钟需要改代码
  - 配置不直观，容易出错
  - 灵活性较低

**STM32CubeMX：**
- **优点**：
  - 图形化配置，直观易懂
  - 时钟树可视化，信号流向清晰
  - 自动生成代码，减少错误
  - 配置灵活，支持多种组合
- **缺点**：
  - 需要学习工具使用
  - 配置步骤相对较多
  - 生成的代码结构较复杂

### 9.3 选择建议

- **初学者**：推荐使用STM32CubeMX
  - 配置直观，不容易出错
  - 时钟树可视化便于理解
  - 官方推荐，长期支持

- **老项目维护**：继续使用标准外设库
  - 避免重构现有代码
  - 团队熟悉，学习成本低

- **新项目开发**：推荐STM32CubeMX
  - 配置灵活，适应性强
  - HAL库持续更新
  - 与STM32CubeIDE集成

**总结：** 标准外设库提供写死的时钟配置是"旧时代"的做法——提供模板文件让开发者手动修改，而不是使用图形工具自动生成。STM32CubeMX后来通过图形化配置工具解决了这个问题，让时钟配置更加直观和灵活。
