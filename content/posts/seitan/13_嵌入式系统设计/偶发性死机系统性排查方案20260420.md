# 偶发性死机系统性排查方案

## 题目

在一个嵌入式系统中，如果出现"偶发性死机"，但长期无法复现，如何设计一套系统性的排查方案？

## 考察点

系统调试能力、问题定位方法论、工程经验

## 回答要点

### 1. 问题特征分析

**偶发性死机的典型特征**：
- 无规律、难以复现
- 可能与特定时序、负载、温度相关
- 现场信息往往丢失

**常见根因分类**：
- 内存越界 / 野指针 / 栈溢出
- 硬件时序违规（setup/hold time）
- 电源纹波 / 电压跌落
- 中断与多任务竞态
- 看门狗超时 / 死循环

### 2. 信息采集层设计

#### 硬件看门狗 + 复位信息保留
- 启用独立看门狗（IWDG），死机后自动复位
- 复位后读取 RCC 复位标志寄存器，判断是看门狗复位、软件复位还是上电复位
- 将复位原因保存到非易失性存储（RTC 备份寄存器 / FRAM / EEPROM）

#### Crash Dump 机制
- 在 `HardFault_Handler` / `BusFault_Handler` 等异常处理函数中保存现场：
  - 栈指针（MSP/PSP）
  - 异常返回地址（LR）
  - 故障寄存器（CFSR、HFSR、MMFAR、BFAR）
  - 通用寄存器压栈内容
- 将 dump 信息写入预留的 RAM 区域（掉电不丢失或复位后读取）
- 上电后检查是否有历史 dump，如有则上报或打印

#### 日志系统增强
- 引入环形缓冲区日志，记录关键事件时间戳
- 记录：任务切换、中断触发频率、内存分配/释放、锁获取/释放
- 日志级别可动态调整，死机前提高级别捕获更多细节

### 3. 软件防护与检测层

#### 栈溢出检测
- 任务栈底部填充特定模式（如 `0xDEADBEEF`）
- 定期或运行时检查栈底水印是否被覆盖
- 使用 MPU 保护栈区域，溢出时触发异常

#### 堆完整性检测
- 定期调用堆检查函数（如 `vPortGetFreeHeapSize` 监控趋势）
- 在 `malloc/free` 中加入简单完整性校验
- 开启 heap poisoning（分配后填充 `0xCC`，释放后填充 `0xDD`）

#### 断言与防御编程
- 关键路径加入 `configASSERT` / 自定义断言
- 函数入口做参数合法性校验
- 状态机中加入非法状态检测

### 4. 压力测试与加速复现

#### 负载压力测试
- 提高中断频率，缩短定时器周期
- 增加任务数量和上下文切换频率
- 模拟高并发场景（多任务同时操作共享资源）

#### 边界条件测试
- 栈空间压缩到接近极限
- 堆碎片化模拟（交替分配释放不同大小块）
- 长时间运行 + 温度循环测试

#### 随机 fuzzing
- 随机延迟插入
- 随机中断屏蔽窗口
- 通信接口注入错误帧

### 5. 硬件排查配合

#### 电源质量检测
- 示波器监测电源纹波和跌落
- 特别关注高负载瞬态（电机启动、射频发射）
- 检查去耦电容是否充足

#### 信号完整性
- 关键信号线做眼图测试
- 检查时钟信号 jitter
- 确认 setup/hold time 余量

#### EMC / ESD
- 静电放电测试
- 快速瞬变脉冲群测试
- 射频辐射抗扰度测试

### 6. 系统性排查流程

```
┌──────────────┐
│ 死机事件发生  │
└──────┬───────┘
       ▼
┌──────────────┐     ┌──────────────────┐
│ 读取复位标志  │────▶│ 判断复位类型      │
└──────┬───────┘     └────────┬─────────┘
       ▼                      ▼
┌──────────────┐     ┌──────────────────┐
│ 读取 Crash   │────▶│ 定位异常指令地址  │
│ Dump         │     │ 分析故障寄存器    │
└──────┬───────┘     └────────┬─────────┘
       ▼                      ▼
┌──────────────┐     ┌──────────────────┐
│ 分析环形日志  │────▶│ 还原死机前事件链  │
└──────┬───────┘     └────────┬─────────┘
       ▼                      ▼
┌──────────────┐     ┌──────────────────┐
│ 检查栈/堆    │────▶│ 排除内存越界     │
│ 水印         │     │ 排除栈溢出       │
└──────┬───────┘     └────────┬─────────┘
       ▼                      ▼
┌──────────────┐     ┌──────────────────┐
│ 压力测试加速  │────▶│ 缩小范围并复现   │
│ 复现         │     │ 修复并验证       │
└──────────────┘     └──────────────────┘
```

### 7. 长期监控机制

- 统计死机频率与运行时长的关系
- 关联死机时刻的系统状态（温度、负载、内存水位）
- 建立设备端黑匣子，定期上报健康数据
- OTA 支持远程开启详细日志模式
