# 掉帧卡顿排查与实时性问题定位

## 题目

出现掉帧或卡顿如何排查？如何定位实时性问题？

## 考察点

性能调试方法、问题定位能力

## 回答要点

### 1. 问题现象分析

#### 掉帧类型
**间隔掉帧**：
- 周期性丢帧
- 可能是定时任务干扰
- 可能是缓存失效

**连续丢帧**：
- 持续掉帧
- 可能是性能瓶颈
- 可能是资源不足

**随机掉帧**：
- 无规律
- 可能是中断处理
- 可能是锁竞争

#### 卡顿类型
**UI 卡顿**：
- 响应慢
- 可能是主线程阻塞
- 可能是渲染问题

**录制卡顿**：
- 帧率不稳
- 可能是编码超时
- 可能是存储瓶颈

### 2. 排查工具

#### ftrace（Function Tracer）
```bash
# 启用 ftrace
echo 1 > /sys/kernel/debug/tracing/tracing_on

# 设置跟踪器
echo function_graph > /sys/kernel/debug/tracing/current_tracer

# 过滤特定函数
echo encode_frame > /sys/kernel/debug/tracing/set_ftrace_filter

# 读取跟踪
cat /sys/kernel/debug/tracing/trace

# 停止跟踪
echo 0 > /sys/kernel/debug/tracing/tracing_on
```

**分析内容**：
- 函数调用时间
- 调度延迟
- 中断处理时间

#### perf（Performance Counter）
```bash
# 统计 CPU 事件
perf stat -e cycles,instructions,cache-misses ./video_encode

# 分析热点函数
perf record -g ./video_encode
perf report

# 分析调用图
perf report --stdio --stdio-call-graph

# 分析缓存
perf stat -e L1-dcache-loads,L1-dcache-load-misses ./video_encode
```

**分析内容**：
- CPU 使用率
- 缓存命中率
- 函数耗时统计
- 调用关系

#### top/htop
```bash
# 实时监控 CPU
top -p $(pidof encode_task)

# 查看线程状态
top -H -p $(pidof encode_task)
```

**关注指标**：
- CPU 使用率
- 内存使用
- 线程状态（R/S/D）
- 优先级

#### 自定义统计
```c
// 帧耗时统计
typedef struct {
    uint64_t frame_num;
    uint64_t timestamp;
    uint64_t encode_time_us;
    uint64_t total_time_us;
} frame_stat_t;

// 统计每一帧
void record_frame_stat(frame_stat_t* stat) {
    // 写入日志
    log_frame(stat);

    // 分析统计
    if (stat->encode_time_us > 33333) {  // 30fps = 33333us
        printf("Frame %lu: encode timeout %lu us\n",
                stat->frame_num, stat->encode_time_us);
    }
}

// 统计分析
void analyze_stats() {
    uint64_t total_frames = 0;
    uint64_t dropped_frames = 0;

    for (int i = 0; i < stat_count; i++) {
        total_frames++;

        if (stats[i].encode_time_us > 33333) {
            dropped_frames++;
        }
    }

    float drop_rate = (float)dropped_frames / total_frames * 100;
    printf("Drop rate: %.2f%%\n", drop_rate);
}
```

### 3. 定位步骤

#### 第一步：统计帧间隔
```c
// 帧间隔监控
void monitor_frame_interval() {
    static uint64_t last_time = 0;
    uint64_t current_time = get_time_us();
    uint64_t interval = current_time - last_time;

    if (interval > 40000) {  // >40ms 认为丢帧
        log_warning("Frame interval: %lu us (expected: 33333 us)", interval);
    }

    last_time = current_time;
}
```

#### 第二步：分析调度延迟
```bash
# 使用 ftrace 分析调度
echo 1 > /sys/kernel/debug/tracing/events/sched/sched_switch/enable
echo 1 > /sys/kernel/debug/tracing/events/sched/sched_wakeup/enable

# 读取调度信息
cat /sys/kernel/debug/tracing/trace_pipe
```

**关注内容**：
- 任务切换延迟
- 唤醒延迟
- 优先级反转

#### 第三步：找出耗时函数
```bash
# 使用 perf 找热点
perf record -F 99 -a -g -- sleep 10
perf report --stdio --stdio-call-graph | head -50
```

**关注内容**：
- 最耗时的函数
- 调用路径
- 热点位置

#### 第四步：检查优先级反转
```c
// 使用优先级继承的锁
pthread_mutexattr_t attr;
pthread_mutexattr_init(&attr);
pthread_mutexattr_setprotocol(&attr, PTHREAD_PRIO_INHERIT);
pthread_mutex_init(&mutex, &attr);
```

**检测方法**：
- 统计锁等待时间
- 监控任务状态
- 分析优先级配置

#### 第五步：分析内存带宽
```bash
# 使用 perf 分析内存访问
perf stat -e cache-references,cache-misses,instructions,cycles \
         ./video_encode

# 计算缓存命中率
# cache hit rate = 1 - (cache-misses / cache-references)
```

### 4. 常见问题与解决

#### CPU 瓶颈
**现象**：
- CPU 使用率 100%
- 编码超时

**解决**：
- 硬件编码器
- 降低分辨率/帧率
- 优化算法复杂度
- 多线程并行

#### 内存带宽瓶颈
**现象**：
- Cache miss 率高
- 内存访问慢

**解决**：
- Zero-copy
- DMA 传输
- 内存对齐
- 优化访问模式

#### 优先级反转
**现象**：
- 高优先级任务被阻塞
- 关键帧丢失

**解决**：
- 使用优先级继承锁
- 减少临界区
- 提高低优先级任务优先级

#### 锁竞争
**现象**：
- 多个任务等待锁
- 吞吐量下降

**解决**：
- 减少锁粒度
- 使用无锁数据结构
- 读写锁代替互斥锁
- 批量处理

#### 中断处理过长
**现象**：
- 任务延迟增加
- 帧率不稳

**解决**：
- 简化中断处理
- 使用 Tasklet/Workqueue
- 底半部处理
- 中断聚合

### 5. 性能优化建议

#### 优化关键路径
```c
// 识别关键路径
critical_path_t path = {
    .steps = {
        { .func = capture, .avg_time = 5000 },
        { .func = process, .avg_time = 15000 },
        { .func = encode, .avg_time = 20000 },
        { .func = store, .avg_time = 3000 }
    }
};

// 优化最慢的步骤
optimize_step(path.steps[2]);  // encode 最慢
```

#### 使用性能分析工具
- **perf**：CPU 性能
- **ftrace**：调度延迟
- **strace**：系统调用
- **top/htop**：资源监控
- **gprof**：函数耗时

#### 建立性能基线
- 记录正常情况下的指标
- 设置性能阈值
- 监控异常情况

### 6. 实时性保障

#### RTOS 配置
```c
// FreeRTOS 配置
#define configUSE_PREEMPTION              1
#define configUSE_TICKLESS_IDLE           1
#define configMAX_PRIORITIES             (7)
#define configTICK_RATE_HZ              (1000)
```

#### 优先级分配
```c
// 任务优先级
typedef enum {
    PRIORITY_IDLE      = 0,
    PRIORITY_LOW       = 1,
    PRIORITY_NORMAL    = 2,
    PRIORITY_HIGH      = 3,
    PRIORITY_CRITICAL  = 4
} task_priority_t;

// 关键任务高优先级
xTaskCreate(capture_task,  "Capture",  STACK_SIZE, NULL,
              PRIORITY_CRITICAL, NULL);
```

#### 堆栈监控
```c
// 监控堆栈使用

    for (int i = 0; i < task_count; i++) {
        UBaseType_t high_water_mark = uxTaskGetStackHighWaterMark(NULL);

    }

```
