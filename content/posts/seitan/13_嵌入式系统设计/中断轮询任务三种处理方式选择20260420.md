# 中断轮询任务三种处理方式的选择判断

## 题目

在多任务系统中，如何判断一个功能应该使用中断、轮询还是任务处理？

## 考察点

系统设计能力、实时性理解、工程权衡

## 回答要点

### 1. 三种方式的特点

```
中断（ISR）：
  外设事件 ──▶ 立即打断 CPU ──▶ 处理 ──▶ 返回
  特点：延迟最低，但有优先级嵌套和重入问题

轮询（主循环中查询）：
  while(1) { if (flag) handle(); }
  特点：最简单，但延迟不确定，浪费 CPU

任务（RTOS 任务）：
  独立上下文，可阻塞等待信号量/消息队列
  特点：延迟可控，可设置优先级，可阻塞
```

### 2. 选择决策矩阵

| 判断维度 | 中断 | 轮询 | 任务 |
|---------|------|------|------|
| 实时性要求 | 极高（μs 级） | 低（无要求） | 中等（ms 级） |
| 处理复杂度 | 极简单 | 简单 | 可复杂 |
| 事件频率 | 低~中 | 高且均匀 | 任意 |
| 能否阻塞 | 不能 | 不适用 | 可以 |
| 上下文 | 中断上下文 | 调用者上下文 | 独立上下文 |
| 优先级 | 硬件优先级 | 无 | 软件优先级 |

### 3. 中断适用的场景

#### 3.1 应该用中断的情况

**硬实时事件（必须立即响应）**：
```c
// 电机过流保护：必须在几 μs 内关断 PWM
void ADC_IRQHandler(void) {
    if (ADC->ISR & ADC_ISR_AWD) {
        TIM1->CCER = 0;           // 立即关闭 PWM 输出
        motor_fault = 1;
    }
}

// 编码器脉冲计数：不能丢脉冲
void TIM3_IRQHandler(void) {
    encoder_count += TIM3->CNT;
    TIM3->CNT = 0;
}
```

**异步外部事件（不知何时到来）**：
```c
// CAN 接收：消息随时可能到来
void CAN1_RX0_IRQHandler(void) {
    CAN_Receive(CAN1, CAN_FIFO0, &rx_msg);
    xQueueSendFromISR(can_rx_queue, &rx_msg, NULL);
}

// 按键检测：用户随机操作
void EXTI0_IRQHandler(void) {
    key_event = 1;
    xSemaphoreGiveFromISR(key_sem, NULL);
}
```

#### 3.2 中断的处理原则

```c
// ISR 中只做最少的工作
// "设标志 + 通知"，实际处理延后到任务中

void UART_IRQHandler(void) {
    uint8_t data = USART1->DR;
    BaseType_t woken = pdFALSE;

    // 只做：存数据 + 通知任务
    ring_buf_put(&uart_rx_buf, data);
    if (data == '\n') {
        xSemaphoreGiveFromISR(uart_rx_sem, &woken);
    }

    portYIELD_FROM_ISR(woken);   // 必要时触发调度
}
```

**中断中不能做的事**：
- 不能调用阻塞 API（`vTaskDelay`、`xSemaphoreTake`）
- 不能做长时间处理（打印、复杂计算）
- 不能调用非线程安全函数（`malloc`、`printf`）
- 不能等待其他中断

### 4. 轮询适用的场景

#### 4.1 应该用轮询的情况

**高频率持续状态检查**：
```c
// 传感器数据采集：每 1ms 读一次 ADC
// 用定时器中断 + DMA 更好，但如果没有 DMA 硬件：
while (1) {
    if (adc_conversion_complete()) {
        process_sample(ADC->DR);
    }
}

// 状态机步进：已知周期的状态推进
while (1) {
    state_machine_step();
    delay_us(100);
}
```

**无中断能力的硬件**：
```c
// 某些简单 GPIO 扩展芯片（如 PCF8574）没有中断引脚
// 只能轮询读取
uint8_t read_pcf8574(void) {
    uint8_t val;
    i2c_read(PCF8574_ADDR, &val, 1);
    return val;
}
```

**调试和验证场景**：
```c
// 调试时轮询比中断更容易控制和观察
while (1) {
    debug_check_registers();
    debug_print_status();
}
```

#### 4.2 轮询的代价

```c
// 浪费 CPU
while (1) {
    if (gpio_read(PIN)) {   // 99.9% 的时间条件不满足
        handle_event();      // 但每次循环都在检查
    }
    // CPU 无法做其他事
}

// 延迟不确定
// 事件发生在两次轮询之间 → 最坏延迟 = 轮询周期
```

### 5. 任务适用的场景

#### 5.1 应该用任务的情况

**需要复杂处理逻辑**：
```c
// 通信协议解析：状态机 + 超时 + 重传
void comm_task(void *arg) {
    while (1) {
        xQueueReceive(comm_rx_queue, &msg, portMAX_DELAY);
        switch (msg.type) {
        case MSG_DATA:
            parse_protocol(&msg);
            break;
        case MSG_TIMEOUT:
            handle_timeout();
            break;
        }
    }
}
```

**需要阻塞等待多个事件**：
```c
// 同时等待串口数据、定时器、按键
void ui_task(void *arg) {
    while (1) {
        event_t evt;
        xQueueReceive(event_queue, &evt, pdMS_TO_TICKS(100));

        switch (evt.type) {
        case EVT_KEY:     handle_key(evt.data);    break;
        case EVT_SERIAL:  handle_serial(evt.data); break;
        case EVT_TIMER:   refresh_display();       break;
        default:          idle_handler();          break;
        }
    }
}
```

**需要独立优先级和栈**：
```c
// 不同功能有不同实时性要求
// 控制任务：高优先级，实时控制
xTaskCreate(control_task, "ctrl", 512, NULL, 5, NULL);

// 日志任务：低优先级，后台记录
xTaskCreate(log_task, "log", 1024, NULL, 1, NULL);

// UI 任务：中优先级，人机交互
xTaskCreate(ui_task, "ui", 1024, NULL, 3, NULL);
```

### 6. 混合模式：中断 + 任务（最常用）

```
硬件事件
   │
   ▼
ISR（中断）：接收数据、设标志、发信号量
   │
   ▼ 信号量 / 消息队列
   │
RTOS 任务：解析协议、处理业务、错误恢复
```

```c
// 这是最常见的模式
// 中断负责"感知"，任务负责"处理"

// ISR
void SPI_IRQHandler(void) {
    uint8_t data = SPI1->DR;
    BaseType_t woken = pdFALSE;
    xQueueSendFromISR(spi_rx_queue, &data, &woken);
    portYIELD_FROM_ISR(woken);
}

// 任务
void spi_process_task(void *arg) {
    uint8_t data;
    while (1) {
        if (xQueueReceive(spi_rx_queue, &data, pdMS_TO_TICKS(100))) {
            process_spi_data(data);     // 复杂处理在这里
        } else {
            check_spi_timeout();        // 超时检测
        }
    }
}
```

### 7. 选择流程

```
需要处理某个事件
       │
       ▼
┌──────────────┐
│ 是否需要 μs   │──Yes──▶ 中断（只做最少工作）
│ 级响应？      │         + 任务处理复杂逻辑
└──────┬───────┘
       │ No
       ▼
┌──────────────┐
│ 事件频率是否  │──Yes──▶ 轮询或 DMA
│ 极高且均匀？  │         （如 ADC 采样）
└──────┬───────┘
       │ No
       ▼
┌──────────────┐
│ 处理是否复杂  │──Yes──▶ RTOS 任务
│ 或需要等待？  │         （阻塞、超时、多事件）
└──────┬───────┘
       │ No
       ▼
   简单轮询即可
```

### 8. 总结

| 方式 | 一句话原则 | 典型例子 |
|------|----------|---------|
| 中断 | 硬实时、不能迟到的响应 | 过流保护、脉冲计数、DMA 完成 |
| 轮询 | 简单场景、无实时要求、高频均匀 | 状态机步进、调试读取 |
| 任务 | 复杂逻辑、需要阻塞等待 | 协议解析、UI 交互、业务流程 |
| 中断+任务 | 绝大多数实际场景 | ISR 接收 + 任务处理 |
