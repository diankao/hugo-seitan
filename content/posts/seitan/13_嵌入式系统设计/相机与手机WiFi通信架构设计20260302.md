# 相机与手机WiFi通信架构设计

## 题目

相机与手机 APP 的 WiFi 通信架构如何设计？协议如何选择？

## 考察点

网络通信架构、协议选择

## 回答要点

### 1. 网络架构设计

#### 连接模式
```
AP 模式（Access Point）：
- 相机作为热点
- 手机连接相机热点
- 优点：简单、直接
- 缺点：手机不能上网

STA 模式（Station）：
- 相机连接路由器
- 手机连接同一路由器
- 优点：手机可上网
- 缺点：需要路由器

P2P 模式（WiFi Direct）：
- 相机和手机直连
- 无需路由器
- 优点：灵活、快速
- 缺点：兼容性问题
```

#### 推荐方案
- 主模式：AP 模式（简单可靠）
- 备选模式：WiFi Direct（高级用户）

### 2. 协议栈设计

#### 传输层协议选择

**TCP（Transmission Control Protocol）**：
```
用途：
- 命令通道
- 文件传输
- 配置同步

优势：
- 可靠传输
- 顺序保证
- 流量控制

劣势：
- 开销大
- 延迟高
```

**UDP（User Datagram Protocol）**：
```
用途：
- 实时预览流
- 实时控制指令

优势：
- 低延迟
- 开销小
- 无连接开销

劣势：
- 不可靠
- 无顺序保证
```

#### 应用层协议

**HTTP（超文本传输协议）**：
```
用途：
- 文件传输
- 大文件上传下载

优势：
- 标准、通用
- 支持断点续传
- 易于调试

实现：
- HTTP Range 支持
- 分块传输
- 进度上报
```

**WebSocket**：
```
用途：
- 实时控制指令
- 状态同步

优势：
- 双向通信
- 低延迟
- 长连接

实现：
- 心跳保活
- 消息队列
- 断线重连
```

**自定义二进制协议**：
```
用途：
- 设备控制
- 参数设置

优势：
- 高效
- 节省带宽
- 快速解析

格式：
[Header][Length][Type][Payload][Checksum]
```

#### 文件传输通道（HTTP）
```cpp
// HTTP 文件上传
void upload_file(const char* filename) {
    // 1. 初始化上传
    send_http_post("/api/upload/init", filename);

    // 2. 分块上传
    const int chunk_size = 1024 * 1024;  // 1MB
    for (int offset = 0; offset < file_size; offset += chunk_size) {
        int len = min(chunk_size, file_size - offset);
        send_http_post("/api/upload/chunk", chunk_data, len, offset);
    }

    // 3. 完成上传
    send_http_post("/api/upload/complete", filename);
}
```

#### 断线重连
```cpp
// 重连逻辑
void reconnect() {
    int retry = 0;
    const int max_retry = 5;

    while (retry < max_retry) {
        if (connect_to_camera()) {
            // 重新连接成功
            restore_state();
            return;
        }
        retry++;
        sleep(2 << retry);  // 指数退避
    }

    // 重连失败
    show_error("连接失败，请检查相机");
}
```
