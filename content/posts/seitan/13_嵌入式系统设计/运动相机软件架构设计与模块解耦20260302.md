# 运动相机软件架构设计与模块解耦

## 题目

如果让你从零设计一款运动相机的软件架构，如何分层？模块如何解耦？

## 考察点

架构设计能力、模块解耦原则

## 回答要点

### 1. 分层架构设计

建议采用五层架构：

#### 硬件抽象层（HAL）
- 统一硬件访问接口
- 屏蔽硬件差异
- 便于移植到不同平台

```
示例接口：
sensor_init()
sensor_start()
sensor_stop()
sensor_get_frame()
```

#### 驱动层
- Sensor 驱动
- ISP 驱动
- 编码器驱动
- WiFi/BT 驱动
- 存储驱动
- IMU 驱动

#### 中间件层
- 算法模块（防抖、拼接）
- 数据管理模块
- 通信协议栈
- 文件系统抽象

#### 服务层
- 录制服务
- 预览服务
- 控制服务
- 升级服务

#### 应用层
- 用户界面
- 业务逻辑
- 场景管理

### 2. 模块解耦原则

#### 接口抽象
- 使用头文件定义接口
- 依赖接口而非具体实现
- 便于单元测试

#### 消息队列
- 模块间异步通信
- 降低耦合度
- 支持多线程

```c
typedef struct {
    int msg_id;
    void *data;
    int size;
} message_t;

// 发送消息
mq_send(queue, &msg, sizeof(msg), 0);
```

#### 回调机制
- 事件驱动
- 松耦合
- 异步通知

```c
typedef void (*callback_t)(int event, void *data);

// 注册回调
register_callback(CAMERA_FRAME_READY, on_frame_ready);
```

#### 状态机
- 明确状态转换
- 便于维护和调试
- 支持复杂业务逻辑

### 3. 考虑的关键因素

#### 可移植性
- HAL 层屏蔽硬件差异
- 抽象平台相关代码
- 编译时条件编译

#### 可扩展性
- 模块化设计
- 插件式架构
- 支持动态加载

#### 可维护性
- 清晰的分层
- 良好的文档
- 统一的编码规范

#### 性能
- 减少跨层调用
- 优化关键路径
- 合理使用缓存
