# 低功耗优化系统层面入手

## 题目

如果需要做低功耗优化，从哪些系统层面入手？

## 考察点

电源管理、低功耗设计、系统级优化

## 回答要点

### 1. 功耗的来源

```
系统总功耗 = 动态功耗 + 静态功耗

动态功耗 ∝ C × V² × f
  C = 负载电容
  V = 工作电压
  f = 工作频率

静态功耗 = 漏电流 × V
  即使不切换也有漏电损耗
```

**低功耗的核心思路**：降低电压、降低频率、减少翻转、关闭不用模块。

### 2. 各层面优化手段

#### 2.1 硬件层面

| 优化手段 | 原理 | 节电效果 |
|---------|------|---------|
| 选用低功耗芯片 | 更小工艺、更低漏电 | 基础决定 |
| 多电源域设计 | 不用模块完全断电 | 显著 |
| 降压供电 | V² 关系，降压效果巨大 | 非常显著 |
| LDO 换 DCDC | 转换效率从 ~60% 到 ~90% | 显著 |
| 外设选型 | 选用支持低功耗模式的外设 | 中等 |

#### 2.2 处理器低功耗模式

```
运行模式功耗递减：

Run        → 全速运行，所有模块开启
Sleep      → CPU 停止，外设继续运行
Stop       → CPU 和大部分外设停止，RAM 保持
Standby    → 仅 RTC 和唤醒电路工作，RAM 丢失
Shutdown   → 几乎完全关闭，仅最低限度唤醒逻辑

功耗量级（以 STM32L4 为例）：
Run:       ~10 mA/MHz
Sleep:     ~1 mA
Stop:      ~10 μA
Standby:   ~0.1 μA
Shutdown:  ~0.01 μA
```

```c
// FreeRTOS 空闲任务中自动进入 Sleep
void vApplicationIdleHook(void) {
    __WFI();   // Wait For Interrupt
    // CPU 进入 Sleep，等待任一中断唤醒
}

// 更深度的低功耗需要主动进入
void enter_stop_mode(void) {
    // 保存外设状态
    save_peripheral_state();

    // 关闭不需要的外设
    disable_unused_peripherals();

    // 配置唤醒源（如 RTC 定时器）
    RTC_SetWakeupTimer(wakeup_interval_ms);

    // 进入 Stop 模式
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);

    // 唤醒后恢复
    SystemClock_Config();           // 重新配置时钟
    restore_peripheral_state();
}
```

#### 2.3 时钟与频率管理

```c
// 动态调频（DVFS：Dynamic Voltage and Frequency Scaling）
// 高负载时高频运行，低负载时降频

void adjust_performance(cpu_load_t load) {
    switch (load) {
    case LOAD_HIGH:
        SystemClock_Config_80MHz();
        break;
    case LOAD_MEDIUM:
        SystemClock_Config_24MHz();
        break;
    case LOAD_LOW:
        SystemClock_Config_4MHz();
        break;
    }
}

// 关闭不用的时钟
// 每个外设的时钟都可以独立开关
__HAL_RCC_USART2_CLK_DISABLE();
__HAL_RCC_ADC2_CLK_DISABLE();
__HAL_RCC_TIM3_CLK_DISABLE();
```

#### 2.4 外设管理

```c
// 原则：不用就关，用时再开

// GPIO 低功耗配置
void gpio_lowpower_init(void) {
    GPIO_InitTypeDef gpio = {0};

    // 未使用的 GPIO 配置为模拟输入（最低功耗）
    gpio.Pin = GPIO_PIN_All;
    gpio.Mode = GPIO_MODE_ANALOG;
    gpio.Pull = GPIO_NOPULL;
    HAL_GPIO_Init(GPIOB, &gpio);

    // 已使用的 GPIO 根据外设需求配置
    // 避免浮空输入（会导致 CMOS 输入级来回翻转，增加功耗）
}

// ADC 低功耗策略
void adc_lowpower_sample(void) {
    // 不用连续采样，改用单次触发
    // 采样完立即关闭 ADC
    HAL_ADC_Start(&hadc1);
    HAL_ADC_PollForConversion(&hadc1, 10);
    uint32_t val = HAL_ADC_GetValue(&hadc1);
    HAL_ADC_Stop(&hadc1);        // 立即关闭
}

// 通信接口低功耗
// UART：不传输时关闭时钟
// SPI：传输完关闭时钟
// I2C：使用 DMA 减少CPU 活跃时间
```

#### 2.5 软件策略优化

```c
// 策略1：任务合并，减少唤醒次数
// 错误：3个任务分别在不同时间唤醒
// Task A: 每 10ms
// Task B: 每 15ms
// Task C: 每 20ms
// CPU 每 5ms 就要醒来一次

// 正确：合并到一个任务中，按时间片调度
void combined_task(void *arg) {
    uint32_t tick = 0;
    while (1) {
        tick++;
        if (tick % 1 == 0) task_a_work();
        if (tick % 2 == 0) task_b_work();
        if (tick % 3 == 0) task_c_work();
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

// 策略2：批量处理代替频繁小操作
// 错误：每收到 1 个数据包就唤醒处理
// 正确：积累一批数据后一次性处理

// 策略3：中断代替轮询
// 轮询会让 CPU 一直运行
// 中断允许 CPU 在无事件时睡眠
```

### 3. Linux 系统的低功耗

```bash
# CPU 调频策略
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
# performance: 始终最高频
# powersave: 始终最低频
# ondemand: 按需调频（推荐）
echo ondemand > /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor

# 关闭不用的 CPU 核心
echo 0 > /sys/devices/system/cpu/cpu1/online

# 挂起（Suspend-to-RAM）
echo mem > /sys/power/state

# 查看各设备功耗状态
cat /sys/power/pm_debug_messages

# 外设 runtime PM
echo auto > /sys/devices/platform/soc/uart0/power/control
```

### 5. 低功耗设计要点

- **能关就关**：不用的外设时钟、GPIO、电源域
- **能降就降**：电压、频率、采样率
- **能合并就合并**：减少唤醒次数
- **测量驱动优化**：用电流表分段定位功耗大户，不要靠猜
- **权衡实时性**：低功耗模式越深，唤醒延迟越长
