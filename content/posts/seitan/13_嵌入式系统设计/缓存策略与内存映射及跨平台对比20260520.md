# 缓存策略与内存映射及跨平台对比

## 题目

Cache 有哪些映射策略和替换策略？内存映射（MMU/MPU）如何实现？在 STM32（Cortex-M）和其他现代 CPU（Cortex-A / x86）上有什么本质区别？

## 考察点

Cache 映射方式与写策略的理解、MMU/MPU 页表机制的掌握、不同处理器架构在缓存和内存管理上的差异。

## 回答要点

### 1. Cache 的核心问题：地址映射

CPU 发出一个内存地址后，cache 控制器需要快速判断"这个数据在不在 cache 里"。这个查找机制就是 **cache 映射策略**。

一个内存地址被分为三段：

```
|-------- Tag --------|---- Index ----|--- Offset ---|
|      标签           |    组号/行号    |   块内偏移    |
```

- **Offset**：块内偏移，决定读取 cache line 中的哪个字节
- **Index**：定位到 cache 中的哪一组/哪一行
- **Tag**：和 cache line 中存储的标签比对，确认是否命中

### 2. 三种映射策略

#### 2.1 直接映射（Direct Mapped）

每个内存地址只能映射到 cache 中的**固定一行**。

```
内存地址 mod cache行数 = cache行号

例：cache 共 4 行
地址 0x00 → 第 0 行
地址 0x10 → 第 0 行（冲突！）
地址 0x20 → 第 0 行（冲突！）
```

```
Cache Line:  [  0  ][  1  ][  2  ][  3  ]
               ↑
    地址 0x00, 0x10, 0x20 都映射到这里
```

- **优点**：硬件简单、查找速度快（只需一次比较）
- **缺点**：冲突率高，两个频繁访问的地址如果映射到同一行会反复驱逐（"抖动"）
- **应用**：早期嵌入式处理器、一些 L1 指令 cache

#### 2.2 全相联映射（Fully Associative）

内存地址可以放在 cache 中的**任意一行**。

```
Cache Line:  [  A  ][  B  ][  C  ][  D  ]
               ↑     ↑     ↑     ↑
    地址 0x00 可以放在任意一行
```

- **优点**：冲突最少，空间利用率最高
- **缺点**：查找时需要和**所有行**比较 Tag，硬件复杂、功耗高
- **应用**：TLB（页表缓存）、小型全相联 cache

#### 2.3 组相联映射（Set-Associative）

折中方案：cache 分成若干**组**，每组包含 N 路（Way）。地址映射到固定组，但在组内可以放在任意一路。

```
2路组相联，共 2 组：

组 0: [ Way 0 ][ Way 1 ]
组 1: [ Way 0 ][ Way 1 ]

地址 0x00 → 组 0，可以放在 Way 0 或 Way 1
地址 0x10 → 组 0，也可以放在 Way 0 或 Way 1（和 0x00 同组，但不冲突）
```

- **优点**：冲突率远低于直接映射，硬件复杂度远低于全相联
- **缺点**：N 越大硬件越复杂（面积、功耗、延迟）
- **应用**：绝大多数现代处理器的 L1/L2/L3 cache

| 参数 | 直接映射 | 2 路组相联 | 4 路组相联 | 全相联 |
|------|---------|-----------|-----------|--------|
| 冲突率 | 高 | 中 | 低 | 最低 |
| 硬件复杂度 | 低 | 中 | 较高 | 最高 |
| 查找延迟 | 1 次比较 | 2 次比较 | 4 次比较 | 全部比较 |
| 典型应用 | 小型 cache | L1 cache | L2 cache | TLB |

> **面试口诀**：直接映射像固定座位，全相联像随便坐，组相联像指定区域随便坐。

### 3. Cache 替换策略

当 cache 满了（或同一组满了），需要选一行驱逐。替换策略决定"赶谁走"。

#### 3.1 LRU（Least Recently Used，最近最少使用）

驱逐**最久没被访问**的那一行。基于"局部性原理"：最近用过的很快还会再用。

```
4路组相联，访问序列：A B C D A B E ?

A B C D → cache 满
A B     → A、B 被再次访问，变为"最近使用"
E       → 需要驱逐 C 或 D，C 和 D 中 C 先进（假设 D 后进），驱逐 C
```

- **优点**：命中率最高（理论最优策略之一）
- **缺点**：需要记录每行的访问顺序，N 路需要 N! 个状态，4 路以上硬件开销大

#### 3.2 PLRU（Pseudo-LRU，伪 LRU）

用**二叉树位**近似 LRU，每个节点只记录一个方向位。

```
4 路 PLRU 需要 3 个 bit：
       [b0]
      /    \
   [b1]    [b2]
   / \     / \
  0   1   2   3

b0=0 表示左边优先替换，b0=1 表示右边优先
每次访问翻转路径上的位
```

- **优点**：硬件开销小（N-1 个 bit 即可）
- **缺点**：不是严格 LRU，命中率略低
- **应用**：ARM Cortex-A 系列 L2 cache

#### 3.3 随机替换（Random）

随机选一行驱逐。

- **优点**：硬件最简单，不需要任何状态
- **缺点**：命中率不稳定
- **应用**：Cortex-M7 的 L1 cache（极低功耗场景）

#### 3.4 FIFO（First In First Out）

驱逐**最先进入** cache 的那一行。

- **优点**：实现简单
- **缺点**：可能驱逐频繁访问的数据（Belady 异常）
- **应用**：较少单独使用

### 4. Cache 写策略

读命中时直接返回 cache 数据。但**写**操作需要额外考虑一致性。

#### 4.1 写命中策略

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **Write-Through（写直通）** | 同时写 cache 和主存 | 一致性好，实现简单 | 每次写都访问主存，慢 |
| **Write-Back（写回）** | 只写 cache，驱逐时才写回主存 | 写速度快，减少总线流量 | 数据不一致窗口，硬件复杂 |

#### 4.2 写缺失策略

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **Write-Allocate（写分配）** | 先把数据从主存加载到 cache，再写 | 利用空间局部性 | 额外的读开销 |
| **No-Write-Allocate（非写分配）** | 直接写主存，不加载到 cache | 避免不必要的 cache 填充 | 连续写同一区域效率低 |

**常见组合**：

- **Write-Through + No-Write-Allocate**：简单场景、Cortex-M7 可选
- **Write-Back + Write-Allocate**：高性能场景、Cortex-A 系列默认

### 5. 内存映射：MMU 与 MPU

#### 5.1 为什么需要内存映射

裸机开发中，程序直接操作物理地址。但在复杂系统中需要：

- **虚拟地址**：每个进程看到独立的地址空间
- **内存保护**：防止进程越界访问
- **内存映射 I/O**：把外设寄存器映射到地址空间

#### 5.2 MMU（Memory Management Unit，内存管理单元）

MMU 通过**页表**将虚拟地址翻译为物理地址。

```
虚拟地址                              物理地址
0x4000_0000  ──── 页表翻译 ────▶   0x8000_0000
0x4000_1000  ──── 页表翻译 ────▶   0x0000_1000
0xFFFF_0000  ──── 页表翻译 ────▶   0x1000_0000（外设寄存器）
```

**多级页表结构**（以 ARM Cortex-A 为例）：

```
虚拟地址：| PGD Index | PMD Index | PTE Index | Offset |
              ↓            ↓           ↓
           一级页表     二级页表     三级页表  ──▶ 物理地址
```

每次内存访问需要查 3 次页表 → 太慢 → **TLB（Translation Lookaside Buffer）** 缓存最近翻译结果。

**页表项中的关键属性**：

| 属性 | 说明 |
|------|------|
| Valid | 页是否存在 |
| Physical Address | 映射的物理页帧号 |
| Access Permissions | 读/写/执行权限（AP bit） |
| Cacheable | 是否允许 cache（C bit） |
| Bufferable | 是否允许写缓冲（B bit） |
| Shareable | 多核间是否共享（S bit） |
| TEX | 内存类型扩展（Device / Normal / Strongly Ordered） |

#### 5.3 MPU（Memory Protection Unit，内存保护单元）

MPU 是 MMU 的**简化版**，没有虚拟地址翻译，只有**访问权限控制**。

```
MPU 区域配置：
Region 0: 0x0000_0000 - 0x0003_FFFF  Flash    (只读+执行)
Region 1: 0x2000_0000 - 0x2000_FFFF  SRAM     (读写)
Region 2: 0x4000_0000 - 0x4000_0FFF  外设      (读写, Device类型)
Region 3: 0xE000_0000 - 0xE000_0FFF  系统控制  (特权读写)
```

- Cortex-M 系列通常有 **8~16 个 MPU 区域**
- 每个区域可配置：起始地址、大小、访问权限、内存属性（Cacheable / Bufferable / Shareable）

### 6. STM32（Cortex-M）vs 现代 CPU 的本质区别

#### 6.1 架构层面对比

| 特性 | Cortex-M0/M3/M4 | Cortex-M7 | Cortex-A53/A72 | x86-64 |
|------|-----------------|-----------|----------------|--------|
| **Cache** | ❌ 无 | ✅ L1（可选 L2） | ✅ L1 + L2 + L3 | ✅ L1 + L2 + L3 |
| **MMU** | ❌ 无 | ❌ 无 | ✅ 有 | ✅ 有 |
| **MPU** | ✅ 8~16 区域 | ✅ 8~16 区域 | ✅（作为补充） | ❌（靠 MMU 页权限） |
| **虚拟地址** | ❌ 仅物理地址 | ❌ 仅物理地址 | ✅ 多级页表 | ✅ 4/5 级页表 |
| **TLB** | ❌ 无 | ❌ 无 | ✅ L1 + L2 TLB | ✅ L1 + L2 TLB |
| **操作系统** | 裸机 / RTOS | 裸机 / RTOS | Linux / Android | Windows / Linux |
| **内存大小** | KB ~ MB 级 | MB 级 | GB 级 | GB ~ TB 级 |

#### 6.2 Cortex-M0/M3/M4：无 Cache 的世界

这些芯片（如 STM32F103、STM32F407）**没有 cache**，也没有 MMU。

```
CPU ──────────────────▶ 总线矩阵 ──────▶ Flash / SRAM / 外设
                        （直接物理地址访问）
```

- 每次访存都直接访问物理存储器
- Flash 访问慢（需要等待周期），通过**预取指缓冲**和**加速器**缓解
- SRAM 访问快（0 等待），但容量有限
- **没有 cache 一致性问题**，没有虚拟地址转换

```c
// Cortex-M4 上直接操作寄存器
#define GPIOA_ODR  (*(volatile uint32_t *)0x40020014)
GPIOA_ODR |= (1 << 5);
```

#### 6.3 Cortex-M7：Cache 可选的世界

STM32H7、STM32F7 等 Cortex-M7 芯片引入了 L1 cache（指令 16KB + 数据 16KB，可配置）。

```
CPU ──▶ L1 I-Cache ──▶
     ──▶ L1 D-Cache ──▶ ART Accelerator ──▶ Flash / SRAM / 外设
```

**关键差异**：Cortex-M7 有 cache 但**没有 MMU**，不能跑 Linux。

- 有 cache → 必须处理 **DMA 一致性问题**
- 没有 MMU → 没有虚拟地址，不能跑需要虚拟内存的 OS
- 只有 MPU → 只能做内存保护，不能做地址翻译
- cache 维护通过 **CP15 协处理器** 或 **SCB（System Control Block）** 寄存器操作

```c
// Cortex-M7 上 DMA 操作前需要维护 cache
void dma_send_prepare(void *buf, uint32_t len)
{
    // 写回 cache 中的脏数据，确保 DMA 读到最新数据
    SCB_CleanDCache_by_Addr((uint32_t *)buf, len);

    // 启动 DMA 传输
    DMA_Start(buf, peripheral_addr, len);
}

void dma_recv_complete(void *buf, uint32_t len)
{
    // DMA 写入了新数据到内存，但 cache 中是旧数据
    // 必须无效化 cache，强制下次从内存重新加载
    SCB_InvalidateDCache_by_Addr((uint32_t *)buf, len);
}
```

**Cortex-M7 的 cache 配置**（通过 MPU）：

```c
// 配置 MPU 区域：SRAM 为 Normal 内存，允许 Cache
MPU->RNR  = 1;                         // 选择 Region 1
MPU->RBAR = 0x20000000;                // 起始地址
MPU->RASR = (0x06 << MPU_RASR_SIZE_Pos)   // 128KB
          | (0x03 << MPU_RASR_AP_Pos)      // 全访问权限
          | (1 << MPU_RASR_TEX_Pos)         // Normal memory
          | MPU_RASR_C_Msk                  // Cacheable
          | MPU_RASR_B_Msk;                 // Bufferable

// 配置 MPU 区域：外设寄存器为 Device 内存，禁止 Cache
MPU->RNR  = 2;
MPU->RBAR = 0x40000000;
MPU->RASR = (0x09 << MPU_RASR_SIZE_Pos)   // 512MB
          | (0x03 << MPU_RASR_AP_Pos)
          | MPU_RASR_B_Msk;                 // Bufferable, 不 Cacheable
```

#### 6.4 Cortex-A 系列：完整的内存管理

Cortex-A53/A72 等（如 i.MX6ULL、RK3399）拥有完整 MMU + 多级 cache。

```
CPU Core 0                CPU Core 1
┌──────────┐              ┌──────────┐
│ L1 I$    │              │ L1 I$    │
│ L1 D$    │              │ L1 D$    │
└────┬─────┘              └────┬─────┘
     │                         │
     ▼                         ▼
┌──────────────────────────────────┐
│     L2 Cache（共享）            │
└──────────────┬───────────────────┘
               │
               ▼
┌──────────────────────────────────┐
│     MMU（虚拟地址翻译）          │
│     TLB → 页表 → 物理地址       │
└──────────────┬───────────────────┘
               │
               ▼
┌──────────────────────────────────┐
│     DDR / 外设                   │
└──────────────────────────────────┘
```

**关键区别**：

1. **虚拟地址**：每个进程有独立页表，MMU 自动翻译
2. **多级 TLB**：L1 TLB（微秒级命中）+ L2 TLB（几百项）
3. **页表属性**：通过页表项的 C/B/TEX 位控制 cache 行为
4. **SCU（Snoop Control Unit）**：硬件维护多核 cache 一致性

```c
// Linux 内核中的内存映射（页表项属性设置）
// ARM64 的页表项格式
pgprot_t prot = __pgprot(
    PTE_VALID         |    // 页有效
    PTE_USER          |    // 用户态可访问
    PTE_RDONLY        |    // 只读
    PTE_NORMAL_CACHE  |    // Normal 内存，允许 cache
    PTE_SHARED             // 多核共享
);

// 设备内存映射（禁止 cache）
pgprot_t device_prot = __pgprot(
    PTE_VALID         |
    PTE_DEVICE_nGnRnE      // Device 类型，不 cache，不重排
);
```

#### 6.5 x86 架构

x86 在缓存和内存管理上更为复杂和成熟：

- **页表级缓存控制**：通过 PAT（Page Attribute Table）和 MTRR（Memory Type Range Register）控制内存类型
- **MESIF 协议**：多核一致性协议（Intel 的 MESI 扩展版）
- **包容性 L3 cache**：L3 包含 L1+L2 的所有内容，便于一致性维护
- **5 级页表**：支持 57 位虚拟地址（128 PB 虚拟地址空间）
- **缓存行 64 字节**：ARM 通常 32 或 64 字节

### 7. 不同平台的 Cache 维护方法对比

| 操作 | Cortex-M7（STM32H7） | Cortex-A（Linux） | x86 |
|------|----------------------|-------------------|-----|
| 清除 D-Cache | `SCB_CleanDCache()` | `__dma_map_area()` | `clwb` 指令 |
| 无效化 D-Cache | `SCB_InvalidateDCache()` | `__dma_unmap_area()` | `clflush` / `clflushopt` |
| 按地址维护 | `SCB_CleanDCache_by_Addr()` | `dma_sync_single_for_device()` | `clwb` + `sfence` |
| 全局维护 | `SCB_CleanInvalidateDCache()` | `flush_cache_all()` | `wbinvd` 指令 |
| 用户态可见 | ✅ 裸机直接操作 | ❌ 需内核系统调用 | ⚠️ `clflush` 可用户态调用 |

### 8. 实际开发中的策略选择

#### 8.1 STM32（无 Cache 的 Cortex-M0/M3/M4）

```
不需要关心 cache，直接操作物理地址：
- volatile 保证编译器不优化寄存器访问
- MPU 配置外设区域为 Device 类型
- DMA 直接操作内存，无一致性问题
```

#### 8.2 STM32H7（有 Cache 的 Cortex-M7）

```
必须主动维护 cache 一致性：
- DMA 发送前：Clean D-Cache（写回脏数据）
- DMA 接收后：Invalidate D-Cache（无效化旧副本）
- 外设寄存器区域：通过 MPU 配置为 Non-Cacheable
- 共享内存区域：配置为 Shareable + Non-Cacheable
- 或者：将 DMA 缓冲区放在 D2 域的 SRAM（默认不经过 D-Cache）
```

#### 8.3 Cortex-A / x86（跑 Linux 的系统）

```
大部分由操作系统和硬件处理：
- 用户空间：通过 mmap() 映射设备内存，内核设置正确的页表属性
- DMA：通过 dma_alloc_coherent() 申请一致性 DMA 缓冲区
- 多核一致性：硬件 MESI/MESIF 协议自动维护
- 驱动开发者：使用内核 DMA API，不要手动刷 cache
```

### 9. 总结

```
                    无 Cache            有 Cache + 无 MMU          有 Cache + 有 MMU
                 ┌─────────────┐     ┌───────────────────┐     ┌──────────────────┐
  代表芯片       │ STM32F103   │     │ STM32H743         │     │ i.MX6ULL / x86   │
  代表核心       │ Cortex-M3   │     │ Cortex-M7         │     │ Cortex-A / x86   │
                 ├─────────────┤     ├───────────────────┤     ├──────────────────┤
  地址空间       │ 纯物理地址   │     │ 纯物理地址         │     │ 虚拟地址          │
  Cache          │ 无          │     │ L1（可选 L2）      │     │ L1 + L2 + L3     │
  内存保护       │ MPU         │     │ MPU               │     │ MMU（页权限）     │
  DMA一致性      │ 不需要处理   │     │ 软件手动维护       │     │ 内核 DMA API     │
  多核一致性     │ 单核为主     │     │ 单核为主           │     │ 硬件协议（MESI）  │
  开发者负担     │ 低          │     │ 中（需理解cache）  │     │ 低（OS 处理）    │
                 └─────────────┘     └───────────────────┘     └──────────────────┘
```

> **面试总结**：cache 映射策略决定了"数据放在哪"（直接/组相联/全相联），替换策略决定了"满了赶谁"（LRU/PLRU/随机），写策略决定了"怎么同步回主存"（写回/写直通）。STM32 的 Cortex-M0/M3/M4 没有这些问题，Cortex-M7 引入了 cache 但没有 MMU 需要手动维护，Cortex-A 和 x86 有完整的 MMU + 多级 cache 由操作系统管理。
