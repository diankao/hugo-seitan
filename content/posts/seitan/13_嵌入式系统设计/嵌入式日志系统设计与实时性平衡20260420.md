# 嵌入式日志系统设计与实时性平衡

## 题目

在一个复杂嵌入式系统中，如何设计日志系统，使其既能用于问题定位，又不会影响实时性？

## 考察点

系统设计能力、实时性理解、工程权衡

## 回答要点

### 1. 核心矛盾

| 需求 | 与之冲突的需求 |
|------|---------------|
| 日志详细 → 好定位问题 | 数据量大 → IO 慢、影响实时性 |
| 日志实时输出 → 即时可见 | 串口/网络输出耗时 → 阻塞调用者 |
| 日志持久化 → 掉电不丢 | 写 Flash 慢 → 延迟不可控 |
| 多任务同时写日志 → 信息完整 | 并发访问 → 需要锁 → 影响实时性 |

**设计目标**：写入端尽可能快（微秒级），耗时操作全部延迟到后台。

### 2. 架构设计：生产者-消费者模型

```
┌──────────┐  ┌──────────┐  ┌──────────┐
│  Task A  │  │  Task B  │  │  ISR     │
└────┬─────┘  └────┬─────┘  └────┬─────┘
     │              │              │
     ▼              ▼              ▼
┌──────────────────────────────────────┐
│         环形缓冲区（无锁/锁粒度极小）  │
│         ring buffer                  │
└──────────────────┬───────────────────┘
                   │
                   ▼
┌──────────────────────────────────────┐
│         日志消费任务（低优先级）        │
│         - 格式化                      │
│         - 串口输出                    │
│         - 写 Flash                   │
│         - 网络上报                    │
└──────────────────────────────────────┘
```

### 3. 写入端设计（快速路径）

#### 3.1 日志条目结构

```c
typedef struct {
    uint32_t timestamp;
    uint8_t  level;
    uint8_t  module;
    uint16_t line;
    const char *fmt;
    uint32_t args[4];
} log_entry_t;

// 固定大小，避免变长数据拷贝
// 用 fmt 指针 + args 延迟格式化
```

#### 3.2 环形缓冲区写入

```c
#define LOG_BUF_SIZE  512
#define LOG_BUF_MASK  (LOG_BUF_SIZE - 1)

static log_entry_t log_buf[LOG_BUF_SIZE];
static volatile uint32_t log_head = 0;
static volatile uint32_t log_tail = 0;

// 单生产者场景（或关中断保护）
int log_write_fast(uint8_t level, uint8_t module,
                   const char *fmt, uint16_t line,
                   uint32_t a0, uint32_t a1) {
    uint32_t next = (log_head + 1) & LOG_BUF_MASK;
    if (next == log_tail) {
        return -1;   // 缓冲区满，丢弃
    }
    log_entry_t *e = &log_buf[log_head];
    e->timestamp = get_cycle_count();
    e->level = level;
    e->module = module;
    e->line = line;
    e->fmt = fmt;
    e->args[0] = a0;
    e->args[1] = a1;
    __dmb(0xF);
    log_head = next;
    return 0;
}
```

#### 3.3 多任务并发写入

```c
// 方案1：关中断（最快，适用于 ISR + Task 混合场景）
int log_write_from_isr(uint8_t level, uint8_t module,
                       const char *fmt, uint16_t line) {
    uint32_t primask = __get_PRIMASK();
    __disable_irq();
    int ret = log_write_fast(level, module, fmt, line, 0, 0);
    if (!(primask & 1)) __enable_irq();
    return ret;
}

// 方案2：自旋锁（多核场景）
// 方案3：每任务独立缓冲区 + 合并（无锁但浪费内存）
```

### 4. 消费端设计（慢速路径）

#### 4.1 日志消费任务

```c
void log_task(void *arg) {
    while (1) {
        if (log_tail != log_head) {
            log_entry_t *e = &log_buf[log_tail];
            char text[128];
            format_log(text, sizeof(text), e);
            output_log(text);
            log_tail = (log_tail + 1) & LOG_BUF_MASK;
        } else {
            ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
        }
    }
}
```

#### 4.2 输出策略

| 输出方式 | 延迟 | 持久化 | 适用场景 |
|---------|------|--------|---------|
| 串口 | 低 | 无 | 开发调试 |
| RTT（SEGGER） | 极低 | 无 | 实时调试 |
| Flash | 高 | 有 | 现场问题定位 |
| 网络 | 中 | 有 | 远程监控 |
| 内存 dump | 无 | 掉电丢 | 事后分析 |

### 5. 实时性保障措施

#### 5.1 分级过滤

```c
typedef enum {
    LOG_NONE = 0,
    LOG_ERROR = 1,
    LOG_WARN = 2,
    LOG_INFO = 3,
    LOG_DEBUG = 4,
    LOG_TRACE = 5,
} log_level_t;

// 编译时过滤：零开销
#if LOG_COMPILE_LEVEL >= LOG_DEBUG
#define LOG_D(fmt, ...) log_write_fast(LOG_DEBUG, MOD, fmt, __LINE__, ##__VA_ARGS__)
#else
#define LOG_D(fmt, ...) ((void)0)
#endif

// 运行时过滤：一次比较
#define LOG_I(fmt, ...) do { \
    if (g_log_level >= LOG_INFO) { \
        log_write_fast(LOG_INFO, MOD, fmt, __LINE__, ##__VA_ARGS__); \
    } \
} while(0)
```

#### 5.2 丢弃策略

```c
// 当缓冲区满时，选择丢弃策略
// 策略1：丢弃新日志（不阻塞写入者）
if (next == log_tail) {
    drop_count++;
    return -1;
}

// 策略2：覆盖旧日志（环形覆盖，适合持续监控）
// head 始终前进，tail 追赶 head
// 适合"只要最近的日志"的场景

// 策略3：提升消费者优先级（紧急刷出）
if (usage > LOG_WATERMARK_HIGH) {
    vTaskPrioritySet(log_task_handle, LOG_FLUSH_PRIO);
}
```

#### 5.3 时间戳方案

```c
// 方案1：tick 计数（精度 = 1/configTICK_RATE_HZ）
uint32_t ts = xTaskGetTickCount();

// 方案2：硬件定时器（微秒精度）
uint32_t ts = TIM2->CNT;    // 32-bit 自由运行定时器

// 方案3：DWT Cycle Counter（纳秒精度，Cortex-M3/M4/M7）
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CYCCNT = 0;
DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
uint32_t ts = DWT->CYCCNT;  // CPU 周期计数
```

### 6. 持久化方案

#### 6.1 Flash 日志（环形存储）

```
Flash 布局：
┌────────┬────────┬────────┬────────┐
│ Sector │ Sector │ Sector │ Sector │
│   0    │   1    │   2    │   3    │
└────────┴────────┴────────┴────────┘
         ↑ write_ptr
   ← read_ptr

写入到扇区末尾时，擦除最旧的扇区继续写
形成逻辑上的环形存储
```

```c
// 每个 Flash 日志条目带 magic 和 CRC
typedef struct {
    uint16_t magic;       // 0xA55A
    uint8_t  level;
    uint8_t  module;
    uint32_t timestamp;
    uint16_t length;
    uint8_t  data[0];     // 变长数据
    // CRC16 在最后
} flash_log_entry_t;
```

#### 6.2 掉电保护

- 每条日志写入后立即 flush（可靠性优先）或批量写入（性能优先）
- 使用 wear leveling 避免频繁擦除同一扇区
- 日志头部的 magic 字段用于上电后扫描有效日志

### 7. 设计总结

```
写入端（快速路径）         消费端（慢速路径）
────────────────         ────────────────
固定大小条目               独立低优先级任务
环形缓冲区                 格式化（不在写入路径）
关中断/细粒度锁            串口/Flash/网络输出
编译时级别过滤             批量写入优化
丢弃而非阻塞               动态优先级提升

写入延迟目标：< 1μs（不含 IO）
消费延迟：不影响实时任务
```
