# 高可靠通信模块设计UART与CAN抗干扰

## 题目

如果让我设计一个高可靠的通信模块（比如UART或CAN），如何保证在干扰环境下数据不丢失、不乱序？

## 考察点

通信协议设计、可靠性工程、抗干扰设计

## 回答要点

### 1. 威胁模型：干扰环境下会出什么问题

| 干扰类型 | 对通信的影响 | 典型场景 |
|---------|------------|---------|
| EMI/RFI | 比特翻转、帧错误 | 电机启停、射频发射 |
| 地线噪声 | 共模电压偏移、信号失真 | 大电流回路、长距离传输 |
| 瞬态脉冲 | 突发错误、帧丢失 | ESD、浪涌、继电器切换 |
| 信号衰减 | 误码率上升 | 长线缆、高波特率 |

### 2. 物理层可靠性设计

#### UART 硬件层面

**接口选择**：
- 短距离（< 1m）：TTL/CMOS，加磁珠和滤波电容
- 中距离（1~10m）：RS-485，差分信号抗共模干扰
- 长距离（> 10m）：RS-485 + 中继，或换 CAN

**PCB 布局**：
- 信号线远离高速信号和电源开关路径
- 差分对等长、阻抗匹配
- 接口处加 TVS 管防护 ESD

#### CAN 硬件层面

**总线终端**：
- 两端各加 120Ω 终端电阻，匹配阻抗防止反射
- 长距离/高速场景考虑 split termination（中心点接电容到地）

**收发器选型**：
- 选择带 EMC 优化的 CAN 收发器（如 TJA1043、SN65HVD230）
- 支持本地唤醒和故障保护的型号

### 3. 数据链路层：帧格式设计

#### UART 帧结构（自定义协议）

```
┌──────┬──────┬──────┬──────────┬──────┬──────┐
│ 帧头  │ 帧序号│ 命令  │   数据    │ CRC  │ 帧尾  │
│ 2B   │ 1B   │ 1B   │  0~255B  │ 2B   │ 1B   │
└──────┴──────┴──────┴──────────┴──────┴──────┘
```

**帧头**：固定模式 `0x5A 0xA5`，用于字节对齐和帧同步
**帧序号**：每帧递增，用于检测丢帧和乱序
**CRC**：CRC-16/MODBUS，检测数据传输错误
**帧尾**：固定模式 `0xAA`，辅助帧完整性校验

#### CAN 帧（标准/扩展格式）

- CAN 控制器内置 CRC 校验、位填充、ACK 机制
- 硬件自动处理比特错误、格式错误、CRC 错误
- 应用层只需关注数据域的完整性

### 4. 不丢失：重传与确认机制

#### 停等协议（简单可靠）

```c
typedef enum {
    FRAME_IDLE,
    FRAME_WAIT_ACK,
    FRAME_TIMEOUT,
    FRAME_ACKED
} frame_state_t;

int send_reliable(uint8_t *data, uint16_t len) {
    uint8_t seq = next_seq++;
    uint8_t retry = 0;

    while (retry < MAX_RETRY) {
        send_frame(seq, data, len);
        frame_state = FRAME_WAIT_ACK;

        if (wait_ack(seq, ACK_TIMEOUT_MS)) {
            return 0;
        }
        retry++;
    }
    return -1;
}
```

#### 滑动窗口（高吞吐）

- 发送方维护发送窗口，连续发多帧不等 ACK
- 接收方回累积确认（ACK 携带期望的下一帧序号）
- 窗口大小根据带宽和延迟动态调整

### 5. 不乱序：序号与排序机制

```c
#define RX_BUF_SIZE 8

typedef struct {
    uint8_t  buffer[RX_BUF_SIZE][MAX_FRAME_LEN];
    uint16_t length[RX_BUF_SIZE];
    uint8_t  received[RX_BUF_SIZE];
    uint8_t  expect_seq;
} rx_manager_t;

void on_frame_received(rx_manager_t *rx, uint8_t seq, uint8_t *data, uint16_t len) {
    if (seq == rx->expect_seq) {
        deliver_to_upper(data, len);
        rx->expect_seq++;

        while (rx->received[rx->expect_seq % RX_BUF_SIZE]) {
            uint8_t idx = rx->expect_seq % RX_BUF_SIZE;
            deliver_to_upper(rx->buffer[idx], rx->length[idx]);
            rx->received[idx] = 0;
            rx->expect_seq++;
        }
    } else if (seq > rx->expect_seq) {
        uint8_t idx = seq % RX_BUF_SIZE;
        memcpy(rx->buffer[idx], data, len);
        rx->length[idx] = len;
        rx->received[idx] = 1;
        send_nack(rx->expect_seq);
    }
}
```

### 6. CAN 应用层可靠性增强

#### CAN 本身的可靠性能力

- **CRC 校验**：15 位 CRC，硬件自动检测
- **位仲裁**：非破坏性仲裁，优先级高的帧先发
- **错误帧**：检测到错误主动发错误帧，通知所有节点
- **错误计数器**：区分主动错误/被动错误/总线关闭三种状态

#### 应用层补充设计

**多帧传输（ISO 15765-2 / ISO-TP）**：
- 单帧（SF）：数据 ≤ 7 字节
- 首帧（FF）+ 连续帧（CF）+ 流控帧（FC）：大数据分段传输
- 每段带序号，FC 控制发送节奏防止溢出

**心跳机制**：
```c
// 周期性发送心跳帧
void heartbeat_task(void *arg) {
    while (1) {
        can_send(HEARTBEAT_ID, &node_status, sizeof(node_status));
        vTaskDelay(pdMS_TO_TICKS(HEARTBEAT_INTERVAL_MS));
    }
}

// 监控对端心跳
void check_peer_timeout(void) {
    if (last_heartbeat_ms + HEARTBEAT_TIMEOUT_MS < get_tick_ms()) {
        handle_peer_lost();
    }
}
```

### 7. 异常处理与恢复

#### UART 异常恢复

| 异常 | 检测方法 | 恢复策略 |
|------|---------|---------|
| 帧错误（FE） | UART 硬件标志 | 丢弃当前帧，重新同步 |
| 噪声错误（NE） | UART 硬件标志 | 重试接收 |
| 溢出错误（ORE） | UART 硬件标志 | 读 DR 清标志，通知上层重传 |
| 超时 | 定时器 | 丢弃不完整帧，复位接收状态机 |
| CRC 错误 | 软件校验 | 发 NAK 请求重传 |

#### CAN 异常恢复

| 异常 | 检测方法 | 恢复策略 |
|------|---------|---------|
| 总线关闭 | TEC > 255 | 自动/软件恢复，重新初始化 |
| 错误被动 | TEC/REC > 127 | 降低发送频率，记录日志 |
| ACK 错误 | 无应答 | 检查总线连接和终端电阻 |
| 位填充错误 | 硬件检测 | 硬件自动重发 |

### 8. 设计总结

```
物理层可靠性          数据链路层可靠性        应用层可靠性
─────────────       ───────────────       ──────────────
差分信号              帧头/帧尾同步          序号机制
TVS/ESD防护          CRC校验               重传/确认
阻抗匹配             字节填充/转义          滑动窗口
终端电阻(CAN)         错误检测码            心跳/超时
滤波电容             帧序号                 多帧传输协议
```
