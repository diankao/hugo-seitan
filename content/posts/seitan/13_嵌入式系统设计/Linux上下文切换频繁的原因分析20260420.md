# Linux上下文切换频繁的原因分析

## 题目

在Linux系统中，如果发现上下文切换频繁，如何分析原因？

## 考察点

Linux性能分析、调度原理、调试工具

## 回答要点

### 1. 什么是上下文切换

```
Task A 运行中
   │
   ▼ 保存 A 的寄存器/栈/TLB → 切换到 Task B
   │
Task B 运行
   │
   ▼ 恢复 A 的寄存器/栈/TLB → 切换回 Task A
   │
Task A 继续运行
```

**每次上下文切换的开销**：
- 保存/恢复寄存器组（几十个通用寄存器 + 浮点寄存器）
- 切换虚拟地址空间（刷 TLB，约 1~10μs）
- cache 冷启动（新任务的代码和数据不在 cache 中）
- 调度器本身的计算开销

**过多的上下文切换意味着 CPU 时间浪费在切换上而非实际工作**。

### 2. 上下文切换的类型

| 类型 | 触发原因 | 典型场景 |
|------|---------|---------|
| 自愿切换（voluntary） | 任务主动调用阻塞 API | read/write/sleep/lock |
| 非自愿切换（non-voluntary） | 被调度器抢占 | 时间片用完、更高优先级就绪 |

### 3. 监控上下文切换

#### 3.1 系统级

```bash
# vmstat：每秒输出一次
vmstat 1
# 关注 cs（context switch）列
#  procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
#   r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
#   2  0      0 123456  12345 234567    0    0    12    15  120 3500  5  2 93  0  0
#                                              ▲
#                                         每秒上下文切换次数

# 一般参考值：
# < 1000/s   正常
# 1000~10000/s  需要关注
# > 100000/s  严重，需要排查
```

#### 3.2 进程级

```bash
# 查看特定进程的上下文切换
pidstat -w -p <pid> 1
#  PID   cswch/s nvcswch/s  Command
#  1234    50.00    10.00    my_app
#         ▲        ▲
#    自愿切换    非自愿切换

# /proc 直接读取
cat /proc/<pid>/status | grep ctxt
# voluntary_ctxt_switches:    12345
# nonvoluntary_ctxt_switches: 678
```

### 4. 自愿切换过多的原因与排查

#### 4.1 频繁的 IO 阻塞

```bash
# 查看进程在等什么
strace -c -e trace=read,write,poll,select,epoll_wait ./my_app

# 使用 perf 分析阻塞点
perf record -e sched:sched_stat_sleep -p <pid> -ag
perf report
```

**常见原因**：
- 磁盘 IO 慢（机械盘、NFS）
- 网络 IO 延迟大
- 管道/Socket 缓冲区太小导致频繁阻塞

**解决方案**：增大缓冲区、使用异步 IO、批量读写

#### 4.2 锁竞争

```bash
# perf 分析锁竞争
perf record -e lock:contention_begin -ag
perf report

# 或使用 perf lock 分析
perf lock record ./my_app
perf lock report
```

**常见原因**：
- 多线程频繁争抢同一把锁
- 锁粒度过大，持锁时间长
- futex 系统调用频繁

**解决方案**：减小锁粒度、用读写锁、用无锁数据结构

#### 4.3 频繁的短时 sleep/nanosleep

```bash
strace -e trace=nanosleep -c ./my_app
```

**常见原因**：
- 轮询循环中加 sleep(0) 或 usleep(100)
- 定时器精度不够用 sleep 模拟

**解决方案**：改用事件驱动（epoll）、条件变量

### 5. 非自愿切换过多的原因与排查

#### 5.1 CPU 密集型任务过多

```bash
# 查看运行队列长度
vmstat 1
# r 列 = 运行队列中的任务数
# 如果 r 持续 > CPU 核心数 → CPU 过载

# 查看哪些进程吃 CPU
top -H    # 线程级视图
pidstat -t -p <pid> 1
```

**解决方案**：减少 CPU 密集任务数、降低优先级、绑核（taskset/cpuset）

#### 5.2 优先级配置不当

```bash
# 查看进程调度策略和优先级
chrt -p <pid>

# 实时任务（SCHED_FIFO/RR）会完全抢占普通任务
# 如果有多个实时任务，会频繁互相抢占
```

**解决方案**：合理设置调度策略和优先级

#### 5.3 时间片过短

```bash
# 查看时间片（通常 1~6ms）
cat /proc/sys/kernel/sched_min_granularity_ns
cat /proc/sys/kernel/sched_wakeup_granularity_ns
```

### 6. 中断导致的"伪"上下文切换

```bash
# vmstat 的 in 列 = 每秒中断次数
vmstat 1
# 如果 in 很高，中断处理本身也会导致切换

# 查看中断分布
cat /proc/interrupts
watch -n 1 cat /proc/softirqs
```

### 7. 综合排查流程

```
上下文切换频繁
       │
       ▼
┌──────────────┐
│ vmstat 看    │──自愿切换多──▶ 查阻塞原因
│ cs 和 in     │               strace / perf
└──────┬───────┘
       │ 非自愿切换多
       ▼
┌──────────────┐
│ pidstat -w   │──某个进程──▶ 锁竞争 / IO 阻塞
│ 定位热点进程  │               perf lock / strace
└──────┬───────┘
       │ 多个进程
       ▼
┌──────────────┐
│ vmstat 看    │──r > CPU数──▶ CPU 过载
│ 运行队列 r   │               减少任务 / 绑核
└──────┬───────┘
       │ r 正常
       ▼
┌──────────────┐
│ 检查中断频率  │──in 很高──▶ 中断优化
│ /proc/interrupts│           DMA / 合并 / 降频
└──────────────┘
```

### 8. 常用工具速查

| 工具 | 用途 | 命令示例 |
|------|------|---------|
| vmstat | 系统级切换/中断/运行队列 | `vmstat 1` |
| pidstat | 进程级自愿/非自愿切换 | `pidstat -w 1` |
| strace | 追踪系统调用和阻塞 | `strace -c ./app` |
| perf | CPU profiling 和锁分析 | `perf record -ag` |
| perf top | 实时热点函数 | `perf top -g` |
| /proc/pid/status | 进程切换计数 | `grep ctxt /proc/pid/status` |
| htop | 可视化线程状态 | `htop -H` |
