# 非x86架构也用多级页表吗

## 题目

为什么教材说"在 x86 兼容的主机上，通过多级页表实现虚拟空间到物理空间的映射"？典型非 x86 指令集的机器不用多级页表吗？

## 考察点

主流 ISA 地址翻译方案的分类（硬件走表 / 软件走表 / 散列表 / 无翻译）、各方案的动机与代价、行业收敛趋势、Linux 通用页表模型。

## 回答要点

### 1. 先给结论

多级页表不是 x86 的专利，恰恰相反，今天几乎所有主流 ISA 都用硬件遍历的多级页表。真正"不这样"的是三类机器：软件管理 TLB 的（MIPS、SPARC）、散列/反置页表的（POWER、IA-64）、没有 MMU 的（Cortex-M）。教材限定 x86，只是因为书的叙述主线是 x86，而 x86 的页表格式是硬件规定的，讲它最具体（见《为什么用多级页表实现虚拟地址映射》）。

### 2. 主流阵营：硬件走表的多级页表

| 架构 | 页机制 | 说明 |
|------|--------|------|
| x86-64 | 4 级（LA57 起 5 级） | 基准 |
| AArch64（4KB 页，48 位 VA） | 4 级 | 与 x86-64 几乎同构 |
| RISC-V Sv39 / Sv48 / Sv57 | 3 / 4 / 5 级 | 同为 radix 树 |
| ARM32 经典 | 2 级粗页表 | 硬件走表 |
| LoongArch | 多级 radix 树 | 龙芯 3A5000 起的自有 ISA |

这些架构的 MMU 都内置硬件页表遍历器，页表格式写进指令集手册，操作系统照格式填表。

### 3. 例外一：软件管理 TLB（MIPS、SPARC）

MIPS 的硬件完全不认识任何页表格式：TLB miss 触发异常，操作系统自己选择数据结构、自己查表、自己把结果写回 TLB。

- x86 是硬件定格式、软件照填；MIPS 是硬件只给 TLB、格式随软件便
- Linux 在 MIPS 上的两级软件页表是内核约定，不是指令集要求
- 代价是每次 miss 都要付出异常进入/退出的开销，性能上限低于硬件走表

TLB miss 与缺页异常的区别见《TLB原理与页表寻址机制》。

### 4. 例外二：散列与反置页表（POWER、IA-64、IBM）

普通页表按"每个虚拟页一项"组织，表随虚拟地址空间增长；反置页表（Inverted Page Table）按"每个物理帧一项"组织，表随**物理内存**增长：

- 8GB 内存的整机，反置页表总共只有几十 MB，且与进程数无关
- 天然适合 64 位大地址空间，IA-64 的 VHPT、POWER 的 HPT 都是这一思路
- 代价：查找要哈希、冲突要拉链，TLB miss 处理复杂，页面共享麻烦
- POWER9 又加回了 radix 树模式（与 x86 同构），说明多级页表是权衡后的收敛解

### 5. 例外三：没有 MMU（Cortex-M）

M profile 只有 MPU，做区域权限检查，不做地址翻译，虚拟地址的概念都不存在，详见《Cortex-M、MPU与MMU辨析》。

### 6. 现状：一场收敛

把"非多级方案"与宿主 ISA 的命运放在一起看：

| ISA / 方案 | 现状 |
|-----------|------|
| IA-64（安腾，VHPT 散列） | 2021 年 Intel 正式停产，EPIC 路线败给 x86-64 |
| MIPS（软件 TLB） | MIPS 公司 2021 年转型卖 RISC-V 核心；存量在路由器（MT7621/OpenWrt）和高校课堂；龙芯 3A5000 起改用 LoongArch |
| PowerPC | 消费级已死（苹果 2006 年弃用、游戏主机换代）；航天抗辐照主控 RAD750 仍在毅力号、韦伯望远镜上服役；老款车规 ECU 有存量 |
| POWER（HPT → radix） | 服务器市场仍活着（POWER10/11），POWER9 起增加 radix 模式 |
| SPARC | Oracle 2017 年停止开发；ESA 的 LEON（SPARC V8）仍在欧洲卫星上使用 |

活下来的阵营——x86-64、AArch64、RISC-V、LoongArch、POWER（radix 模式）——清一色是硬件遍历的多级页表。注意因果要说准：这些 ISA 的兴衰源于生态与商业模式，不是页表设计；"硬件走表多级页表"只是幸存者的共同特征。

### 7. Linux 的通用模型：为什么书上限定 x86

Linux 维护一套通用的四级模型 pgd → pud → pmd → pte，形状按 x86-64 设计：

- 跑在 2 级页表的架构上，中间层级被"折叠"成空操作
- 跑在 MIPS 这类软件走表的架构上，它退化为内核自己的软件数据结构
- 于是在 Linux 里看什么架构都像多级页表；以 x86 为主线的教材就写成了"在 x86 兼容的主机上通过多级页表实现映射"
