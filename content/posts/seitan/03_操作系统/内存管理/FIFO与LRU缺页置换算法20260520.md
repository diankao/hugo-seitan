# FIFO与LRU缺页置换算法

## 题目

1. 给定页面引用串和物理块数，分别用 FIFO 和 LRU 算法计算缺页次数和缺页号。
2. FIFO 和 LRU 算法的原理是什么？有什么区别？
3. 什么是 Belady 异常？

## 考察点

虚拟内存页面置换算法的理解、手工模拟推算能力、算法优缺点对比。

## 回答要点

### 1. 基本概念

**缺页中断**：CPU 访问的页面不在物理内存中时，触发缺页中断，需要从磁盘调入该页面。如果物理内存已满，则需要用页面置换算法选择一个页面淘汰喵~

**页面引用串**：程序访问页面的序列，例如 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3`

**缺页率** = 缺页次数 / 总访问次数

| 维度 | FIFO | LRU |
|------|------|-----|
| 淘汰依据 | 进入内存的时间 | 最近访问的时间 |
| 实现复杂度 | 简单（队列） | 较复杂（时间戳/栈） |
| 性能 | 较差 | 较好 |
| Belady 异常 | 会发生 | 不会发生 |
| 硬件支持 | 不需要 | 需要硬件辅助 |

### 5. Belady 异常

**FIFO 特有的现象**：物理块数增加，缺页率反而上升喵~

经典示例：引用串 `1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5`

- 3 个物理块：缺页 **9** 次
- 4 个物理块：缺页 **10** 次

LRU 是**栈算法**，满足"更多的物理块不会导致更多缺页"的性质，因此不会出现 Belady 异常喵~
LRU 不会出现 Belady 异常，根本原因就是它是 栈算法（Stack Algorithm） 。

栈性质 的含义是： n 个物理块时的内存页面集合，一定是 n+1 个物理块时的子集 。

换句话说：

- 3 个块时内存里有 {A, B, C}
- 4 个块时内存里一定 至少 包含 {A, B, C}，再加上一个 D
因为 LRU 总是淘汰"最久未用"的，多给一块空间只会 多保留 一个页面，不可能反而把之前命中的页面给丢了喵。

而 FIFO 不满足这个性质——它只看"谁先来"，多一块空间可能改变淘汰顺序，导致之前命中的页面反而被淘汰喵。

### 6. LRU 的实现方式

#### 6.1 时间戳法

每个页面记录最后一次访问的时间戳，淘汰时找最小的喵~

```c
typedef struct {
    int page;
    unsigned long last_access;
} frame_t;

int find_lru_victim(frame_t *frames, int n) {
    int victim = 0;
    for (int i = 1; i < n; i++) {
        if (frames[i].last_access < frames[victim].last_access) {
            victim = i;
        }
    }
    return victim;
}
```

#### 6.2 栈实现

维护一个栈，每次访问将页面移到栈顶，淘汰栈底页面喵~

```
访问 7: 栈 = [7]
访问 0: 栈 = [7, 0]
访问 1: 栈 = [7, 0, 1]  （满）
访问 2: 淘汰栈底7, 栈 = [0, 1, 2]
访问 0: 0移到栈顶, 栈 = [1, 2, 0]
```

#### 6.3 Clock 算法（近似 LRU）

实际操作系统中常用 Clock 算法作为 LRU 的近似喵~

```c
typedef struct {
    int page;
    int reference_bit;
} clock_frame_t;

int clock_replace(clock_frame_t *frames, int n, int *hand) {
    while (1) {
        if (frames[*hand].reference_bit == 0) {
            int victim = *hand;
            *hand = (*hand + 1) % n;
            return victim;
        }
        frames[*hand].reference_bit = 0;
        *hand = (*hand + 1) % n;
    }
}
```

### 7. 其他页面置换算法

| 算法 | 原理 | 特点 |
|------|------|------|
| OPT | 淘汰未来最长时间不用的页面 | 理论最优，无法实现 |
| FIFO | 淘汰最早进入的页面 | 简单，有 Belady 异常 |
| LRU | 淘汰最近最久未用的页面 | 性能好，开销大 |
| Clock | LRU 的近似，用引用位 | 实际系统常用 |
| LFU | 淘汰访问频率最低的页面 | 需要计数器 |

### 8. 做题技巧

1. **FIFO**：画一个队列，先进先出，命中不改变队列顺序
2. **LRU**：每步标注最近使用顺序，淘汰最久未用的
3. 注意**命中时不产生缺页**，但 LRU 中命中会更新使用顺序
4. 前几步（物理块未满时）都是缺页
5. 最后统计缺页次数，列出所有缺页时访问的页号

### 9. 总结

| 要点 | 说明 |
|------|------|
| FIFO | 按进入顺序淘汰，简单但性能差 |
| LRU | 按使用时间淘汰，性能好但实现复杂 |
| Belady 异常 | FIFO 增加物理块可能增加缺页 |
| Clock 算法 | LRU 的实用近似方案 |
| 做题关键 | 逐帧模拟，注意命中时的状态更新 |
