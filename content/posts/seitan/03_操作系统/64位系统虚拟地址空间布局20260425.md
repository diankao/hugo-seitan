# 64位系统虚拟地址空间布局

## 题目

在64位系统中指针是8字节，有一个函数返回了一个指针变量，查看它的高32位全是0，这是什么原因？

## 考察点

- 64位系统中虚拟地址空间的有效位数
- 用户空间与内核空间的地址范围划分
- x86-64 / AArch64 架构下实际使用的地址位数

## 回答要点

### 1. 64位并非真正使用全部64位地址

虽然指针变量占8字节（64位），但**现有64位架构并不会使用全部64位进行寻址**喵~

以 x86-64 为例，目前只使用了 **48位** 虚拟地址（即 canonical address），可寻址空间为 256TB。ARM64（AArch64）类似，根据配置使用 48 位或 52 位。

```text
63                    48 47                              0
┌──────────────────────┬──────────────────────────────────┐
│    符号扩展位         │         有效地址位                │
│  (全0 或 全1)        │        (48 bit)                  │
└──────────────────────┴──────────────────────────────────┘
```

### 2. 用户空间指针高32位为0的原因

用户空间地址范围在 x86-64 下为 `0x0000000000000000` ~ `0x00007FFFFFFFFFFF`，即：

| 区域 | 地址范围 | 高16位 | 说明 |
|------|---------|--------|------|
| 用户空间 | `0x0000_0000_0000_0000` ~ `0x0000_7FFF_FFFF_FFFF` | 全0 | 低128TB |
| 非规范地址 | `0x0000_8000_0000_0000` ~ `0xFFFF_7FFF_FFFF_FFFF` | — | 访问触发异常 |
| 内核空间 | `0xFFFF_8000_0000_0000` ~ `0xFFFF_FFFF_FFFF_FFFF` | 全1 | 高128TB |

用户空间的指针，**高16位为0**。当转换为32位视图时，高32位（bit 63~32）自然也全是0，因为用户空间地址最大只有 `0x0000_7FFF_FFFF_FFFF`，其 bit 32 以上全部为0喵~

### 3. 代码验证

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

int main() {
    int *p = (int *)malloc(sizeof(int));
    *p = 42;

    printf("指针值:       0x%016llx\n", (unsigned long long)(uintptr_t)p);
    printf("高32位:       0x%08x\n",   (uint32_t)((uintptr_t)p >> 32));
    printf("低32位:       0x%08x\n",   (uint32_t)((uintptr_t)p & 0xFFFFFFFF));

    free(p);
    return 0;
}
```

典型输出（Linux x86-64 用户态）：

```text
指针值:       0x00005555555592a0
高32位:       0x00005555
低32位:       0x555592a0
```

可以看到高32位只有 `0x00005555`，远小于 `0xFFFFFFFF`。如果在32位兼容环境或特定嵌入式Linux中，用户空间地址更低，高32位就完全是0了喵~

### 4. 为什么不全用64位？

- **页表过大**：64位地址空间需要层级极多的页表，内存开销巨大
- **硬件成本**：地址译码电路需要更多晶体管
- **实际不需要**：48位可寻址 256TB，对绝大多数应用已足够

### 5. 扩展：内核空间指针特征

内核空间的指针高位为全1，例如 `0xFFFF888000000000`。利用这个特性，Linux内核代码中经常通过检查高位来判断指针属于用户空间还是内核空间：

```c
#define IS_KERNEL_ADDR(addr) ((uintptr_t)(addr) >= 0xFFFF800000000000ULL)
```

## 总结

用户态函数返回的指针，其高32位为0，是因为64位系统（如x86-64）实际只使用48位地址，且用户空间地址位于低半部分，高位全为0。这是虚拟地址空间布局的直接体现，并非指针损坏或异常喵~
