# FreeRTOS任务抢占与调度机制

## 标签
#嵌入式 #面试题 #FreeRTOS #任务调度 #操作系统

## 问题描述
项目中FreeRTOS 3个任务发生抢占会怎么样？抢占式调度具体怎么实现的，要原理性的，怎么暂停当前运行的中优先级的任务？

## 参考答案
### 1. FreeRTOS任务抢占原理

**抢占式调度概念：**
- 高优先级任务就绪时，会立即抢占低优先级任务的CPU使用权
- 系统总是运行就绪任务中优先级最高的任务
- 低优先级任务被抢占后，进入就绪状态等待下次调度

**任务抢占发生时机：**
1. **高优先级任务从阻塞态变为就绪态**
   - 延时时间到
   - 信号量/队列获取成功
   - 中断唤醒任务

2. **当前任务主动让出CPU**
   - 调用taskYIELD()
   - 等待信号量/队列

3. **中断服务程序结束**
   - 优先级高于当前任务的任务被中断唤醒

### 2. 抢占式调度实现原理

**任务状态管理：**
```c
typedef enum {
    eRunning,    // 运行态
    eReady,      // 就绪态
    eBlocked,    // 阻塞态
    eSuspended,  // 挂起态
    eDeleted     // 删除态
} eTaskState;
```

**就绪列表管理：**
- FreeRTOS为每个优先级维护一个就绪链表
- 使用位图（pxReadyTasksLists）快速查找最高优先级就绪任务
- 位图查找算法：`uxTopReadyPriority = __clz(ulReadyTasks)`

**任务切换流程：**

1. **保存上下文**：
   ```assembly
   ; Cortex-M3/4汇编示例
   vPortYieldFromISR:
       PUSH    {r4-r11, lr}      ; 保存R4-R11和LR
       LDR     r0, =pxCurrentTCB ; 获取当前任务控制块
       LDR     r1, [r0]
       STR     sp, [r1]         ; 保存当前任务SP到TCB
   ```

2. **选择新任务**：
   ```c
   void vTaskSwitchContext(void) {
       // 查找最高优先级就绪任务
       listGET_OWNER_OF_NEXT_ENTRY(pxCurrentTCB, &pxReadyTasksLists[uxTopReadyPriority]);
   }
   ```

3. **恢复上下文**：
   ```assembly
   vTaskSwitchContext:
       LDR     r0, =pxCurrentTCB
       LDR     r1, [r0]
       LDR     sp, [r1]         ; 恢复新任务SP
       POP     {r4-r11, pc}     ; 恢复寄存器并跳转
   ```

### 3. 暂停当前任务的具体机制

**中断引起的任务切换：**
```c
void xPortPendSVHandler(void) {
    __disable_irq();  // 关中断
    
    // 保存当前任务上下文到栈中
    asm volatile (
        "mrs r0, psp\n\t"
        "stmdb r0!, {r4-r11, lr}\n\t"
        "vstmdb r0!, {s16-s31}\n\t"
    );
    
    // 保存当前任务栈指针到TCB
    pxCurrentTCB->pxTopOfStack = pxCurrentTCB->pxStack;
    
    // 调度器查找最高优先级任务
    vTaskSwitchContext();
    
    // 恢复新任务上下文
    asm volatile (
        "vldmia r0!, {s16-s31}\n\t"
        "ldmia r0!, {r4-r11, lr}\n\t"
        "msr psp, r0\n\t"
        "bx lr\n\t"
    );
    
    __enable_irq();  // 开中断
}
```

**软件触发的任务切换：**
```c
void taskYIELD(void) {
    portYIELD();  // 触发PendSV中断
}

#define portYIELD()  \
    vPortYieldFromISR()

static inline void vPortYieldFromISR(void) {
    portNVIC_INT_CTRL_REG = portNVIC_PENDSVSET_BIT;  // 设置PendSV挂起位
}
```

### 4. 3个任务抢占示例

**场景：3个任务优先级不同**
```c
TaskHandle_t task1, task2, task3;

void vTask1(void *pvParameters) {
    while(1) {
        vTaskDelay(pdMS_TO_TICKS(100));
        // 低优先级任务，优先级1
    }
}

void vTask2(void *pvParameters) {
    while(1) {
        vTaskDelay(pdMS_TO_TICKS(50));
        // 中优先级任务，优先级2
    }
}

void vTask3(void *pvParameters) {
    while(1) {
        vTaskDelay(pdMS_TO_TICKS(20));
        // 高优先级任务，优先级3
    }
}

// 创建任务
xTaskCreate(vTask1, "Task1", 128, NULL, 1, &task1);
xTaskCreate(vTask2, "Task2", 128, NULL, 2, &task2);
xTaskCreate(vTask3, "Task3", 128, NULL, 3, &task3);
```

**执行过程：**
1. Task3（优先级3）就绪，立即抢占CPU
2. Task3执行完毕或阻塞，调度器选择Task2（优先级2）
3. Task2执行完毕或阻塞，调度器选择Task1（优先级1）
4. 如果Task3再次就绪，立即抢占Task1

### 5. 关键点总结

**中断与调度的关系：**
- 中断服务程序（ISR）中不应直接调用任务切换API
- ISR中应使用`xHigherPriorityTaskWoken`机制
- 中断结束后触发PendSV进行任务切换

**时间片轮转：**
- 相同优先级任务间使用时间片轮转
- 时间片由configTICK_RATE_HZ定义

**任务优先级设置：**
- 数值越大优先级越高（0最低，configMAX_PRIORITIES-1最高）
- 建议优先级间隔至少为2，方便扩展
- 避免过多高优先级任务导致饥饿

**调度器锁：**
- `vTaskSuspendAll()` / `xTaskResumeAll()` 可临时禁用调度
- 中断中不要调用可能引起任务切换的函数
