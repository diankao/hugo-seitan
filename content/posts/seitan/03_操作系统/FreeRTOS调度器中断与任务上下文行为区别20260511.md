# FreeRTOS调度器中断与任务上下文行为区别

## 题目

FreeRTOS 内核调度器在中断上下文与任务上下文中的行为有什么区别？

## 考察点

FreeRTOS 中断安全机制、FromISR API 设计、中断优先级与调度器的交互。

## 回答要点

### 1. 核心区别总览

| 方面 | 任务上下文 | 中断上下文 |
|------|-----------|-----------|
| API 后缀 | 无后缀（`xQueueSend`） | `FromISR`（`xQueueSendFromISR`） |
| 能否阻塞 | ✅ 可以（`portMAX_DELAY`） | ❌ **绝对不能**阻塞 |
| 调度器行为 | 操作后可能立即触发任务切换 | 延迟到中断退出后才切换 |
| 优先级 | 任务优先级（软件概念） | 硬件中断优先级（NVIC 管理） |
| 栈 | 使用任务栈（PSP） | 使用主栈（MSP） |
| 时间约束 | 可以长时间运行 | 必须快速返回 |

### 2. 为什么中断中不能调用阻塞 API

```c
// ❌ 严重错误：ISR 中调用阻塞 API
void UART_IRQHandler(void) {
    xQueueSend(queue, &data, portMAX_DELAY);  // 如果队列满了...
    // ISR 会尝试阻塞等待队列有空间
    // 但 ISR 不是任务，调度器无法切换 ISR！
    // 系统直接死锁
}

// ✅ 正确：ISR 中使用 FromISR 版本
void UART_IRQHandler(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    xQueueSendFromISR(queue, &data, &xHigherPriorityTaskWoken);

    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

**根本原因**：ISR 不受调度器管理。调度器管理的是任务，ISR 由硬件中断机制驱动。如果 ISR 阻塞了，调度器无法"切换走"它——因为 ISR 的进入和退出由硬件控制。

### 3. FromISR API 的设计逻辑

#### 3.1 不做调度决策，只标记

```c
// 任务上下文：xQueueSend 内部逻辑
BaseType_t xQueueSend(QueueHandle_t xQueue, const void *pvItemToQueue, TickType_t xTicksToWait) {
    // 1. 检查队列是否满
    if (队列满) {
        // 2. 可以阻塞等待（挂起当前任务）
        vTaskPlaceOnEventList(&(pxQueue->xTasksWaitingToSend), xTicksToWait);
        // 3. 触发任务切换
        portYIELD();
    }
    // ...
}

// 中断上下文：xQueueSendFromISR 内部逻辑
BaseType_t xQueueSendFromISR(QueueHandle_t xQueue, const void *pvItemToQueue, BaseType_t *pxHigherPriorityTaskWoken) {
    // 1. 检查队列是否满
    if (队列满) {
        // 2. 不能阻塞！直接返回失败
        return errQUEUE_FULL;
    }
    // 3. 数据入队
    // 4. 如果有任务在等待数据，标记需要切换
    if (有任务在等待) {
        *pxHigherPriorityTaskWoken = pdTRUE;  // 只是标记！
        // 注意：这里不切换，等 ISR 退出后再切换
    }
    return pdTRUE;
}
```

#### 3.2 延迟切换机制

```c
// ISR 退出后的切换判断
#define portYIELD_FROM_ISR(xHigherPriorityTaskWoken) \
    do {                                              \
        if (xHigherPriorityTaskWoken != pdFALSE) {    \
            portNVIC_INT_CTRL_REG = portNVIC_PENDSVSET_BIT; \
        }                                             \
    } while(0)

// PendSV 被设为最低优先级中断
// 当所有高优先级 ISR 执行完后，CPU 才会响应 PendSV
// 此时才真正执行上下文切换
```

### 4. 中断优先级与调度器的交互

FreeRTOS 有一个关键配置：

```c
#define configMAX_SYSCALL_INTERRUPT_PRIORITY  5  // 假设用优先级分组4
```

```
中断优先级（数值越小越高）：
  0 (最高) ─── NMI, HardFault（不可屏蔽）
  1         ─── 高于 FreeRTOS 管理范围
  2         ─── 高于 FreeRTOS 管理范围
  │         ─── configMAX_SYSCALL_INTERRUPT_PRIORITY 边界
  5         ─── 可以调用 FromISR API 的最高优先级
  6         ─── 可以调用 FromISR API
  7 (最低)  ─── PendSV（任务切换，永远最低）
```

| 优先级范围 | 能否调用 FreeRTOS API | 说明 |
|-----------|---------------------|------|
| 0 ~ (configMAX-1) | ❌ **绝对不能** | 优先级高于调度器，会破坏内核数据 |
| configMAX ~ 最低 | ✅ 可以调用 FromISR | 受调度器管理，可以安全调用 |

```c
// ❌ 危险：高优先级中断中调用 FreeRTOS API
// 假设 configMAX_SYSCALL_INTERRUPT_PRIORITY = 5
void HighPriority_ISR(void) {     // 优先级 = 3（高于 5）
    xQueueSendFromISR(...);        // 可能在中断嵌套中破坏内核数据
    // 因为调度器的临界区保护（BASEPRI）无法屏蔽这个优先级
}

// ✅ 安全：在管理范围内的中断调用
void NormalPriority_ISR(void) {    // 优先级 = 6（低于 5）
    xQueueSendFromISR(...);         // 安全
}
```

### 5. 完整对比表

| 操作 | 任务上下文 | 中断上下文 |
|------|-----------|-----------|
| 发送队列 | `xQueueSend(queue, &data, timeout)` | `xQueueSendFromISR(queue, &data, &woken)` |
| 接收队列 | `xQueueReceive(queue, &data, timeout)` | `xQueueReceiveFromISR(queue, &data, &woken)` |
| 获取信号量 | `xSemaphoreTake(sem, timeout)` | `xSemaphoreTakeFromISR(sem, &woken)` |
| 释放信号量 | `xSemaphoreGive(sem)` | `xSemaphoreGiveFromISR(sem, &woken)` |
| 任务通知 | `xTaskNotify(task, val, eAction)` | `xTaskNotifyFromISR(task, val, eAction, &woken)` |
| 事件组 | `xEventGroupSetBits(eg, bits)` | `xEventGroupSetBitsFromISR(eg, bits, &woken)` |
| 延时 | `vTaskDelay(ticks)` | ❌ 不可用 |
| 进入临界区 | `taskENTER_CRITICAL()` | `portSET_INTERRUPT_MASK_FROM_ISR()` |
| 退出临界区 | `taskEXIT_CRITICAL()` | `portCLEAR_INTERRUPT_MASK_FROM_ISR(state)` |

### 6. 面试速记

- **任务上下文**：可以阻塞、直接切换、使用 PSP
- **中断上下文**：不能阻塞、延迟切换（PendSV）、使用 MSP
- **API 规则**：ISR 中只能用 `FromISR` 后缀的 API
- **优先级规则**：高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断不能调用任何 FreeRTOS API
