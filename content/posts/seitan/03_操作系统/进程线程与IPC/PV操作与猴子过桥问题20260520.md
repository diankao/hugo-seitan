# PV操作与猴子过桥问题

## 题目

一座独木桥，南北两个方向各有猴子要过桥。同一方向的猴子可以同时过桥，但两个方向的猴子不能同时在桥上。使用 PV 操作（信号量）实现同步与互斥。

## 考察点

信号量（PV 操作）的理解、进程/线程同步互斥的经典模型、读者-写者问题的变种。

## 回答要点

### 1. PV 操作基础

**P 操作（wait）**：申请资源，若信号量值 > 0 则减 1 并继续；否则阻塞等待喵~

```c
void P(semaphore *s) {
    s->value--;
    if (s->value < 0) {
        block(s->queue);
    }
}
```

**V 操作（signal）**：释放资源，信号量值加 1；若有等待进程则唤醒一个喵~

```c
void V(semaphore *s) {
    s->value++;
    if (s->value <= 0) {
        wakeup(s->queue);
    }
}
```

### 2. 题目分析

**关键约束：**
- 桥上同一方向可以有多个猴子（共享）
- 桥上不能同时有南北两个方向的猴子（互斥）
- 这本质上是**读者-写者问题**的变种，每个方向是一组"读者"喵~

**需要的信号量：**

| 信号量 | 初值 | 作用 |
|--------|------|------|
| `bridge` | 1 | 桥的使用权，保证两个方向互斥 |
| `mutex_s` | 1 | 保护南方向计数器 |
| `mutex_n` | 1 | 保护北方向计数器 |
| `count_s` | 0 | 当前桥上南方向的猴子数 |
| `count_n` | 0 | 当前桥上北方向的猴子数 |

### 3. 解法一：读者优先型

每个方向的第一只猴子负责"锁桥"，最后离开的猴子负责"解锁"喵~

```c
semaphore bridge = 1;
semaphore mutex_s = 1;
semaphore mutex_n = 1;
int count_s = 0;
int count_n = 0;

void monkey_south_to_north(int id) {
    P(&mutex_s);
    count_s++;
    if (count_s == 1) {
        P(&bridge);
    }
    V(&mutex_s);

    cross_bridge(id, "南→北");

    P(&mutex_s);
    count_s--;
    if (count_s == 0) {
        V(&bridge);
    }
    V(&mutex_s);
}

void monkey_north_to_south(int id) {
    P(&mutex_n);
    count_n++;
    if (count_n == 1) {
        P(&bridge);
    }
    V(&mutex_n);

    cross_bridge(id, "北→南");

    P(&mutex_n);
    count_n--;
    if (count_n == 0) {
        V(&bridge);
    }
    V(&mutex_n);
}
```

**执行流程分析：**

```
南→北猴子1 到达: count_s=1, P(bridge) 获取桥 → 过桥
南→北猴子2 到达: count_s=2, 不需要P(bridge) → 直接过桥
北→南猴子1 到达: count_n=1, P(bridge) 阻塞 → 等待
南→北猴子1 离开: count_s=1
南→北猴子2 离开: count_s=0, V(bridge) → 北→南猴子1 被唤醒
北→南猴子1 过桥
北→南猴子1 离开: count_n=0, V(bridge)
```

### 4. 解法二：公平型（防止饥饿）

解法一中，如果南方向猴子源源不断，北方向猴子可能永远等不到桥（饥饿）。加入一个"公平锁"信号量喵~

```c
semaphore bridge = 1;
semaphore mutex_s = 1;
semaphore mutex_n = 1;
semaphore fair = 1;
int count_s = 0;
int count_n = 0;

void monkey_south_to_north(int id) {
    P(&fair);
    P(&mutex_s);
    count_s++;
    if (count_s == 1) {
        P(&bridge);
    }
    V(&mutex_s);
    V(&fair);

    cross_bridge(id, "南→北");

    P(&mutex_s);
    count_s--;
    if (count_s == 0) {
        V(&bridge);
    }
    V(&mutex_s);
}

void monkey_north_to_south(int id) {
    P(&fair);
    P(&mutex_n);
    count_n++;
    if (count_n == 1) {
        P(&bridge);
    }
    V(&mutex_n);
    V(&fair);

    cross_bridge(id, "北→南");

    P(&mutex_n);
    count_n--;
    if (count_n == 0) {
        V(&bridge);
    }
    V(&mutex_n);
}
```

`fair` 信号量确保每个方向的第一只猴子公平竞争获取桥的使用权喵~

### 5. 两种解法对比

| 维度 | 解法一（读者优先） | 解法二（公平型） |
|------|-------------------|-----------------|
| 吞吐量 | 高（同方向可连续过桥） | 中（交替机会更多） |
| 公平性 | 差（可能饥饿） | 好（不会饥饿） |
| 信号量数 | 3 | 4 |
| 复杂度 | 低 | 中 |

### 6. 这类题的通用解题步骤

1. **找共享资源**：桥（互斥资源）
2. **找计数器**：每个方向在桥上的猴子数
3. **第一只上锁，最后一只解锁**：读者-写者模式的核心
4. **考虑公平性**：是否需要防止饥饿

### 7. 类似题型

| 题目 | 模型 | 关键点 |
|------|------|--------|
| 猴子过桥 | 双向互斥 | 第一只锁桥，最后一只解锁 |
| 读者-写者 | 读写互斥 | 读者共享，写者独占 |
| 理发师问题 | 生产者-消费者 | 等待队列 + 服务者 |
| 哲学家就餐 | 资源竞争 | 环形等待，防止死锁 |
| 生产者-消费者 | 缓冲区同步 | 满了停止生产，空了停止消费 |

### 8. 总结

| 要点 | 说明 |
|------|------|
| 问题本质 | 读者-写者问题的变种 |
| 核心思想 | 同方向共享，不同方向互斥 |
| 关键模式 | 第一只上锁，最后一只解锁 |
| 公平方案 | 加入 fair 信号量防止饥饿 |
| PV 操作 | P 申请资源，V 释放资源 |
