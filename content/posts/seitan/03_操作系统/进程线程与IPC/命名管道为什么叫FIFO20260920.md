# 命名管道为什么叫FIFO

## 题目

named pipe（命名管道）为什么也叫 FIFO？匿名管道和命名管道、消息队列有什么区别？

## 考察点

管道的内核本质（环形缓冲区队列）、命名管道的文件系统实体、FIFO 语义（顺序保证、不可寻址、读即消费）、匿名管道与命名管道及消息队列的对比。

## 回答要点

### 1. 两个名字各说一半真相

- **pipe（管道）是方向比喻**：数据像水一样从写端单向流向读端
- **FIFO 是顺序契约**：先写入的字节先被读到，顺序是硬保证

而且 FIFO 才是官方正式名，"named pipe"反而是解释性的俗称。证据遍布系统接口：创建调用叫 `mkfifo()`，`stat` 结构里的文件类型位叫 `S_IFIFO`，判别宏叫 `S_ISFIFO()`，`stat` 命令输出文件类型直接写 "fifo"，`ls -l` 显示类型字母 `p`，POSIX 文本称其为 "FIFO special file"（FIFO 特殊文件），BSD 内核里对应的 vnode 操作表就叫 `fifo_vnops.c`。

### 2. FIFO 语义具体指什么

这个对象本质上是**内核里的一条先进先出字节流队列**：

- 一端写、另一端读，先写的字节先被读到，顺序是硬保证
- 不可 `lseek()`（返回 `ESPIPE`）——没有"位置"概念，读就是出队，数据被消费一次就没了
- 无消息边界，纯字节流——对比 System V 消息队列还能按类型 `msgrcv` 挑着取，管道严格按序

实现上，Linux 的 `pipe_inode_info` 就是一个由页组成的**环形缓冲区**（默认 16 页、64KB，head/tail 两个游标）——定长环形缓冲正是 FIFO 队列的标准实现手法，"FIFO"这个名字没有一丝夸张。

### 3. 为什么"有名的"那个才跟 FIFO 绑定

关键在于：**两种管道都是 FIFO，但只有命名管道需要出现在文件系统里，而文件系统登记类型总得有个正式名字。**

- 匿名管道（`pipe()`，1973 年进入 Unix）没有文件系统实体，只返回两个 fd，靠 fork 继承传递——所以只有亲缘进程能用，它不需要"户口"，大家就叫它 pipe
- 命名管道把这个 FIFO 队列挂载成文件系统里的一个特殊文件（早期靠 `mknod` 创建，POSIX 专门定了 `mkfifo()`），任意两个无亲缘的进程各自 `open` 同一个路径就能在队列两头汇合。既然要上户口，就得选个类型名——语义名 FIFO 胜出

一个容易误解的点：FIFO 特殊文件在磁盘上**只有 inode 没有数据块**。路径持久存在，队列本体永远在内核内存里，最后一个读写端关闭时数据就没了——它与"持久化队列"毫无关系。

### 4. 代码示例

匿名管道，父子进程通信：

```c
#include <unistd.h>

int main(void)
{
    int fd[2];
    char buf[16];

    pipe(fd);

    if (fork() == 0) {
        close(fd[0]);
        write(fd[1], "hello", 5);
        close(fd[1]);
    } else {
        close(fd[1]);
        read(fd[0], buf, sizeof(buf));
        close(fd[0]);
    }
    return 0;
}
```

命名管道，两个无亲缘进程。进程 A：

```c
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    mkfifo("/tmp/myfifo", 0666);

    int fd = open("/tmp/myfifo", O_WRONLY);
    write(fd, "hello", 5);
    close(fd);
    return 0;
}
```

进程 B：

```c
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    char buf[16];

    int fd = open("/tmp/myfifo", O_RDONLY);
    read(fd, buf, sizeof(buf));
    close(fd);
    return 0;
}
```

几个关键行为：

- 两个方向的 `open` 都会**阻塞直到对方打开**（`O_RDONLY` 等写端，`O_WRONLY` 等读端），加 `O_NONBLOCK` 可改变此行为——首次使用命名管道最常见的"卡住不动"就是它
- 管道容量满时 `write` 阻塞，空时 `read` 阻塞
- 不超过 `PIPE_BUF`（Linux 为 4096 字节）的单次 `write` 是原子的，多个写者并发写同一条管道不会交错

### 5. 三种机制对比

| 维度 | 匿名管道 | 命名管道（FIFO） | System V 消息队列 |
|------|---------|-----------------|------------------|
| 创建接口 | pipe() | mkfifo() | msgget() |
| 实体位置 | 内核内存，无文件系统入口 | 文件系统特殊文件（只有 inode 无数据块），队列在内核 | 内核内存 |
| 进程关系 | 仅亲缘进程（fork 继承 fd） | 任意进程（open 同一路径） | 任意进程（同一个 key） |
| 数据模型 | 单向字节流 | 单向字节流 | 带类型的有边界消息 |
| 顺序 | 严格 FIFO | 严格 FIFO | 同类型内 FIFO，可按类型挑选 |
| 数据生命周期 | 所有 fd 关闭即消失 | 路径持久，数据随两端关闭消失 | 需 msgctl(IPC_RMID) 显式删除，否则留到内核重启 |
| 典型用途 | shell 的 \|、父子进程 | 无亲缘进程的本地通信 | 需要消息边界或优先级的本地通信 |

### 6. 一句话总结

管道是方向比喻，FIFO 是顺序契约，两个名字合起来才是完整定义：**挂了名字、可被无关进程打开的、先进先出的单向字节流**。
