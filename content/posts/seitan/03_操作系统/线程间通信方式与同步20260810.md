# 线程间通信方式与同步

## 题目

线程间通信有哪些方式？和进程间通信（IPC）有什么区别？

## 考察点

线程模型、线程同步机制、共享内存的本质。

## 回答要点

### 1. 为什么线程间通信比进程间"简单"

同一进程内的线程**共享同一地址空间**：代码段、数据段、堆、全局变量、文件描述符表都是共享的，唯一私有的是栈和寄存器上下文。因此线程间"通信"本质上就是直接读写共享变量——不需要像进程那样借助管道、消息队列、共享内存等内核机制。

```c
// 线程间最朴素的"通信"：直接访问共享全局变量
int g_data = 0;

void* writer(void* arg) {
    g_data = 42;          // 线程 A 写
    return NULL;
}

void* reader(void* arg) {
    while (g_data == 0);  // 线程 B 忙等
    printf("%d\n", g_data);
    return NULL;
}
```

但直接共享带来了**竞态（Race Condition）**，所以线程间通信的核心问题不是"如何传数据"，而是"如何安全地同步"。

### 2. 线程间通信 / 同步的主要方式

| 方式 | 用途 | 本质 | 适用场景 |
|------|------|------|----------|
| 互斥锁（Mutex） | 保护临界区 | 保证同一时刻只有一个线程进入 | 共享数据的读写 |
| 读写锁（RWLock） | 读多写少优化 | 多读单写 | 配置表、缓存 |
| 自旋锁（Spinlock） | 极短临界区 | 忙等不睡眠 | 内核、中断上下文 |
| 信号量（Semaphore） | 资源计数 | 计数器 + 等待队列 | 限流、生产消费 |
| 条件变量（Condvar） | 等待条件成立 | 配合 Mutex，通知唤醒 | 生产者-消费者 |
| 屏障（Barrier） | 多线程汇合 | 等齐再放行 | 并行计算分阶段 |
| 管道/消息队列 | 跨线程传递消息 | 内核缓冲区（也可进程间用） | 解耦、流式数据 |
| Future/Promise | 单次结果传递 | 一次写多次读 | 异步任务取结果 |

### 3. 互斥锁 + 条件变量（经典生产者-消费者）

这是最常考的组合：Mutex 保护队列，Condvar 通知"有数据了/有空位了"。

```c
#include <pthread.h>

typedef struct {
    int buf[BUF_SIZE];
    int in, out, count;
    pthread_mutex_t mtx;
    pthread_cond_t  not_full;
    pthread_cond_t  not_empty;
} queue_t;

void queue_put(queue_t* q, int val) {
    pthread_mutex_lock(&q->mtx);
    while (q->count == BUF_SIZE) {           // 队列满，等待
        pthread_cond_wait(&q->not_full, &q->mtx);
    }
    q->buf[q->in] = val;
    q->in = (q->in + 1) % BUF_SIZE;
    q->count++;
    pthread_cond_signal(&q->not_empty);      // 通知消费者
    pthread_mutex_unlock(&q->mtx);
}

int queue_get(queue_t* q) {
    pthread_mutex_lock(&q->mtx);
    while (q->count == 0) {                   // 队列空，等待
        pthread_cond_wait(&q->not_empty, &q->mtx);
    }
    int val = q->buf[q->out];
    q->out = (q->out + 1) % BUF_SIZE;
    q->count--;
    pthread_cond_signal(&q->not_full);       // 通知生产者
    pthread_mutex_unlock(&q->mtx);
    return val;
}
```

> 为什么 `wait` 必须用 `while` 而不是 `if`？防止**虚假唤醒（Spurious Wakeup）**——POSIX 允许 `pthread_cond_wait` 在没有 signal 的情况下返回。

### 4. 信号量：资源计数

信号量本质是一个计数器，`wait(P)` 减一、`post(V)` 加一，减到 0 就阻塞。既能做互斥（初值 1），也能做资源池（初值 N）。

```c
#include <semaphore.h>

sem_t sem;
sem_init(&sem, 0, 5);   // 5 个资源（0 表示线程间共享）

// 工作线程
sem_wait(&sem);         // 申请一个资源，没有就阻塞
do_critical_work();
sem_post(&sem);         // 释放资源
```

对比 Mutex：Mutex 强调"所有权"（谁加锁谁解锁），信号量没有所有权概念，因此**不能解决优先级继承**，实时系统里保护临界区一般优先选 Mutex。

### 5. 读写锁：读多写少场景

```c
#include <pthread.h>
pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

// 读线程（可并发）
pthread_rwlock_rdlock(&rwlock);
read_config();
pthread_rwlock_unlock(&rwlock);

// 写线程（独占）
pthread_rwlock_wrlock(&rwlock);
update_config();
pthread_rwlock_unlock(&rwlock);
```

| 操作 | 并发性 |
|------|--------|
| 多个读 | 允许并发 |
| 一个写 | 独占，阻塞所有读和写 |
| 读+写 | 写优先或读优先（取决于实现） |

### 6. 自旋锁：极短临界区

```c
// Linux 内核自旋锁（忙等，不睡眠）
spinlock_t lock;
spin_lock_init(&lock);

spin_lock(&lock);     // 抢不到就 while(1) 循环
// 临界区（必须极短，不能睡眠、不能 IO）
spin_unlock(&lock);
```

**自旋锁 vs 互斥锁**：

| 维度 | 自旋锁 | 互斥锁 |
|------|--------|--------|
| 抢不到时 | 忙等（CPU 100%） | 睡眠（让出 CPU） |
| 上下文 | 中断、软中断可用 | 只能在进程上下文 |
| 适用 | 临界区极短（< 几 us） | 临界区较长、可能阻塞 |
| 多核 | 才有意义 | 单核也能用 |

### 7. 屏障 Barrier：多线程汇合

```c
#include <pthread.h>
pthread_barrier_t bar;
pthread_barrier_init(&bar, NULL, 4);   // 4 个线程汇合

// 每个线程
phase1_work();
pthread_barrier_wait(&bar);            // 等到 4 个都到齐，再一起放行
phase2_work();
```

适用于分阶段并行计算（矩阵乘法、归约）。

### 8. Future / Promise：异步结果传递

C++11 的 `std::future` / `std::promise` 用于一次性的"结果回传"：

```cpp
#include <future>
std::promise<int> prom;
std::future<int>  fut = prom.get_future();

std::thread worker([&prom]() {
    int result = heavy_compute();
    prom.set_value(result);        // 子线程设值
});

int v = fut.get();                 // 主线程阻塞等待结果
worker.join();
```

### 9. 线程间通信 vs 进程间通信（IPC）

| 维度 | 线程间 | 进程间（IPC） |
|------|--------|--------------|
| 地址空间 | 共享 | 隔离 |
| 数据传递 | 直接读写共享变量 | 管道、消息队列、共享内存、Socket |
| 同步 | Mutex/Condvar/Semaphore | System V 信号量、文件锁 |
| 性能 | 高（无内核参与数据搬运） | 低（多数要内核中转，共享内存除外） |
| 隔离性 | 差（一个线程崩溃全进程崩溃） | 好 |

> 进程间通信的"共享内存（shm）"方式，本质上就是让两个进程映射同一块物理页，从而获得类似线程的共享访问能力，但仍需用信号量等机制同步。

### 10. 平台差异说明

| 机制 | POSIX (Linux/Mac) | Windows | FreeRTOS / RT-Thread |
|------|-------------------|---------|----------------------|
| 互斥锁 | `pthread_mutex_t` | `CRITICAL_SECTION` / `Mutex` | `SemaphoreHandle_t`(Mutex) |
| 条件变量 | `pthread_cond_t` | `CONDITION_VARIABLE` | 用任务通知 / 二值信号量模拟 |
| 读写锁 | `pthread_rwlock_t` | `SRWLOCK` | 一般无，用互斥代替 |
| 信号量 | `sem_t` | `Semaphore` | `xSemaphoreCreateCounting` |
| 自旋锁 | `pthread_spinlock_t` | 无（用户态少用） | 取决于芯片（SMP 才有意义） |

嵌入式 RTOS 中更常用的是**任务通知（Task Notification）**或**消息队列（Queue）**，它们比条件变量更轻量、中断中也可用。

## 扩展问题

面试官可能会追问：
- 条件变量为什么必须配合 Mutex 使用？（避免"检查-等待"之间的竞态）
- 互斥锁怎么实现优先级继承？（解锁前若被高优先级线程阻塞，临时提升持锁者优先级）
- 线程安全一定要加锁吗？（原子操作、无锁数据结构、thread_local）
- `volatile` 能保证线程安全吗？（不能，它只防编译器优化，不保证多核可见性和原子性）
