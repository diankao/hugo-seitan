# 互斥锁原理与原子操作

## 参考答案
### 1. 互斥锁原理

**互斥锁定义：**
互斥锁（Mutex）是一种同步机制，用于保护共享资源，确保同一时刻只有一个任务可以访问被保护的资源。

**互斥锁工作原理：**

1. **获取锁（Lock）**：
   - 任务尝试获取锁
   - 如果锁未被占用，任务获得锁并继续执行
   - 如果锁已被占用，任务进入阻塞状态等待

2. **释放锁（Unlock）**：
   - 任务完成对共享资源的访问后释放锁
   - 如果有等待任务，唤醒其中一个高优先级任务

**互斥锁特性：**
- **互斥性**：同一时刻只能有一个持有者
- **所有权**：只有锁的持有者才能释放锁
- **优先级继承**：防止优先级反转
- **递归锁**：同一任务可多次获取同一个锁

**FreeRTOS互斥锁实现：**
```c
SemaphoreHandle_t xMutex;

// 创建互斥锁
xMutex = xSemaphoreCreateMutex();

// 获取锁
if (xSemaphoreTake(xMutex, portMAX_DELAY) == pdTRUE) {
    // 访问共享资源
    critical_section();
    
    // 释放锁
    xSemaphoreGive(xMutex);
}
```

**互斥锁底层实现：**
```c
typedef struct {
    TaskHandle_t xTaskHolder;        // 锁的持有者
    UBaseType_t uxRecursiveCount;    // 递归计数
    List_t xTasksWaitingToReceive;   // 等待获取锁的任务链表
} StaticSemaphore_t;

BaseType_t xSemaphoreTake(SemaphoreHandle_t xSemaphore, TickType_t xTicksToWait) {
    // 检查是否递归锁且为当前任务持有
    if (pxQueue->uxQueueType == queueQUEUE_IS_MUTEX && 
        pxQueue->pxMutexHolder == xTaskGetCurrentTaskHandle()) {
        pxQueue->uxRecursiveCount++;
        return pdPASS;
    }
    
    // 尝试获取锁
    if (pxQueue->uxMessagesWaiting > 0) {
        pxQueue->pxMutexHolder = xTaskGetCurrentTaskHandle();
        pxQueue->uxMessagesWaiting--;
        return pdPASS;
    }
    
    // 锁被占用，进入等待状态
    vTaskPlaceOnEventList(&pxQueue->xTasksWaitingToReceive, xTicksToWait);
    taskYIELD();
    
    return pdFAIL;
}
```

### 2. 原子操作

**原子操作定义：**
原子操作是指在执行过程中不会被中断机制打断的操作，要么全部执行成功，要么完全不执行。

**原子操作特点：**
- **不可分割**：操作过程中不会被其他线程打断
- **无锁同步**：不使用互斥锁也能保证数据一致性
- **高效性**：避免了锁的开销和上下文切换

**常见原子操作：**

1. **原子读（Atomic Read）**：
   ```c
   static inline int atomic_read(const atomic_t *v) {
       return v->counter;
   }
   ```

2. **原子写（Atomic Write）**：
   ```c
   static inline void atomic_set(atomic_t *v, int i) {
       v->counter = i;
   }
   ```

3. **原子加（Atomic Add）**：
   ```c
   static inline int atomic_add_return(int i, atomic_t *v) {
       int result;
       __asm__ __volatile__(
           "lock; xaddl %0, %1"
           : "+r" (i), "+m" (v->counter)
           : : "memory", "cc"
       );
       return i + v->counter;
   }
   ```

4. **原子比较交换（CAS - Compare And Swap）**：
   ```c
   static inline int atomic_cmpxchg(atomic_t *ptr, int old, int new_val) {
       int prev;
       __asm__ __volatile__(
           "lock; cmpxchgl %2, %1"
           : "=a" (prev), "+m" (ptr->counter)
           : "r" (new_val), "0" (old)
           : "memory", "cc"
       );
       return prev;
   }
   ```

**基于原子操作实现的自旋锁：**
```c
typedef struct {
    volatile int locked;
} spinlock_t;

void spin_lock(spinlock_t *lock) {
    while (atomic_cmpxchg(&lock->locked, 0, 1) != 0) {
        // 自旋等待
        __asm__ __volatile__("pause");
    }
}

void spin_unlock(spinlock_t *lock) {
    atomic_set(&lock->locked, 0);
}
```

**基于原子操作实现的互斥锁：**
```c
typedef struct {
    volatile atomic_t state;
    TaskHandle_t owner;
    int count;
} atomic_mutex_t;

#define MUTEX_UNLOCKED 0
#define MUTEX_LOCKED 1

int atomic_mutex_lock(atomic_mutex_t *mutex) {
    int expected = MUTEX_UNLOCKED;
    
    // 尝试原子获取锁
    if (atomic_cmpxchg(&mutex->state, expected, MUTEX_LOCKED) == expected) {
        mutex->owner = xTaskGetCurrentTaskHandle();
        mutex->count = 1;
        return 0;
    }
    
    // 锁已被占用，检查是否为递归
    if (mutex->owner == xTaskGetCurrentTaskHandle()) {
        mutex->count++;
        return 0;
    }
    
    // 进入阻塞状态（需要RTOS支持）
    return -1;
}

int atomic_mutex_unlock(atomic_mutex_t *mutex) {
    if (mutex->owner != xTaskGetCurrentTaskHandle()) {
        return -1;  // 不是锁的持有者
    }
    
    if (--mutex->count == 0) {
        mutex->owner = NULL;
        atomic_set(&mutex->state, MUTEX_UNLOCKED);
    }
    
    return 0;
}
```

**ARM Cortex-M原子操作实现：**
```c
static inline uint32_t atomic_load(volatile uint32_t *ptr) {
    uint32_t value;
    __asm__ volatile("ldrex %0, [%1]" : "=r"(value) : "r"(ptr));
    return value;
}

static inline int atomic_store(volatile uint32_t *ptr, uint32_t value) {
    uint32_t result;
    __asm__ volatile(
        "strex %0, %2, [%1]"
        : "=&r"(result) : "r"(ptr), "r"(value) : "memory"
    );
    return result == 0;
}
```

### 3. 原子操作 vs 互斥锁

| 特性 | 原子操作 | 互斥锁 |
|------|---------|--------|
| 性能 | 高（无锁） | 较低（有开销） |
| 复杂性 | 简单操作 | 支持复杂临界区 |
| 阻塞 | 自旋等待 | 任务阻塞 |
| 适用场景 | 简单计数器、标志位 | 复杂数据结构、长时间操作 |
| 优先级反转 | 无 | 需要优先级继承 |

### 4. 应用场景选择

**使用原子操作：**
- 简单计数器（如任务统计）
- 标志位设置和清除
- 单个变量的读写
- 短时间的临界区

**使用互斥锁：**
- 复杂数据结构保护（链表、队列）
- 长时间的临界区操作
- 需要任务阻塞等待的场景
- 需要优先级继承的场景
