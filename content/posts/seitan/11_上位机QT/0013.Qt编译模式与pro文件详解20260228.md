# Qt编译模式与pro文件详解

## 题目

Qt中debug、release、profile三种编译模式有什么区别？pro文件的主要配置项有哪些？

## 答案

### 三种编译模式对比

**Debug模式：**
- 编译后可执行文件很大
- 包含调试符号信息
- 开启所有断言
- 性能差，运行慢
- 适合开发调试

**Release模式：**
- 编译后可执行文件很小
- 不包含调试符号信息
- 关闭所有断言
- 经过各种优化，性能最好
- 适合发布程序

**Profile模式：**
- 文件大小介于debug和release之间
- 包含部分调试符号信息
- 兼顾性能和调试
- 性能比debug好，方便调试

```cpp
class BuildModeTest : public QObject {
    Q_OBJECT

public:
    BuildModeTest(QObject *parent = nullptr) : QObject(parent) {}

    void testBuildMode() {
        QElapsedTimer timer;

    }
```

### pro文件基本配置

```qmake
# 项目名称
TARGET = MyApplication

# 项目类型
TEMPLATE = app

# 引入Qt模块
QT += core gui widgets network sql

# 超过Qt4需要widgets模块
greaterThan(QT_MAJOR_VERSION, 4): QT += widgets

# 定义宏
DEFINES += QT_NO_DEBUG_OUTPUT

# 头文件
HEADERS += \
    mainwindow.h \
    dialog.h

# 源文件
SOURCES += \
    main.cpp \
    mainwindow.cpp \
    dialog.cpp

# UI文件
FORMS += \
    mainwindow.ui \
    dialog.ui

# 资源文件
RESOURCES += \
    resources.qrc

# 动态库链接
LIBS += -L$$PWD/lib -lavformat -lavcodec

# 目标输出目录
DESTDIR = $$PWD/bin

# 临时文件目录
MOC_DIR = temp/moc
RCC_DIR = temp/rcc
UI_DIR = temp/ui
OBJECTS_DIR = temp/obj

# 包含路径
INCLUDEPATH += $$PWD/include

# 编译配置
CONFIG += c++11
CONFIG += warn_off
```

### Debug和Release配置

```qmake
# Debug模式下添加d后缀
CONFIG(debug, debug|release) {
    win32:      TARGET = $$join(TARGET,,,d)
    mac:        TARGET = $$join(TARGET,,,_debug)
    unix:!mac:  TARGET = $$join(TARGET,,,d)
}

# 判断当前模式
CONFIG(debug, debug|release) {
    message("Building in debug mode")
    DEFINES += DEBUG_MODE
}

CONFIG(release, debug|release) {
    message("Building in release mode")
    DEFINES += RELEASE_MODE
}
```

### 引入pri模块文件

```qmake
# ui.pri文件内容
HEADERS += \
    $$PWD/mainwindow.h \
    $$PWD/dialog.h

SOURCES += \
    $$PWD/mainwindow.cpp \
    $$PWD/dialog.cpp

FORMS += \
    $$PWD/mainwindow.ui \
    $$PWD/dialog.ui

# 在主pro文件中引入
include($$PWD/ui/ui.pri)
INCLUDEPATH += $$PWD/ui
```

### 条件编译

```qmake
# Windows平台
win32 {
    SOURCES += windows_specific.cpp
    DEFINES += WINDOWS_OS
}

# Linux平台
unix {
    SOURCES += linux_specific.cpp
    DEFINES += LINUX_OS
}

# macOS平台
macx {
    SOURCES += mac_specific.cpp
    DEFINES += MAC_OS
}

# ARM平台
contains(QT_ARCH, arm) {
    DEFINES += ARM_PLATFORM
}

# 32位系统
contains(QT_ARCH, i386) {
    DEFINES += X86_PLATFORM
}

# 64位系统
contains(QT_ARCH, x86_64) {
    DEFINES += X64_PLATFORM
}

# Qt版本判断
greaterThan(QT_MAJOR_VERSION, 4) {
    greaterThan(QT_MINOR_VERSION, 11) {
        message("Qt version >= 5.12")
    }
}

# 编译器判断
msvc {
    message("Using MSVC compiler")
    DEFINES += USE_MSVC
}

mingw {
    message("Using MinGW compiler")
    DEFINES += USE_MINGW
}
```

### 自定义编译配置

```qmake
# 禁用qdebug打印输出
DEFINES += QT_NO_DEBUG_OUTPUT

# 关闭编译警告提示
CONFIG += warn_off

# 启用C++11
greaterThan(QT_MAJOR_VERSION, 4): CONFIG += c++11

# 大资源文件支持
CONFIG += resources_big

# 静态编译
CONFIG += static

# 动态编译
CONFIG += shared

# UNICODE支持
DEFINES += UNICODE
DEFINES += _UNICODE
```

### 编译前后操作

```qmake
# 编译前执行
QMAKE_PRE_LINK += copy /Y $$PWD/config.ini $$DESTDIR

# 编译后执行
QMAKE_POST_LINK += copy /Y $$PWD/*.dll $$DESTDIR

# Windows路径转换
srcFile = $$PWD/1.txt
srcFile ~= s,/,\\,g
dstPath = $$PWD/bin
dstPath ~= s,/,\\,g

QMAKE_POST_LINK += copy /Y $$srcFile $$dstPath
```

### 版本信息设置

```qmake

VERSION = 2025.10.01

QMAKE_TARGET_COMPANY = MyCompany
```

### 动态库配置

```qmake
# 动态库项目
TEMPLATE = lib

# 库文件名
TARGET = MyLibrary

# 库版本
VERSION = 1.0.0

# 定义导出宏
DEFINES += MYLIBRARY_LIBRARY

# API宏定义
DEFINES += QT_NO_CAST_FROM_ASCII

# 导出符号
DEFINES += QT_DEPRECATED_WARNINGS
```

### 插件配置

```qmake
# 插件项目
TEMPLATE = lib
CONFIG += plugin

# 插件类型
QT += widgets

# 插件元数据
CONFIG += c++11

# 目标路径
DESTDIR = $$PWD/plugins
```

### 总结

**三种编译模式：**
- Debug：包含调试信息，性能差，适合开发
- Release：无调试信息，性能最好，适合发布
- Profile：部分调试信息，性能和调试平衡

**pro文件主要配置：**
- TARGET：目标文件名
- TEMPLATE：项目类型
- QT +=：引入Qt模块
- HEADERS/SOURCES：头文件和源文件
- FORMS：UI文件
- RESOURCES：资源文件
- LIBS：链接库
- DEFINES：宏定义
- CONFIG：编译配置

**最佳实践：**
- 使用pri文件分模块管理
- Debug模式添加d后缀
- 设置合理的临时文件目录
- 使用条件编译处理平台差异
- 合理设置包含路径和库路径
