# Qt C++ 项目构建、部署与验收工作清单

## 说明

按工作流顺序排列的实操清单，从建项目到发布验收。其中 **B 段和 D 段**专治"Creator 里好好的、打包就坏"的问题。

## A. 项目结构（一开始就定好）

- [ ] 源码目录与构建目录分离（影子构建），build 产物绝不进源码树
- [ ] 目录分层固定：`src/`（源码）、`resources/`（qrc、图片、图标）、`third_party/`（第三方库）、`tools/`（脚本）、`dist/`（打包输出）
- [ ] 所有资源文件进 `.qrc`，代码里用 `:/path/to/res` 访问
- [ ] 确实无法进 qrc 的大文件（视频、数据库模板）放 `resources/` 下，并集中在一个 `paths.h` / `Paths` 类里定义查找逻辑，禁止散落各处的相对路径

## B. 资源与路径规范（防"Creator 能跑、双击就崩"）

- [ ] 全局搜索 `QDir::currentPath()`、`QFileInfo(".")`——逐个替换为 `QCoreApplication::applicationDirPath()`
- [ ] 检查所有字符串形式的相对路径（`"images/…"`、`"config.ini"`），确认都基于 applicationDirPath 或 qrc
- [ ] 不依赖 `QT_PLUGIN_PATH`、`QML2_IMPORT_PATH` 等环境变量（Creator 注入的这些是假象）
- [ ] 日志/配置写入位置用 `QStandardPaths`（AppData），不写 exe 目录（安装到 Program Files 后没有写权限）

## C. 构建配置（保证命令行 = Creator）

- [ ] CMakeLists.txt 顶部注释明确 `CMAKE_PREFIX_PATH`，或提供 `CMakePresets.json` 固定 Kit（MSVC/MinGW、Qt 版本、架构）
- [ ] Debug/Release 明确区分，第三方库按配置链接对应的 debug/release 版本
- [ ] `AUTOMOC` / `AUTORCC` / `AUTOUIC` 开启，检查所有含 `Q_OBJECT` 的头文件都在目标源列表里（防 `vtable` 链接错误）
- [ ] 提供 `build.bat` 或一条命令说明，让 agent 和人用完全相同的命令构建
- [ ] 把编译器版本写进 README，避免多 Kit 机器上 cmake 猜错

## D. 开发期自检（每次大改后跑一遍）

- [ ] 不通过 Creator，直接在 build 目录双击 exe（或 `start exe`）跑一次——这是发现环境变量依赖的最快方法
- [ ] 用 Creator 的 Projects → Run → Working directory 改成 exe 目录再跑一次，对比行为
- [ ] 清空 build 目录全量重编一次（`cmake --fresh` / 直接删目录），确认没有依赖旧产物的隐式状态
- [ ] 运行时设 `QT_DEBUG_PLUGINS=1` 跑一次，看有没有静默加载失败的插件

## E. 打包部署（发布前）

- [ ] 用 windeployqt 从**干净构建**的 exe 开始部署，不手工东拷西拷
- [ ] QML 项目：`windeployqt --qmldir <源码qml目录>` 指定 qmldir 扫描
- [ ] 检查插件子目录结构完整：`platforms/`、`imageformats/`、`sqldrivers/`、`styles/` 等保持目录层级，不平铺
- [ ] MSVC：确认 VC 运行库方式（`/MD` + 装 redist，或静态链接）
- [ ] MinGW：确认 MinGW 运行时 DLL（libgcc、libstdc++、libwinpthread）已随包
- [ ] Debug/Release 的 Qt DLL 不混包（Release 发布不带 `d.dll`）
- [ ] 如果布局自定义，检查 qt.conf 的 Plugins/Prefix 路径

## F. 干净机器验收（最后一关）

- [ ] 在没装 Qt 的机器/虚机上解压运行，全功能过一遍
- [ ] 重点测：图片格式（用到 jpeg 才有部署）、数据库驱动、翻译加载、高 DPI、中文路径安装
- [ ] 路径含空格和中文时安装运行一次（`Program Files (x86)` 这类路径）
- [ ] 首次启动写配置、第二次启动读配置（权限问题）

## G. 交给 AI 代理协作时的约定

- [ ] README 写明：Kit 名称、构建命令、运行方式、打包命令
- [ ] agent 修完必须执行"双击 exe 直接跑"这一步，不能只看 Creator 里正常
- [ ] 改动涉及资源/插件/部署时，必须重新跑 E 段而不是增量拷贝
- [ ] `.gitignore` 覆盖 build 目录，但 `CMakePresets.json`、`build.bat`、打包脚本入库

## 记忆锚点

- **B 段**（路径规范）和 **D 段**（双击直跑）是性价比最高的两段，前者防病、后者快速验病
- 打包工具（PyInstaller/windeployqt）会强迫分层，因为不分层打包就炸；纯跑脚本的工程没有任何东西逼你分层，烂结构也能一直跑下去——所以**清单要主动执行**，不能指望环境倒逼
