# 在Qt5的信号处理中如何使用lambda机制

## 题目

在 Qt5 的信号处理中如何使用 lambda 机制？可以给出代码示例吗？

## 考察点

Qt5 connect 的新语法（lambda 作为槽）、lambda 槽的典型使用场景、接收者上下文对象与生命周期保护、跨线程连接的行为。

## 回答要点

### 1. Qt5 connect 的三种写法

| 写法 | 示例 | 特点 |
|------|------|------|
| 旧宏语法（Qt4） | `connect(obj, SIGNAL(sig(int)), this, SLOT(slot(int)))` | 字符串签名，错误到运行期才暴露 |
| 成员函数指针（Qt5） | `connect(obj, &Obj::sig, this, &Cls::slot)` | 编译期检查签名 |
| lambda/仿函数（Qt5） | `connect(obj, &Obj::sig, this, [this](int v){...})` | 可携带捕获状态，逻辑就地展开 |

槽的位置本质上要求一个"可调用对象"，lambda 天然满足，所以**信号定义好了，可以不写对应的槽函数，直接把逻辑写在槽的位置**：

```cpp
connect(button, &QPushButton::clicked, this, [this] {
    ui->label->setText("clicked");
});
```

lambda 的参数可以比信号少（`clicked` 信号带的 `bool checked` 不接也行），但不能多、类型要匹配。

### 2. 为什么 lambda 槽成了主流：三大场景

**场景一：给信号"补参数"，一槽多用。** 信号不带业务参数、但每个调用点需要的参数不同时，lambda 用捕获把参数带进去：

```cpp
// 10 个按钮对应 10 个频道：循环里捕获各自的 i
for (int i = 0; i < 10; ++i) {
    auto *btn = new QPushButton(QString("频道 %1").arg(i), this);
    connect(btn, &QPushButton::clicked, this, [this, i] {
        switchChannel(i);       // i 是捕获来的，信号本身没传
    });
}
```

Qt4 时代做这件事要写 10 个槽函数，或借助 `QSignalMapper`；而 `QSignalMapper` 已在 Qt 5.15 被官方废弃，**推荐的替代方案就是 lambda**——官方盖章的迁移方向。

**场景二：短小的一次性逻辑。** 三五行代码不值得起函数名塞进类里（避免头文件里堆满 `onBtnXxx` 这类一次性槽），就地写完就地结束：

```cpp
connect(ui->btnRefresh, &QPushButton::clicked, this, [this] {
    ui->statusBar->showMessage("刷新中...");
    refreshData();
    ui->statusBar->showMessage("完成", 2000);
});
```

**场景三：异步/延时回调。** 网络回复、一次性定时器是最自然的 lambda 位置：

```cpp
connect(reply, &QNetworkReply::finished, this, [this, reply] {
    ui->textEdit->setPlainText(reply->readAll());
    reply->deleteLater();
});

QTimer::singleShot(3000, this, [this] { ui->splash->close(); });
```

### 3. 最重要的坑：接收者上下文对象（context object）

lambda 槽的 connect 有两种形式，安全性天差地别：

```cpp
connect(timer, &QTimer::timeout,
        [this] { doWork(); });                       // 危险：没有 context 对象

connect(timer, &QTimer::timeout,
        this, [this] { doWork(); });                 // 正确：this 作为 context
```

第三个参数 `this` 在 lambda 槽的语境里叫**上下文对象**，它提供两个保证：

1. **生命周期保护**：context 对象析构时，Qt 自动断开这条连接。没有它，lambda 捕获的 `this` 悬垂后信号再触发，就是访问已释放内存的崩溃。
2. **跨线程投递目标**：信号从别的线程发出时，`Qt::AutoConnection` 依据 context 对象**所在线程**决定是排队投递还是直接调用；没有 context 的仿函数连接只能直接调用（相当于 DirectConnection），跨线程信号会直接在工作线程里执行 lambda。

规矩就一条：**lambda 槽永远写上 context 对象**（通常是 `this`）。

### 4. lambda 槽如何断开连接

lambda 没有函数名，不能按 `SLOT()` 名字断连，需要保存 `connect` 的返回值：

```cpp
QMetaObject::Connection conn = connect(timer, &QTimer::timeout, this, [this]{ poll(); });

disconnect(conn);        // 用返回的连接对象断开

// 或者一次性全断：把该信号连接的所有槽断开
disconnect(timer, &QTimer::timeout, nullptr, nullptr);
```

### 5. 原理：lambda 槽就是闭包

槽的本质要求是可调用，lambda 捕获 `i`、`this` 形成闭包对象，connect 内部把它包装成可触发的槽。捕获语义（`[i]` 按值快照、`[this]` 存指针）完全遵循 C++ 闭包规则——循环里捕获要用 `[this, i]` 按值，别用默认捕获 `[=]`/`[&]`，否则 `i` 出作用域即悬垂；`[=]` 对成员变量实际是引用语义（经 this 指针）这类分裂语义与默认捕获的各类陷阱，详见《lambda捕获方式与默认捕获陷阱》。闭包原理详见《闭包的C与C++实现》与《lambda表达式本质与实现机制》。
