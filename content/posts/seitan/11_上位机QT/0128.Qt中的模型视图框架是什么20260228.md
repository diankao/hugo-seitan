# Qt中的模型视图框架是什么

## 题目

列表控件 QListWidget / QTableWidget / QListView 怎么选？大数据量怎么优化？Qt 中的模型视图框架是什么？

## 考察点

- 理解 Qt Model/View 架构的设计思想
- 掌握便利控件（Widget）与框架控件（View）的区别
- 大数据量列表的性能优化手段

## 回答要点

### 1. Qt Model/View 架构概述

Qt 的模型/视图（Model/View）架构将数据存储与数据显示分离，遵循改进的 MVC 模式：

| 角色 | Qt 实现 | 职责 |
|------|---------|------|
| Model（模型） | `QAbstractItemModel` 及子类 | 管理数据，提供统一接口 |
| View（视图） | `QAbstractItemView` 及子类 | 显示数据，处理用户交互 |
| Delegate（委托） | `QAbstractItemDelegate` 及子类 | 控制单项的渲染和编辑方式 |

```mermaid
graph LR
    A[数据源] --> B[Model 模型]
    B --> C[View 视图]
    B --> D[Delegate 委托]
    D --> C
```

### 2. 便利控件 vs 框架控件

Qt 提供了两套列表/表格控件：

| 控件 | 类型 | 内部模型 | 适用场景 |
|------|------|---------|---------|
| `QListWidget` | 便利控件 | 内置 `QListWidgetItem` | 简单列表，数据量小 |
| `QTableWidget` | 便利控件 | 内置 `QTableWidgetItem` | 简单表格，数据量小 |
| `QTreeWidget` | 便利控件 | 内置 `QTreeWidgetItem` | 简单树形，数据量小 |
| `QListView` | 框架控件 | 需要外部 Model | 自定义数据，大数据量 |
| `QTableView` | 框架控件 | 需要外部 Model | 自定义数据，大数据量 |
| `QTreeView` | 框架控件 | 需要外部 Model | 自定义数据，大数据量 |

**选择原则：**
- 数据量小、逻辑简单 → 用 Widget 便利控件（开发快）
- 数据量大、需要自定义 → 用 View + Model 框架控件（性能好）

### 3. 各控件详解

**QListWidget（简单列表）：**

```cpp
QListWidget *list = new QListWidget();
list->addItem("Item 1");
list->addItem("Item 2");
list->addItem(new QListWidgetItem(QIcon(":/icon.png"), "Item 3"));

QListWidgetItem *item = new QListWidgetItem("Custom Item");
item->setData(Qt::UserRole, 42);
item->setForeground(QBrush(Qt::blue));
list->addItem(item);
```

**QTableWidget（简单表格）：**

```cpp
QTableWidget *table = new QTableWidget(4, 3);
table->setHorizontalHeaderLabels({"Name", "Age", "City"});

table->setItem(0, 0, new QTableWidgetItem("Alice"));
table->setItem(0, 1, new QTableWidgetItem("25"));
table->setItem(0, 2, new QTableWidgetItem("Beijing"));

table->setEditTriggers(QAbstractItemView::DoubleClicked);
table->setAlternatingRowColors(true);
table->setSortingEnabled(true);
```

**QListView + 自定义 Model（框架方式）：**

```cpp
QStringListModel *model = new QStringListModel();
model->setStringList({"Apple", "Banana", "Cherry"});

QListView *view = new QListView();
view->setModel(model);

QItemSelectionModel *selModel = view->selectionModel();
connect(selModel, &QItemSelectionModel::currentChanged,
        [](const QModelIndex &current, const QModelIndex &) {
    qDebug() << "Selected:" << current.data().toString();
});
```

### 4. 大数据量优化方案

**问题：** Widget 类控件（QListWidget/QTableWidget）为每个 Item 创建一个对象，数据量大时内存占用高、初始化慢。

**方案一：使用 Model/View 框架替代 Widget**

```cpp
class LargeDataModel : public QAbstractTableModel {
    Q_OBJECT

public:
    LargeDataModel(const QVector<QStringList> &data, QObject *parent = nullptr)
        : QAbstractTableModel(parent), m_data(data) {}

    int rowCount(const QModelIndex &) const override {
        return m_data.size();
    }

    int columnCount(const QModelIndex &) const override {
        return m_data.isEmpty() ? 0 : m_data[0].size();
    }

    QVariant data(const QModelIndex &index, int role) const override {
        if (!index.isValid() || role != Qt::DisplayRole)
            return QVariant();
        return m_data[index.row()][index.column()];
    }

    QVariant headerData(int section, Qt::Orientation orientation,
                        int role) const override {
        if (role != Qt::DisplayRole || orientation != Qt::Horizontal)
            return QVariant();
        static const QStringList headers = {"Name", "Age", "City"};
        return headers.value(section);
    }

private:
    QVector<QStringList> m_data;
};

QVector<QStringList> data;
for (int i = 0; i < 100000; ++i) {
    data.append({QString("User %1").arg(i),
                 QString::number(20 + i % 50),
                 "City"});
}

LargeDataModel *model = new LargeDataModel(data);
QTableView *view = new QTableView();
view->setModel(model);
```

**方案二：按需加载数据（canFetchMore / fetchMore）**

```cpp
class PagedModel : public QAbstractTableModel {
    Q_OBJECT

public:
    PagedModel(QObject *parent = nullptr)
        : QAbstractTableModel(parent), m_loadedRows(0), m_pageSize(100) {}

    int rowCount(const QModelIndex &) const override {
        return m_loadedRows;
    }

    int columnCount(const QModelIndex &) const override { return 3; }

    QVariant data(const QModelIndex &index, int role) const override {
        if (!index.isValid() || role != Qt::DisplayRole)
            return QVariant();
        return QString("Row %1 Col %2").arg(index.row()).arg(index.column());
    }

    bool canFetchMore(const QModelIndex &) const override {
        return m_loadedRows < totalRowCount();
    }

    void fetchMore(const QModelIndex &) override {
        int remaining = totalRowCount() - m_loadedRows;
        int toFetch = qMin(remaining, m_pageSize);
        beginInsertRows(QModelIndex(), m_loadedRows, m_loadedRows + toFetch - 1);
        m_loadedRows += toFetch;
        endInsertRows();
    }

private:
    int totalRowCount() const { return 1000000; }
    int m_loadedRows;
    int m_pageSize;
};
```

**方案三：其他优化手段**

| 优化手段 | 说明 | 代码 |
|---------|------|------|
| `setUniformRowHeights(true)` | 告知视图行高一致，跳过高度计算 | `view->setUniformRowHeights(true)` |
| `setViewportMargins` | 固定表头区域，减少重绘 | 适用于自定义表头 |
| 批量插入 | 使用 `beginInsertRows` / `endInsertRows` | 避免逐行 `addItem` |
| 延迟排序 | 数据加载完毕后再 `setSortingEnabled(true)` | 避免每次插入都排序 |
| 关键字过滤 | Model 层实现 `QSortFilterProxyModel` | 不修改源数据 |
| 异步加载 | 后台线程加载数据，完成后通知 Model | 避免阻塞 UI 线程 |

```cpp
QSortFilterProxyModel *proxy = new QSortFilterProxyModel();
proxy->setSourceModel(model);
proxy->setFilterKeyColumn(0);
proxy->setFilterCaseSensitivity(Qt::CaseInsensitive);

view->setModel(proxy);
proxy->setFilterFixedString("search text");
```

### 5. 三种列表控件对比总结

| 对比维度 | QListWidget | QTableWidget | QListView + Model |
|---------|-------------|-------------|-------------------|
| 使用难度 | 简单 | 简单 | 中等 |
| 数据存储 | 内置 Item 对象 | 内置 Item 对象 | 外部 Model 管理 |
| 适合数据量 | < 1000 行 | < 1000 行 | 无上限（按需加载） |
| 自定义渲染 | 需要子类化 Item | 需要子类化 Item | 通过 Delegate |
| 排序/过滤 | 内置简单排序 | 内置排序 | QSortFilterProxyModel |
| 内存效率 | 低（每项一个对象） | 低 | 高（按需生成） |
| 编辑支持 | 内置 | 内置 | 通过 Delegate |
| 灵活性 | 低 | 低 | 高 |

**面试建议：** 回答时先说明 Widget 和 View 的区别，然后强调大数据量场景必须用 Model/View 框架，再补充 `canFetchMore` 按需加载和 `QSortFilterProxyModel` 过滤排序两种优化手段。
