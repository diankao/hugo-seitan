# ASLR 地址空间随机化与绕过手段

ASLR（Address Space Layout Randomization）让进程的栈、堆、库加载基址每次运行都不同，使漏洞利用无法假定关键地址。本文整理 ASLR 的工作机制、哪些绕过思路真实有效，以及为什么 ROP 本身并不构成对 ASLR 的绕过。

## ASLR 机制

内核把用户态各内存区域的加载基址随机化，使攻击者无法假定关键数据/代码的地址：

- 开关：`/proc/sys/kernel/randomize_va_space`（0 关闭 / 1 保守：栈与库 / 2 完全：栈+库+堆+vdso）；
- 编译配合：PIE（位置无关可执行文件）让主程序基址也可随机化；
- 每次 exec 重新随机（fork 继承父进程布局，exec 才重掷）。

## 真实有效的绕过思路

**信息泄漏**——最主流的绕过：借助未初始化内存、格式化字符串等漏洞读出 libc 某函数地址，推算库基址，再计算 `system()` 等目标地址。

**爆破低熵区域**——熵取决于位数：32 位下 mmap 基址熵只有 8~12 位，几百次尝试就能命中；64 位熵 28 位以上，爆破代价高，但 fork 型服务（子进程布局不变）依然可以逐次试探。

**直接关闭随机化**——`echo 0 > /proc/sys/kernel/randomize_va_space`（需要 root）或 `setarch -R`，属于"环境不设防"。

## 为什么 ROP 不是 ASLR 的绕过

ROP（Return-Oriented Programming）把栈上返回地址串成 gadget 链，复用二进制内现有代码片段——它的发明是为了绕过 **NX/DEP**（栈不可执行）。

ROP 的前提是**知道 gadget 的确切地址**。ASLR 开启时，库与程序的基址每次运行都变，gadget 地址不"固定"，ROP 链拼不起来。所以：

- ROP ≠ 绕过 ASLR；
- 正确组合是"信息泄漏拿到基址 → ROP 完成利用"，泄漏才是绕过 ASLR 的那一步。

## 纵深防御组合

单靠 ASLR 不够，实际防护是组合拳：

| 机制 | 防什么 |
| --- | --- |
| ASLR + PIE | 地址不可预测 |
| DEP/NX（栈不可执行） | 注入的 shellcode 跑不起来 |
| Stack Canary | 覆盖返回地址前先踩中哨兵值 |
| Full RELRO / GOT 只读 | 劫持 GOT 表 |

攻防就是这样螺旋上升的：NX 逼出 ROP，ASLR 逼出信息泄漏，于是防御继续加 canary、RELRO、CFI。
