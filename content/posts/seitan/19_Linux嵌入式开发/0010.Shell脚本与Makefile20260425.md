# Shell脚本与Makefile

## 题目

围绕 Linux Shell 基础与构建脚本的系列问题：

1. Shell 变量的命名和赋值有哪些规则？等号两边可以有空格吗？
2. 文件权限数字 741 对应的权限字符串是什么？rwx 和数字怎么互相换算？
3. Shell 脚本和 Makefile 各有哪些最高频的语法要素？

## 考察点

Shell 变量的命名与赋值规则（尤其"等号两边不能有空格"）、Linux 文件权限的八进制表示与 rwx 字符串的换算、Shell 脚本与 Makefile 的基本语法要素。

## 回答要点

### 1. Shell 变量的命名与赋值规则

命名规则：

- 只能使用**英文字母、数字和下划线**，不能使用标点符号（`-`、`$`、`.` 等）；
- **首个字符不能是数字**，可以是字母或下划线（`_count`、`var1` 合法，`1var` 非法）；
- **不能与 bash 关键字**（`if`、`then`、`for`、`while`、`case` 等）**重名**。

赋值规则：

- **等号两边绝不能有空格**：`name = "tom"` 会被解释成"执行 name 命令，参数是 = 和 tom"，这是 shell 与 C/Python 最容易踩的差异；`name="tom"` 才是赋值；
- 使用变量用 `$name` 或推荐形式 `${name}`，拼接时后者不会有歧义（`echo "${name}s"`）；
- 单引号内不展开变量，双引号内展开：`'I am $name'` 原样输出，`"I am $name"` 输出变量值。

```bash
name="tom"
count=10
_pid=$$

echo ${name}
readonly name
name="jerry"
```

一个反向的坑：赋值时等号两边不能有空格，但 `test` 表达式里 `=` 作为比较运算符**两边必须有空格**（`[ "$a" = "$b" ]`），两套语境正好相反。

### 2. 文件权限数字 741 的换算

三位八进制数字分别对应**属主（u）、属组（g）、其他人（o）**三组权限，每位是 rwx 的权值和：

| 权限 | r（read，读） | w（write，写） | x（execute，执行） |
|------|------|------|------|
| 权值 | 4 | 2 | 1 |

741 逐位拆开：

| 位 | 数字 | 拆解 | 权限串 |
|----|------|------|--------|
| 属主 | 7 | 4+2+1 = r+w+x | `rwx` |
| 属组 | 4 | 4 = r | `r--` |
| 其他人 | 1 | 1 = x | `--x` |

合并起来就是 `rwxr----x`。

对应的修改命令两种写法等价：

```bash
chmod 741 file
chmod u=rwx,g=r,o=x file
```

常用权限速记：

| 数字 | 含义 | 典型用途 |
|------|------|---------|
| 755 | 属主全权，其他人读+执行 | 目录、可执行脚本 |
| 644 | 属主读写，其他人只读 | 普通配置文件 |
| 600 | 仅属主读写 | 私钥、敏感配置 |
| 777 | 所有人全权 | 临时测试（生产环境避免） |

### 3. Shell 脚本常用语法速查

开发中最高频的几块：

| 类别 | 写法 | 说明 |
|------|------|------|
| 特殊变量 | `$0` `$1` `$#` `$@` `$?` | 脚本名/第 1 参数/参数个数/全部参数/上条命令退出码 |
| 条件判断 | `if [ -f "$f" ]; then ... fi` | 方括号两边必须有空格 |
| 循环 | `for f in *.c; do ... done` | 遍历文件常用 |
| 命令替换 | `files=$(ls)` 或反引号 | 把命令输出存进变量 |
| 管道与重定向 | `cmd 2>&1 | tee log.txt` | 标准错误并入标准输出同时落盘 |
| 后台执行 | `./app &`、`nohup ./app &` | 脱离终端长期运行 |

### 4. Makefile 核心要素

嵌入式开发中 Makefile 主要记住"一条规则 + 三个要素"：

```makefile
target: dependencies
	command

app: main.o utils.o
	gcc -o app main.o utils.o

main.o: main.c utils.h
	gcc -c main.c

clean:
	rm -f *.o app
```

| 要素 | 说明 |
|------|------|
| 目标（target） | 要生成的文件名，或伪目标（`clean`） |
| 依赖（dependencies） | 生成目标所依赖的文件 |
| 命令（command） | 必须**以 Tab 开头**，这是 Makefile 最著名的坑 |
| 变量 | `CC = gcc`，引用 `$(CC)` |
| 伪目标 | `.PHONY: clean`，避免与同名文件冲突 |
| 自动变量 | `$@`（目标）、`$<`（第一个依赖）、`$^`（全部依赖） |

Makefile 判断依据是**文件时间戳**：依赖比目标新才重新生成，这既是增量编译的效率来源，也是"改了头文件没重编"类问题的根源。

### 5. 小结

- Shell 变量：等号两边**不能有空格**，命名只能字母/数字/下划线且不能数字开头（首字符可以是下划线），不能用标点和关键字；
- 权限换算：`r=4、w=2、x=1`，741 = 属主 rwx + 属组 r + 其他人 x = `rwxr----x`；
- Shell 与 C 风格差异最大的两点：赋值无空格、测试表达式 `[ ]` 内有空格；Makefile 命令行必须 Tab 开头。
