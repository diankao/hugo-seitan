# Linux设备树Device Tree

## 题目

1. Linux 设备树是什么？为什么要引入设备树？
2. I2C 设备在设备树里怎么配置？
3. 设备树中的 compatible 属性有什么作用？

## 考察点

设备树的基本概念、DTS 语法、I2C 设备配置方法、compatible 匹配机制。

## 回答要点

### 1. 设备树是什么

设备树（Device Tree）是一种**用树形结构描述硬件信息**的数据结构，将硬件描述从内核代码中分离出来。

```
引入前：
  硬件信息硬编码在内核源码中（arch/arm/mach-xxx）
  每个板子都需要修改内核代码 → 代码膨胀

引入后：
  硬件信息放在独立的 .dts 文件中
  内核代码与硬件描述解耦 → 同一内核支持不同板子
```

**编译流程**：

```
.dts（源码）→ dtc（编译器）→ .dtb（二进制）→ U-Boot 传递给内核
```

### 2. 设备树基本语法

```dts
// 设备树是树形结构，根节点为 /
/ {
    // 属性 = 值
    model = "RK3588 ROCK 5B";
    compatible = "radxa,rock-5b", "rockchip,rk3588";

    // 子节点
    cpus {
        cpu0: cpu@0 {
            device_type = "cpu";
            compatible = "arm,cortex-a76";
            reg = <0x0 0x0>;
            clocks = <&scmi_clk 0>;
        };
    };

    // 节点引用（覆盖/扩展已有节点）
    &i2c1 {
        status = "okay";
    };
};
```

### 3. I2C 设备在设备树中的配置

#### 3.1 I2C 控制器节点

```dts
// 通常在 SoC 级别的 .dtsi 中定义
i2c1: i2c@fe150000 {
    compatible = "rockchip,rk3588-i2c";
    reg = <0x0 0xfe150000 0x0 0x1000>;   // 控制器寄存器地址
    clocks = <&cru CLK_I2C1>, <&cru PCLK_I2C1>;
    clock-frequency = <100000>;            // 默认 100kHz
    interrupts = <GIC_SPI 15 IRQ_TYPE_LEVEL_HIGH>;
    #address-cells = <1>;                  // 从地址用 1 个 cell
    #size-cells = <0>;                     // 无长度
    status = "disabled";                   // 默认禁用
};
```

#### 3.2 板级启用 + 挂载 I2C 设备

```dts
// 板级 .dts 中启用控制器并添加设备
&i2c1 {
    status = "okay";                       // 启用 I2C1 控制器
    clock-frequency = <400000>;            // 设为 400kHz（快速模式）

    // 温度传感器
    temperature-sensor@48 {
        compatible = "ti,tmp102";          // 匹配驱动的 of_device_id
        reg = <0x48>;                      // I2C 从地址 0x48
        #thermal-sensor-cells = <1>;
    };

    // 加速度计
    accelerometer@50 {
        compatible = "bosch,bma222";
        reg = <0x50>;
        interrupt-parent = <&gpio0>;
        interrupts = <7 IRQ_TYPE_EDGE_FALLING>;
        vdd-supply = <&vcc_3v3>;
    };

    // EEPROM
    eeprom@57 {
        compatible = "atmel,24c256";
        reg = <0x57>;
        pagesize = <64>;
        size = <32768>;
    };
};
```

#### 3.3 各属性说明

| 属性 | 说明 | 示例 |
|------|------|------|
| `compatible` | 匹配驱动的字符串，必须与驱动中一致 | `"bosch,bma222"` |
| `reg` | I2C 从地址（7位地址） | `<0x50>` |
| `status` | "okay" 启用，"disabled" 禁用 | `"okay"` |
| `clock-frequency` | I2C 总线时钟频率 | `<400000>` |
| `interrupts` | 中断配置 | `<7 IRQ_TYPE_EDGE_FALLING>` |
| `vdd-supply` | 供电 regulator | `<&vcc_3v3>` |

### 4. compatible 匹配机制

```
设备树: compatible = "bosch,bma222"
                │
                ▼ 内核解析设备树
I2C 总线驱动遍历已注册的 i2c_driver
                │
                ▼ 逐个比对 of_device_id
驱动中: .compatible = "bosch,bma222"
                │
                ▼ 匹配成功
调用驱动的 probe 函数
```

```c
// 驱动代码
static const struct of_device_id bma222_of_ids[] = {
    { .compatible = "bosch,bma222" },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, bma222_of_ids);

static struct i2c_driver bma222_driver = {
    .driver = {
        .name = "bma222",
        .of_match_table = bma222_of_ids,
    },
    .probe = bma222_probe,
};
module_i2c_driver(bma222_driver);
```

### 5. 常用调试命令

```bash
# 查看完整设备树
dtc -I fs /sys/firmware/devicetree/base

# 查看某个节点
cat /sys/firmware/devicetree/base/i2c@fe150000/temperature-sensor@48/compatible

# 查看 I2C 总线上的设备
ls /sys/bus/i2c/devices/

# 实时查看设备树变化
ls /proc/device-tree/i2c*/*

# 编译设备树源码
dtc -I dts -O dtb board.dts -o board.dtb
# 反编译
dtc -I dtb -O dts board.dtb -o board.dts
```

### 6. 面试速记

- **设备树**：用树形结构描述硬件，将硬件信息从内核代码中分离
- **I2C 设备配置**：在 I2C 控制器节点下添加子节点，设置 compatible + reg
- **compatible**：驱动匹配的桥梁，设备树中的值必须与驱动的 of_device_id 一致
- **编译**：.dts → dtc → .dtb → U-Boot 传递给内核
- **状态**：status = "okay" 启用，"disabled" 禁用
