# GDB调试与性能分析工具

## 题目

gdb 常用命令有哪些？Linux 下有哪些常用的性能分析和调试工具？

## 考察点

GDB 调试流程、断点/单步/变量查看、Linux 性能分析工具链（strace/perf/valgrind）。

## 回答要点

### 1. GDB 基本调试流程

```bash
# 编译时加 -g 保留调试信息
gcc -g -O0 main.c -o main

# 启动 GDB
gdb ./main

# 附加到运行中的进程
gdb -p $(pidof main)

# 交叉调试（嵌入式）
arm-linux-gnueabihf-gdb ./main
(gdb) target remote /dev/ttyUSB0    # 连接目标板
(gdb) target remote 192.168.1.100:1234  # 网络连接
```

### 2. GDB 常用命令

#### 2.1 断点管理

| 命令 | 缩写 | 说明 |
|------|------|------|
| `break main` | `b main` | 在函数入口设断点 |
| `break file.c:42` | `b file.c:42` | 在指定行设断点 |
| `break file.c:42 if x > 10` | | 条件断点 |
| `info breakpoints` | `i b` | 查看所有断点 |
| `delete 1` | `d 1` | 删除断点 1 |
| `disable 1` | `dis 1` | 禁用断点 1 |
| `enable 1` | `en 1` | 启用断点 1 |
| `clear` | | 清除所有断点 |

#### 2.2 执行控制

| 命令 | 缩写 | 说明 |
|------|------|------|
| `run` | `r` | 从头开始运行 |
| `continue` | `c` | 继续运行到下一个断点 |
| `next` | `n` | 单步（不进入函数） |
| `step` | `s` | 单步（进入函数） |
| `finish` | `fin` | 运行到当前函数返回 |
| `until` | `u` | 运行到循环结束 |
| `advance file.c:100` | | 运行到指定位置 |
| `return` | | 立即从当前函数返回 |

#### 2.3 查看变量和内存

| 命令 | 缩写 | 说明 |
|------|------|------|
| `print x` | `p x` | 打印变量值 |
| `print *ptr` | `p *ptr` | 解引用指针 |
| `print arr[0]@10` | `p arr[0]@10` | 打印数组前 10 个元素 |
| `print/x x` | `p/x x` | 十六进制打印 |
| `display x` | | 每次停止都自动打印 x |
| `info locals` | `i lo` | 查看所有局部变量 |
| `info args` | `i ar` | 查看函数参数 |
| `x/10xw 0x20000000` | | 查看内存（10个十六进制32位值） |
| `x/s str` | | 查看字符串 |
| `ptype struct_name` | | 查看类型定义 |

#### 2.4 栈帧和调用栈

| 命令 | 缩写 | 说明 |
|------|------|------|
| `backtrace` | `bt` | 查看调用栈 |
| `bt full` | | 调用栈 + 所有局部变量 |
| `frame 2` | `f 2` | 切换到第 2 层栈帧 |
| `up` | | 上一层栈帧 |
| `down` | | 下一层栈帧 |
| `info frame` | | 当前栈帧详细信息 |

#### 2.5 多线程调试

| 命令 | 说明 |
|------|------|
| `info threads` | 查看所有线程 |
| `thread 2` | 切换到线程 2 |
| `thread apply all bt` | 所有线程的调用栈 |
| `break file.c:42 thread 3` | 只在线程 3 停 |

### 3. GDB 实战场景

#### 3.1 段错误定位

```bash
# 方法一：直接运行，GDB 会停在崩溃位置
(gdb) run
# Program received signal SIGSEGV, Segmentation fault.
# 0x0000000000400526 in deref_null () at main.c:8

# 方法二：事后分析 core dump
ulimit -c unlimited              # 允许生成 core 文件
./main                           # 运行崩溃，生成 core
gdb ./main core                  # 加载 core dump
(gdb) bt                         # 查看崩溃时的调用栈
```

#### 3.2 远程调试（嵌入式）

```bash
# 目标板上
gdbserver :1234 ./my_app

# 开发机上
arm-linux-gnueabihf-gdb ./my_app
(gdb) target remote 192.168.1.100:1234
(gdb) break main
(gdb) continue
```

### 4. Linux 性能分析工具

#### 4.1 strace：系统调用追踪

```bash
# 追踪程序的所有系统调用
strace ./main

# 只追踪文件相关调用
strace -e trace=file ./main

# 追踪已运行的进程
strace -p $(pidof my_app)

# 统计系统调用耗时
strace -c ./main
```

#### 4.2 perf：性能分析

```bash
# CPU 性能剖析（采样）
perf record -g ./main
perf report                      # 查看结果

# 实时查看热点函数
perf top

# 查看缓存未命中
perf stat -e cache-misses ./main

# 追踪特定函数
perf probe -x ./main 'my_func'
perf record -e probe_main:my_func ./main
```

#### 4.3 valgrind：内存错误检测

```bash
# 内存泄漏检测
valgrind --leak-check=full ./main

# 缓存分析
valgrind --tool=cachegrind ./main

# 线程错误检测
valgrind --tool=helgrind ./main
```

### 5. 工具选择速查

| 需求 | 工具 | 命令 |
|------|------|------|
| 段错误定位 | GDB + core dump | `gdb ./app core` → `bt` |
| 系统调用追踪 | strace | `strace -p PID` |
| CPU 热点分析 | perf | `perf record -g` → `perf report` |
| 内存泄漏 | valgrind | `valgrind --leak-check=full` |
| 查看进程状态 | /proc | `cat /proc/PID/status` |
| 实时监控 | top/htop | `htop -H`（显示线程） |
| 网络抓包 | tcpdump | `tcpdump -i eth0 -w capture.pcap` |

### 6. 面试速记

- **GDB 核心**：`break` 设断点、`run` 运行、`next/step` 单步、`print` 查看变量、`bt` 看调用栈
- **段错误**：`gdb ./app core` + `bt` 一键定位
- **远程调试**：目标板 `gdbserver`，开发机 `gdb` + `target remote`
- **strace**：追踪系统调用，排查 IO/网络/文件问题
- **perf**：CPU 热点分析，`perf record -g` + `perf report`
- **valgrind**：内存泄漏检测，`--leak-check=full`
