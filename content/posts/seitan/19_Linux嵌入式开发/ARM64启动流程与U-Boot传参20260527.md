# ARM64启动流程与U-Boot传参

## 题目

1. RK3588 / ARM64 从上电到 Linux 启动流程是什么？
2. 为什么要先初始化 DDR？
3. U-Boot 会传什么给 Linux 内核？

## 考察点

ARM64 多阶段启动、BootROM → SPL → U-Boot → Linux 的完整链路、DDR 初始化的必要性、U-Boot 与内核的接口。

## 回答要点

### 1. ARM64 完整启动流程

以 RK3588（ARM64 SoC）为例，从上电到 Linux 运行经历以下阶段：

```
① 上电复位
   │
   ▼
② BootROM（芯片内部固化代码）
   │ 从 eMMC/SD/NAND/SPI Flash/UART/USB 加载 SPL
   │
   ▼
③ SPL（Secondary Program Loader，一级引导）
   │ 初始化 DDR、时钟
   │ 加载 U-Boot proper
   │
   ▼
④ U-Boot（二级引导）
   │ 初始化网络/USB/显示等外设
   │ 加载 Linux 内核 + 设备树（.dtb）到内存
   │ 传递参数给内核
   │ 跳转到内核入口
   │
   ▼
⑤ Linux 内核
   │ 解压（如果压缩）
   │ 解析设备树
   │ 初始化内存管理/中断/调度器
   │ 挂载根文件系统
   │ 启动 init 进程（PID=1）
   │
   ▼
⑥ 用户空间
   │ systemd / init 脚本
   │ 启动应用程序
```

### 2. 各阶段详解

#### 2.1 BootROM

芯片出厂时烧录在内部 ROM 中，不可修改。

```c
// BootROM 的工作：
// 1. 配置最基本的时钟（内部 RC 振荡器）
// 2. 根据启动引脚（BOOT_SEL）选择启动介质
// 3. 从启动介质的固定位置读取 SPL 头部
// 4. 校验 SPL（RSA/SHA 签名验证，安全启动时）
// 5. 将 SPL 加载到 SRAM 并跳转
```

**限制**：此时 DDR 还没初始化，SRAM 通常只有几十 KB，所以 SPL 必须很小。

#### 2.2 SPL（Secondary Program Loader）

SPL 运行在 SRAM 中，首要任务是初始化 DDR。

```c
// SPL 的工作流程：
void spl_main(void) {
    // 1. 初始化基本硬件
    clock_init();        // 配置 PLL 和总线时钟
    uart_init();         // 串口（调试输出）

    // 2. 初始化 DDR（最关键！）
    ddr_init();          // 配置 DDR 控制器、训练时序

    // 3. 从存储介质加载 U-Boot 到 DDR
    load_image("u-boot.itb", CONFIG_UBOOT_LOAD_ADDR);

    // 4. 跳转到 U-Boot
    jump_to_image(CONFIG_UBOOT_LOAD_ADDR);
}
```

#### 2.3 U-Boot

U-Boot 运行在 DDR 中，功能丰富得多。

```bash

```

### 3. 为什么要先初始化 DDR

**核心原因**：SRAM 容量太小，无法放下 Linux 内核和设备树。

```
典型 SoC 的存储大小对比：

SRAM（片内）:  几十 ~ 几百 KB    ← 放不下内核
DDR（片外）:   几百 MB ~ 几十 GB  ← 内核通常 5~20 MB

Linux 内核 Image:   ~20 MB（未压缩）
设备树 .dtb:        ~100 KB
根文件系统:         几十 MB ~ 几 GB
```

**DDR 初始化为什么复杂**：

| 步骤 | 说明 |
|------|------|
| 时钟配置 | DDR 需要精确的参考时钟 |
| 时序训练 | DDR4/LPDDR4 需要读写训练（read/write training） |
| ZQ 校准 | 阻抗校准，保证信号完整性 |
| 地址映射 | 配置 DDR 控制器的 bank/row/column 映射 |
| ECC 初始化 | 如果支持 ECC，需要初始化并清零 |

```c
// DDR 初始化的简化流程
void ddr_init(void) {
    // 1. 设置 DDR PHY 的时钟和电压
    ddr_set_voltage(DDR_VOLT_1_1V);    // LPDDR4: 1.1V
    ddr_pll_init(1600);                 // DDR4-3200 (1600 MHz)

    // 2. 配置 DDR 控制器
    ddr_ctrl_config(
        .type = DDR4,
        .density = 8192,    // 8GB
        .bus_width = 32,
        .banks = 8
    );

    // 3. 时序训练（最耗时，可能需要几百毫秒）
    ddr_write_training();
    ddr_read_training();

    // 4. ZQ 校准
    ddr_zq_calibration();

    // 5. 测试 DDR 可用性
    ddr_memtest();
}
```

### 4. U-Boot 传什么给 Linux 内核

U-Boot 通过 **ARM64 的启动协议**向内核传递信息，主要有两种方式：

#### 4.1 设备树（Device Tree Blob，.dtb）

**这是最主要的信息传递方式**。设备树描述了硬件信息。

```bash
# U-Boot 加载设备树并传给内核
=> load mmc 0:1 ${fdt_addr_r} rk3588-rock-5b.dtb
=> fdt addr ${fdt_addr_r}

# U-Boot 可以动态修改设备树
=> fdt set /memory@0 reg <0x0 0x0 0x0 0x40000000>  // 设置内存大小
=> fdt set /chosen bootargs "console=ttyS2,1500000 root=/dev/mmcblk0p7"  // 设置启动参数
```

**设备树中 U-Boot 传递的关键信息**：

```dts
/ {
    // 1. 内存布局
    memory@0 {
        reg = <0x0 0x0 0x0 0x40000000>;  // 起始地址和大小
    };

    // 2. 启动参数（chosen 节点）
    chosen {
        stdout-path = "serial2:1500000n8";
        bootargs = "console=ttyS2,1500000 root=/dev/mmcblk0p7 rw rootwait";
        linux,initrd-start = <0x...>;     // initramfs 地址（如果有）
        linux,initrd-end = <0x...>;
    };

    // 3. 硬件描述（CPU、外设、时钟、引脚等）
    cpus { ... };
    i2c@fe150000 { ... };
    ...
};
```

#### 4.2 寄存器传递

ARM64 启动协议规定，U-Boot 跳转到内核时通过寄存器传递少量信息：

| 寄存器 | 内容 | 说明 |
|--------|------|------|
| x0 | 设备树 .dtb 的物理地址 | **最重要的参数** |
| x1 | 0 | 保留 |
| x2 | 0 | 保留 |
| x3 | 0 | 保留 |

```c
// U-Boot 跳转到内核的简化代码
void boot_linux(uintptr_t kernel_addr, uintptr_t fdt_addr) {
    void (*kernel_entry)(uintptr_t fdt, uintptr_t res0,
                         uintptr_t res1, uintptr_t res2);

    kernel_entry = (void *)kernel_addr;

    // 清理 cache
    invalidate_icache_all();
    flush_dcache_all();

    // 禁用 MMU 和中断
    disable_mmu_el1();
    disable_irq();

    // 跳转到内核，x0 = fdt 地址
    kernel_entry(fdt_addr, 0, 0, 0);
    // 内核从 x0 中读取设备树地址
}
```

### 5. 完整的内存布局

```
RK3588 DDR 内存布局（简化）：

0x00000000 ┌────────────────────────────┐
           │  ARM Trusted Firmware (ATF) │  几百 KB
0x00100000 ├────────────────────────────┤
           │  U-Boot                     │  ~1 MB
0x00400000 ├────────────────────────────┤
           │  设备树 (.dtb)              │  ~100 KB
0x00800000 ├────────────────────────────┤
           │  Linux 内核 (Image)         │  ~20 MB
0x02000000 ├────────────────────────────┤
           │  initramfs（可选）          │  几 MB
0x04000000 ├────────────────────────────┤
           │                             │
           │  空闲内存                    │  给内核和用户空间使用
           │                             │
           └────────────────────────────┘
```

### 6. 面试速记

- **启动链**：BootROM → SPL（初始化 DDR）→ U-Boot → Linux → init
- **先初始化 DDR**：因为 SRAM 太小（几十 KB），内核有几十 MB，必须先初始化 DDR 才能加载
- **U-Boot 传参**：通过 x0 寄存器传递设备树地址，设备树中包含内存布局、启动参数、硬件描述
- **chosen 节点**：bootargs（内核命令行）、initramfs 地址
- **ARM64 启动协议**：x0 = fdt 地址，x1/x2/x3 = 0
