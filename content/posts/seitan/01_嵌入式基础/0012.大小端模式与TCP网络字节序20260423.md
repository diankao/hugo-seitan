# 大小端模式与TCP网络字节序

## 题目

1. 说一下大小端模式？
2. TCP网络传输采用什么模式？

## 考察点

大小端的概念与存储方式、常见处理器的大小端特性、网络字节序、字节序转换函数。

## 回答要点

### 1. 大小端概念

**字节序（Byte Order）** 指多字节数据在内存中的存放顺序喵~

以 `uint32_t val = 0x12345678` 为例，假设起始地址为 `0x100`：

#### 大端模式（Big-Endian）

**高位字节存放在低地址**喵~

```
地址:    0x100  0x101  0x102  0x103
内容:    0x12   0x34   0x56   0x78
         高位 ←────────────────→ 低位
```

#### 小端模式（Little-Endian）

**高位字节存放在高地址**喵~

```
地址:    0x100  0x101  0x102  0x103
内容:    0x78   0x56   0x34   0x12
         低位 ←────────────────→ 高位
```

### 2. 各处理器的大小端

| 处理器 | 默认字节序 | 可配置 |
|--------|-----------|--------|
| STM32 (Cortex-M) | 小端 | 部分可配 |
| ARM Cortex-A | 小端 | 可配 |
| x86/x64 | 小端 | 否 |
| MIPS | 大端 | 可配 |
| PowerPC | 大端 | 可配 |
| AVR (Arduino) | 小端 | 否 |
| ESP32 | 小端 | 否 |

### 3. 如何判断大小端

```c
int check_endian(void) {
    uint32_t val = 0x12345678;
    uint8_t *p = (uint8_t *)&val;

    if (p[0] == 0x12) {
        return 1;
    } else {
        return 0;
    }
}
```

### 4. TCP网络传输采用什么模式

**TCP/IP 协议规定网络传输使用大端模式（网络字节序）喵~**

这意味着发送方在发送多字节数据前，必须将主机字节序转换为网络字节序（大端）；接收方收到后，再从网络字节序转换回主机字节序喵~

### 5. 字节序转换函数

```c
#include <arpa/inet.h>

uint16_t port = 8080;
uint32_t ip = 0xC0A80101;

uint16_t net_port = htons(port);
uint32_t net_ip = htonl(ip);

uint16_t host_port = ntohs(net_port);
uint32_t host_ip = ntohl(net_ip);
```

| 函数 | 作用 | 全称 |
|------|------|------|
| `htons` | 主机→网络（16位） | Host TO Network Short |
| `htonl` | 主机→网络（32位） | Host TO Network Long |
| `ntohs` | 网络→主机（16位） | Network TO Host Short |
| `ntohl` | 网络→主机（32位） | Network TO Host Long |

**在小端机器上**，这些函数会做字节翻转喵~
**在大端机器上**，这些函数是空操作（直接返回原值）喵~

### 6. 嵌入式通信中的字节序问题

在嵌入式开发中，SPI、I2C、UART、CAN 等协议也涉及字节序问题喵~

```c
typedef struct {
    uint16_t header;
    uint8_t  cmd;
    uint8_t  len;
    uint32_t data;
    uint16_t crc;
} frame_t;

void frame_send(frame_t *f) {
    uint8_t buf[10];
    buf[0] = (f->header >> 8) & 0xFF;
    buf[1] = f->header & 0xFF;
    buf[2] = f->cmd;
    buf[3] = f->len;
    buf[4] = (f->data >> 24) & 0xFF;
    buf[5] = (f->data >> 16) & 0xFF;
    buf[6] = (f->data >> 8) & 0xFF;
    buf[7] = f->data & 0xFF;
    buf[8] = (f->crc >> 8) & 0xFF;
    buf[9] = f->crc & 0xFF;

    uart_send(buf, 10);
}

void frame_recv(uint8_t *buf) {
    frame_t f;
    f.header = ((uint16_t)buf[0] << 8) | buf[1];
    f.cmd = buf[2];
    f.len = buf[3];
    f.data = ((uint32_t)buf[4] << 24) | ((uint32_t)buf[5] << 16) |
             ((uint32_t)buf[6] << 8) | buf[7];
    f.crc = ((uint16_t)buf[8] << 8) | buf[9];
}
```

### 7. 对比总结

| 对比项 | 大端（Big-Endian） | 小端（Little-Endian） |
|--------|-------------------|----------------------|
| 高位字节存放 | 低地址 | 高地址 |
| 人类阅读 | 直观（和书写顺序一致） | 不直观 |
| 强制转换 | 取低地址即取高位 | 取低地址即取低位 |
| 类型转换开销 | 无需转换 | 网络通信需转换 |
| 典型代表 | 网络字节序、PowerPC | x86、ARM、STM32 |
