# JTAG 调试接口与嵌入式调试手段

JTAG 是芯片级调试与测试的标准接口（IEEE 1149.1）：不依赖操作系统就能 halt CPU、读写寄存器与内存，是嵌入式开发中定位硬件级问题的最后手段。本文整理 JTAG 的信号定义、TAP 状态机与边界扫描原理、SWD 对比、OpenOCD + GDB 实操，以及与串口、示波器、逻辑分析仪等调试手段的分工。

## JTAG 五线

| 信号 | 全称 | 作用 | 必选？ |
| --- | --- | --- | --- |
| TDI | Test Data In | 测试数据串行输入 | ✅ |
| TDO | Test Data Out | 测试数据串行输出 | ✅ |
| TMS | Test Mode Select | 控制 TAP 状态机迁移 | ✅ |
| TCK | Test Clock | 时钟（典型 ≤10MHz，器件而定） | ✅ |
| TRST | Test Reset | 状态机异步复位 | ❌ **可选** |

注意 **TRST 是可选信号**：TMS 保持高电平 5 个 TCK 周期就能同步复位到 Test-Logic-Reset 状态，所以 TRST 并非必需。

## TAP 控制器：16 状态状态机

TAP（Test Access Port）是 JTAG 的控制核心。每个 TCK 上升沿，TAP 根据 TMS 在 16 个状态间迁移：

```
                 ┌──────────────────────────────┐
                 │      Test-Logic-Reset        │◄── TMS=1 连续5拍，随时回到这里
                 └──────────┬───────────────────┘
                            │ TMS=0
                 ┌──────────▼───────────┐
                 │    Run-Test/Idle     │◄────────────┐
                 └───┬──────────────┬───┘             │
             TMS=1   │              │ TMS=0           │
        ┌────────────▼───┐   ┌──────▼─────────┐       │
        │ Select-DR-Scan │   │ Select-IR-Scan │       │
        └───────┬────────┘   └───────┬────────┘       │
            TMS=0│                TMS=0│               │
        ┌───────▼────────┐   ┌───────▼────────┐       │
        │  Capture-DR    │   │  Capture-IR    │       │
        └───────┬────────┘   └───────┬────────┘       │
                │ Shift        │ Shift                  │
        ┌───────▼────────┐   ┌───────▼────────┐       │
        │  Shift-DR ◄──► │   │  Shift-IR ◄──► │───────┘（经 Update/Exit 回 Idle）
        └───────┬────────┘   └───────┬────────┘  TDI/TDO 在 Shift 态串行移位
                ▼                    ▼
           Update-DR             Update-IR      （新指令/新数据生效）
```

主干只有两条工作通道：**IR（指令寄存器）扫描**选择"要干什么"，**DR（数据寄存器）扫描**传输数据。Shift 状态下每个 TCK 搬一位，TDI 进 TDO 出——JTAG 的一切操作（读 IDCODE、跑边界扫描、访问调试模块）都是这两条通道的组合。

## 边界扫描原理

JTAG 的本职（1149.1 的设计初衷）是**生产测试**：芯片每根引脚内侧放一个边界扫描单元（BSC），串成一条围绕芯片的移位链。

- **SAMPLE**：快照所有引脚当前电平，移出查看——抓总线状态不动目标；
- **PRELOAD/EXTEST**：把移入的值打到引脚上，或驱动到 PCB 走线——即使 CPU 不跑程序也能逐网络测开路/短路；
- **IDCODE**（最常用的探测指令）：读出 32 位器件身份码（厂商/型号/版本），`OpenOCD`/探针靠它识别链上有几个器件、型号是什么；
- **BYPASS**：单比特直通，跳过链上无关器件。

嵌入式调试正是复用这套基础设施：调试探针经 TAP 访问芯片内置的**调试模块**（ARM 的 DAP：Debug Access Port），进而halt核、读写寄存器/内存/外设、设硬件断点（FPB）、跟踪（DWT/ETM）。

## SWD：JTAG 的两线替代

ARM Cortex-M 上常用 SWD（Serial Wire Debug）：

| | JTAG | SWD |
| --- | --- | --- |
| 信号 | TDI/TDO/TMS/TCK(/TRST) 4~5 根 | SWDIO/SWCLK 2 根 |
| 状态机 | 16 态 TAP | 线协议（request/ACK/parity，host 主导） |
| 调试能力 | 等同 | 等同（访问同一套 DAP） |
| trace | — | SWO（单线，复用引脚）输出 printf/ITM |
| 多器件链 | 天然支持（菊花链） | 每核一个 DAP，靠 AP 编址 |
| 适配器 | J-Link/ST-Link/ULK2 均支持 | 同左（引脚复用，探针自动识别） |

SWD 省引脚（对小封装 MCU 关键），是 Cortex-M 事实标准；FPGA/CPU 类仍以 JTAG 为主。

## OpenOCD + GDB 实操

OpenOCD 把"探针 + 目标"封装成 GDB server，是最通用的开源组合：

```tcl
# openocd.cfg：ST-Link + STM32F4
source [find interface/stlink.cfg]
transport select hla_swd
source [find target/stm32f4x.cfg]
reset_config srst_only
```

```bash
# 终端1：起 OpenOCD（默认 GDB server 3333 端口）
openocd -f openocd.cfg

# 终端2：GDB 连接
arm-none-eabi-gdb firmware.elf
(gdb) target remote localhost:3333   # 连上目标
(gdb) monitor reset halt             # 复位并停住
(gdb) load                           # 下载固件
(gdb) monitor reset run              # 复位运行
(gdb) break main                     # 软件断点（Flash 目标自动用 FPB 硬断点）
(gdb) continue
(gdb) bt                             # 看调用栈（HardFault 现场分析神器）
(gdb) x/16wx 0x20000000              # 直接看内存（验证外设寄存器/缓冲）
```

典型用途：HardFault 时 `bt` 看压栈现场、直接改外设寄存器做实验、`monitor reset init` 把目标带到一个确定状态。

常见连不上的原因：SWDIO/SWCLK 接反或没接复位脚、目标没上电、芯片读了保护（RDP，需 `monitor stm32f4x unlock` 解锁再擦除）、探针驱动被 IDE 独占。

## 硬件异常与软件观测的层级差异

调试工具分两层，能力完全不同：

| 工具 | 层级 | 能看到什么 |
| --- | --- | --- |
| **JTAG 调试器** | 芯片级（不依赖 OS） | halt 住 CPU、看 PC/寄存器/内存、硬件断点，Kernel Panic/HardFault 时定位现场 |
| **串口** | 控制台 | 内核 oops/panic 打印、boot log，是嵌入式 Linux 的第一现场 |
| perf top | OS 之上 | 用户态/内核态热点函数采样，不是异常分析工具 |
| strace | OS 之上 | 系统调用跟踪，与硬件异常无关 |

关键区别：JTAG 不需要内核活着就能工作（连 HardFault 都能抓）；perf/strace 依赖内核正常运行，只能观测软件行为。

## 调试四件套的分工

- **在线调试**（JTAG/SWD + J-Link/ST-Link/OpenOCD）：断点、单步、内存查看；
- **串口打印**：最低成本、最通用，驱动/内核/应用都靠它；
- **示波器**：模拟域真实波形——时序边沿、抖动、电源纹波、信号完整性；
- **逻辑分析仪**：多通道数字时序抓取与协议解码（SPI/I2C/UART 批量分析）。

四种手段互补：软件逻辑问题靠调试器/串口，信号完整性/时序问题靠示波器/逻辑分析仪。
