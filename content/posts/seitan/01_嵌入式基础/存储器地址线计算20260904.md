# 存储器地址线计算

## 题目

一个存储器的地址范围为 8000H 至 BFFFH，它需要多少根地址线？这类"地址范围 → 地址线数量"的换算怎么做？

## 考察点

存储器地址空间与地址线数量的换算关系，十六进制减法及"结束地址减起始地址要加一"的细节。

## 回答要点

### 1. 计算方法

三步走：

1. **求存储单元总数**：`单元数 = 末地址 - 首地址 + 1`
   ```
   BFFFH - 8000H + 1 = 3FFFH + 1 = 4000H = 16384
   ```
2. **换算成 2 的幂**：`16384 = 2^14`
3. **地址线数 n 满足 `2^n ≥ 单元数`**：`2^14 = 16384`，正好覆盖，所以需要 **14 根**。

最容易犯的错就是忘记 **+1**：算成 3FFFH = 16383，不是 2 的整数次幂，然后纠结半天。地址范围是**闭区间**，两头都要算。

### 2. 十六进制减法的速算技巧

观察到 `BFFF - 8000`：高 4 位 `B - 8 = 3`，低 12 位 `FFF - 000 = FFF`，得 `3FFF`。也可以用"地址长度"直接看：

- 8000H 到 BFFFH 的最高位是 8、9、A、B 共 **4 个值**（每个值对应 1000H = 4096 个地址）；
- `4 × 4096 = 16384 = 2^14`。

更进一步：地址范围跨了 2 位十六进制（低 12 位取满 FFF，再加高位 2 比特），12 + 2 = 14 根。

### 3. 通用公式与常见容量对照表

地址线 n 根 → 最多寻址 `2^n` 个单元：

| 地址线数 | 可寻址单元数 | 对应容量（8 位机/字节编址） |
|---------|-------------|---------------------------|
| 10 | 1024 (2^10) | 1KB |
| 12 | 4096 (2^12) | 4KB |
| 13 | 8192 (2^13) | 8KB |
| **14** | **16384 (2^14)** | **16KB（上文示例）** |
| 16 | 65536 (2^16) | 64KB（8051 经典寻址空间） |
| 20 | 2^20 | 1MB |
| 32 | 2^32 | 4GB |

反过来记也常用：1KB 对应 A0~A9 共 10 根，64KB 对应 A0~A15 共 16 根。

### 4. 几个易混点

| 易混点 | 辨析 |
|--------|------|
| 地址线 vs 数据线 | 地址线决定"多少个单元"，数据线决定"每个单元多少位"；8 根数据线 + 14 根地址线的芯片容量 = 16K × 8 bit = 128Kbit |
| 单元数 vs 容量（bit/byte） | 地址线只管单元个数，与位宽无关；芯片总容量 = 单元数 × 位宽 |
| 忘记 +1 | 8000H~BFFFH 是 4000H 个单元（含两端），不是 3FFFH 个 |
| 片选信号 | 实际接线中高位地址线（如 A14、A15）常用作译码产生片选，不参与片内寻址，但总数计算时仍按整个地址范围算 |

### 5. 代码验证思路

用 C 语言可以快速验证单元数与地址线的关系：

```c
#include <stdio.h>
#include <math.h>

int main(void)
{
    unsigned int start = 0x8000;
    unsigned int end   = 0xBFFF;
    unsigned long units = (unsigned long)(end - start) + 1;

    printf("units = %lu\n", units);
    printf("address lines = %lu\n", (unsigned long)log2(units));
    return 0;
}
```

输出 `units = 16384`、`address lines = 14`。

### 6. 小结

口诀：**单元数 = 末 − 首 + 1，n 根地址线寻址 2^n 个单元**。看到十六进制地址范围，先闭区间算总数，再看它是不是 2 的整数次幂，答案就出来了。
