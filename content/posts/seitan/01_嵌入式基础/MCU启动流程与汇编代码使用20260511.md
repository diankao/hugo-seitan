# MCU启动流程与汇编代码使用

## 题目

1. MCU的启动流程是怎样的？从上电复位到执行main函数经历了哪些步骤？为什么Bootloader刚开始会有一段汇编代码？
2. Linux开发过程中，汇编代码一般什么时候会用？

## 考察点

MCU上电启动过程、向量表机制、C运行时环境初始化、汇编在嵌入式开发中的使用场景。

## 回答要点

### 1. MCU上电复位到main函数的完整流程

以 ARM Cortex-M 系列（如 STM32）为例，从上电到执行 `main()` 经历以下阶段：

```
上电复位
  │
  ▼
① CPU 从向量表读取初始 MSP（主栈指针）
  │  向量表第 0 个字 → 0x2000xxxx（SRAM 顶部地址）
  │
  ▼
② CPU 从向量表读取 Reset_Handler 地址
  │  向量表第 1 个字 → Reset_Handler 的入口地址
  │
  ▼
③ 执行 Reset_Handler（启动文件，汇编编写）
  │  ├── 调用 SystemInit()：配置时钟、Flash 延迟
  │  ├── 初始化 .data 段：从 Flash 拷贝到 RAM
  │  ├── 清零 .bss 段
  │  ├── 调用 __libc_init_array()（C++ 构造函数等）
  │  └── 调用 main()
  │
  ▼
④ 进入 main() 函数（C 语言世界）
```

#### 1.1 向量表（Vector Table）

```c
// 链接器脚本中定义的向量表（启动文件生成）
// 地址 0x00000000（或 0x08000000，取决于 BOOT 引脚配置）
__Vectors:
    .word   0x20020000      // [0] 初始栈指针 MSP
    .word   Reset_Handler   // [1] 复位向量
    .word   NMI_Handler     // [2] NMI
    .word   HardFault_Handler // [3] HardFault
    .word   MemManage_Handler  // [4]
    .word   BusFault_Handler   // [5]
    .word   UsageFault_Handler // [6]
    // ... 更多中断向量
```

CPU 上电后硬件**自动**完成前两步：读 MSP、读 PC，这是硬件行为，不可编程。

#### 1.2 Reset_Handler 做了什么

```arm
; STM32 启动文件（startup_stm32f407xx.s）核心逻辑
Reset_Handler:
    ; 1. 调用 SystemInit（配置系统时钟）
    LDR     R0, =SystemInit
    BLX     R0

    ; 2. 拷贝 .data 段（Flash → RAM）
    LDR     R0, =_sdata      ; .data 起始地址（RAM）
    LDR     R1, =_edata      ; .data 结束地址
    LDR     R2, =_sidata     ; .data 在 Flash 中的加载地址
CopyDataInit:
    CMP     R0, R1
    BCS     ZeroFillBSS
    LDR     R3, [R2]
    STR     R3, [R0]
    ADDS    R0, R0, #4
    ADDS    R2, R2, #4
    B       CopyDataInit

    ; 3. 清零 .bss 段
ZeroFillBSS:
    LDR     R0, =_sbss
    LDR     R1, =_ebss
    MOV     R2, #0
FillZeros:
    CMP     R0, R1
    BCS     CallMain
    STR     R2, [R0]
    ADDS    R0, R0, #4
    B       FillZeros

    ; 4. 调用 main
CallMain:
    LDR     R0, =main
    BX      R0
```

#### 1.3 各阶段的作用

| 阶段 | 做了什么 | 为什么必须 |
|------|---------|-----------|
| 设置 MSP | 从向量表加载栈指针 | C 函数调用依赖栈，没有栈就无法调用任何函数 |
| SystemInit | 配置系统时钟（HSE/PLL/Flash等待周期） | 默认使用内部低速 RC，需切换到外部晶振达到目标主频 |
| 拷贝 .data | 将初始化的全局变量从 Flash 搬到 RAM | `.data` 段的**初始值**存在 Flash，**运行地址**在 RAM |
| 清零 .bss | 将未初始化的全局变量所在 RAM 区域清零 | C 标准规定未初始化全局变量为 0，上电 RAM 内容随机 |
| __libc_init_array | 执行 C++ 全局构造函数 | C++ 全局对象的构造函数需在 main 前执行 |

### 2. 为什么 Bootloader / 启动文件必须用汇编

#### 2.1 根本原因：C 语言运行环境还没建立

```
问题：C 函数需要什么才能运行？
  ├── 栈（SP 必须有效）        → 上电时 SP 是随机值
  ├── .data 段已初始化         → 此时还在 Flash 里，没搬
  ├── .bss 段已清零            → 此时 RAM 是随机值
  └── 全局构造函数已执行        → 还没调用 __libc_init_array

所以：在 C 运行环境建立之前，只能用汇编！
```

**第一个 C 函数 `SystemInit()` 能被调用，是因为汇编已经完成了最关键的步骤——设置栈指针。** 只要 SP 有效，就能调用 C 函数（只要该函数不依赖全局变量）。

#### 2.2 其他需要汇编的场景

| 场景 | 原因 |
|------|------|
| 启动文件（Reset_Handler） | 建立 C 运行环境 |
| 中断向量表 | 需要精确控制入口地址 |
| 上下文切换（RTOS） | 需要直接操作寄存器 R4-R11、PSP |
| 使能/禁用 FPU | 需要写 CPACR 等协处理器寄存器 |
| 自修改代码 | C 无法在运行时生成机器码 |
| 极端性能优化 | 对特定热点循环手工优化 |

### 3. Linux 开发中汇编的使用场景

Linux 内核开发中汇编使用比 MCU 裸机少得多，但以下场景仍不可避免：

| 场景 | 示例 |
|------|------|
| 内核入口（head.S） | `stext`，建立页表、使能 MMU，在虚拟地址生效前必须用汇编 |
| 系统调用入口 | `entry_64.S` 中 `entry_SYSCALL_64`，需要精确保存/恢复寄存器 |
| 中断/异常入口 | `entry_64.S` 中各种中断入口，需要切换栈帧 |
| 上下文切换 | `__switch_to`，保存/恢复 callee-saved 寄存器 |
| 原子操作 | `arch/x86/lib/cmpxchg.S`，需要 lock 前缀等特殊指令 |
| 休眠/唤醒 | `acpi/wakeup.S`，CPU 从睡眠状态恢复时需要汇编初始化 |
| 内联汇编优化 | `asm volatile("nop")`，在 C 代码中嵌入特定指令 |

**Linux 汇编的原则**：能用 C 就用 C，只在**必须直接操作硬件寄存器**或**对时序/指令序列有精确要求**时才用汇编。

```c
// Linux 内核中典型的内联汇编：内存屏障
#define barrier() __asm__ __volatile__("" ::: "memory")

// 原子比较并交换
static inline int atomic_cmpxchg(atomic_t *v, int old, int new)
{
    asm volatile("lock; cmpxchgl %2, %1"
                 : "=a" (old), "+m" (v->counter)
                 : "r" (new), "0" (old)
                 : "memory");
    return old;
}
```

### 4. 对比总结

| 对比项 | MCU 裸机 | Linux 内核 |
|--------|---------|-----------|
| 启动文件 | **必须**手写汇编（startup.s） | 有，但由内核源码提供 |
| 日常开发 | 偶尔用内联汇编（寄存器操作） | 极少，内核已封装好接口 |
| RTOS 移植 | 需要写汇编（PendSV、上下文切换） | 不涉及（内核自带） |
| 汇编占比 | 整个工程的 1%-5% | 内核源码中 < 1% |
