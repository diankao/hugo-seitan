# DMA与虚拟地址及触发机制

## 题目

1. DMA 是什么？为什么不能说"DMA 通过虚拟地址搬运"？
2. DMA 是怎么触发的？

## 考察点

DMA 工作原理、虚拟地址与物理地址的区别、DMA 触发方式、嵌入式/Linux 中的 DMA 使用。

## 回答要点

### 1. DMA 是什么

DMA（Direct Memory Access，直接存储器访问）是一种**无需 CPU 参与即可在内存与外设之间搬运数据**的机制。DMA 控制器独立于 CPU，直接操作总线完成数据传输。

```
不使用 DMA：
CPU ←读取→ 外设寄存器 → CPU 写入 → 内存
（CPU 全程参与搬运，期间无法执行其他任务）

使用 DMA：
DMA控制器 ←→ 内存
    ↑
  外设寄存器
（CPU 只需配置 DMA，搬运期间可执行其他任务）
```

### 2. 为什么不能说"DMA 通过虚拟地址搬运"

**核心原因：DMA 控制器只认物理地址，不经过 MMU。**

```
CPU 的访问路径：
CPU → MMU（虚拟地址 → 物理地址）→ 内存控制器 → 物理内存

DMA 的访问路径：
DMA控制器 → 总线 → 内存控制器 → 物理内存
            ↑ 不经过 MMU！只能使用物理地址
```

**虚拟地址**是 CPU 通过 MMU（内存管理单元）映射后的地址，只有 CPU 在访问时才会经过 MMU 转换。DMA 控制器直接连接在系统总线上，**不经过 MMU**，因此：

- DMA 看不到虚拟地址
- 如果把虚拟地址给 DMA，DMA 会直接把这个值当地址去访问内存，大概率访问到错误的物理位置
- 在 Linux 中，用户空间的虚拟地址对 DMA 来说毫无意义

```c
// 错误示范：把虚拟地址给 DMA
void *buf = malloc(1024);          // 返回用户态虚拟地址
dma_src = (uint32_t)buf;           // 错误！DMA 无法识别这个地址
DMA->SRC_ADDR = dma_src;           // 数据搬运到错误的位置！

// 正确做法：将虚拟地址转换为物理地址
void *buf = kmalloc(1024, GFP_KERNEL);       // 内核虚拟地址
dma_addr_t phys = dma_map_single(dev, buf, 1024, DMA_TO_DEVICE);
DMA->SRC_ADDR = phys;             // 正确：物理地址
```

### 3. 不同平台下的 DMA 地址处理

#### 3.1 裸机 / MCU（无 MMU）

裸机没有虚拟地址概念，所有地址都是物理地址，DMA 直接使用。

```c
// STM32 DMA 配置（裸机，无 MMU）
uint8_t rx_buffer[256];

DMA_InitStruct.DMA_PeripheralBaseAddr = (uint32_t)&USART1->DR;  // 外设寄存器地址
DMA_InitStruct.DMA_MemoryBaseAddr = (uint32_t)rx_buffer;        // 内存地址
// 直接就是物理地址，无需转换
```

#### 3.2 嵌入式 Linux（有 MMU）

Linux 中需要通过 DMA 映射 API 将内核虚拟地址转换为 DMA 可用的物理地址（或总线地址）。

```c
// Linux 内核 DMA 映射
// 一致性 DMA 映射（适合长时间持有）
void *virt = dma_alloc_coherent(dev, size, &dma_handle, GFP_KERNEL);
// virt: CPU 使用的虚拟地址
// dma_handle: DMA 控制器使用的物理/总线地址

// 流式 DMA 映射（适合一次性传输）
dma_addr_t dma_handle = dma_map_single(dev, virt_addr, size, direction);
// 使用完后
dma_unmap_single(dev, dma_handle, size, direction);
```

#### 3.3 IOMMU / SMMU

现代 SoC（如 RK3588）可能有 IOMMU（ARM 上叫 SMMU），它给 DMA 提供了独立的地址翻译：

```
有 IOMMU 的系统：
DMA控制器 → IOMMU（设备虚拟地址 → 物理地址）→ 内存控制器
```

即使有 IOMMU，DMA 使用的也不是 CPU 的虚拟地址，而是**设备虚拟地址（IOVA）**，需要通过 IOMMU 映射。

### 4. DMA 的触发方式

#### 4.1 硬件触发（最常见）

外设产生 DMA 请求信号，DMA 控制器自动启动传输。

```
外设（如 UART）收到一个字节
       │
       ▼ 产生 DMA 请求信号（DMA_REQ）
DMA 控制器检测到请求
       │
       ▼ 从外设数据寄存器搬运一个字节到内存缓冲区
       │
       ▼ 内存地址自动递增
       │
       ▼ 传输计数减 1
       │
       ▼ 计数为 0？→ 产生 DMA 传输完成中断
```

```c
// STM32 UART DMA 硬件触发配置
DMA_InitStruct.DMA_DIR = DMA_DIR_PeripheralSRC;  // 外设 → 内存
DMA_InitStruct.DMA_Mode = DMA_Mode_Circular;     // 循环模式
DMA_InitStruct.DMA_PeripheralBaseAddr = (uint32_t)&USART1->DR;

// 使能 UART 的 DMA 请求
USART_DMACmd(USART1, USART_DMAReq_Rx, ENABLE);

// 每当 UART 收到一个字节，硬件自动触发 DMA 传输
```

#### 4.2 软件触发

程序主动写 DMA 控制器寄存器启动传输。

```c
// 内存到内存的 DMA 搬运（软件触发）
DMA_InitStruct.DMA_DIR = DMA_DIR_MemoryToMemory;
DMA_InitStruct.DMA_MemoryBaseAddr = (uint32_t)src;
DMA_InitStruct.DMA_MemoryBaseAddr = (uint32_t)dst;
DMA_InitStruct.DMA_BufferSize = len;

DMA_Cmd(DMA1_Channel1, ENABLE);  // 软件启动传输
```

#### 4.3 Linux 内核中的 DMA 触发

```c
// Linux 驱动中使用 DMA engine
struct dma_chan *chan = dma_request_channel(mask, NULL, NULL);
struct dma_async_tx_descriptor *desc;

desc = dmaengine_prep_slave_single(chan, dma_addr, len, DMA_DEV_TO_MEM, flags);
desc->callback = dma_complete_callback;
desc->callback_param = &completion;

dmaengine_submit(desc);
dma_async_issue_pending(chan);  // 触发 DMA 传输
```

### 5. 常见 DMA 触发场景

| 触发源 | 方向 | 说明 |
|--------|------|------|
| UART 接收 | 外设 → 内存 | 每收到字节触发一次 |
| SPI 接收 | 外设 → 内存 | 每次时钟沿触发 |
| ADC 采样 | 外设 → 内存 | 每次转换完成触发 |
| 网卡收包 | 外设 → 内存 | 收到数据帧触发 |
| 内存拷贝 | 内存 → 内存 | 软件主动触发 |
| SPI 发送 | 内存 → 外设 | 软件触发，DMA 自动搬运 |

### 6. 面试速记

- **DMA 只认物理地址**：不经过 MMU，不能使用虚拟地址
- **裸机**：直接用物理地址（没有虚拟地址概念）
- **Linux**：用 `dma_map_single` / `dma_alloc_coherent` 做地址映射
- **触发方式**：硬件触发（外设请求信号）和软件触发（写寄存器）
- **IOMMU/SMMU**：给 DMA 提供独立的地址翻译，但用的不是 CPU 虚拟地址
