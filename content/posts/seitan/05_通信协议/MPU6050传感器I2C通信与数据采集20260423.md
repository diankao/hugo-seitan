## 回答要点

### 1. MPU6050与MCU之间使用什么接口通信？

MPU6050支持两种通信接口：

- **I2C**（最常用）：支持标准模式（100kHz）和快速模式（400kHz），地址引脚AD0接地为0x68，接高为0x69
- **SPI**（最高18MHz）：仅MPU6500之后的版本支持，MPU6050不支持SPI

大多数嵌入式项目使用I2C接口，原因：
- 引脚少（SCL + SDA），节省GPIO
- 总线可挂载多个设备
- 速率满足IMU数据采集需求

### 2. I2C配置的速度是多少？

MPU6050的I2C支持两种速度：

| 模式 | 速率 | 适用场景 |
|------|------|----------|
| 标准模式 | 100 kHz | 低速采集、长距离 |
| 快速模式 | 400 kHz | 高速采集、常规使用 |

**实际配置建议**：
- 使用400kHz快速模式，读取14字节（加速度+陀螺仪+温度）约需 14×9/400000 ≈ 0.315ms
- 如果总线挂载多个设备，需注意总负载电容对速率的影响
- STM32 HAL库配置示例：

```c
hi2c1.Instance = I2C1;
hi2c1.Init.ClockSpeed = 400000;
hi2c1.Init.DutyCycle = I2C_DUTYCYCLE_2;
hi2c1.Init.OwnAddress1 = 0;
hi2c1.Init.AddressingMode = I2C_ADDRESSINGMODE_7BIT;
hi2c1.Init.DualAddressMode = I2C_DUALADDRESS_DISABLE;
hi2c1.Init.GeneralCallMode = I2C_GENERALCALL_DISABLE;
hi2c1.Init.NoStretchMode = I2C_NOSTRETCH_DISABLE;
HAL_I2C_Init(&hi2c1);
```

### 3. MPU6050陀螺仪的采样周期是多少？

采样周期由寄存器 `SMPLRT_DIV`（0x19）配置：

```
采样率 = 陀螺仪输出速率 / (1 + SMPLRT_DIV)
```

- 陀螺仪输出速率：数字低通滤波器（DLPF）禁用时为8kHz，使能时为1kHz
- 常用配置：DLPF使能 + SMPLRT_DIV=7 → 采样率 = 1000/(1+7) = 125Hz（8ms周期）
- DLPF使能 + SMPLRT_DIV=0 → 采样率 = 1kHz（1ms周期）

**常见采样率配置**：

| SMPLRT_DIV | DLPF使能 | 采样率 | 采样周期 |
|-----------|---------|--------|----------|
| 0 | 是 | 1kHz | 1ms |
| 7 | 是 | 125Hz | 8ms |
| 9 | 是 | 100Hz | 10ms |
| 19 | 是 | 50Hz | 20ms |

### 4. 每次读取的数据量有多大？需要读取哪些数据？

MPU6050的数据寄存器分布（从0x3B开始连续14字节）：

| 寄存器 | 长度 | 数据 |
|--------|------|------|
| 0x3B-0x40 | 6字节 | 加速度 X/Y/Z（各16位） |
| 0x41-0x42 | 2字节 | 温度（16位） |
| 0x43-0x48 | 6字节 | 陀螺仪 X/Y/Z（各16位） |

**读取方式**：
- 一次性读取14字节（推荐）：从0x3B开始连续读
- 单独读取加速度或陀螺仪：各6字节
- 如果需要温度，共14字节；不需要温度可只读12字节

```c
#define MPU6050_ADDR         0x68
#define MPU6050_ACCEL_XOUT_H 0x3B

uint8_t buf[14];
HAL_I2C_Mem_Read(&hi2c1, MPU6050_ADDR << 1,
                  MPU6050_ACCEL_XOUT_H, I2C_MEMADD_SIZE_8BIT,
                  buf, 14, 100);

int16_t accel_x  = (buf[0] << 8) | buf[1];
int16_t accel_y  = (buf[2] << 8) | buf[3];
int16_t accel_z  = (buf[4] << 8) | buf[5];
int16_t temp     = (buf[6] << 8) | buf[7];
int16_t gyro_x   = (buf[8] << 8) | buf[9];
int16_t gyro_y   = (buf[10] << 8) | buf[11];
int16_t gyro_z   = (buf[12] << 8) | buf[13];
```

### 5. 是否按固定周期读取并立即计算？流程如何？

是的，通常按固定周期读取并计算。典型流程如下：

**方式一：定时器中断触发读取**

```
定时器中断（如1ms/5ms/10ms）
  → I2C读取14字节数据（DMA或中断方式）
  → 数据存入缓冲区
  → 设置数据就绪标志
主循环/任务检测到标志
  → 取出数据进行姿态解算（互补滤波/Mahony/卡尔曼）
  → 输出姿态角
```

**方式二：MPU6050 INT引脚中断触发**

```
MPU6050数据就绪中断（INT引脚）
  → 外部中断回调
  → I2C DMA读取14字节
  → 数据就绪标志置位
主循环/任务检测到标志
  → 姿态解算
  → 输出姿态角
```

**方式三（FreeRTOS环境）**：

```c
void MPU6050_Task(void *pvParameters)
{
    TickType_t xLastWakeTime = xTaskGetTickCount();
    for (;;) {
        vTaskDelayUntil(&xLastWakeTime, pdMS_TO_TICKS(5));
        MPU6050_Read_All(&mpu_data);
        MahonyAHRSupdateIMU(
            mpu_data.gx, mpu_data.gy, mpu_data.gz,
            mpu_data.ax, mpu_data.ay, mpu_data.az
        );
        roll  = atan2f(q2, q0) * 57.29578f;
        pitch = asinf(-q1) * 57.29578f;
        yaw   = atan2f(q3, q0) * 57.29578f;
    }
}
```

**关键原则**：读取和计算在同一周期内完成，避免数据不同步。使用DMA或中断方式读取I2C，不阻塞CPU。

### 6. 算法计算耗时多久？性能是否够用？

不同姿态解算算法在STM32（72MHz Cortex-M3）上的典型耗时：

| 算法 | 耗时（约） | 精度 | 适用场景 |
|------|-----------|------|----------|
| 互补滤波 | 10~20μs | 中 | 简单应用、资源受限 |
| Mahony（互补滤波改进） | 50~100μs | 高 | 通用嵌入式、无人机 |
| Madgwick | 80~150μs | 高 | 学术研究、高精度 |
| 卡尔曼滤波 | 100~200μs | 最高 | 工业级、高动态 |

**性能评估**（以5ms调度周期为例）：

- 总周期预算：5000μs
- I2C读取14字节（400kHz DMA）：约315μs
- Mahony姿态解算：约100μs
- 总耗时：约415μs，占周期预算的 **8.3%**
- 剩余约4585μs可用于其他任务

**结论**：在常规MCU（72MHz以上）上，姿态解算性能完全够用，甚至可以在200Hz~500Hz的高采样率下运行。

**优化手段**：
- 使用查表法替代三角函数（如ARM CMSIS-DSP的 `arm_sin_f32`）
- 启用FPU（Cortex-M4F/M7），浮点运算速度提升10倍以上
- 使用定点数运算替代浮点（无FPU的M0/M3）
- 合理设置采样率，不必一味追求高频

### 7. 系统调度周期是多少？

调度周期取决于应用场景和系统架构：

| 应用场景 | 典型调度周期 | 采样率 | 说明 |
|---------|-------------|--------|------|
| 平衡车/自平衡 | 5ms | 200Hz | 响应速度要求高 |
| 四轴飞行器 | 2~5ms | 200~500Hz | 高动态，需要快速姿态响应 |
| 机器人关节 | 10ms | 100Hz | 中等动态需求 |
| 姿态监测/计步 | 20ms | 50Hz | 低动态，省电优先 |
| 手持云台 | 1~2ms | 500~1000Hz | 超高响应要求 |

**调度周期选取原则**：

1. **Nyquist采样定理**：采样率至少为被测信号最高频率的2倍。人体运动带宽约20Hz，飞行器振动可达100Hz以上
2. **传感器采样率匹配**：调度周期应为传感器采样周期的整数倍，避免数据丢失或重复读取
3. **计算余量**：调度周期需大于"读取+解算+通信"总耗时的3~5倍，留出余量处理其他任务
4. **FreeRTOS中的实现**：

```c
#define IMU_TASK_PERIOD_MS  5

void IMU_Task(void *pvParameters)
{
    TickType_t xLastWakeTime = xTaskGetTickCount();
    for (;;) {
        vTaskDelayUntil(&xLastWakeTime, pdMS_TO_TICKS(IMU_TASK_PERIOD_MS));
        IMU_Process();
    }
}
```

**裸机系统**则使用定时器中断触发，在主循环中用标志位判断是否执行姿态解算。

### 8. MPU6050零漂、温漂如何补偿？

#### 零漂（Zero-Rate Offset / Bias）
### 1. MEMS陀螺仪的物理原理决定了它一定会漂
MPU6050内部的陀螺仪是 振动MEMS结构 ——一个微小的音叉在谐振，旋转时产生科里奥利力，通过检测这个力来测量角速度喵。这种机制的固有缺陷：

- 零漂 ：音叉结构不可能绝对对称，静止时就有残余信号输出
- 温漂 ：硅材料的弹性模量、谐振频率都随温度变化，零漂值跟着变
这不是MPU6050独有的， 是所有MEMS陀螺仪的共同问题 喵~
陀螺仪静止时输出不为零的现象，原因包括：
- MEMS谐振结构的不对称性
- PCB安装应力
- 电源噪声耦合

**零漂补偿方法**：

```c
#define CALIBRATION_SAMPLES  1000

typedef struct {
    float gyro_offset_x;
    float gyro_offset_y;
    float gyro_offset_z;
    float accel_offset_x;
    float accel_offset_y;
    float accel_offset_z;
} MPU6050_Calib_t;

MPU6050_Calib_t calib = {0};

void MPU6050_Calibrate(void)
{
    int32_t gx_sum = 0, gy_sum = 0, gz_sum = 0;
    int32_t ax_sum = 0, ay_sum = 0, az_sum = 0;

    for (int i = 0; i < CALIBRATION_SAMPLES; i++) {
        uint8_t buf[14];
        HAL_I2C_Mem_Read(&hi2c1, MPU6050_ADDR << 1,
                          0x3B, I2C_MEMADD_SIZE_8BIT, buf, 14, 100);

        ax_sum += (int16_t)((buf[0] << 8) | buf[1]);
        ay_sum += (int16_t)((buf[2] << 8) | buf[3]);
        az_sum += (int16_t)((buf[4] << 8) | buf[5]);
        gx_sum += (int16_t)((buf[8] << 8) | buf[9]);
        gy_sum += (int16_t)((buf[10] << 8) | buf[11]);
        gz_sum += (int16_t)((buf[12] << 8) | buf[13]);

        HAL_Delay(2);
    }

    calib.gyro_offset_x = (float)gx_sum / CALIBRATION_SAMPLES;
    calib.gyro_offset_y = (float)gy_sum / CALIBRATION_SAMPLES;
    calib.gyro_offset_z = (float)gz_sum / CALIBRATION_SAMPLES;
    calib.accel_offset_x = (float)ax_sum / CALIBRATION_SAMPLES;
    calib.accel_offset_y = (float)ay_sum / CALIBRATION_SAMPLES;
    calib.accel_offset_z = (float)az_sum / CALIBRATION_SAMPLES - 16384.0f;
}

void MPU6050_GetCorrectedData(MPU6050_Data_t *data)
{
    data->gx -= calib.gyro_offset_x;
    data->gy -= calib.gyro_offset_y;
    data->gz -= calib.gyro_offset_z;
    data->ax -= calib.accel_offset_x;
    data->ay -= calib.accel_offset_y;
    data->az -= calib.accel_offset_z;
}
```

#### 温漂（Temperature Drift）

温度变化导致零漂偏移量改变，是长时间运行中姿态角漂移的主要原因。

**温漂补偿方法**：

1. **查表法（推荐）**：在不同温度点采集零漂值，建立温度-零漂对照表，运行时根据当前温度插值补偿

```c
#define TEMP_TABLE_SIZE  5

typedef struct {
    float temp;
    float gx_offset;
    float gy_offset;
    float gz_offset;
} TempCalibPoint_t;

TempCalibPoint_t temp_table[TEMP_TABLE_SIZE] = {
    {  0.0f,  50.0f, -30.0f,  20.0f},
    { 25.0f,  10.0f,  -5.0f,   3.0f},
    { 40.0f, -20.0f,  15.0f, -10.0f},
    { 60.0f, -50.0f,  40.0f, -25.0f},
    { 85.0f, -80.0f,  60.0f, -40.0f},
};

float TempInterpolate(float temp, float *offset_table, int size)
{
    if (temp <= temp_table[0].temp) return offset_table[0];
    if (temp >= temp_table[size - 1].temp) return offset_table[size - 1];

    for (int i = 0; i < size - 1; i++) {
        if (temp >= temp_table[i].temp && temp <= temp_table[i + 1].temp) {
            float ratio = (temp - temp_table[i].temp) /
                          (temp_table[i + 1].temp - temp_table[i].temp);
            return offset_table[i] + ratio * (offset_table[i + 1] - offset_table[i]);
        }
    }
    return offset_table[0];
}
```

2. **在线自适应补偿**：当检测到传感器静止时（加速度方差极小），动态更新零漂估计值

```c
#define STILL_THRESHOLD  0.05f

void OnlineDriftCompensation(MPU6050_Data_t *data, float dt)
{
    static float accel_var = 0;
    static float gyro_bias_x = 0, gyro_bias_y = 0, gyro_bias_z = 0;

    float accel_mag = sqrtf(data->ax * data->ax + data->ay * data->ay + data->az * data->az);
    float deviation = fabsf(accel_mag - 16384.0f) / 16384.0f;

    if (deviation < STILL_THRESHOLD) {
        float alpha = 0.001f;
        gyro_bias_x += alpha * (data->gx - gyro_bias_x);
        gyro_bias_y += alpha * (data->gy - gyro_bias_y);
        gyro_bias_z += alpha * (data->gz - gyro_bias_z);
    }

    data->gx -= gyro_bias_x;
    data->gy -= gyro_bias_y;
    data->gz -= gyro_bias_z;
}
```

3. **MPU6050内部DMP**：DMP固件内置了零漂补偿算法，启用后自动补偿，但精度有限

**综合补偿策略**：

| 补偿方式 | 时机 | 精度 | 复杂度 |
|---------|------|------|--------|
| 上电静态校准 | 开机时 | 中 | 低 |
| 温度查表补偿 | 运行时持续 | 高 | 中 |
| 在线自适应补偿 | 检测到静止时 | 较高 | 高 |
| DMP内部补偿 | 始终 | 一般 | 低 |

实际工程中通常组合使用：上电校准 + 温度查表 + 在线补偿。

### 9. 校准时有什么姿态或动作要求？

#### 基本校准要求

| 项目 | 要求 | 原因 |
|------|------|------|
| 传感器状态 | 完全静止 | 采集的零偏才有参考价值 |
| 放置姿态 | 水平放置（Z轴向上） | 加速度Z轴应输出1g，X/Y轴应输出0 |
| 环境振动 | 无 | 振动会引入陀螺仪和加速度计噪声 |
| 温度稳定 | 等待芯片上电稳定后（约1~2分钟） | 温度变化影响零漂值 |
| 采样数量 | 500~2000次取平均 | 消除随机噪声影响 |

#### 六面校准法（高精度场景）

对于需要高精度加速度计校准的场景，使用六面校准法：

```
面1: Z轴向上  →  ax≈0,  ay≈0,  az≈+1g
面2: Z轴向下  →  ax≈0,  ay≈0,  az≈-1g
面3: X轴向上  →  ax≈+1g, ay≈0,  az≈0
面4: X轴向下  →  ax≈-1g, ay≈0,  az≈0
面5: Y轴向上  →  ax≈0,  ay≈+1g, az≈0
面6: Y轴向下  →  ax≈0,  ay≈-1g, az≈0
```

通过六个面的数据可以解出加速度计的零偏和比例因子（共6个参数）。

#### 校准注意事项

1. **陀螺仪校准**只需要静止放置，与姿态无关（只测角速度零偏）
2. **加速度计校准**需要已知姿态（如水平放置），用于确定重力参考方向
3. **磁力计校准**（如MPU9250）需要做"8字形"运动，以覆盖三维空间各方向
4. 校准数据应持久化存储（Flash/EEPROM），避免每次上电重新校准
5. 如果产品安装角度固定，可以在产线进行一次精密校准并固化参数

```c
typedef struct {
    float gyro_offset[3];
    float accel_offset[3];
    float accel_scale[3];
    uint32_t magic;
} MPU6050_CalibData_t;

#define CALIB_MAGIC  0x6050CA1B
#define FLASH_CALIB_ADDR  0x08060000

void SaveCalibData(MPU6050_CalibData_t *data)
{
    data->magic = CALIB_MAGIC;
    HAL_FLASH_Unlock();
    FLASH_EraseInitTypeDef erase = {
        .TypeErase = FLASH_TYPEERASE_PAGES,
        .PageAddress = FLASH_CALIB_ADDR,
        .NbPages = 1
    };
    uint32_t err;
    HAL_FLASHEx_Erase(&erase, &err);

    uint32_t *src = (uint32_t *)data;
    for (int i = 0; i < sizeof(MPU6050_CalibData_t) / 4; i++) {
        HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD,
                          FLASH_CALIB_ADDR + i * 4, src[i]);
    }
    HAL_FLASH_Lock();
}

int LoadCalibData(MPU6050_CalibData_t *data)
{
    memcpy(data, (void *)FLASH_CALIB_ADDR, sizeof(MPU6050_CalibData_t));
    return (data->magic == CALIB_MAGIC) ? 0 : -1;
}
```
