# SPI从机响应慢的主机侧表现与排查

## 题目

SPI通信中，如果从机响应变慢，主机这边会怎样？你在项目中有没有遇到过SPI通信异常，是怎么排查的？

## 考察点

SPI协议主从交互机制、超时处理、通信异常排查方法论。

## 回答要点

### 1. SPI协议特点：主机控制时钟

SPI 是**主机驱动时钟**的协议，主机不知道从机是否"准备好"喵~ 主机一旦拉低 CS、发出 SCK，从机就必须在时钟沿上提供数据。如果从机响应变慢，不会像 I2C 那样通过 clock stretching 暂停通信，而是直接导致**数据错误**喵~

| 对比项 | SPI | I2C |
|--------|-----|-----|
| 时钟控制 | 主机单向控制 | 从机可 stretch |
| 从机慢了怎么办 | 无法通知主机，直接出错 | 拉低 SCL 暂停 |
| 流控机制 | 无（需自行实现） | 有（clock stretching） |
| 应答信号 | 无 | 有（ACK/NACK） |

### 2. "从机响应慢"的具体场景

#### 场景一：从机需要准备时间

```c
// 典型场景：读取传感器数据
// 1. 主机发命令：读取温度寄存器
// 2. 从机需要 ADC 转换时间（比如 2ms）
// 3. 但主机发完命令后立即读数据
// 4. 从机还没准备好，返回的是旧值或无效值

uint8_t read_sensor(uint8_t reg) {
    uint8_t cmd = reg | 0x80;
    uint8_t data;

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_RESET);
    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
    HAL_SPI_Receive(&hspi1, &data, 1, 100);
    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);

    return data;
}
```

**主机侧表现**：读到的数据全是 `0xFF`、`0x00` 或上一次的旧值喵~

#### 场景二：从机中断处理延迟

```c
// 从机是另一颗 MCU，通过中断接收 SPI 数据
// 如果从机中断被更高优先级中断阻塞
// 或者从机在中断中做了太多操作
// 导致 SPI 接收缓冲区溢出

// 从机侧（如果也是 MCU）：
void SPI_IRQHandler(void) {
    // 如果这里执行太慢，主机的下一个字节已经到了
    // RXNE 标志被覆盖 → 数据丢失
    uint8_t data = SPI1->DR;
    process(data);  // 耗时操作！
}
```

**主机侧表现**：部分字节丢失或错位喵~

#### 场景三：从机 DMA 配置不及时

```c
// 从机使用 DMA 接收
// 如果 DMA 还没配置好，主机就开始发送
// 第一个或前几个字节会丢失

// 从机侧：
void setup_dma_receive(void) {
    HAL_SPI_Receive_DMA(&hspi1, rx_buf, len);
    // 如果主机在这之后立即发数据，可能丢失
}
```

**主机侧表现**：数据的前几个字节是垃圾值喵~

### 3. 主机侧的具体表现

| 表现 | 可能原因 | 诊断方法 |
|------|---------|---------|
| 读到全 0xFF | 从机未驱动 MISO（CS未选中或从机未初始化） | 示波器看 MISO 是否有变化 |
| 读到旧值 | 从机还没更新数据就返回了 | 加延时后重读，对比数据 |
| 部分字节错误 | 从机处理速度跟不上 SCK 频率 | 降低 SPI 频率测试 |
| 偶发错误 | 从机偶尔来不及（中断延迟、任务调度） | 统计错误率，关联系统负载 |
| OVR 标志置位 | 从机 RXNE 未及时读取就被新数据覆盖 | 检查从机 SR 寄存器 |
| 完全无响应 | 从机死机或 CS 接线问题 | 示波器看 CS/SCK/MISO |

### 4. 排查方法论

#### 第一步：确认是"慢"还是"错"

```c
// 用逻辑分析仪或示波器抓取完整通信波形
// 对比主机发送和从机返回的每一帧数据

// 如果是偶发错误：
// 1. 统计错误频率（每 1000 次出错几次）
// 2. 关联错误时刻的系统状态
// 3. 降低频率看是否消失

typedef struct {
    uint32_t total;
    uint32_t errors;
    uint32_t last_error_code;
    uint32_t last_error_tick;
} spi_stats_t;

static spi_stats_t spi_stats;

void spi_record_transfer(int result) {
    spi_stats.total++;
    if (result != HAL_OK) {
        spi_stats.errors++;
        spi_stats.last_error_code = result;
        spi_stats.last_error_tick = HAL_GetTick();
    }
}

float spi_error_rate(void) {
    if (spi_stats.total == 0) return 0;
    return (float)spi_stats.errors / spi_stats.total * 100;
}
```

#### 第二步：降频测试

```c
// 将 SPI 时钟降到最低（如 100kHz）
// 如果低频不出错 → 时序问题
// 如果低频也出错 → 配置或接线问题

void test_spi_frequencies(void) {
    uint32_t freqs[] = {100000, 500000, 1000000, 5000000, 10000000};
    uint32_t dividers[] = {
        SPI_BAUDRATEPRESCALER_256,
        SPI_BAUDRATEPRESCALER_64,
        SPI_BAUDRATEPRESCALER_32,
        SPI_BAUDRATEPRESCALER_8,
        SPI_BAUDRATEPRESCALER_4
    };

    for (int i = 0; i < 5; i++) {
        hspi1.Init.BaudRatePrescaler = dividers[i];
        HAL_SPI_Init(&hspi1);

        spi_stats = (spi_stats_t){0};
        for (int j = 0; j < 1000; j++) {
            spi_record_transfer(test_transfer());
        }

        printf("Freq %lu Hz: error rate = %.2f%%\n",
               freqs[i], spi_error_rate());
    }
}
```

#### 第三步：加延时验证

```c
// 如果怀疑从机需要准备时间
// 在命令和读数据之间加延时

uint8_t read_sensor_with_delay(uint8_t reg) {
    uint8_t cmd = reg | 0x80;
    uint8_t data;

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_RESET);

    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
    HAL_Delay(5);
    HAL_SPI_Receive(&hspi1, &data, 1, 100);

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);

    return data;
}

// 如果加延时后数据正确 → 确认是从机需要准备时间
// 逐步缩短延时，找到最小稳定延时
```

### 5. 常见解决方案

#### 方案一：协议层增加状态查询

```c
// 主机发命令后，轮询从机的"就绪"标志
// 而不是盲等固定延时

uint8_t read_sensor_polling(uint8_t reg) {
    uint8_t cmd = reg | 0x80;
    uint8_t status;
    uint8_t data;
    uint32_t timeout = 1000;

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_RESET);

    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);

    do {
        uint8_t dummy = 0xFF;
        HAL_SPI_TransmitReceive(&hspi1, &dummy, &status, 1, 100);
        timeout--;
    } while (status != 0xAA && timeout > 0);

    if (timeout == 0) {
        HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);
        return 0xFF;
    }

    uint8_t dummy = 0xFF;
    HAL_SPI_TransmitReceive(&hspi1, &dummy, &data, 1, 100);

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);
    return data;
}
```

#### 方案二：额外 GPIO 作为就绪信号

```c
// 从机准备完成后拉高 GPIO，主机检测到后读取
// 比 SPI 轮询更快更可靠

uint8_t read_sensor_with_ready(uint8_t reg) {
    uint8_t cmd = reg | 0x80;
    uint8_t data;

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_RESET);
    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);

    uint32_t timeout = 10000;
    while (HAL_GPIO_ReadPin(SENSOR_READY_PORT, SENSOR_READY_PIN) == GPIO_PIN_RESET) {
        if (--timeout == 0) {
            HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);
            return 0xFF;
        }
    }

    HAL_SPI_Receive(&hspi1, &data, 1, 100);
    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);

    return data;
}
```

#### 方案三：降低 SPI 时钟频率

```c
// 如果从机最大支持的 SCK 频率低于当前配置
// 或者长走线导致信号质量差
// 降低频率是最简单的解决方案

// 从 10 MHz 降到 1 MHz
hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_32;
HAL_SPI_Init(&hspi1);
```

#### 方案四：重试 + 校验机制

```c
#define MAX_SPI_RETRY  3

int spi_read_with_retry(uint8_t reg, uint8_t *data) {
    for (int retry = 0; retry < MAX_SPI_RETRY; retry++) {
        *data = read_sensor(reg);

        if (is_valid_data(*data)) {
            return 0;
        }

        HAL_Delay(1);
    }

    return -1;
}

// 带CRC的帧格式
typedef struct {
    uint8_t cmd;
    uint8_t data[4];
    uint8_t crc;
} spi_frame_t;

int spi_transfer_verified(spi_frame_t *tx, spi_frame_t *rx) {
    tx->crc = calc_crc8(tx->data, 4);

    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_RESET);
    HAL_SPI_TransmitReceive(&hspi1, (uint8_t *)tx, (uint8_t *)rx,
                            sizeof(spi_frame_t), 100);
    HAL_GPIO_WritePin(SPI_CS_PORT, SPI_CS_PIN, GPIO_PIN_SET);

    uint8_t crc = calc_crc8(rx->data, 4);
    if (crc != rx->crc) {
        return -1;
    }

    return 0;
}
```

### 6. 排查流程总结

```
SPI 通信异常
     │
     ▼
┌──────────────┐
│ 降频到 100kHz │──问题消失──▶ 时序/信号完整性问题
│ 测试         │             → 降低工作频率
└──────┬───────┘             → 检查走线
       │ 不消失              → 检查 GPIO 驱动能力
       ▼
┌──────────────┐
│ 加延时后重读  │──数据正确──▶ 从机需要准备时间
│ 测试         │             → 加状态查询/GPIO ready
└──────┬───────┘             → 或固定延时
       │ 仍错误
       ▼
┌──────────────┐
│ 示波器/逻辑  │──波形异常──▶ 硬件问题
│ 分析仪抓波形  │             → 检查接线、电源、焊接
└──────┬───────┘
       │ 波形正常
       ▼
┌──────────────┐
│ 检查从机状态  │──从机异常──→ 从机固件问题
│ 寄存器和日志  │             → 检查从机中断/DMA配置
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 加 CRC +     │             → 提高鲁棒性
│ 重试机制     │             → 记录错误日志
└──────────────┘
```
