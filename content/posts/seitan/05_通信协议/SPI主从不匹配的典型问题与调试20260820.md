# SPI主从不匹配的典型问题与调试

SPI 没有标准组织、没有合规认证，主控和外设之间"是不是同一个 SPI"从来不靠协议协商，而是靠**事实约定 + 数据手册人工对表 + 电气匹配**拼出来的。平时用 HAL 库 + 现成驱动一切正常，一旦裁剪 HAL、迁移芯片、更换外设型号（换料/替代料），这些被隐藏的对表工作就会重新暴露出来。本文按层归堆这些不匹配问题，每条基于真实芯片，并给出症状→根因的速查表。

## 同一性从哪来：三层契约

| 层 | 内容 | 谁来保证 |
|------|------|------|
| 事实约定 | mode 0、MSB first、CS 低有效、8 位帧、低速起步 | 全行业几十年收敛的最大公约数，所有厂家扩展都向后兼容它 |
| 数据手册 | 支持的 CPOL/CPHA、fmax、位序、dummy 周期、命令集 | 工程师人工对表配置，配错没有任何协议层报错 |
| 电气层 | 电压域、VIH/VIL、走线 | 原理图阶段人工确认 |

SPI 没有 ACK、没有版本协商、没有错误检测，线上是什么就是什么——所以 SPI 调试离不开逻辑分析仪，这是它与 I2C（有 ACK 反馈）调试体验的本质区别。

## 模式层：不是所有器件都兼容 mode 0/3

最常见的 flash 确实 mode 0/3 都支持，造成"SPI 随便配"的错觉，但真实分布是：

| 器件 | 支持的模式 | 踩坑点 |
|------|-----------|--------|
| Winbond W25Q 系列、Microchip MCP2515 | mode 0 和 3 | 产生"随便配"错觉的来源 |
| ENC28J60、nRF24L01+ | 仅 mode 0 | 从 mode 3 设备迁移配置就挂 |
| TI ADS1256（24 位 ADC） | 仅 mode 1 | 默认 mode 0 的驱动直接数据错乱 |
| Maxim MAX31855（热电偶） | 仅 mode 1 | Adafruit 官方库明写 `SPI_MODE1` |
| TI ADS1299（生物电 AFE） | 仅 mode 1 | OpenBCI 官方固件即设 `SPI_MODE1` |
| ST MEMS 家族（LIS3DH、LSM6DS3）、ILI9341 | 仅 mode 3 | Linux 内核 `st_sensors` 框架统一 mode 3 |

症状规律：**CPHA 差半拍 → 数据整体错一位；CPOL 反了 → 首 bit 丢失或读全 0xFF**。

TI 的精密 ADC/AFE（ADS1256、ADS1299）是 mode 1 的重灾区，同一个厂家的接口约定一脉相承——做模拟前端采集的驱动模板不能从 flash 驱动抄模式配置。

## 位序与帧长：小众器件的格式陷阱

| 器件 | 特殊格式 | 后果 |
|------|---------|------|
| PCD8544（Nokia 5110 屏） | LSB first | 硬件 SPI 默认 MSB，显示"镜像乱码"，Adafruit 库在软件里逐位反转再发 |
| PCF8833（Nokia 6100 屏） | 9 位 SPI（D/C 是第 9 位） | STM32F1 的 SPI 只支持 8/16 位帧（CR1 的 DFF 就一位），9 位帧配不出来只能位带模拟；F3/L4/H7 起才支持 4~16 位任意帧长 |
| ADNS2610（光学鼠标 sensor） | 三线 SPI（SDIO 双向单线） | 标准四线主控接不上，STM32 要开 CR1 的 BIDIMODE 半双工模式 |

## CS 行为：冲突最多的一层

### 从机要求"全程保持"，主控给不了

W25Q 系列手册规定命令+地址+数据期间 CS 必须连续为低，中途弹起即命令作废。而主控侧被逼出的一系列补丁，本身就是这个问题真实存在的化石证据：

- STM32 F1/F4 时代硬件 NSS 的帧间行为不可控，社区结论"驱动 flash 一律软件 CS"沿用至今
- ESP32 的 SPI 驱动专门加了 `SPI_TRANS_CS_KEEP_ACTIVE` 标志，让相邻事务拼接时 CS 不断开
- STM32H7 的 SPI_CFG2 新增 SSOM 位，显式选择"帧间保持"还是"帧间脉冲"

### 从机要求"必须翻转"

MAX31855 的转换结果只在 CS 为高期间装载进移位寄存器——CS 不拉高，读一百次都是同一帧。症状是"数据合法但永远不更新"，极具迷惑性。

### 从机对"CS 电平 + 时钟"组合有前置要求

SD 卡进 SPI 模式前，物理层规范要求先在 CS 和 MOSI 都为高时打 74 个时钟（所以所有 SD 初始化代码开头都有一段发 10 个 0xFF 的操作）；且必须在 CS 为低时发 CMD0 才能进入 SPI 模式——**一张被 SDIO 驱动用过的卡，不重新上电切不回 SPI 模式**。

### CS 永久接地 = 总线共享的定时炸弹

TI ADS1299 手册允许 CS 永久拉低省掉片选管理，但代价是空闲时 DIN 必须保持低电平。一旦把它挂上共享 SPI 总线，对其他器件的每次读写字节流都会被 1299 解码成一串杂命令（可能改写寄存器配置）——这是"总线共享层"最隐蔽的真实案例。

## 速度上限与下限：双向都有坑

### 上限：同一条总线、同一个芯片、不同命令不同限速

| 器件 | 限制 |
|------|------|
| Winbond W25Q64JV | 0x03 普通读 ≤50MHz，0x0B 快读 ≤133MHz——命令决定时序余量，0x0B 存在的意义就是这个 |
| ENC28J60 | SPI 上限仅 10MHz |
| TI ADS1256 | SCLK ≤ fCLKIN/4（7.68MHz 晶振时约 1.9MHz） |

### 下限：读不过来也是不匹配

TI ADS1299 连续读模式下每帧 = 24 位状态字 + 8 通道 × 24 位 = **216 位**，且必须在下一个 DRDY 到来前读完。最高 16kSPS 时帧间隔 62.5µs，平均 SCLK 至少约 3.5MHz——**时钟太慢会丢帧**。这与 flash 的"超速读错数据"正好是对偶问题：flash 怕太快，ADS1299 怕太慢。

超速的症状是"裕量型失败"：短线能跑长线挂、低温能跑高温挂、板子之间良率不一——不做确定性复现，最难排查。

## 命令层：挂在 SPI 传输层上的私有协议皮

- **QE（四线使能）位各家不同**：Winbond 的 QE 在状态寄存器-2 的 S1，要用 0x31 命令写；Macronix MX25L 的 QE 在状态寄存器-1 的 S6，用 0x01 一起写。Linux 的 spi-nor 子系统至今为 QE 维护按厂商区分的处理函数——驱动只按一家模板写，换牌子后**单线读正常、四线读全 0xFF**，极难排查
- **W25Q256（32MB）的 16MB 悬崖**：容量超过 16MB 后必须进 4 字节地址模式（EN4B 或换 0x13/0x0C 命令集），只发 3 字节地址的驱动会在 16MB 处静默回绕
- **dummy 周期数随命令甚至随模式变**：0x03 无 dummy，0x0B 是 8 个，0xEB 在 SPI 模式下 4 个、切到 QPI 后变 2 个。差一个 dummy 数据整体移位——症状和 CPHA 配错很像，容易查错方向
- **页写入 256 字节回绕**：Page Program 一个命令写超过 256 字节时页内地址 A7-A0 回绕，后半段数据覆盖前半段开头，不报任何错
- **写/擦期间读**：不轮询状态寄存器 SR1 的 BUSY 位就去读，读到的是未定义数据

## 电气层

- **3.3V 主控驱 5V 的 74HC595**：VIH = 0.7×VCC = 3.5V > 3.3V，工作在临界区，症状"时好时坏、跟温度和个体相关"。修法：换 74HCT（VIH=2V）或让 595 也跑 3.3V
- **1.8V 家族与 3.3V 同封装混料**：Macronix 的 MX25U（1.8V）和 MX25L（3V）封装兼容，BOM 混入即过压，读数像鬼影

## 总线共享

- SDIO/SPI 模式残留（见 CS 行为一节，需断电重置）
- 个别老器件 CS 拉高后不释放 MISO，拉死整条共享总线——症状是"挂上它之后别的器件也读不了"

## 主控侧固有差异（迁移芯片时撞上）

- FIFO 深度、DMA 描述符结构、单次事务最大长度（ESP32 的 DMA 单事务有长度上限，长读要靠 CS 保持标志拼接）
- 纯 RX 主模式的停机判据各家不同（BSY/RXNE 的时序关系），停早丢字节、停晚多发时钟
- 带 QSPI IP 的片子（如 i.MX RT 的 FlexSPI）用 LUT 查找表描述命令序列——等于厂家承认"协议皮问题"是常态，干脆显式化成配置项

## 软件 CS：最通用的兜底

```c
#define FLASH_CS_L()  LL_GPIO_ResetOutputPin(GPIOA, LL_GPIO_PIN_4)
#define FLASH_CS_H()  LL_GPIO_SetOutputPin(GPIOA, LL_GPIO_PIN_4)

uint8_t flash_read_status(void)
{
    uint8_t sr;
    FLASH_CS_L();
    sr = spi_rw(0x05);       // 发 RDSR 命令,全双工同时收
    sr = spi_rw(0xFF);       // 发 dummy 字节,收返回
    FLASH_CS_H();
    return sr;
}
```

牺牲一点 GPIO 操作时间，换取对 CS 时序的完全控制——整段命令期间 CS 保持、何时弹起全由代码说了算，绕开所有硬件 NSS 的帧间行为差异。这也是它成为社区默认实践的原因。

## 症状速查表（调试时反着查）

| 症状 | 首查项 |
|------|--------|
| 读全 0xFF / 0x00 | 片选、供电、模式、电压域 |
| 数据固定错一位 | CPHA 差半拍（mode 0↔1、2↔3） |
| 第一字节对、后面全错 | flash：dummy 周期数 |
| 地址超过 16MB 回绕 | 4 字节地址模式没开（W25Q256 类） |
| 页写后数据自相覆盖 | 256 字节页回绕 |
| 单线正常、四线全 0xFF | QE 位没按这家厂商的方式置位 |
| 数据合法但永远不更新 | MAX31855 类：CS 没翻转 |
| 数据帧偶发丢失 | ADS1299 类：SCLK 太慢读不完一个帧间隔 |
| 命令偶发被截断 | 硬件 NSS 中途弹起 |
| 短线能跑、长线挂 | 时钟超限 / 信号完整性 |
| 显示内容像位镜像 | LSB-first 器件（PCD8544 类） |
| 别的器件一上线它就乱 | 共享总线 + CS 接地器件把流量当命令解码 |

## 速记口诀

- SPI 无标准组织，同一性 = 事实约定 + 手册对表 + 电气匹配，没有任何协议内保障
- 器件模式分布：flash 0/3 皆可，TI 精密 ADC/AFE（ADS1256/ADS1299）仅 mode 1，ST MEMS 仅 mode 3
- CPHA 错半拍 = 数据错一位；dummy 错一个 = 后面全错——症状像，方向别查偏
- CS 三向冲突：要求保持（flash）、要求翻转（MAX31855）、要求特定电平时序（SD 卡 74 时钟）
- CS 接地要谨慎：ADS1299 类器件会把共享总线流量解码成命令
- 速度双向都有坑：flash 怕快（0x03 只有 50MHz），ADS1299 怕慢（216 位帧赶 DRDY）
- QE 位一家一个样，换 flash 品牌必查
- 硬件 NSS 不可靠是历史共识：软件 CS 是兜底，新主控的 SSOM/KEEP_ACTIVE 标志是后来补的课
