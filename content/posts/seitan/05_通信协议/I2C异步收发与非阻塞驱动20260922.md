# I2C异步收发与非阻塞驱动

## 题目

有关于异步 I2C：I2C 不是同步协议吗，"异步 I2C"到底指什么？怎么用中断、DMA 方式做非阻塞的 I2C 收发，异步驱动层怎么设计？

## 考察点

同步/异步的概念辨析（协议层 vs 驱动层）、阻塞轮询/中断/DMA 三种收发方式对比、异步驱动的状态机与队列设计、回调与错误路径、RTOS 下的封装、平台差异、总线挂死恢复。

## 回答要点

### 1. 概念辨析：I2C 是同步协议，"异步"说的是驱动用法

I2C 协议本身是**同步**的：SCL 时钟线由主机驱动，每个 bit 都在时钟沿上对齐，不存在"异步 I2C 协议"。工程语境里的"异步 I2C"指**驱动层的非阻塞用法**——发起传输后 CPU 不原地等它完成，传输由中断/DMA 在后台推进，完成后用回调或信号量通知。

两个维度是正交的，放一张表就清楚：

| | 协议层同步（I2C/SPI） | 协议层异步（UART） |
|---|---|---|
| **驱动阻塞**（轮询忙等） | `HAL_I2C_Master_Transmit` | `HAL_UART_Transmit` |
| **驱动非阻塞**（中断/DMA+回调） | `HAL_I2C_Master_Transmit_IT/_DMA` | `HAL_UART_Transmit_IT/_DMA` |

上一条竖线里的下方那格就是本文主题。它和《DMA串口接收数据解析与吞吐优化》是同一套思想在不同总线上的落地：**让 CPU 在传输期间去干别的**。

### 2. 三种收发方式对比与选型

以 STM32 HAL 为例：

| 方式 | API 后缀 | 传输期间 CPU | 每字节介入 | 适用场景 |
|------|---------|------------|-----------|---------|
| 阻塞轮询 | 无 | 全占（查标志忙等） | — | 上电初始化配置、极低频访问 |
| 中断非阻塞 | `_IT` | 空闲，事件进 ISR | 每字节 1~2 次中断 | 通用，短传输 |
| DMA 非阻塞 | `_DMA` | 空闲，仅启停介入 | 无 | 大块传输：传感器批量读、EEPROM 页写、摄像头配置 |

定量感受：400kHz 快速模式读 MPU6050 的 14 字节 ≈ 0.33ms。100Hz 采样下阻塞式纯忙等约占 3.3% CPU——看着不多，但**阻塞的真正代价不是 CPU 占用，而是任务停摆**：RTOS 里拿着别的资源忙等会放大优先级反转，中断里调用阻塞版更可能直接死锁（I2C 中断本身进不来，完成标志永远等不到）。所以异步不是"高性能才需要"，而是**任何多任务/多外设系统的基本盘**。

### 3. 异步驱动的三件套：状态机、回调、错误路径

- **状态机推进**：硬件 I2C 的 TXE/RXNE/ADDR/STOPF/TC 等标志，阻塞版在循环里查，异步版搬进 ISR 查——`_IT`/`_DMA` 版 HAL 内部就是这样一个状态机，调用立即返回 `HAL_OK`，传输由中断推进
- **完成回调**：`HAL_I2C_MemRxCpltCallback` / `HAL_I2C_MemTxCpltCallback` 等在最后一次中断里被调用，是"结果交付点"
- **错误回调**：`HAL_I2C_ErrorCallback` 里查 `hi2c->ErrorCode`——NACK（从机不应答，多半是地址错或器件忙）、ARLO（多主仲裁丢失）、BERR（总线时序错）

异步 API 的三条纪律：

1. **一条总线同一时刻只有一个在途传输**，必须在完成或出错回调之后才能发起下一个，否则 `HAL_BUSY`
2. **回调运行在中断上下文**：不能阻塞、不能再调用阻塞版 I2C、尽量短——回调里只做通知，解析处理放任务
3. **必须有超时兜底**：异步传输没有天然的"卡死感知"，从机时钟拉伸异常或总线挂死不会自愈，软件定时器/信号量超时是最后防线

### 4. 队列化：多任务多从机共用一条总线

实际系统一条 I2C 上挂多个器件、多个任务都要访问，异步驱动要在"单在途传输"约束上再叠一层**请求队列**：

- API 形态：提交 `(从机地址, 读/写, 寄存器地址, 缓冲, 长度, 完成回调)` 入队后立即返回
- 总线空闲则立刻启动硬件；忙则排队，完成回调里取队首接力启动
- 生产者侧用关中断或互斥锁保护队列的入队操作（ISR 只出队不入队，方向单一，竞态窗口小）

裸机没有"提交任务"的一方，等价物是"主循环各状态机按序置请求标志"，调度逻辑相同。

### 5. 代码示例

最小可用形态——任务侧发起 DMA 读，信号量同步等待（内部异步，外部可控地等）：

```c
static SemaphoreHandle_t i2c_done_sem;
static volatile int i2c_err;

void mpu6050_init(void)
{
    i2c_done_sem = xSemaphoreCreateBinary();
}

// 异步发起 + 可选等待：内部非阻塞，外部用信号量收敛
int mpu6050_read_accel_dma(uint8_t *buf)
{
    if (HAL_I2C_Mem_Read_DMA(&hi2c1, MPU_ADDR << 1, ACCEL_REG,
                             I2C_MEMADD_SIZE_8BIT, buf, 14) != HAL_OK)
        return -1;

    if (xSemaphoreTake(i2c_done_sem, pdMS_TO_TICKS(10)) != pdTRUE)
        return -2;                      // 超时：总线异常，走恢复流程
    return i2c_err ? -3 : 0;
}

void HAL_I2C_MemRxCpltCallback(I2C_HandleTypeDef *hi2c)
{
    i2c_err = 0;
    xSemaphoreGiveFromISR(i2c_done_sem, NULL);
}

void HAL_I2C_ErrorCallback(I2C_HandleTypeDef *hi2c)
{
    i2c_err = hi2c->ErrorCode;
    xSemaphoreGiveFromISR(i2c_done_sem, NULL);
}
```

队列化骨架——多请求串行：

```c
typedef struct {
    uint16_t addr;                      // 含读写位的从机地址
    uint16_t mem;                       // 寄存器地址
    uint8_t *buf;
    uint16_t len;
    uint8_t  is_read;
    void (*done)(void *arg, int err);   // 完成回调，中断上下文里调
    void *arg;
} i2c_req_t;

int i2c_submit(i2c_req_t *r)            // 关中断保护下入队；总线空闲则立即启动
{
    // 入队后若总线空闲：调 HAL_I2C_Mem_Read/Write_DMA 启动
    // 否则等回调接力
}

// 每个 MemRxCpltCallback / MemTxCpltCallback / ErrorCallback 的公共尾巴：
// 通知当前请求的 done()，取队首启动下一个
```

### 6. 平台差异

| 平台 | 异步形态 |
|------|---------|
| 裸机 | 中断状态机 + 主循环轮询完成标志；软件模拟 I2C（GPIO 位拆）也能异步化——主循环或定时器分步推进状态机，速度慢但引脚灵活 |
| RTOS（MCU） | `_IT`/`_DMA` + 完成信号量/任务通知；对上层可再封同步外观（内部异步、外部可选等待），本文示例即此形态 |
| Linux | `i2c_transfer()` 在内核 API 层是同步语义（驱动内部可以用中断/DMA），用户态 `read/ioctl` 阻塞或 `O_NONBLOCK`；regmap 再叠异步缓存写合并。应用层基本感知不到中断细节，"异步"体现在系统调用行为上 |

### 7. 错误处理与总线恢复（异步特有）

- **NACK**：HAL 收到 NACK 会自动发 STOP 并进错误回调；器件偶尔 NACK（如 EEPROM 页写期间"忙"）的标准对策是重试若干次
- **总线挂死**：从机在传输中途复位，把 SDA 拉死在低电平，主机连 START 都发不出去。标准恢复手法：手动控制 SCL 打最多 9 个时钟脉冲，直到从机释放 SDA，再补一个 STOP；无效则复位 I2C 外设重新初始化引脚
- **超时看门狗**：每笔在途请求挂一个软件定时器，超时未回调即按挂死处理——异步驱动没有它等于裸奔
- 详细排查思路见《I2C底层通信机制与异常排查》

### 8. 高频坑清单

1. **在中断里调阻塞版**：I2C 中断被挡住，完成标志永远置不了，死等
2. **上一个没完成就发起下一个**：`HAL_BUSY` 被无视，丢请求
3. **回调里干重活**：printf/长解析拖慢整条总线，多器件排队雪崩
4. **局部数组当 DMA 缓冲**：函数已返回，DMA 还在往失效的栈帧里写——缓冲必须跨越传输生命周期（static 或调用者持有）
5. **没有超时**：从机异常时任务永远挂起，还占着队列
6. **带 D-Cache 的芯片不做维护**：DMA 写的是内存，CPU 读的是 cache 旧值
7. **队列入队没做并发保护**：多任务同时 submit 竞态

### 9. 一句话总结

**"异步 I2C"不是协议是用法——同步的 SCL 之上，用中断/DMA 把传输变成后台任务：状态机推进、回调交差、队列串行、超时兜底**，CPU 全程不必陪跑。
