# UART 串口通信基础与帧格式

UART（通用异步收发器）是嵌入式里最古老也最常用的通信接口：两根线、异步、全双工，调试打印和模块对接都靠它。本文整理它的帧格式、波特率机制、电平标准与常见问题。

## 核心特性

- **异步**：没有时钟线，收发双方事先约定波特率，接收端用本地时钟过采样恢复数据；
- **全双工**：TX/RX 两根独立信号线，可同时收发；
- **点对点**：一主一从直连（不同于总线型多机的 RS-485/CAN）；
- 硬件简单、速率不高（常见 9600~115200 bps，短距离可到数 Mbps）。

## 帧格式

空闲时 TX 保持高电平，一帧数据从起始位（拉低一个位时间）开始：

```
空闲  ──┐ 起始位   D0  D1  D2  D3  D4  D5  D6  D7   校验(可选)  停止位  ──┐ 空闲
(高)    └──▼──  ┌───┬───┬───┬───┬───┬───┬───┬───┐                ┌─┐
        1bit低 │      数据位 5~8 位（LSB 先发）      │  0/1 bit      │1│
               └───┴───┴───┴───┴───┴───┴───┴───┘                └─┘
```

- **起始位**：1 位低电平，接收端检测到下降沿后按位时间对齐采样；
- **数据位**：5~8 位可配（几乎总用 8 位），LSB 在前；
- **校验位**：可选 none/odd/even，弱校验（只能发现奇数个位错），原理见下文专节；
- **停止位**：1、1.5 或 2 位高电平，帧间回到空闲。

最常用配置写作 **8-N-1**（8 数据位、无校验、1 停止位）——串口调不通时第一件事就是核对两端的波特率与 8-N-1 配置。

## 校验位：奇校验与偶校验

校验位（parity bit）是数据位后附加的 1 位，发送端统计 D0~D7 中 "1" 的个数并补一位，使整帧满足约定：

- **偶校验（even）**：数据位 + 校验位中 1 的总个数为偶数——数据里已有偶数个 1 则校验位置 0，奇数个则置 1；
- **奇校验（odd）**：数据位 + 校验位中 1 的总个数为奇数。

| 数据（D0~D7） | 数据中 1 的个数 | 偶校验位 | 奇校验位 |
| --- | --- | --- | --- |
| 0x55（0101 0101） | 4 | 0 | 1 |
| 0x07（0000 0111） | 3 | 1 | 0 |

接收端对收到的数据位重新统计并与校验位比对，不符就置 **PE（Parity Error）标志**，软件查到后按出错帧丢弃或请求重发。两端校验方式必须配置一致，一边 none 一边 even 时所有带校验帧都报 PE。

发送端常用异或折叠计算偶校验位：

```c
uint8_t parity_even(uint8_t d)
{
    d ^= d >> 4;
    d ^= d >> 2;
    d ^= d >> 1;
    return d & 1;    // 1 的个数为奇数则返回 1，正好是要补的偶校验位
}
```

**局限要能说清**：

1. 只能检测**奇数个位翻转**（1、3、5…位同时错），偶数个位同时翻转相互抵消，检测不到——所以它是"弱校验"；
2. 只能检错不能纠错，不知道错的是哪一位；
3. 可靠传输场景升级为 CRC（如 MODBUS-RTU 用 CRC16）或上层校验和，UART 校验位只是最底层的低成本兜底。

## 波特率与采样恢复

双方各自用自己的本地时钟，**波特率误差必须控制在 ±2~3% 以内**（最后一位停止位采样点累积偏差不越过半个位）。接收端通常在位中心 16 倍过采样（16x oversampling）取多数，提高抗抖动能力。

```
所需精度 ≈ 0.5 / 位总数 ≈ 0.5/10 = 5%（理论），留裕量后工程上取 ≤2%
```

MCU 的 UART 波特率由时钟分频产生，奇怪的分频比是误差来源——例如 72MHz 时钟下 115200 的分频误差远小于某些低频时钟下的结果。

## 电平标准：UART ≠ RS-232 ≠ RS-485

| 名字 | 层级 | 电平 | 距离/拓扑 |
| --- | --- | --- | --- |
| UART（TTL） | 芯片引脚 | 0 / 3.3V（或 5V） | 板内十几 cm，点对点 |
| RS-232 | 电气标准 | ±3~15V 单端 | ~15m，点对点 |
| RS-485 | 电气标准 | 差分 ±1.5V 以上 | ~1200m，多点总线 |

MCU 的 TX/RX 是 TTL 电平，接 PC 的 DB9 要经 MAX232 电平转换，长距离多机要走 RS-485 收发器——**UART 是数据链路层的帧协议，RS-232/485 只是物理层电气标准**，可以组合（UART 帧 over RS-485 总线）。

## 与 SPI / I2C 对比

| | UART | SPI | I2C |
| --- | --- | --- | --- |
| 时钟 | 无（异步） | 有 | 有 |
| 线数 | 2（TX/RX） | 4+（MOSI/MISO/SCK/CS） | 2（SDA/SCL） |
| 双工 | 全双工 | 全双工 | 半双工 |
| 拓扑 | 点对点 | 一主多从 | 多主多从（地址） |
| 典型速率 | ≤1 Mbps | 数十 Mbps | 100k~3.4M |
| 典型用途 | 调试打印、GPS/蓝牙模块 | Flash、屏幕、高速传感器 | 低速传感器、配置接口 |

## 常见问题排查

- **收到乱码**：波特率不匹配（占 90%）、时钟配置与波特率计算不符、数据位/校验配置不一致；
- **只收不发 / 只发不收**：TX/RX 交叉接反（A 的 TX 接 B 的 RX）；
- **偶尔丢字节**：软件未及时读走 DR 触发 overrun（ORE 标志）、中断被长时间屏蔽——用 DMA + 空闲中断接收更稳；
- **帧错（FE）/ 校验错（PE）**：波特率边界、地线未共地、干扰——强干扰场景的应对见 [高可靠通信模块设计UART与CAN抗干扰](../13_嵌入式系统设计/高可靠通信模块设计UART与CAN抗干扰20260420.md)；
- 波形层面：示波器量一个位时间反推实际波特率（1 位时间 = 1/baud），是最硬的核对手段。
