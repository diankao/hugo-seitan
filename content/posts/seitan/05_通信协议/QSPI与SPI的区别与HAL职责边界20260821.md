# QSPI与SPI的区别与HAL职责边界

一句话定位：**QSPI 不是新协议，是 SPI 针对 flash 场景的四线数据扩展**——时钟和片选不动，数据线从 1 条变 4 条，而且线宽由每条命令自己决定。但"QSPI"一词在器件侧和 MCU 侧各指一样东西，需要拆开讲；顺带厘清一个常见误区——用了 HAL 是否就不用关心它的细节。

## 一、器件协议角度：线宽可切换的 SPI

四线 flash 的引脚从 `MOSI/MISO/WP/HOLD` 改名 `IO0/IO1/IO2/IO3`——后两条是从写保护和保持脚征用来的（QE 位置 1 后 WP/HOLD 功能失效，硬件接法要注意）。同一个器件上单线和四线命令并存，行业标准用"命令-地址-数据"三元组表示线宽：

| 命令 | 三元组 | 含义 |
|------|------|------|
| 0x03 | 1-1-1 | 传统慢读，纯 SPI |
| 0x3B / 0xBB | 1-1-2 / 1-2-2 | 双线过渡形态 |
| 0x6B | **1-1-4** | 命令地址单线、数据四线 |
| 0xEB | **4-4-4** | 全四线（QPI 风格访问） |

三个关键机制：

- **上电默认单线**。所有厂家扩展都保持对 mode 0 单线读的向后兼容（全行业最大公约数），必须先用单线命令置 QE 位，四线命令才生效——而 QE 位的位置一家一个样（Winbond 在 SR2 经 0x31 写，MXIC 在 SR1 经 0x01 写），忘了或写错就是"单线正常、四线全 0xFF"的经典坑
- **QPI 模式是更激进的 4-4-4**：连命令相位都走四线（0x38 进入、0xFF 退出），省掉单线命令的字节时间，但主从双方都得在 QPI 里，退出前复位另一边就失联
- **dummy 周期随命令和频率变**：四线读的 dummy 配错一个，数据整体移位——和 CPHA 配错症状很像，排查方向别搞混

速率账：50MHz 单线 = 50Mbps，100MHz 四线 = 400Mbps。但**不是所有访问都快 4 倍**：读状态寄存器这类小命令永远走单线；随机小块访问的延迟被命令+地址+dummy 相位主导，四线收益有限——连续大块读收益最大。

## 二、MCU 外设角度：QSPI 是"会发命令序列的控制器"

普通 SPI 外设**干不了四线的活**（数据引脚就两条），四线必须专用外设——STM32 的 QUADSPI、i.MX RT 的 FlexSPI、ESP32 的可配置 SPI。它和普通 SPI 外设的差别不是线数，是结构性的：

| | 普通 SPI 外设 | QSPI 控制器 |
|---|---|---|
| 工作单位 | 字节/缓冲区，软件搬运 | 完整命令序列：命令/地址/dummy/数据四相位各自配置线宽和长度 |
| 使用方式 | 间接模式（读写 FIFO） | 间接模式 + **内存映射模式（XIP）** |
| XIP | 无 | flash 映射进 MCU 地址空间，CPU 直接取指执行 |
| 配套 | — | 预取/缓存（对冲随机取指的小块访问短板）、连续读模式支持 |

**XIP 是 QSPI 控制器存在的最大理由**：代码放在片外 flash 上直接跑，CPU 像访问 SRAM 一样取指，控制器在后台拼装命令序列。它依赖 flash 的连续读模式（把命令字节替换成模式位 M[7:0]），配套的预取和缓存就是补"随机小块访问四线收益小"的短板。

所以 QSPI 的实现有**两半，缺一不可**：flash 芯片支持四线命令（器件侧），MCU 有四线控制器（主控侧）。不存在"QSPI 只藏在 flash 里、主控无所谓"——选型时主控侧的控制器决定了能不能用四线。

## 三、两个必踩的关联坑

- **XIP 与擦写冲突**：代码正在 flash 里执行时不能擦写它——要么把擦写函数搬进 RAM（RAMFUNC），要么用双区 RWW
- **模式切换残留**：STM32 上用 XIP 时突然切间接模式发命令，控制器 busy/ABORT 处理不干净会挂住

## 四、HAL 的真实边界：帮你"怎么发"，不替你决定"发什么"

STM32 的 QSPI HAL 是"最需要懂协议的 HAL"，因为它的 API 参数表**本身就是一份协议知识清单**：

```c
QSPI_CommandTypeDef cmd = {0};
cmd.InstructionMode   = QSPI_INSTRUCTION_1_LINE;   // 命令相位线宽:你定
cmd.Instruction       = QUAD_CMD_FAST_READ_QUAD;   // 用哪条命令:你定
cmd.AddressMode       = QSPI_ADDRESS_1_LINE;       // 地址相位线宽:你定
cmd.AddressSize       = QSPI_ADDRESS_24_BITS;      // 地址长度:你定
cmd.DataMode          = QSPI_DATA_4_LINES;         // 数据相位线宽:你定
cmd.DummyCycles       = 4;                         // dummy 数:你查手册定
HAL_QSPI_Command(&hqspi, &cmd, HAL_QSPI_TIMEOUT);
```

1-1-4 三元组、命令码、dummy 周期数全是开发者填的。HAL 不知道接的是哪颗 flash，它只负责把描述好的命令序列翻译成控制器寄存器操作和 FIFO/DMA 搬运——**HAL 抽象的是主控侧寄存器细节，外设侧的命令皮原封不动仍是驱动开发者的职责**。

| HAL 替你做的 | 仍然属于你的 |
|---|---|
| 控制器寄存器配置、时钟 | **QE 位置位**（各家位置和写法不同） |
| FIFO/DMA/中断/超时框架 | **dummy 周期数**（随命令、频率、厂家变） |
| 命令序列的硬件发射 | **命令选择**（0x03/0x0B/0x6B/0xEB 的取舍） |
| AutoPolling 轮询机制 | **轮询什么**（BUSY/WIP 的掩码和匹配值还是你配） |
| 内存映射模式的启用 | **XIP 与擦写冲突**（RAMFUNC 搬迁自己做，HAL 不会自己搬家） |
| — | 容量超 16MB 的 4 字节地址模式、扇区保护配置 |

一个例外：STM32 对个别评估板 flash 提供了 BSP/中间件驱动，里面带现成的器件表（QE、dummy 都写好了）——用那几颗特定芯片确实能再省一层，但**换料即失效**。

调试视角最能说明边界：QE 没置位时，HAL 返回的是 `HAL_QSPI_ERROR`（传输错误/超时），它不知道也不告诉你"这是 QE 在 SR2 没置"——**细节的全部成本在出问题的那一刻重新出现**。"用 HAL 所以不用懂"是错觉，"用 HAL 所以不用手搓寄存器"才是事实。

## 速记口诀

- QSPI = SPI 的四线数据扩展：CLK/CS 不动，IO0-IO3 四条数据线，线宽按命令切换
- 三元组记法：0x03 是 1-1-1，0x6B 是 1-1-4，0xEB 是 4-4-4；上电默认单线，置 QE 才进四线
- QE 一家一个样（Winbond SR2 / MXIC SR1），忘置的症状是"单线正常、四线全 FF"
- QSPI 两半实现：器件侧的命令支持 + 主控侧的专用控制器，普通 SPI 外设物理上做不了四线
- XIP 是 QSPI 控制器存在的最大理由，预取/缓存补随机小块访问的短板
- XIP 下擦自己 = 灾难，擦写函数 RAMFUNC 搬出去
- HAL 帮你"怎么发"，你决定"发什么"——QSPI HAL 的参数表本身就是协议知识清单
